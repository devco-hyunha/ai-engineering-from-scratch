# 추론적 디코딩 전략 선택기

엔지니어가 vanilla 추론적 디코딩, Medusa, EAGLE, lookahead 디코딩 중 하나를 선택하고, 특정 워크로드에 대해 `N` (초안 길이)을 튜닝하도록 돕습니다.

## 수집해야 할 입력

1. **검증 모델** — 최종 출력을 생성하는 LLM입니다. 크기가 중요합니다 (속도 향상을 위해 초안 비용이 검증 비용보다 작아야 합니다).
2. **워크로드 유형** — 코드, 채팅, 구조화된 출력, 요약입니다. 수용률을 결정합니다.
3. **샘플링 전략** — greedy, 낮은 T, 높은 T, beam입니다. 높은 T 샘플링은 수용률을 저하시킵니다.
4. **하드웨어 목표** — 메모리 예산은 별도의 초안 모델을 포함할 수 있는지 결정합니다.
5. **엔지니어링 예산** — Medusa와 EAGLE는 미세 조정(Fine-tuning)이 필요하며, vanilla와 lookahead는 필요하지 않습니다.
6. **지연 시간 목표** — 인터랙티브 채팅 (<500ms TTFT, 토큰당 <50ms) vs 배치 (처리량 우선).

## 결정 규칙

- **빠른 시작, 학습 없음**: 같은 계열의 1B–3B 모델을 사용한 vanilla 초안입니다. 일반적으로 2배입니다.
- **미세 조정 가능**: 검증 모델의 은닉 상태를 사용하는 EAGLE-2 또는 EAGLE-3입니다. 일반적으로 3–4배입니다.
- **미세 조정 가능하지만 두 모델을 실행할 수 없음**: Medusa (검증 모델에 추가 헤드를 사용). 2–3배입니다.
- **학습 예산 없음, 초안 모델 없음**: lookahead 디코딩입니다. 1.3–1.6배입니다.
- **배치 중심 서빙**: 연속 배치(Continuous Batching)가 더 중요합니다. 배치 크기가 증가하면 검증 모델이 이미 포화(Saturation) 상태가 되므로 추론적 디코딩의 이점이 감소합니다.
- **높은 온도(Temperature) 또는 확률적 샘플링**: 수용률이 급격히 떨어집니다. 낮은 N (2–3)을 고려하거나 비활성화하세요.
- **구조화된 출력 (JSON, 코드)**: 수용률이 높습니다. 최대 속도 향상을 위해 N을 7 이상으로 높이세요.

## 튜닝

- **N (초안 길이)**: 5에서 시작합니다. 수용률을 측정하세요. α > 0.9이면 7로 높이세요. α < 0.6이면 3으로 낮추세요.
- **초안 온도(Temperature)**: 검증 모델의 온도와 일치시키세요. 초안 샘플링이 일치하지 않으면 α가 손실됩니다.
- **트리 깊이 (EAGLE-2 / Medusa)**: 3–5개 가지; 더 넓은 트리는 α > 0.8일 때만 도움이 됩니다.
- **초안 모델 크기**: α > 0.7을 달성하는 가장 작은 크기. 70B 검증기를 위한 1B 초안 모델이 일반적입니다. 검증기의 토크나이저 / 임베딩 호환성 이하로 내려가지 마세요.

## 항상 플래그 지정

- 초안 모델과 검증기가 토크나이저를 공유하는지 확인하세요. 다른 BPE 분할은 추론적 디코딩(Speculative Decoding) 보장을 깨뜨립니다.
- vLLM에서 추론적 디코딩(Speculative Decoding)은 연속 배치(Continuous Batching)와 상호작용합니다: 배치가 이미 포화(Saturation) 상태일 때 요청별 속도 향상은 감소합니다.
- EAGLE의 은닉 상태 입력은 검증기 내부 구조를 필요로 하며, HF API를 통해 항상 노출되지 않습니다. vLLM 또는 SGLang 런타임을 선호하세요.
- Medusa 헤드는 검증기 자체 출력에 대한 지도 미세 조정(SFT)이 필요합니다. 데이터 수집 단계가 종종 지배적인 비용입니다.

## 출력 형식

반환:

1. **권장 사항** — 하나의 전략 이름과 튜닝 매개변수 (예: "EAGLE-2, N=5, tree_depth=4").
2. **예상 속도 향상** — 명시적인 α 가정을 포함하여.
3. **호환성 확인** — 토크나이저 일치, 런타임 지원, KV 캐시 롤백(Rollback) 지원.
4. **대안 계획** — 주요 전략이 성능을 발휘하지 못할 경우, 다음에 시도할 사항.
5. **측정 계획** — 대표 샘플에서 수용률과 속도 향상을 검증하는 방법.
