## 문제점

70B 모델에서의 자기회귀(Autoregressive) 디코딩은 H100에서 초당 약 35토큰 속도로 실행됩니다. GPU는 포화 상태에 전혀 근접하지 못합니다. 메모리 대역폭이 상한선입니다. 모든 토큰은 HBM에서 70B의 가중치를 로드하고, 한 단계의 연산을 수행하며, 하나의 float를 생성합니다. 연산 유닛은 대부분 유휴 상태입니다.

추론적 디코딩(Speculative Decoding)은 이를 실제로 해결할 수 있는 처리량 문제로 전환합니다. 값싼 초안(draft)이 `N` 토큰을 `N`개의 작은 순방향 전방 연산(forward pass)으로 제안합니다. 검증자(verifier)는 접두어(prefix)와 모든 `N`개의 초안을 한 번에 실행합니다. 검증자의 `i` 위치에서의 분포가 초안과 일치하면(우리가 정밀하게 정의할 통계적 의미에서) 수락하고, 일치하지 않으면 거부하고 잔여 분포(residual distribution)에서 보정 샘플을 추출합니다. 단일 대형 모델 순방향 연산은 토큰 1개 대신 최대 `N+1`개의 수락된 토큰을 생성합니다.

중요한 정리는 Leviathan, Kalman, Matias (ICML 2023)입니다: 출력 분포는 검증자로부터 직접 샘플링했을 때 생성될 분포와 동일합니다. 대략적으로가 아니라, 완전히 동일합니다. 이것이 추론적 디코딩이 프로덕션 환경에서 허용되는 유일한 이유입니다. 품질 트레이드오프가 없는 순수한 지연(latency) 최적화이기 때문입니다.

7단계 · 16강이 제공한 것은 수학이었습니다. 이 강이 제공하는 것은 훈련 스택입니다. 좋은 초안은 값싼 초안보다 2배 더 큰 속도 향상을 가져옵니다. EAGLE, EAGLE-2, EAGLE-3 (Li et al., 2024–2025)는 "초안 = 동일 모델의 더 작은 버전"을 정밀한 엔지니어링 규범으로 전환했습니다. 2026년 프로덕션 추론 서버는 EAGLE-3을 기본값으로 사용합니다.

## 개념

### 불변 조건: Leviathan 거부 샘플링

`p(t)`을 특정 접두어에 대한 초안의 다음 토큰 분포, `q(t)`을 검증자의 분포라고 합시다. 초안 토큰 `d ~ p`을 샘플링합니다. `min(1, q(d) / p(d))` 확률로 수락합니다. 거부 시, 잔여 분포 `(q - p)_+ / ||(q - p)_+||_1`에서 샘플링합니다. 결과 샘플은 `q`에 따라 분포됩니다. `p`이 얼마나 나쁜지와는 무관하게 이 사실은 참입니다. 이 나쁠수록 거부 빈도가 높아지지만, 출력은 정확성을 유지합니다.

`prefix + d_1 + ... + d_N`에 대한 단일 검증자 순방향 연산을 사용하여 `N`개의 호출을 연속으로 쌓습니다. 검증자는 `q_1, q_2, ..., q_{N+1}`를 동시에 반환합니다. 왼쪽에서 오른쪽으로 진행합니다. `j` 위치에서 첫 거부가 발생하면 `residual(q_j, p_j)`에서 샘플링하고 중단합니다. 완전히 수락되면 `q_{N+1}`에서 보너스 토큰 하나를 샘플링합니다.

### 속도 향상을 결정하는 요소

`α`을 초안 토큰당 기대 수락률이라고 합시다. `c = cost(draft) / cost(verifier)`을 비용 비율이라고 합시다. 검증자 순방향 연산당 기대 수락 토큰 수는 다음과 같습니다:

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

수락된 토큰당 예상 총 월타임(wall time)은 `(N * c + 1) / E[accepted]`입니다. `N`에 대해 이를 최소화하면 최적점을 얻을 수 있습니다. `α = 0.8, c = 0.05`의 경우: 최적의 `N`는 약 5–7이며, 속도 향상은 3.2배입니다. `α = 0.95, c = 0.02`의 경우: 최적의 `N`는 약 8–10이며, 속도 향상은 5배까지 도달합니다.

가장 큰 레버는 `α`입니다. 고정된 `N = 5`에서 `α = 0.6`(바닐라 드래프트)에서 `α = 0.9`(EAGLE-3)로 변경하면 검증기(verifier)의 순방향당 예상 수락 토큰 수가 2.2에서 4.1로 증가합니다. 동일한 검증기에서 처리량이 거의 2배 증가합니다.

### 2년간의 발전 과정

**바닐라 추론적 디코딩(Speculative Decoding)(Leviathan, 2023).** 드래프트 모델은 동일한 계열에서 독립적으로 훈련된 더 작은 LLM입니다. 연결이 간단하며, `α ≈ 0.6`, 최대 속도 향상은 약 2배입니다.

**EAGLE-1 (Li et al., 2024).** 드래프트는 작은 트랜스포머로, 일반적으로 한두 개의 레이어로 구성되며, 검증기의 마지막 레이어 은닉 상태를 입력으로 받아 다음 토큰을 직접 예측합니다. 드래프트가 검증기의 특징 표현을 보기 때문에, 그 분포는 검증기의 분포와 훨씬 더 가깝습니다. `α`는 0.7–0.8로 상승합니다.

**EAGLE-2 (Li et al., 2024).** 동적 드래프트 트리를 추가합니다. `N`개의 토큰으로 구성된 단일 시퀀스를 제안하는 대신, 후보들의 작은 트리를 제안하고, 하나의 순방향 패스(트리 어텐션)로 검증기가 각 후보를 점수화하며, 가장 높은 확률의 경로를 따라갑니다. 드래프트 길이가 단계별로 적응형이 됩니다. 수락된 경로 토큰당 `α`는 0.85 이상으로 상승합니다.

**EAGLE-3 (Li et al., 2025, NeurIPS).** 두 가지 추가 변경 사항이 있습니다. 첫째, 특징 예측 손실(feature-prediction loss)을 완전히 제거합니다. EAGLE-1/2는 드래프트가 검증기의 은닉 상태를 일치하도록 훈련했으며, 이는 데이터가 도움이 되는 정도를 제한합니다. EAGLE-3는 토큰 예측에 직접적으로 훈련합니다. 둘째, 훈련 시간 테스트(TTT): 드래프트 훈련 중, 추론 시 작동하는 것과 동일한 방식으로 여러 단계에 걸쳐 드래프트의 이전 예측을 입력으로 되돌려 줍니다. 이는 훈련 및 테스트 분포를 정렬하고 오류 누적(error accumulation)을 방지합니다. 측정된 속도 향상: 채팅에서 최대 6.5배, H100에서 SGLang의 배치 크기 64에서 처리량 38% 개선.

### KV 캐시 롤백

검증은 한 번의 패스로 검증기의 KV 캐시를 `N` 항목만큼 확장합니다. `j` 위치에서 거부(rejection)가 발생하면 `j-1` 위치 이후의 캐시 내용은 이제 부정확해집니다. 두 가지 일반적인 구현 방식이 있습니다: 스크래치 버퍼에 기록하고 승인 시 커밋하는 방식(vLLM, TensorRT-LLM) 또는 물리적 KV 캐시와 논리적 길이를 유지하고 거부 시 잘라내는 방식입니다. 어느 쪽이든 롤백 비용은 레이어당 헤드당 바이트이며, 이는 순방향 패스 비용에 비해 무시할 수 있는 수준입니다.

EAGLE-2 트리 검색의 경우, 검증기는 트리 위상을 반영하는 비 인과(non-causal) 마스크로 어텐션을 실행합니다. 엔지니어링은 까다롭지만, 연산은 커스텀 마스크를 사용한 표준 플래시 어텐션 호출입니다.

## 구현하기

`code/main.py`을 참조하세요. 이는 모든 구성 요소를 포함한 Leviathan 추론적 루프입니다: N개 초안 생성, 검증기 병렬 패스, 위치별 거부, 잔여 샘플링, 보너스 토큰, KV 롤백, 그리고 `q`에서 직접 샘플링한 출력 분포가 일치함을 실증적으로 검증하는 과정입니다.

### 1단계: 거부 규칙

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 2단계: 잔여 분포

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 3단계: 완전한 추론적 단계

`spec_step` 함수는 `p`에서 `N` 토큰을 초안 작성한 후, 하나의 병렬 `q` 평가로 모든 토큰을 검증합니다. 초안 작성된 각 토큰에 대해 거부 규칙을 적용하며, 첫 번째 거부 발생 시 잔여(residual)에서 보정 토큰을 샘플링합니다. 모든 토큰이 승인되면 `q_{N+1}`에서 보너스 토큰을 방출합니다.

### 4단계: KV 롤백 기록 관리

시뮬레이터는 각 워커에 대해 논리적 `kv_length`을 추적합니다. `k` 초안들이 승인되면 `kv_length += k`이 됩니다. `j` 위치에서 거부 발생 시, 캐시는 이미 `j`을 넘어 기록되어 있지만, 논리적 길이는 보정 토큰 다음 위치인 `prefix_length + j + 1`로 설정됩니다. 이후 읽기 작업은 논리적 길이에 따라 잘라냅니다.

### 5단계: Leviathan 검증

50,000번의 추론적(speculative) 스텝을 실행합니다. 승인된 토큰의 경험적 분포를 계산합니다. `q`에서 직접 샘플링한 50,000개와 비교합니다. 카이 제곱 통계량은 임계값보다 충분히 작아야 합니다. 이 정리는 실제로 통과합니다.

### 6단계: α 대비 속도 향상

`p`을 `q`에서 다양한 진폭으로扰动하여 초안 품질을 스윕(sweep)합니다. `α`을 측정한 후, `α`과 `N`의 함수로서 검증자 호출당 기대 토큰 수를 플롯합니다. 코드는 EAGLE-3급 초안 품질(`α ≈ 0.9`)이 검증자 호출당 4~5개 토큰을 가능하게 하는 방식을 보여주는 표를 출력합니다.

## 사용하기

EAGLE-3를 사용한 프로덕션급 `vllm serve`:

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

H100에서 배치 크기 64로 EAGLE-3를 사용하는 SGLang는, EAGLE-3 논문에 따르면 배치 크기 64의 일반 디코딩 대비 약 1.38배 더 높은 처리량을 제공합니다.

추론적 디코딩을 고려해야 하는 경우:

- p50 지연 시간이 피크 처리량보다 중요한 모든 대화형 채팅 워크로드.
- 코드 생성 및 구조화된 출력(JSON, SQL). `α`이 0.9 이상인 이유는 대상 분포가 매우 예측 가능하기 때문입니다.
- 장문 생성(수천 개 토큰). 상각(amortized)된 속도 향상이 계속 이익을 가져다줍니다.

사용하지 말아야 하는 경우:

- 매우 작은 모델(< 3B). 초안 모델이 검증자보다 훨씬 저렴하지 않습니다.
- 소규모 배치 1 CPU 배포. 초안 모델의 메모리 오버헤드가 가치 있는 비용이 아닐 수 있습니다.
- `α`이 붕괴(collapsing)하는 매우 높은 온도의 창의적 샘플링.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| Leviathan 규칙 | "min(1, q over p)" | `min(1, q(d)/p(d))` 확률로 베르누이(Bernoulli) 승인/거부를 수행하며, 거부 시 잔여(residual)에서 샘플링하면 검증자 분포를 정확히 보존합니다 |
| 잔여 분포 | "(q minus p) plus, normalized" | `(q - p)_+`을 0으로 클램프(clamp)하고 재정규화한 분포로, 거부 시 샘플링해야 하는 올바른 분포입니다 |
| 승인율 α | "초안 모델이 얼마나 자주 맞는지" | 거부 규칙 하에서 토큰별 베르누이 성공 확률의 기대값으로, 모든 속도 향상 계산에 영향을 미칩니다 |
| EAGLE-1 | "은닉 상태 초안 모델" | 검증자의 마지막 레이어 은닉 상태(hidden state)에 조건을 건 초소형 트랜스포머 초안 모델(Li et al., 2024) |
| EAGLE-2 | "동적 초안 트리" | EAGLE-1에 트리 어텐션으로 점수화된 후보 연속 초안 트리를 추가하여 한 번의 검증자 패스로 처리 |
| EAGLE-3 | "학습 시간 테스트" | 특징 예측 손실을 제거하고, 학습 중 초안이 자체 출력으로 입력되는 직접 토큰 예측으로 학습 |
| 학습 시간 테스트 (TTT) | "노출 편향 수정" | 학습 중 초안을 자기회귀적으로 실행하여 학습 및 테스트 입력 분포가 일치하도록 함 — 스케줄링 샘플링의 직접적인 유사점 |
| KV 롤백 | "거부된 초안 되돌리기" | 거부 후 검증자의 KV 캐시를 승인된 접두어 길이로 리셋하는 관리 |
| 보너스 토큰 | "무료 토큰" | 모든 `N` 초안이 승인될 때, 추가 검증자 비용 없이 `q_{N+1}`에서 하나의 추가 토큰을 샘플링 |
| 트리 어텐션 | "많은 후보를 한 번에 검증" | 초안 트리의 위상을 반영하는 비 인과적 마스크를 사용하는 어텐션; 한 번의 순전파로 트리의 모든 노드에 대해 `q_i`를 계산 |
