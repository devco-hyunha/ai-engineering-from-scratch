# 보상 모델 설계자

언어 모델을 목표 행동(유용성, 코딩 능력, 안전성, 정직성)으로 정렬하기 위해 RLHF 파이프라인을 구축할 때, 이 프레임워크를 사용하여 데이터 수집 프로토콜을 설계하고, 보상 모델을 학습하며, PPO를 구성해 보세요.

## 입력 요구 사항

다음 항목을 제공하세요:
- **목표 행동** (예: "유용하고 무해한 어시스턴트", "전문 Python 코더", "안전성을 고려한 의료 Q&A")
- **기본 모델** (예: SFT 후의 Llama 3 8B, Mistral 7B Chat)
- **보상 모델 크기** (일반적으로 정책 모델과 같은 크기이거나 더 큰 크기)
- **주석 달기 예산** (사용 가능한 인간 시간 또는 비교 쌍)
- **컴퓨팅 예산** (보상 모델 학습 + PPO를 위한 GPU 시간)

## 1단계: 선호 데이터 수집

### 주석 달기 프로토콜

1. **프롬프트 선택**: SFT 학습 분포와 분포 외(OOD) 프롬프트(10-20% 신규)에서 샘플링하세요
2. **응답 생성**: SFT 모델을 사용하여 서로 다른 온도(0.3, 0.7, 1.0)로 프롬프트당 2-4개의 응답을 생성하세요
3. **비교 형식**: 주석자에게 정확히 2개의 응답을 보여주고 "어떤 응답이 더 좋은가요?"라고 물어보세요
4. **평가 기준 루브릭**: 사용 사례에 대해 "더 좋음"이 무엇을 의미하는지 정의하세요

### 루브릭 템플릿

| 기준 | 가중치 | 설명 |
|-----------|--------|-------------|
| 유용성 | 40% | 질문에 완전히 그리고 정확하게 답변하는가? |
| 무해성 | 25% | 해롭고, 편향되거나, 오해를 불러일으키는 내용을 피하는가? |
| 정직성 | 20% | 환각(Hallucination)을 일으키지 않고 불확실성을 인정하는가? |
| 간결성 | 15% | 응답이 질문에 대해 적절한 길이인가? |

사용 사례에 따라 가중치를 조정하세요. 코딩 어시스턴트는 정확성을 60%, 간결성을 20%로 가중치를 매길 수 있습니다.

### 데이터 크기 가이드라인

| 규모 | 비교 쌍 | 주석자 시간 | 예상 RM 정확도 |
|-------|-----------------|-----------------|---------------------|
| 최소 실행 가능 | 5,000-10,000 | 400-800 | 60-65% |
| 프로덕션 v1 | 20,000-50,000 | 1,600-4,000 | 65-72% |
| 프로덕션 v2 | 100,000-500,000 | 8,000-40,000 | 72-78% |

InstructGPT는 40명의 계약직 인력으로부터 33,000건의 비교 데이터를 사용했습니다. Anthropic의 초기 논문은 20명의 어노테이터로부터 22,000건을 사용했습니다. 어노테이터 간 일치율은 일반적으로 70-75%이며, 보상 모델은 인간 일치율을 초과할 수 없습니다.

### 품질 관리

- **일치율 필터링**: 어노테이터의 70% 미만이 일치하는 쌍은 폐기합니다
- **어노테이터 보정**: 실제 어노테이션 전에 알려진 좋은 쌍으로 보정 라운드를 수행합니다
- **편향 감지**: 어노테이터가 더 긴 응답, 격식 있는 언어, 특정 패턴을 일관되게 선호하는지 모니터링합니다
- **적대적 예제**: 주의 깊게 읽지 않는 어노테이터를 잡아내기 위해 설계된 예제를 5-10% 포함합니다

## 2단계: 보상 모델 아키텍처

### 아키텍처 결정

| 결정 | 권장 사항 | 근거 |
|----------|---------------|-----------|
| 기본 아키텍처 | 정책과 동일한 트랜스포머 | SFT 체크포인트에서의 가중치 초기화가 강력한 시작 특성을 제공합니다 |
| 출력 헤드 | 마지막 은닉 상태로부터 단일 선형 투영 | 가장 완전한 위치 표현에서 스칼라 보상을 산출합니다 |
| 모델 크기 | >= 정책 모델 크기 | 더 작은 보상 모델은 PPO를 불안정하게 만드는 신뢰할 수 없는 신호를 생성합니다 |
| 초기화 | 새로운 출력 헤드를 가진 SFT 체크포인트 | 사전 학습된 특성이 이미 언어 품질을 포착합니다 |

### 학습 구성

| 매개변수 | 범위 | 참고 |
|-----------|-------|-------|
| 학습률 | 1e-5 ~ 5e-5 | 작업이 더 단순하므로 SFT보다 낮습니다 |
| 에포크 | 1-3 | 제한된 비교 데이터로 과적합이 주요 위험입니다 |
| 배치 크기 | 64-256 | 각 "예제"는 쌍이므로 유효 데이터는 2배입니다 |
| 손실 함수 | Bradley-Terry: -log(sigmoid(r_preferred - r_rejected)) | 쌍별 비교의 표준입니다 |
| 검증 분할 | 10-20% | 보존된 쌍에 대한 정확도를 모니터링합니다 |

### 평가 지표

1. **짝수 정확도**: 홀드아웃 선호 쌍 중 RM이 올바르게 순위를 매기는 비율은 얼마인가요? 목표: > 65%
2. **마진 분포**: (r_preferred - r_rejected)의 분포를 플롯하세요. 0보다 약간 위에 중심이 잡혀야 하며 음수 값은 적어야 합니다.
3. **보정**: sigmoid(r_preferred - r_rejected)가 실제 인간 선호 확률에 가까운가요?
4. **OOD 일반화**: 학습과 다른 분포의 프롬프트로 테스트하세요. 정확도는 10% 미만으로 감소해야 합니다.

## 3단계: PPO 구성

### 하이퍼파라미터

| 매개변수 | 일반적인 값 | 너무 높을 때의 영향 | 너무 낮을 때의 영향 |
|-----------|--------------|-------------------------|------------------------|
| KL 계수 (beta) | 0.01-0.05 | 모델이 거의 학습되지 않으며 SFT에 너무 가깝게 유지됨 | 보상 해킹, 퇴화된 출력 |
| 학습률 | 5e-6 ~ 3e-5 | 학습 불안정, 발산 | 느린 수렴, 컴퓨팅 자원 낭비 |
| 클리핑 비율 (epsilon) | 0.1-0.3 | 크고 잠재적으로 불안정하게 만드는 업데이트 | 매우 보수적인 업데이트, 느린 학습 |
| 배치당 PPO 에포크 | 1-4 | 현재 배치에 과적합 | 각 배치를 충분히 활용하지 못함 |
| 생성 배치 크기 | 128-512 | 메모리 문제 | 잡음이 많은 기울기 추정 |
| 최대 응답 길이 | 256-1024 | 느린 생성, 메모리 문제 | 유용한 응답이 잘림 |

### 모니터링 대시보드

PPO 학습 중 다음 지표들을 추적하세요:

1. **평균 보상**: 학습 동안 증가해야 합니다. 평평한 상태는 괜찮지만, 감소는 불안정성을 의미합니다.
2. **KL 발산**: 10-20 nats 아래로 유지되어야 합니다. 급증은 보상 해킹을 의미합니다.
3. **응답 길이**: 안정적으로 유지되어야 합니다. 단조 증가 = 장황함 보상 해킹.
4. **엔트로피**: 토큰 분포 엔트로피는 천천히 감소해야 합니다. 급격한 감소 = 모드 붕괴.
5. **보상 모델 일치**: 보상 모델로 PPO 응답을 점수 매기세요; 일치도가 개선되어야 합니다.

### PPO 중 위험 신호

| 증상 | 가능한 원인 | 해결책 |
|---------|-------------|-----|
| 보상이 증가하지만 출력은 퇴화됨 | 보상 해킹 | KL 계수 증가, 적대적 예제로 RM 재학습 |
| KL 발산이 폭발 | 학습률이 너무 높거나 KL 계수가 너무 낮음 | 학습률(lr)을 낮추고 beta를 높임 |
| 응답 길이가 단조롭게 증가 | 보상 모델(RM)이 장황함을 보상함 | 보상에 길이 페널티를 추가하고, 길이 제어 쌍으로 보상 모델(RM)을 재학습함 |
| 모든 응답이 동일해짐 | 모드 붕괴(Mode collapse) | 생성 온도를 높이고 PPO 에포크 수를 줄임 |
| 보상이 극심하게 진동 | PPO 불안정성 | 학습률을 낮추고 클리핑 비율을 높임 |

## 4단계: 엔드투엔드 검증

RLHF로 학습된 모델을 배포하기 전에:

1. **SFT 대비 A/B 테스트**: SFT 모델과 RLHF 모델을 200개 이상의 테스트 프롬프트에서 실행합니다. 3명 이상의 평가자가 응답을 비교하도록 하세요. RLHF 모델이 60% 이상의 시간에서 승리해야 합니다.
2. **안전성 평가**: 알려진 적대적 프롬프트(제일브레이크, 유해한 요청)로 테스트합니다. RLHF 모델이 적절히 거부해야 합니다.
3. **회귀 테스트**: 표준 벤치마크(MMLU, HumanEval, MT-Bench)를 실행하여 RLHF 모델이 핵심 능력을 잃지 않았는지 확인합니다.
4. **망각 테스트**: 일반 텍스트 코퍼스에 대해 퍼플렉시티를 측정합니다. SFT 모델 대비 증가량이 10% 미만이어야 합니다.
5. **길이 분석**: SFT 모델과 RLHF 모델의 평균 응답 길이를 비교합니다. RLHF 모델이 50% 이상 길다면, 보상 모델에 장황함 편향이 있을 가능성이 높습니다.
