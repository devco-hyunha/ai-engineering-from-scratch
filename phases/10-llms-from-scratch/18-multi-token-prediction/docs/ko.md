# 멀티 토큰 예측 (MTP)

> GPT-2부터 Llama 3까지 모든 자기회귀 LLM은 각 위치에서 하나의 손실로 학습합니다: 다음 토큰을 예측하는 것입니다. DeepSeek-V3는 각 위치에 두 번째 손실을 추가했습니다: 그 다음 토큰을 예측하는 것입니다. 671B 모델에 추가된 14B 파라미터는 기울기 흐름을 통해 메인 모델로 증류(distilled)되었으며, 학습된 MTP 헤드는 추론 시 스펙큘레이티브 디코딩(speculative-decoding)의 초안 생성기로 재사용되어 80% 이상의 수용률을 달성했습니다. 생성 처리량이 1.8배로 무료 증가했습니다. 이 강의는 DeepSeek 기술 보고서의 순차적 MTP 모듈을 구축하고, 손실 및 공유 헤드의 파라미터 레이아웃을 계산하며, MTP가 인과적 체인을 유지하는 반면 Gloeckle et al.의 원래 병렬 MTP는 이를 깨뜨렸는지 설명합니다.

## 문제점

다음 토큰 예측은 표준 LLM 학습 목적입니다. 모든 은닉 상태(hidden state)는 정확히 한 가지를 예측하도록 지도됩니다: 바로 다음 토큰입니다. 이는 놀라울 정도로 약한 신호입니다. 시퀀스 내의 대부분의 정보는 하나의 토큰을 넘어서 확장됩니다 — 구조, 일관성, 사실성, 산술 흐름. 모델은 수조 개의 토큰에 걸쳐 많은 단일 토큰 신호를 축적하여 이러한 것들을 학습해야 합니다.

MTP는 모든 은닉 상태가 여러 미래 토큰을 한 번에 예측하도록 지도 supervision을 받는다면 어떨까라고 묻습니다. Gloeckle 등(Meta, 2024)은 이것이 도움이 된다는 것을 보여 주었습니다. 그들의 구현은 백본 위에 여러 개의 독립적인 출력 헤드를 배치하여 각각 다른 오프셋을 예측하도록 했습니다. 병렬적이고 단순하지만, 헤드는 계층적 정제 없이 동일한 은닉 상태를 보게 되며, 예측이 인과적으로 연결되지 않아 추론적 디코딩(Speculative Decoding)에 사용할 수 없었습니다.

DeepSeek-V3 (2024년 12월)는 MTP를 각 예측 깊이에서 인과적 연결을 유지하는 순차적 모듈로 재설계했습니다. 모델은 `h_i^(0)`에서 `t+1`을 예측한 후, `h_i^(0)`과 `E(t+1)` 임베딩을 결합한 새로운 은닉 상태 `h_i^(1)`에서 `t+2`을 예측하는 식으로 진행합니다. 각 깊이는 자체적인 작은 트랜스포머 블록입니다. 공유 임베딩과 공유 출력 헤드는 매개변수 오버헤드를 적절히 유지합니다. DeepSeek-V3의 규모에서는 671B의 메인 모델 가중치 위에 MTP 모듈로 추가된 14B의 매개변수가 있습니다. 이 2%의 오버헤드는 더 밀도 있는 학습 신호와 추론 시 즉시 사용 가능한 추론적 디코딩 초안을 확보했습니다.

이 강의에서는 단일 MTP 모듈과 D-depth 손실을 처음부터 구축합니다. 수식은 깔끔하고, 구현은 150줄입니다.

## 개념

### 순차적 MTP 레시피

DeepSeek-V3는 메인 모델 위에 `D`개의 MTP 모듈을 추가합니다. 각 모듈 `k` (`k = 1..D`에 대해)는 깊이 `k`의 토큰, 즉 위치 `i`까지의 접두어(prefix)가 주어졌을 때 `t_{i+k}`를 예측합니다.

모듈 `k`은 다음으로 구성됩니다:

- 자체 어텐션과 MLP를 가진 트랜스포머 블록 `T_k`.
- 이전 깊이의 은닉 상태와 다음 깊이의 정답 토큰 임베딩을 결합하는 투영 행렬 `M_k`.
- 공유 임베딩 `E` (메인 모델과 동일).
- 공유 출력 헤드 `Out` (메인 모델과 동일).

학습 시, 위치 `i`까지의 접두어에 대해 각 깊이의 은닉 상태는 다음과 같습니다:

```
h_i^(0) = main model backbone at position i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

각 깊이의 예측은 다음과 같습니다:

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

각 깊이의 손실은 정답 `t_{i+k}`에 대한 교차 엔트로피(Cross-Entropy)입니다:

```
L_k = CE(logits_{i+k}, t_{i+k})
```

깊이에 걸친 결합 손실은 다음과 같습니다:

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda`는 작은 가중치 계수입니다. DeepSeek-V3는 훈련의 첫 10% 동안 0.3을, 이후에는 0.1을 사용합니다. 총 훈련 손실은 `L_main + L_MTP`입니다.

### 순차적 설계가 병렬 설계보다 나은 이유

Gloeckle의 원래 병렬 MTP는 D개의 출력 헤드를 가지며, 각 헤드는 `h_i^(0)`에 직접 적용됩니다. 각 헤드는 동일한 백본 은닉 상태(hidden state)에서 `t_{i+k}`을 예측합니다. 이는 잘 훈련되지만, 예측들이 서로 조건부되지 않습니다. `head_1`의 출력을 `head_2`을 돕는 데 사용할 수 없습니다. 헤드가 병렬로 작동하기 때문입니다.

DeepSeek-V3의 순차적 설계는 `h_i^(k-1)`과 실제 다음 토큰 임베딩 `E(t_{i+k})`로부터 `h_i^(k)`을 구축합니다. 이는 인과적 사슬(causal chain)을 보존합니다. `t_{i+k+1}`을 예측하기 위해, 깊이 `k+1`에 있는 모듈은 `t_{i+k}`에 있던 내용을 참조합니다. 이는 자기회귀 디코더가 자신의 출력을 소비하는 방식과 구조적으로 동일하며, MTP 모듈을 추론적 디코딩(Speculative Decoding)의 초안 생성기(drafter)로 직접 사용할 수 있게 합니다.

추론 시: `h_i^(k-1)`과 생성된 초안 `t_{i+k}`을 모듈 `k+1`에 입력하여 `t_{i+k+1}`에 대한 예측을 얻습니다. 이를 반복합니다. 이는 훈련된 MTP 모듈을 초안 네트워크로 사용하는 EAGLE 스타일의 초안 생성과 정확히 동일합니다. DeepSeek-V3는 첫 번째 MTP 모듈에서 80% 이상의 수용률과 약 1.8배의 속도 향상을 보고합니다.

### 매개변수 계산

은닉 차원(hidden size)이 `h`이고 어휘 크기가 `V`인 모델의 경우:

- 주 모델: 수십억 개의 매개변수, 그리고 크기가 `V * h`인 출력 헤드 하나.
- 공유 출력 헤드: 주 모델의 헤드를 재사용합니다. 추가 매개변수가 없습니다.
- 공유 임베딩: 주 모델의 임베딩을 재사용합니다. 추가 매개변수가 없습니다.
- MTP 모듈별:
  - 투영(Projection) `M_k`: `(2h) * h = 2h^2`.
  - 트랜스포머 블록 `T_k`: 어텐션(MHA의 경우 `4h^2`)과 MLP(SwiGLU의 경우 비율 8/3로 일반적으로 `8h^2`)를 포함합니다. 블록당 약 `12h^2`입니다.

모듈당 총 추가 매개변수: `~14h^2`. DeepSeek-V3의 `h = 7168`의 경우, D = 1 모듈: 이론상 `~14 * 7168^2 = ~720M` 매개변수입니다. DeepSeek-V3는 14B를 보고합니다. 차이는 주로 MTP 모듈 내의 전문가 레이어가 MoE로 구성되기 때문입니다.

### 추론적 디코딩의 이점

사전 훈련(pre-training) 동안, MTP 모듈은 훈련을 약 10% 늦춥니다(더 많은 순방향 연산, 추가 손실). 이점에는 두 가지가 있습니다:

1. 더 밀도 높은 학습 신호. 각 은닉 상태는 D+1개의 감독 대상을 봅니다. DeepSeek-V3의 Ablation 실험에서 MMLU, GSM8K, MATH, HumanEval에 측정된 효과: 일관된 몇 퍼센트 포인트의 개선.

2. 추론 시 무료 추론적 디코딩(Speculative Decoding) 초안. MTP 모듈은 이미 다음 몇 토큰을 예측하도록 학습되어 있습니다. 초안 네트워크로 재활용하면 80% 이상의 수용률을 달성합니다. 이 수준에서 N=3 또는 N=5의 추론적 디코딩은 1.8배의 처리량을 제공합니다. 학습 시간의 10% 비용은 추론을 실행하는 첫 시점에 회수됩니다.

### EAGLE과의 관계

EAGLE는 사전 학습 이후에 작은 초안 모델을 별도로 학습합니다. MTP는 초안을 사전 학습에 포함시킵니다. 두 접근법은 유사한 수용률로 수렴하지만, 서로 다른 파이프라인을 통해 달성합니다:

| 차원 | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| 학습 시점 | 사전 학습 이후 | 사전 학습 중 |
| 기존 가중치와의 하위 호환성 | 예 | 아니요 (재학습 필요) |
| 초안 매개변수 | 1-2 트랜스포머 레이어 | 1 트랜스포머 블록 + 투영 |
| 수용률 | 0.88-0.92 | 깊이 1에서 0.80+ |
| 속도 향상 외의 이점 | 추론적 디코딩만 | 더 밀도 높은 학습 신호 + 속도 향상 |

## 구현하기

`code/main.py`는 단일 MTP 모듈을 엔드투엔드로 구축합니다: 공유 임베딩, 투영, 트랜스포머 블록, 공유 출력 헤드. 이후 짧은 합성 시퀀스에 대해 깊이별 교차 엔트로피 손실(Cross-Entropy Loss)을 계산하고 구성 요소별 매개변수 수를 출력합니다. 32개 토큰의 장난감 어휘는 숫자를 읽기 쉽게 유지합니다.

### 1단계: 공유 임베딩 테이블

단일 `vocab_size x hidden` 테이블은 메인 모델과 모든 깊이의 모든 MTP 모듈에서 사용됩니다. 두 번째 복사본이 아니라 문자 그대로 동일한 텐서입니다.

### 2단계: 깊이별 조합

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 특징 차원을 따라 연결(concat)한 후, 은닉 차원으로 투영
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 벡터 덧셈 대체
    projected = matvec(M_k, concat)
    return projected
```

실제 DeepSeek-V3는 두 RMSNorm된 벡터를 `[2h]`에 연결(concat)하고 `h x 2h` 행렬로 투영합니다. 장난감 예제는 표준 라이브러리의 간결함을 위해 벡터 덧셈을 사용합니다.

### 3단계: 깊이 k에서의 트랜스포머 블록

셀프 어텐션(Self-Attention)과 MLP. 토이 예제에서는 한 층의 선형 어텐션 블록과 SwiGLU MLP를 사용하여 numpy 없이 구조를 명확하게 볼 수 있습니다.

### 4단계: 공유 출력 헤드

메인 모델의 출력 투영을 재사용합니다. 어휘에 대한 로짓(Logits)을 생성합니다.

### 5단계: 깊이별 손실

오프셋 `k`에서의 정답 토큰에 대한 softmax(logits)의 교차 엔트로피(Cross-Entropy)를 계산합니다. `lambda / D` 스케일링 팩터로 깊이를 걸쳐 집계합니다.

### 6단계: 매개변수(Parameter) 계산

총 매개변수 수, 공유된 (임베딩, 헤드) 매개변수 수, 모듈별 추가 매개변수 수를 출력합니다. MTP 추가 매개변수가 메인 모델 크기에 대한 비율을 표시합니다.

## 사용하기

MTP는 DeepSeek-V3 (2024년 12월) 및 DeepSeek-R1 시리즈에 통합되었습니다. 추론 시:

- DeepSeek 자체 서빙 스택은 MTP 모듈을 추론적 디코딩(Speculative Decoding) 도구로 즉시 사용합니다.
- vLLM과 SGLang는 2026년 4월 기준으로 DeepSeek-V3 MTP에 대한 통합 경로를 제공합니다.
- AMD의 ROCm SGLang 튜토리얼은 V3 체크포인트(Checkpoint)에서 측정된 1.8배 속도 향상을 보여주는 특정 MTP 추론적 디코딩 구성을 보여줍니다.

새로운 사전 학습(pre-training) 실행에서 MTP를 사용할 때:

- 전체 사전 학습 파이프라인을 통제하며 더 밀도 높은 학습 신호를 확보하고 싶을 때.
- 모델을 대규모로 서빙할 것을 알고 있으며, 추론적 디코딩을 무료로 얻고 싶을 때.
- 히든 크기가 최소 4096일 때. 1B 규모에서는 오버헤드가 이득보다 더 큰 피해를 줍니다.

사용하지 않을 때:

- 기존 사전 학습된 밀집(dense) 모델을 미세 조정(Fine-tuning)할 때. MTP 모듈은 학습되지 않았습니다.
- 비교를 위해 깨끗한 기준선(baseline)이 필요한 연구 모델일 때. MTP는 아키텍처를 변경합니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 합성 신호가 강해질수록 깊이별 손실이 단조롭게 감소하는 것을 확인하세요. 합성 신호를 고정 패턴으로 수정하고 깊이 1 및 깊이 2 손실이 모두 수렴하는지 검증하세요.

2. 은밀한(hidden) 70B 모델(hidden 크기 8192, 80층)에 D=1 MTP 모듈을 적용했을 때의 매개변수 오버헤드를 계산해 보세요. DeepSeek-V3에서 보고된 14B 오버헤드와 비교해 보세요. DeepSeek의 수치가 더 높은 이유를 설명해 보세요: MTP 트랜스포머 블록은 동일한 MoE 구조를 상속받으므로, 모듈당 매개변수 수가 증가합니다.

3. 토이(toy) 모델에 D=2를 구현해 보세요: h^(1)을 입력으로 받아 `t_{i+2}`를 예측하는 두 번째 MTP 모듈을 추가합니다. 결합 손실과 매개변수 계산이 DeepSeek 논문의 방정식 19-21강 일치하는지 확인해 보세요.

4. 토이 모델을 병렬(parallel) MTP(Gloeckle 스타일)로 전환해 보세요: 주요 은밀 상태(main hidden state) 위에 D개의 출력 헤드를 추가하고, 각 헤드가 서로 다른 오프셋을 예측하도록 합니다. 동일한 합성 신호(synthetic signal)에서 깊이별 손실이 순차적(sequential) 버전과 어떻게 비교되는지 측정해 보세요. 순차적 버전은 중간 예측값에 조건을 걸기 때문에 k > 1일 때 깊이-k 손실이 더 낮아야 합니다.

5. 학습된 MTP 모듈을 EAGLE 스타일의 초안(draft)으로 사용해 보세요: 추론 시 모듈 k를 호출하여 `t_{i+k}`를 제안합니다. 홀드아웃(held-out) 시퀀스에서 주요 모델의 예측과 비교하여 이러한 초안 토큰의 수용률(acceptance rate)을 측정해 보세요. 토이 모델에서 50% 이상을 달성하면, MTP를 초안으로 사용하는 경험적 특성을 재현한 것입니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| MTP 모듈 | "추가 손실 블록" | 주요 모델보다 `k` 위치 앞의 토큰을 예측하는 작은 트랜스포머 블록 및 투사(projection) |
| 예측 깊이 | "어떤 오프셋" | 모듈 `k`가 위치 `i`까지의 접두어(prefix)로부터 `t_{i+k}`를 예측하는 정수 `k` |
| 병렬 MTP | "Gloeckle 스타일" | 동일한 백본(backbone) 은밀 상태 위에 D개의 독립적인 헤드가 있으며, 조건부 연쇄가 없음 |
| 순차적 MTP | "DeepSeek-V3 스타일" | 각 모듈이 이전 깊이의 은밀 상태와 다음 토큰의 임베딩(embedding)에 조건을 걸며; 인과적 연쇄(causal chain)를 보존 |
| 공유 출력 헤드 | "주요 헤드 재사용" | MTP 모듈은 주요 모델의 LM 헤드를 호출하며, 별도의 출력 투사(projection)를 사용하지 않음 |
| 공유 임베딩 | "주요 테이블 재사용" | 동일한 어휘 임베딩 테이블이 모든 곳에서 사용됨; 중복 매개변수 없음 |
| 투사 행렬 M_k | "은닉 상태 + 다음 토큰 결합" | 이전 은닉 상태와 대상 토큰 임베딩을 다음 깊이(depth)의 입력으로 합치는 `h x 2h` 선형 레이어 |
| 결합 손실 L_MTP | "평균화된 추가 손실" | 각 깊이의 교차 엔트로피 손실의 산술 평균으로, `lambda`에 의해 스케일링됨 |
| 깊이 1에서의 수용률 | "MTP 초안이 얼마나 자주 맞는지" | D=1 MTP 모듈의 top-1 예측이 메인 모델의 top-1 예측과 일치하는 비율; DeepSeek-V3에서 80% 이상 |
| Lambda 가중치 | "추가 손실의 중요도" | 각 깊이의 스케일링 팩터; DeepSeek-V3에서는 학습 시작 시 0.3, 이후 0.1 |
