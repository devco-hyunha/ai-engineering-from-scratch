# 차분 어텐션 (V2)

> 소프트맥스 어텐션은 모든 비매칭 토큰에 소량의 확률을 분산합니다. 10만 토큰 이상에서는 이 잡음이 누적되어 신호를 압도합니다. Differential Transformer (Ye et al., ICLR 2025)는 두 소프트맥스의 차이로 어텐션을 계산하여 공유 잡음 바닥을 제거함으로써 이를 해결합니다. DIFF V2 (Microsoft, 2026년 1월)는 프로덕션 스택의 재작성 버전으로, 기본 트랜스포머와 동일한 디코딩 지연 시간을 가지며, 커스텀 커널이 필요 없고 FlashAttention과 호환됩니다. 이 강의는 V1에서 V2까지의 전체 과정을 다루며, 표준 라이브러리 Python으로 실행할 수 있는 차이 연산의 토이 구현을 포함합니다.

**유형:** Build
**언어:** Python (stdlib)
**선수 요건:** 7단계 · 02강 (셀프 어텐션), 7단계 · 15강 (어텐션 변형), 10단계 · 14강 (아키텍처 상세 설명)
**시간:** 약 60분

## 학습 목표

- 소프트맥스 어텐션에 잡음 바닥이 존재하는 이유와 그 잡음이 컨텍스트 길이에 따라 증가하는 이유를 정확히 설명해 보세요.
- 차분 어텐션 공식을 유도하고, 왜 뺄셈이 공유 잡음 성분을 상쇄하면서 신호는 보존하는지 설명해 보세요.
- V1에서 V2로의 차이를 살펴보세요: 무엇이 더 빨라졌고, 무엇이 더 단순해졌으며, 무엇이 더 안정적으로 변했는지, 그리고 프로덕션 사전 학습을 위해 각 변경이 왜 필요했는지 확인해 보세요.
- 순수 Python으로 차분 어텐션을 처음부터 구현하고, 합성 신호+잡음 쿼리에서 잡음 상쇄 특성을 경험적으로 검증해 보세요.

## 문제점

표준 소프트맥스 어텐션은 대규모 환경에서 운영상의 문제로 이어지는 수학적 특성을 가지고 있습니다. 쿼리 `q`에 대해 어텐션 가중치는 `softmax(qK^T / sqrt(d))`입니다. 소프트맥스는 절대 정확한 0을 생성할 수 없으며, 모든 비매칭 토큰은 양의 확률 질량을 받습니다. 이 잔여 질량은 잡음이며, 컨텍스트 길이에 따라 증가합니다. 128k 토큰에서는 각 비매칭 토큰이 확률의 0.001%만 받더라도, 127,999개 토큰의 합은 전체의 약 12%를 기여합니다. 모델은 컨텍스트와 함께 증가하는 잡음 바닥을 우회하는 방법을 학습해야 합니다.

경험적으로 이는 어텐션 헤드 간 간섭으로 나타납니다. 긴 컨텍스트 RAG에서 환각된 인용, 100k 토큰 검색 작업에서의 '중간 손실' 실패, 그리고 32k를 넘어서는 needle-in-haystack 벤치마크에서의 미묘한 정확도 저하가 이에 해당합니다. Differential Transformer 논문(arXiv:2410.05258, ICLR 2025)은 이 격차를 측정했습니다. DIFF Transformer는 동일한 크기의 기준 모델보다 낮은 퍼플렉시티, 높은 긴 컨텍스트 정확도, 그리고 더 적은 환각을 기록했습니다.

DIFF V1에는 세 가지 문제가 있어 프론티어 사전 학습 파이프라인에 도입되지 못했습니다. 값 캐시를 디코딩 단계마다 두 번 로드해야 했고, FlashAttention 호환성을 깨뜨리는 커스텀 CUDA 커널이 필요했으며, 헤드별 RMSNorm이 70B 이상 규모에서의 장기 학습을 불안정하게 만들었습니다. DIFF V2 (Microsoft unilm 블로그, 2026년 1월 20일)는 이 세 가지 문제를 모두 해결했습니다. 이 강의에서는 두 버전을 모두 다루고, 차분 연산자를 구축하며, 장난감 쿼리에서 잡음 제거를 벤치마킹합니다.

## 개념

### 소프트맥스의 잡음 바닥

쿼리 `q`과 키 `K = [k_1, ..., k_N]`에 대해 어텐션 가중치는 다음과 같습니다:

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

`w_i`은 절대 0이 되지 않습니다. `k_i`이 `q`과 완전히 무관하다면, 점수 `q . k_i`은 0이 아닙니다. 이는 분산 `||q||^2 / d`으로 0 주변에서 변동합니다. 소프트맥스 정규화 후에도 각 무관한 토큰은 가중 합에 `O(1/N)`을 기여합니다. 무관한 토큰들의 총 기여도는 `O((N-1)/N) = O(1)`이며, 이는 작은 양이 아닙니다.

모델이 원하는 것은 하드 top-k와 유사한 형태입니다. 일치하는 토큰에는 높은 가중치를, 나머지 모든 곳에는 거의 0에 가까운 가중치를 부여하는 것입니다. 소프트맥스는 이를 직접 수행하기에는 너무 매끄럽습니다.

### 차분 개념

각 헤드의 Q 및 K 투영을 두 부분으로 분할합니다: Q = (Q_1, Q_2) 및 K = (K_1, K_2). 두 개의 어텐션 맵을 계산합니다:

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

출력:

```
DiffAttn = (A_1 - lambda * A_2) V
```

뺄셈은 두 맵이 공유하는 잡음 분포를 상쇄합니다. 두 맵 모두 127k개의 무관한 토큰에 대해 대략 균일한 가중치를 가진다면 (무작위 초기화 시 그렇게 될 것입니다), 이 가중치들은 상쇄됩니다. 신호, 즉 실제로 관련 있는 몇 안 되는 토큰에 대한 첨두 가중치는, 두 맵에서 동일한 크기로 나타날 때만 상쇄되는데, 모델이 학습되면 그렇게 되지 않습니다.

`lambda`은 헤드별 학습 가능한 스칼라이며, `lambda = exp(lambda_q1 dot lambda_k1) - exp(lambda_q2 dot lambda_k2) + lambda_init`로 매개변수화됩니다. 음수일 수 있습니다. `lambda_init`는 0.08강 같은 작은 양수로 기본 설정됩니다.

### 헤드별 노이즈 캔슬링과 일치하는 이유

두 개의 노이즈가 있는 마이크가 같은 목소리를 녹음한다고 생각해 보세요. 두 마이크 모두 화자의 목소리와 상관된 배경 잡음을 함께 포착합니다. 하나를 다른 하나에서 빼면 공유된 잡음이 사라집니다. 두 신호가 위상 또는 진폭이 충분히 달라서 완전한 상쇄가 일어나지 않기 때문에 목소리는 살아남습니다. 헤드별 `lambda`은 정확히 이 균형을 학습합니다.

### V1 vs V2: 차이점

V1은 매개변수 수를 기본 Transformer와 동일하게 유지했습니다. 헤드당 두 개의 쿼리를 얻기 위해 헤드 차원을 절반으로 줄였습니다. 이는 헤드 표현력을 떨어뜨렸고, 더 고통스럽게도 헤드당 값(value) 캐시를 절반으로 줄였습니다. 디코딩은 매 단계마다 값 캐시를 두 번 로드해야 했습니다 (소프트맥스 분기마다 한 번). 결과: 매개변수 수가 일치함에도 디코딩이 기본 모델보다 느렸습니다.

V2는 쿼리 헤드 수를 두 배로 늘리고 KV 헤드는 그대로 유지합니다 (업 프로젝션에서 매개변수를 차용). 헤드 차원은 기본 모델과 동일하게 유지됩니다. 뺄셈 후, 추가 차원은 기본 Transformer의 O_W 프로젝션과 일치하도록 다시 아래로 투영됩니다. 세 가지가 동시에 일어납니다:

1. 디코딩 속도가 기본 모델과 일치합니다 (KV 캐시를 한 번만 로드).
2. FlashAttention이 변경 없이 실행됩니다 (커스텀 커널 불필요).
3. 디코딩 시 연산 강도가 증가합니다 (HBM에서 로드한 바이트당 더 많은 연산).

V2는 V1이 뺄셈을 안정화하기 위해 사용했던 헤드별 RMSNorm도 제거합니다. 70B급 사전 학습 규모에서 그 RMSNorm은 후반 학습을 불안정하게 만들었습니다. V2는 추가 모듈 없이 학습을 안정적으로 유지하는 더 단순한 초기화 방식으로 대체합니다.

## 구현하기

`code/main.py`는 순수 Python으로 차등 어텐션을 구현합니다. 알려진 신호+잡음 구조를 가진 장난감 쿼리를 통해 잡음 제거 비율을 직접 측정해 보세요.

### 1단계: 표준 소프트맥스 어텐션

표준 라이브러리 행렬 연산: 리스트의 리스트, 수동 행렬 곱, 최대값을 빼서 수치적 안정성을 확보한 소프트맥스.

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### 2단계: Q, K를 두 부분으로 나누기

V1 스타일: 헤드 차원을 절반으로 줄입니다. V2 스타일: 헤드 차원을 유지하고 헤드 수를 두 배로 늘립니다. 장난감 구현은 교육적 명확성을 위해 V1을 사용합니다 — 수식은 동일하며, 관리 방식만 다릅니다.

### 3단계: 두 개의 소프트맥스 분기 + 뺄셈

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

참고: 출력 가중치는 음수가 될 수 있습니다. 이는 문제없습니다 — 값 캐시가 부호 있는 기여도를 처리합니다. 이후 V 투영이 부호를 흡수합니다.

### 4단계: 잡음 제거 측정

길이 1024의 합성 시퀀스를 만드세요. 신호 토큰을 알려진 위치에 배치하고, 나머지는 잡음으로 채우세요. (a) 신호 위치에서의 표준 소프트맥스 어텐션 가중치와 (b) 차등 어텐션 가중치를 계산하세요. 각각의 신호 대 잡음 비율을 측정하세요. DIFF 어텐션은 두 분기가 얼마나 서로 다르게 학습되었는지에 따라 3배에서 10배까지 신뢰할 수 있게 더 높은 신호 대 잡음 비율을 생성합니다.

### 5단계: V1 대 V2 매개변수 계산

구성(hidden=4096, heads=32, d_head=128)이 주어지면 다음을 출력하세요:

- 기본 트랜스포머: Q, K, V 각각 크기 `hidden * hidden`, MLP는 4 * hidden.
- DIFF V1: Q, K 각각 크기 `hidden * hidden`, V 크기 `hidden * hidden` (변화 없음), 헤드 차원 내부적으로 절반으로 줄임. 헤드별 `lambda` 매개변수 추가 (O(heads * d_head)).
- DIFF V2: Q 크기 `2 * hidden * hidden`, K 크기 `hidden * hidden`, V 크기 `hidden * hidden`. O_W 전에 추가 차원을 투영하여 축소. 동일한 `lambda` 매개변수 추가.

이 장난감(toy)은 V2의 추가 매개변수 비용(대략 어텐션 블록당 `hidden * hidden` 추가)을 측정하고 출력합니다.

## 사용하기

DIFF V2는 2026년 4월 기준으로 모든 프로덕션 추론 서버에 배포되지 않았지만, vLLM과 SGLang에서 통합이 진행 중입니다. 한편, 이 패턴은 다음에서 나타납니다:

- Microsoft 내부 장문 컨텍스트 프로덕션 모델.
- 256k 이상의 컨텍스트를 목표로 하는 여러 오픈 모델 학습 실행에서의 연구 재현.
- DIFF 어텐션과 슬라이딩 윈도우 어텐션을 교대 레이어에 결합한 하이브리드 아키텍처.

2026년에 이 기법을 사용해야 하는 경우:

- 64k 이상의 유효 컨텍스트를 목표로 새 모델을 처음부터 학습할 때. 처음부터 차등 어텐션을 추가하세요. 나중에 재학습하는 비용은 높습니다.
- 평가에서 '중간 손실'(lost-in-the-middle) 실패가 지배적인 장문 컨텍스트 모델을 미세 조정할 때. Q 투영에 대한 LoRA는 DIFF 구조를 근사할 수 있습니다.

사용하지 않아야 하는 경우:

- 안정적인 장문 컨텍스트 성능을 가진 사전 학습된 밀집(dense) 모델을 서빙할 때. 기존 가중치에 대한 재학습 비용은 거의 회수되지 않습니다.
- 컨텍스트가 항상 16k 미만일 때. 잡음 바닥(noise floor)은 무시할 수 있습니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 합성 쿼리에 대해 차등 어텐션의 신호 대 잡음비(signal-to-noise ratio)가 표준 소프트맥스 어텐션보다 높음을 확인하세요. 잡음 진폭을 변경하여 표준 어텐션이 사용 불가능해지는 교차점을 보여주세요.

2. 7B급 모델(hidden=4096, heads=32, d_head=128, 32 layers)에 대해, baseline에서 DIFF V1까지의 매개변수 수 변화량과 baseline에서 DIFF V2까지의 매개변수 수 변화량을 계산해 보세요. 어떤 구성 요소가 매개변수를 추가했고 어떤 구성 요소는 그대로 유지되었는지 표시해 보세요.

3. DIFF V1 논문(arXiv:2410.05258)의 3절과 DIFF V2 Hugging Face 블로그의 2절을 읽어 보세요. V1의 head별 RMSNorm이 왜 필요했는지, 그리고 V2가 이를 제거해도 학습 발산(training divergence)을 일으키지 않은 이유를 두 문장으로 설명해 보세요.

4. 추상화(ablation)를 구현해 보세요: `lambda = 0` (순수한 첫 번째 softmax)와 `lambda = 1` (전체 차감)로 차등 주의(differential attention)를 계산합니다. 합성 쿼리(synthetic query)에서 sweep에 따라 신호 대 잡음비(signal-to-noise)가 어떻게 변하는지 측정해 보세요. 신호 대 잡음비를 최대화하는 `lambda`를 식별해 보세요.

5. toy 모델을 GQA + DIFF V2로 확장해 보세요. KV head는 8개, Q head는 32개를 선택합니다. 동일한 (8, 32) 구성을 가진 baseline GQA 모델과 KV 캐시 크기가 일치함을 보여 주세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 차등 주의(Differential attention) | "두 개의 softmax를 서로 뺀 것" | Q, K를 두 반으로 나누고, 두 개의 softmax 맵을 계산한 뒤, 두 번째 것을 (lambda로 스케일링하여) 첫 번째 것에서 차감하고, V와 곱합니다 |
| 잡음 바닥(Noise floor) | "softmax의 비영(non-zero) 꼬리" | softmax가 모든 무관한 토큰에 부여하는 O(1/N) 가중치로, 긴 컨텍스트에서 합산하면 O(1)이 됩니다 |
| lambda | "차감 스케일" | head별 학습 가능한 스칼라 매개변수로 `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`로 매개변수화되며, 음수일 수 있습니다 |
| DIFF V1 | "ICLR 2025 버전" | 원본 차등 트랜스포머(Differential Transformer); 매개변수 수를 보존하기 위해 head dim을 절반으로 줄이며, 커스텀 커널이 필요하고 디코딩이 느립니다 |
| DIFF V2 | "2026년 1월의 수정" | Q head를 두 배로 늘리고 KV head는 유지합니다; baseline 디코딩 속도와 일치하며 FlashAttention와 함께 작동합니다 |
| head별 RMSNorm | "V1의 안정화 장치" | 차감 이후에 적용되는 추가 정규화; V2는 late-training instability를 방지하기 위해 이를 제거했습니다 |
| 신호 대 잡음비(Signal-to-noise ratio) | "주의가 얼마나 낭비되는지" | 실제 신호 위치에 대한 가중치와 무관한 위치에 대한 평균 가중치의 비율 |
| Lost in the middle | "긴 컨텍스트 실패 모드" | 긴 컨텍스트의 중간에 있는 문서에 대해 검색 정확도가 떨어지는 경험적 현상 — 차등 주의(DIFF attention)는 이를 감소시킵니다 |
| 연산 강도 | "로드된 바이트당 FLOPs" | KV 로드당 쿼리 수를 두 배로 늘려 디코딩 시 V2 비율이 증가했습니다. 메모리 바운드 디코딩에 중요합니다. |
