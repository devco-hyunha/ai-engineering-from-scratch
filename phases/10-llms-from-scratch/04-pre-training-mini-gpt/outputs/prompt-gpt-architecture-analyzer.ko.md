# GPT 아키텍처 분석기

기술 보고서, 모델 카드, 또는 학습 로그에서 GPT 스타일 모델을 평가할 때, 이 프레임워크를 사용하여 아키텍처를 분해하고 설계 상의 트레이드오프를 식별해 보세요.

## 분석 프로토콜

### 1. 매개변수 할당 분해

각 구성 요소의 정확한 매개변수 수를 계산합니다:

- **토큰 임베딩**: vocab_size x embed_dim
- **위치 임베딩**: max_seq_len x embed_dim
- **블록별 어텐션**: 4 x embed_dim x embed_dim (Q, K, V, 출력 투영)
- **블록별 FFN**: 2 x embed_dim x ff_dim + embed_dim + ff_dim (두 선형 레이어 + 편향)
- **블록별 LayerNorm**: 4 x embed_dim (두 정규화, 각각 스케일 + 편향 포함)
- **최종 LayerNorm**: 2 x embed_dim
- **출력 헤드**: vocab_size x embed_dim (토큰 임베딩과 가중치가 공유되는 경우 0)

단일 구성 요소가 전체 매개변수의 40%를 초과하는지 표시합니다. 작은 모델에서는 임베딩 행렬이 지배적입니다. 큰 모델에서는 어텐션과 FFN이 지배적입니다.

### 2. 어텐션 설계 분석

어텐션 구성을 평가합니다:

- **헤드 차원**: embed_dim / num_heads. 표준은 64 (GPT-2) 또는 128 (Llama 3)입니다. 32 미만이면 헤드별 표현력이 제한됩니다. 128 초과 시 계산 자원을 낭비하며 혜택이 거의 없습니다.
- **레이어당 헤드 수**: 헤드 수가 많을수록 더 다양한 어텐션 패턴을 생성하지만, KV 캐시에 더 많은 메모리가 필요합니다.
- **그룹화 쿼리 어텐션 (GQA)**: 모델이 여러 Q 헤드에 걸쳐 K/V 헤드를 공유합니까? Llama 3은 32개의 Q 헤드에 대해 8개의 KV 헤드를 사용하는 GQA를 적용합니다. 이는 KV 캐시를 4배 줄입니다.
- **컨텍스트 길이**: 최대 위치 임베딩. RoPE는 학습 길이를 넘나드는 외삽을 허용합니다. 절대 위치 임베딩은 이를 허용하지 않습니다.

### 3. 메모리 예산

모델의 최대 컨텍스트 길이에서 추론할 때:

- **가중치 (FP16)**: total_params x 2 bytes
- **KV 캐시 (FP16)**: 2 x num_layers x num_kv_heads x head_dim x max_seq_len x 2 bytes
- **활성화**: batch_size x seq_len x embed_dim x 2 bytes x num_layers (근사치)

KV 캐시가 가중치 메모리를 초과하는지 플래그를 지정하세요. 이는 긴 컨텍스트 모델(128K+)에서 발생하며, 디코딩 중 모델이 메모리 바운드 상태임을 나타냅니다.

### 4. 컴퓨팅 프로파일

- **프리필 FLOPS per token**: 약 2 x total_params (순방향 전파 시 매개변수당 하나의 행렬 곱)
- **디코딩 FLOPS per token**: 프리필과 동일하지만 단일 토큰에 대해 계산
- **프리필 병목**: 컴퓨팅 바운드 (GPU TFLOPS)
- **디코딩 병목**: 메모리 바운드 (GPU 메모리 대역폭)
- **연산 강도**: 접근한 메모리 바이트당 FLOPS. 100 미만이면 메모리 바운드입니다.

### 5. 확장 결정

알려진 확장 법칙에 대해 평가하세요:

- **Chinchilla 최적**: 주어진 컴퓨팅 예산 C에 대해 최적 모델 크기 N과 토큰 수 D는 N ~ D (대략적으로 동일한 확장)를 만족합니다. 7B 모델은 약 140B 토큰이 필요합니다.
- **Llama 3 과훈련**: Meta는 Llama 3 8B를 15T 토큰으로 훈련했습니다 (Chinchilla 최적의 100배). 작은 모델을 더 많은 데이터로 과훈련하면 토큰당 추론 비용이 더 좋아집니다.
- **너비 vs 깊이**: 더 깊은 모델(레이어 수 증가)은 동일한 매개변수 수에서 더 넓은 모델(embed_dim 증가)보다 일반적으로 샘플 효율성이 더 높습니다.

## 적신호

- **FFN 비율이 4x가 아님**: 표준은 ff_dim = 4 x embed_dim입니다. Llama는 SwiGLU를 사용하여 8/3 x embed_dim을 사용합니다. 편차는 정당화되어야 합니다.
- **가중치 공유 없음**: vocab_size가 embed_dim에 비해 매우 크지 않는 한, 출력 헤드는 토큰 임베딩과 가중치를 공유해야 합니다.
- **13B 이상에서 GQA 없음**: 13B 이상 모델에서 그룹 쿼리 어텐션(grouped-query attention)이 없으면 KV 캐시가 과도하게 커집니다.
- **긴 컨텍스트에 RoPE 없음**: 절대 위치 임베딩은 훈련 길이를 넘어서 외삽되지 않습니다. 32K+ 컨텍스트를 목표로 하는 모델은 회전 임베딩(rotary embeddings)을 사용해야 합니다.
- **모델 크기에 비해 학습률이 너무 높음**: 더 큰 모델은 더 낮은 피크 학습률이 필요합니다. GPT-2 Small은 6e-4를 사용합니다. Llama 3 405B는 8e-5를 사용합니다.

## 출력 형식

1. **매개변수 표**: 구성 요소별 매개변수 수와 백분율
2. **메모리 예산**: 최대 컨텍스트 길이에서의 가중치, KV 캐시, 활성화 메모리
3. **연산 프로파일**: A100/H100에서의 프리필 및 디코딩 처리량 추정
4. **설계 평가**: 모델이 잘 수행하는 부분과 비표준적인 부분
5. **확장성 판단**: 모델이 학습 데이터에 대해 적절하게 크기가 조정되었는지 여부
