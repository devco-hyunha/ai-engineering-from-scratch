# Jamba — 하이브리드 SSM-트랜스포머

> 상태 공간 모델(SSM)과 트랜스포머는 서로 다른 것을 추구합니다. 트랜스포머는 2차 비용으로 어텐션을 통해 품질을 확보합니다. SSM은 재귀(recurrence)를 통해 선형 시간 추론과 고정 메모리를 확보하지만 품질이 뒤처집니다. AI21의 Jamba (2024년 3월)와 Jamba 1.5 (2024년 8월)는 이 둘을 하나의 모델에 결합했습니다: Mamba 레이어 7개마다 트랜스포머 레이어 1개, 모든 짝수 블록에 MoE, 그리고 단일 80GB GPU에 맞는 256k 컨텍스트 윈도우. Mamba-3 (ICLR 2026)는 복소수 값 상태 공간과 MIMO 투영으로 SSM 측면을 강화합니다. 이 강의는 두 아키텍처를 처음부터 끝까지 읽어보며, 순수 SSM 및 순수 트랜스포머의 긴 컨텍스트 시도가 실패한 반면 하이브리드 레시피가 3년간의 스케일링을 생존한 이유를 설명합니다.

**유형:** Learn
**언어:** Python (stdlib, 레이어 혼합 계산기)
**선수 요건:** 10단계 · 14강 (오픈 모델 아키텍처), 10단계 · 17강 (네이티브 희소 어텐션)
**시간:** 약 60분

## 학습 목표

- Jamba 블록의 세 가지 기본 요소 — 트랜스포머 레이어, Mamba 레이어, MoE — 와 1:7:짝수(interleaving) 레시피를 설명하세요.
- SSM의 재귀(recurrence)가 고수준에서 어떻게 생겼는지, 그리고 이것이 왜 고정 메모리 추론을 가능하게 하는지 서술하세요.
- 256k 컨텍스트에서 Jamba 모델의 KV 캐시 발자취(footprint)를 계산하고, 순수 트랜스포머 모델이 필요로 하는 것과 비교하세요.
- Mamba-3의 세 가지 혁신 (지수 사다리꼴 이산화, 복소수 값 상태 업데이트, MIMO)과 각각이 해결하려는 문제를 나열하세요.

## 문제점

어텐션은 시퀀스 길이에 대해 2차적입니다. 상태 공간 모델은 선형적입니다. 이 차이는 누적됩니다: 256k 토큰에서 트랜스포머 어텐션 맵은 헤드당 650억 항목입니다. SSM의 재귀 상태는 시퀀스 길이에 관계없이 고정 크기입니다.

순수 SSM 모델 (Mamba, Mamba-2)은 작은 규모에서 트랜스포머의 퍼플렉시티(perplexity)를 따라잡지만, 상태 추적(state-tracking) 작업에서는 뒤처지고 일부 범주의 인컨텍스트(in-context) 검색에서는 실패합니다. 직관적으로, SSM은 역사를 고정된 상태로 압축하며, 역사가 길어지면 정보가 유출됩니다. 어텐션은 모든 것을 정확히 기억하지만 2차 비용을 지불합니다.

명백한 해결책은 두 가지를 모두 사용하는 것입니다. 정확한 기억(recall)이 중요한 곳에는 트랜스포머(Transformer) 레이어를 배치하고, 그 외의 곳에는 SSM 레이어를 사용하세요. 비율을 조정해 보세요. Jamba는 이 하이브리드 레시피를 대규모로 출시한 최초의 프로덕션급 모델입니다 (총 52B, 활성 12B, 컨텍스트 256k, 단일 80GB GPU). Jamba 1.5는 이 계열을 총 398B / 활성 94B로 확장했습니다. Mamba-3 (ICLR 2026)은 하이브리드가 재구성될 수 있는 현재 최상의 순수 SSM 기준선입니다.

이 강의는 세 논문을 모두 읽고 "올바른 비율을 선택하는" 것에 대한 멘탈 모델을 만들어냅니다.

## 개념

### 한 페이지로 보는 SSM

상태 공간 모델은 시퀀스 `x_1, ..., x_N`를 고정 크기 상태 `h`를 통해 처리합니다:

```
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

각 단계에서 상태는 선형 동역학 `A`를 통해 진화하며, 입력 `B x_t`를 받아 출력 `C h_t`를 방출합니다. `A, B, C`는 학습될 수 있습니다. 중요한 특성을 주의하세요: `y_t`를 계산하는 데는 `h_{t-1}`와 `x_t`만 필요하며, 이전의 `x`는 필요하지 않습니다. 메모리는 일정합니다. 추론은 토큰당 O(1)입니다.

모델링 품질을 위한 핵심은 `A`의 구조입니다. S4 (Gu 2021)는 학습 중 긴 컨볼루션으로 효율적으로 평가할 수 있는 고도로 구조화된 행렬을 사용했습니다. Mamba (Gu, Dao 2023)는 고정된 `A, B, C`를 데이터에 의존하는 것으로 대체했습니다 ("선택적" 부분). Mamba-2 (2024)는 구조를 더 단순화했습니다. Mamba-3 (2026)은 특정 위치에서 복잡성을 다시 추가합니다.

핵심 특성: 디코더 LLM의 경우, SSM 레이어는 어텐션 레이어의 드롭인(drop-in) 대체재이며, 성장하는 KV 캐시 대신 고정 크기의 레이어별 상태를 사용합니다.

### Jamba 블록

Jamba 블록은 두 가지 숫자에 따라 레이어를 인터리빙(interleave)합니다:

- `l`: 어텐션 대 Mamba 비율. Jamba는 `l = 8`를 사용하며, 이는 Mamba 레이어 7개마다 트랜스포머 레이어 1개를 의미합니다 (7 Mamba + 1 어텐션 = 그룹당 8 레이어).
- `e`: MoE 빈도. Jamba는 `e = 2`를 사용하며, 이는 모든 레이어마다 MoE를 적용한다는 의미입니다.

블록 내의 레이어 순서:

```
M  M  M  M  M  M  M  A    (7 Mamba + 1 Attention)
|  M  |  M  |  M  |  M    (where | marks MoE applied)
```

각 Jamba 블록은 8 레이어입니다. 4 블록 깊이 (총 32 레이어)에서는 Mamba 레이어 28개와 어텐션 레이어 4개를 얻습니다. 그 중 16개가 MoE를 사용합니다.

### 1:7 비율을 사용하는 이유

AI21은 Ablation 실험을 수행했습니다. 긴 컨텍스트 평가에서 Perplexity-per-parameter와 In-context Recall를 동시에 최적화하는 Attention-to-Mamba 비율은 무엇일까요?

- Attention이 너무 많은 경우 (1:1): 품질은 향상되지만 메모리와 속도가 저하됩니다.
- Attention이 너무 적은 경우 (1:15): 메모리 효율은 뛰어나지만 In-context Retrieval이 실패합니다.
- 적정 비율: 1:7 또는 1:8입니다.

직관적인 이해: Transformer 레이어는 정확한 Recall과 상태 추적(State Tracking)을 담당합니다. Mamba 레이어는 처리의 대부분을 저비용으로 수행합니다.

### Positional Encoding

Mamba 레이어 자체는 Recurrence를 통해 Position-aware합니다. 초기 Mamba 기반 Hybrid 모델의 Attention 레이어는 RoPE를 사용하지 않았습니다. SSM 레이어가 Position 정보를 제공했기 때문입니다. Jamba 1.5는 긴 컨텍스트 일반화를 위해 Attention 레이어에 RoPE를 추가했습니다. 이는 Empirical Long-context Evaluation에 기반한 사후 개선입니다.

### 메모리 예산

Jamba-1 형태 (32 레이어: 28 Mamba + 4 Attention, Hidden 4096, 32 Attention Heads)의 경우:

- KV Cache (Attention 레이어만 해당): `2 * 4 * 32 * 128 * 256k * 2 = 8.4 GB` (256k BF16 기준). 4개의 Attention 레이어만 기여합니다.
- SSM State: 토큰 Prefix당 `28 * hidden * state_size`. 이는 레이어당 고정 크기이며 Sequence Length에 따라 확장되지 않습니다. 일반적인 Mamba State는 Feature당 16, Hidden 4096이므로 총 `28 * 4096 * 16 * 2 = 3.7 MB`입니다.

32 레이어, 동일한 Hidden, 32 Heads를 사용하는 Full MHA Pure Transformer와 비교해 보세요. 256k BF16 기준 `2 * 32 * 32 * 128 * 256k * 2 = 128 GB`입니다. KV Cache가 8배 감소했습니다. 대부분의 2024 모델이 사용하는 GQA(8) Baseline (`2 * 32 * 8 * 128 * 256k * 2 = 32 GB`)과 비교해도, Jamba의 1:7 Hybrid는 16 GB로 2배 더 작습니다.

AI21이 "단일 80GB GPU에서 256k Context"라고 말하는 이유입니다. Full-MHA Pure Transformer의 KV Cache는.fit되지 않습니다. GQA Baseline조차 Weight와 Activation을 위한 공간을 남기지 못합니다. Jamba는 가능합니다.

### Mamba-3: 2026년 Pure-SSM Baseline

Mamba-3 (ICLR 2026, arXiv:2603.15569)는 Pure-SSM 측면에서 세 가지 혁신을 도입했습니다:

1. **Exponential-trapezoidal Discretization.** Mamba-2의 Euler-method Discretization을 더 표현력이 높은 Recurrence로 대체합니다. `x_t`에 대한 Outer Convolution가 아니라, Core Recurrence 내의 State-input에 Convolution-like Operation을 적용합니다.

2. **복소수 상태 업데이트.** 이전 Mamba 모델은 상태 행렬을 복소수(S4)에서 실수 대각(Mamba)으로, 그리고 스케일된 항등 행렬(Mamba-2)로 축소했습니다. Mamba-3는 복소수 값을 다시 도입합니다. 이는 상태에 대한 데이터 의존적 회전 임베딩(rotary embedding)과 동일합니다. 이는 이전 실수 기반 단순화로 인해 잃었던 상태 추적 기능을 복원합니다.

3. **다중 입력 다중 출력(MIMO) 투영.** 개별 특징별 스칼라 투영 대신 행렬 값 투영을 사용합니다. 디코딩 지연 시간을 늘리지 않으면서 모델링 성능과 추론 시 하드웨어 활용도를 향상시킵니다.

1.5B 파라미터 규모에서 Mamba-3는 Gated DeltaNet 대비 평균 다운스트림 정확도를 0.6 포인트 개선합니다. MIMO 변형은 추가로 1.2 포인트를 더하여 총 1.8 포인트의 성능 향상을 달성합니다. 동일한 상태 크기에서 Mamba-3는 상태 크기를 절반으로 줄인 Mamba-2와 동일한 성능을 보입니다.

Mamba-3는 아직 대규모 생산 환경의 하이브리드 모델에 탑재되지 않았습니다. 하지만 다음 세대 Jamba급 모델의 SSM 측면에 가장 유력한 후보입니다.

### 하이브리드를 선택해야 하는 경우

하이브리드가 유리한 경우:

- 컨텍스트가 충분히 길어 순수 트랜스포머의 KV 캐시가 부담스러워지는 경우(64k 이상).
- 단기 구조(SSM에 유리)와 장기 기억(트랜스포머 필요)이 혼합된 작업을 수행하는 경우.
- 트랜스포머 KV 캐시만으로는 메모리에 담을 수 없는 단일 GPU 메모리 예산으로 배포해야 하는 경우.

하이브리드가 불리한 경우:

- 컨텍스트가 짧은 경우(16k 미만). SSM 오버헤드가 낭비되며, 순수 트랜스포머가 적합합니다.
- 모든 위치에서 모든 위치로 연결되는 어텐션(심층 추론, 다중 문서 교차 참조)이 필요한 경우. 하이브리드 내 어텐션 레이어의 희소성이 성능을 저해합니다.
- 조 단위 파라미터의 프론티어 모델로 확장하는 경우. 현재 순수 트랜스포머 + MLA + MoE(DeepSeek-V3 스타일)가 성능 경쟁에서 우위를 점하고 있습니다.

## 사용하기

`code/main.py`는 하이브리드 아키텍처를 위한 메모리 계산기입니다. SSM-트랜스포머 비율과 숨김 크기(hidden-size) / 레이어 수(layer-count) 구성을 입력하면 다음을 계산합니다:

- 목표 컨텍스트에서의 KV 캐시.
- SSM 상태 메모리.
- 다양한 모델 형태에 대해 컨텍스트 N에서의 총 메모리.

이 계산기는 다음을 지원합니다:

- 순수 트랜스포머 기준선(KV 캐시가 N에 따라 증가).
- Jamba 스타일의 1:7 하이브리드.
- 순수 SSM(KV 캐시 없음).

이 수치들은 Jamba-1 및 Jamba-1.5 논문에서 공개된 형태에 대해 직접 가져온 것이며, 가상의 변형에 대해서는 외삽(extrapolated)한 값입니다.

실제 배포를 위한 통합 고려 사항:

- 대부분의 프로덕션 추론 서버(vLLM, SGLang)는 Jamba와 Mamba를 지원합니다. 특정 버전을 확인해 보세요.
- 256k 컨텍스트에서 Jamba의 메모리 이점은 동시 요청 처리량(concurrent-request throughput)에서 나타납니다. 동일한 VRAM에서 트랜스포머 시퀀스보다 Jamba 시퀀스를 더 많이 수용할 수 있습니다.
- Mamba-3는 독립 모델로서 아직 프로덕션에 출시되지 않았습니다. 1.5B 규모로 연구 프리뷰(research preview) 상태입니다.

## 출시하기

이 강의는 `outputs/skill-hybrid-picker.md`를 생성합니다. 워크로드 사양(컨텍스트 길이 프로필, 작업 혼합, 메모리 예산)이 주어지면 순수 트랜스포머, Jamba 스타일 하이브리드, 순수 SSM 중 하나를 추천하며, 메모리와 품질의 트레이드오프(tradeoff)에 대한 명시적인 근거를 제시합니다.

## 연습 문제

1. `code/main.py`를 실행하여 숨김 크기 4096, 헤더 32개인 32레이어 순수 트랜스포머와 동일한 형태의 Jamba-1 하이브리드에 대해 256k 컨텍스트에서의 KV 캐시를 계산해 보세요. AI21 논문이 주장하는 약 8배의 메모리 감소가 맞는지 검증해 보세요.

2. 계산기를 수정하여 1:3 하이브리드(Mamba 4 : 어텐션 1)와 1:15 하이브리드(Mamba 14 : 어텐션 1)를 모델링해 보세요. 비율에 따른 KV 캐시를 그래프로 그려 보세요. KV 캐시가 SSM 상태 메모리와 같아지는 비율은 어디인가요?

3. Jamba 논문(arXiv:2403.19887)의 섹션 3을 읽어 보세요. Mamba-2가 더 빠름에도 불구하고 AI21이 Mamba-1을 사용하는 이유를 설명해 보세요. 힌트: 하이브리드 Ablation 섹션에 이 내용이 문서화되어 있습니다.

4. Jamba 1.5 Large (총 398B, 활성 94B)에서 MoE-every-other-layer의 매개변수 오버헤드를 계산해 보세요. 활성 비율을 DeepSeek-V3 (37B/671B)와 비교하고, Jamba의 아키텍처가 활성 비율을 더 높게 만드는 이유를 설명해 보세요.

5. Mamba-3 논문(arXiv:2603.15569)의 3장을 읽어 보세요. 복소수 상태 업데이트가 데이터 의존적 회전 임베딩과 동등한 이유를 세 문장으로 설명해 보세요. 답변을 7단계 · 04강의 RoPE 유도 과정과 연결해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 상태 공간 모델 (SSM) | "고정된 상태로 재귀하는 것" | 학습된 재귀 `h_t = A h_{t-1} + B x_t`를 가진 레이어; 토큰당 상수 메모리 |
| 선택적 SSM | "Mamba의 트릭" | 선형 시간에서 모델의 게이팅과 유사한 선택성을 제공하는 데이터 의존적 A, B, C 매개변수 |
| Attention-to-Mamba 비율 | "얼마나 많은 어텐션 레이어가 있는지" | Jamba에서 `l = 8`는 Mamba 레이어 7개당 어텐션 레이어 1개를 의미합니다 |
| Jamba 블록 | "8레이어 그룹" | 어텐션 1개 + Mamba 7개 + 교대 위치에 MoE |
| SSM 상태 | "숨겨진 버퍼" | Mamba 레이어의 KV 캐시를 대체하는 레이어당 고정 크기 상태 |
| 256k 컨텍스트 | "Jamba의 대표 수치" | Jamba-1이 단일 80GB GPU에서 처리하는 시퀀스 길이; 순수 트랜스포머는 그 크기에서 처리할 수 없습니다 |
| Mamba-3 | "2026 순수 SSM" | 복소 상태 + MIMO를 사용하는 현재 최고의 순수 SSM 아키텍처; 하이브리드 모델들이 이를 기준으로 재구성합니다 |
| MIMO | "다중 입력 다중 출력" | 스칼라별 특징 대신 행렬 값 프로젝션을 사용하는 Mamba-3의 혁신 |
| 지수 사다리꼴 이산화 | "Mamba-3의 재귀" | Mamba-2의 오일러 방법 이산화를 포함하는 더 표현력 있는 재귀 |
| 하이브리드 아키텍처 | "어텐션과 SSM을 혼합" | 트랜스포머와 SSM 레이어를 교대로 배치하는 모든 모델; Jamba는 생산 아키타입입니다 |
