스택, 지연 시간 예산, 필요한 프리미티브, 운영 형태가 주어지면 런타임을 선택해 보세요.

결정:

1. Python + FastAPI + 초당 수천 개의 짧은 수명 에이전트 -> **Agno**.
2. TypeScript + Next.js/Vercel + 통합 다중 공급자 -> **Mastra**.
3. 내구성 있는 상태, 명시적 그래프, 실패 시 재개 -> **LangGraph** (13강).
4. Claude 우선 제품, Claude Code 하네스 형태를 원함 -> **Claude Agent SDK** (17강).
5. OpenAI 우선 제품, 핸드오프 + 가드레일 + 추적(tracing)을 원함 -> **OpenAI Agents SDK** (16강).
6. 다중 에이전트 팀, 액터 모델 동시성, 장애 격리 -> **AutoGen v0.4** / **Microsoft Agent Framework** (14강).
7. 역할 기반 협업 또는 이벤트 주도 결정론적 워크플로 -> **CrewAI** Crew 또는 Flow (15강).
8. 위 항목에 해당하지 않음 -> 직접 API 호출 + 01강의 표준 라이브러리 루프.

산출물:

- 짧은 결정 문서: 스택, 지연 시간 목표, 필요한 프리미티브, 관찰된 트레이드오프.
- 선택한 런타임에서의 최소한의 스캐폴드(scaffold).
- 오늘날 다른 런타임을 사용 중이라면 마이그레이션 계획.

거부 조건:

- 작업 부하가 요청당 하나의 느린 호출일 때 순수하게 "성능"을 이유로 Agno나 Mastra를 선택하는 것. 성능은 거의 병목이 되지 않습니다.
- 이유 없이 Python 모노레포에서 TypeScript 런타임을 선택하는 것. 혼합 언어 에이전트 코드는 운영적 세금입니다.
- 상태 비저장 짧은 작업을 위해 LangGraph를 선택하는 것. 체크포인터는 단순 워크플로(12강)가 피하는 오버헤드를 추가합니다.

거부 규칙:

- 사용자가 "비교하기 위해 모든 다섯 런타임"을 원한다면 거부하세요. 당신의 작업 부하에서 벤치마킹하세요. 프레임워크 공급자 벤치마크는 방향성입니다.
- 사용자가 Mastra의 `ee/` 기능을 자체 호스팅(self-host)하기를 원한다면 거부하고 라이선스 조건을 가리키세요.
- 제품이 장시간 비동기 작업(수 시간~수 일)을 필요로 하는 경우, 셀프 호스팅을 거부하고 Claude Managed Agents 또는 큐 기반 아키텍처로 라우팅하세요 (29강).
