제품 도메인과 추적 저장소가 주어지면, 에이전트 실패 모드에 대한 감지기를 생성합니다.

생성 대상:

1. 모드별 감지기: `hallucinated_action`, `scope_creep`, `cascading_errors`, `context_loss`, `tool_misuse`, `success_hallucination`.
2. 도메인별 감지기 (예: 개발 도구의 경우 "이슈를 연결하지 않고 PR을 생성", 마케팅 도구의 경우 "확인 없이 5명 이상의 수신자에게 이메일 전송").
3. 모든 감지기를 각 추적에 적용하고 분포를 출력하는 태거.
4. 임계값 기반 알림: 오늘 추적의 5% 이상이 모드를 태깅하면 페이지를 호출하거나 티켓을 오픈합니다.
5. 샘플 보존: 태깅된 각 추적에 대해 입력 + 출력 + 상태 스냅샷을 연산자 검토용으로 유지합니다.

하드 리젝트:

- 프로덕션 환경에서 추적마다 LLM 호출이 필요한 감지기. 패턴 기반 감지기를 사용하며, LLM 판정(judge)은 샘플링된 검토용으로 예약합니다.
- 크래시에서만 태깅하는 경우. 대부분의 실패는 정상적으로 보이는 출력을 생성합니다. 콘텐츠 + 상태에 대한 서명 체크가 필요합니다.
- PII 마스킹 없이 태깅된 추적을 저장하는 경우. 실패 샘플은 최악의 콘텐츠를 포함하므로, 저장 전에 스크럽(scrub)해야 합니다.

거부 규칙:

- 사용자가 "모든 추적을 영원히 저장"하기를 원한다면, 비용 및 컴플라이언스 이유로 거부합니다. 태그 + 비율로 샘플링합니다.
- 제품에 "알려진 좋은" 기준선이 없다면, 드리프트(drift) 알림을 거부합니다. 드리프트는 참조 기준이 필요합니다.
- 감지기가 버전 관리되지 않으면 거부합니다. 감지기 회귀(regression)는 알림 없이 신호를 깨뜨립니다.

출력: `detectors.py`, `tagger.py`, `alerts.py`, `retention.py`, `README.md`. 임계값, 보존 정책, 알림 라우팅을 설명합니다. "다음에 읽을 것"으로 끝내며, 적대적 실패 모드에 대해 24강(관측성 백엔드) 또는 27강(프롬프트 인젝션)을 가리킵니다.
