# 실패 모드: 에이전트가 고장 나는 이유

> MASFT (Berkeley, 2025)는 3가지 범주에 걸쳐 14가지 다중 에이전트 실패 모드를 분류합니다. Microsoft의 분류 체계(Taxonomy)는 기존 AI 실패가 에이전트 환경에서 어떻게 증폭되는지 문서화합니다. 산업 현장 데이터는 환각된 행동, 범위 확장, 연쇄적 오류, 컨텍스트 손실, 도구 오용이라는 5가지 반복적인 모드로 수렴합니다.

**유형:** 학습 + 빌드
**언어:** Python (표준 라이브러리)
**선수 요건:** 14단계 · 05강 (Self-Refine 및 CRITIC), 14단계 · 24강 (관측 가능성)
**시간:** 약 60분

## 학습 목표

- MASFT의 세 가지 실패 범주와 각 범주에 속하는 최소 네 가지 특정 모드를 나열해 보세요.
- 에이전트 환경의 실패가 기존 AI 실패 모드(편향, 환각)를 왜 증폭시키는지 설명해 보세요.
- 산업 현장에서 반복되는 5가지 모드와 그 완화 전략을 설명해 보세요.
- 에이전트 추적을 실패 모드 레이블로 태깅하는 표준 라이브러리 기반 감지기를 구현해 보세요.

## 문제점

팀들은 90%의 추적에서 작동하는 에이전트를 출시합니다. 나머지 10%의 실패는 무작위 잡음이 아닙니다. 이 실패는 소수의 반복적인 범주로 분류됩니다. 이 범주를 식별할 수 있다면, 이를 모니터링하고 수정할 수 있습니다.

## 개념

### MASFT (Berkeley, arXiv:2503.13657)

다중 에이전트 시스템 실패 분류 체계(Taxonomy). 14가지 실패 모드가 3가지 범주로 군집화됩니다. annotator 간 Cohen's Kappa는 0.88로, 범주들이 신뢰할 수 있게 구분됩니다.

핵심 주장: 실패는 다중 에이전트 시스템의 근본적인 설계 결함이며, 더 나은 기본 모델로 해결할 수 있는 LLM의 한계가 아닙니다.

### 에이전트형 AI 시스템의 실패 모드에 대한 Microsoft 분류 체계(Taxonomy)

- 기존 AI 실패(편향, 환각, 데이터 유출)는 에이전트 환경에서 증폭됩니다.
- 자율성에서 새로운 실패가 발생합니다. 대규모 의도하지 않은 행동, 도구 오용, 임무 이탈(mission drift) 등이 이에 해당합니다.
- 이 백서는 에이전트형 제품의 위험 등록부(risk register)입니다.

### 에이전트형 AI의 결함 특성화 (arXiv:2603.06847)

- 실패는 오케스트레이션, 내부 상태 진화, 환경 상호작용에서 발생합니다.
- 단순한 "나쁜 코드"나 "나쁜 모델 출력"이 아닙니다.

### LLM 에이전트 환각(Hallucination) 조사(arXiv:2509.18970)

두 가지 주요 양상:

1. **지시문 따르기(Instruction Following) 이탈** — 에이전트(Agent)가 시스템 프롬프트(System Prompt)를 따르지 않습니다.
2. **장기 컨텍스트 오용(Long-range Contextual Misuse)** — 에이전트(Agent)가 이전 턴의 컨텍스트를 잊거나 잘못 적용합니다.

하위 의도 오류: 생략(Omission, 단계 누락), 중복(Redundancy, 단계 반복), 순서 오류(Disorder, 순서가 뒤섞인 단계).

### 산업계에서 반복적으로 나타나는 다섯 가지 모드

Arize, Galileo, NimbleBrain의 2024-2026년 현장 분석이 수렴하는 결과:

1. **환각(Hallucination)된 행동.** 에이전트(Agent)가 존재하지 않는 도구를 호출하거나 인자를 조작합니다.
2. **범위 확장(Scope Creep).** 에이전트(Agent)가 사용자의 요청을 넘어 작업을 확장합니다(추가 PR 생성, 추가 이메일 발송 등).
3. **연쇄 오류(Cascading Errors).** 하나의 잘못된 호출이 하류 효과를 유발합니다. 환각(Hallucination)된 SKU가 네 번의 API 호출을 유발하여 다중 시스템 사고로 이어집니다.
4. **컨텍스트 손실(Context Loss).** 장기 작업이 초기 턴의 제약 조건을 잊습니다.
5. **도구 오용(Tool Misuse).** 올바른 도구를 잘못된 인자로 호출하거나, 완전히 다른 도구를 호출합니다.

연쇄 오류가 치명적입니다. 에이전트(Agent)는 "실패했다"와 "작업이 불가능하다"를 구분할 수 없으며, 400 오류에서 루프를 닫기 위해 성공 메시지를 환각(Hallucination)하는 경우가 많습니다.

### 완화책: 모든 단계에 게이트(Gate)를 두기

추론 체인의 모든 단계에서 환경 상태에 대한 사실적 그라운딩(Grounding)을 확인하는 자동화된 검증 게이트(Verification Gate)를 적용합니다. 구체적으로:

- 단계별 안전 게이트(안전 게이트) 분류기(21강).
- 도구 호출 인자 검증(06강).
- 검색된 콘텐츠를 알려진 사실과 교차 검증(05강, CRITIC).
- 상태를 재탐지하여 성공 환각(Hallucination)을 감지합니다(파일이 실제로 생성되었는지 확인).

### 실패 모니터링이 잘못된 경우

- **충돌(Crash)만 태깅하는 경우.** 대부분의 에이전트(Agent) 실패는 합리적으로 보이는 출력을 생성합니다. 콘텐츠 수준의 체크가 필요합니다.
- **기준선(Baseline) 없음.** 드리프트(Drift) 감지에는 마지막 알려진 정상 상태가 필요하며, 이것이 없으면 "상황이 악화되고 있다"고 말할 수 없습니다.
- **과도한 알림.** 모든 실패가 페이지를 생성합니다. 클러스터링하고 속도 제한(Rate Limit)을 적용하세요.

## 구현하기

`code/main.py`은 표준 라이브러리 기반 실패 모드 태거(Tagger)를 구현합니다:

- 5가지 모드를 포괄하는 합성 추적(trace) 데이터셋입니다.
- 각 모드별 탐지 함수 (도구 호출, 출력, 반복 동작에 대한 시그니처 패턴)입니다.
- 각 추적을 라벨링하고 모드 분포를 보고하는 태거(tagger)입니다.

실행해 보세요:

```
python3 code/main.py
```

출력: 추적별 라벨 + 집계된 분포, Phoenix의 추적 클러스터링이 드러내는 내용을 저렴하게 재현합니다.

## 사용하기

- 프로덕션 환경의 드리프트 클러스터링에는 **Phoenix**를 사용하세요 (24강).
- 세션 재생 및 어노테이션에는 **Langfuse**를 사용하세요.
- 관측성 플랫폼이 감지할 수 없는 도메인 특화 시그니처에는 **Custom**을 사용하세요.

## 연습 문제

1. "성공 환각(success hallucination)" 탐지기를 추가하세요: 에이전트가 성공을 반환하지만 대상 상태가 변경되지 않는 경우입니다.
2. 직접 구축한 제품에서 실제 추적 100개를 태깅하세요. 어떤 모드가 지배적인가요? 이를 수정하는 비용은 얼마인가요?
3. "연쇄 반경(cascade radius)" 메트릭을 구현하세요: N단계에서 실패가 발생했을 때, 하류 단계 몇 개가 영향을 받았나요?
4. MASFT의 14가지 실패 모드를 읽어보세요. 제품 적용 가능한 세 가지를 선택하고 탐지기를 작성하세요.
5. 탐지기 하나를 CI 작업에 연결하세요: 추적의 5% 이상이 모드를 태깅하면 빌드가 실패하도록 설정합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| MASFT | "멀티 에이전트 실패 분류 체계" | Berkeley의 14가지 모드 분류 |
| 연쇄 오류(Cascading error) | "파급 실패" | 초기의 작은 실수가 N단계에 걸쳐 전파됨 |
| 컨텍스트 손실(Context loss) | "제약을 잊음" | 장기 관점(turn)에서 초기 turn의 사실들이 사라짐 |
| 도구 오용(Tool misuse) | "잘못된 도구 / 잘못된 인자" | 유효한 호출이지만 잘못된 실행 |
| 성공 환각(Success hallucination) | "완성을 위조함" | 에이전트가 400 상태에 대해 성공을 주장함; 상태는 변경되지 않음 |
| 범위 초과(Scope creep) | "과잉 수행" | 에이전트가 요청된 것보다 더 많은 작업을 수행함 |
| 지시문 따르기 편차(Instruction-following deviation) | "불복종" | 시스템 프롬프트나 사용자 제약을 무시함 |
| 하위 의도 오류(Sub-intention errors) | "계획 버그" | 계획 실행 중 생략, 중복, 순서 오류 |
