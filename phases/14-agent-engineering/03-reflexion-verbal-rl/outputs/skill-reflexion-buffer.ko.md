작업 클래스(반복되는 에이전트 실행 유형, 예: "함수 리팩토링", "지원 티켓 닫기")가 주어지면, 회상(reflection)을 위한 일화 기억 버퍼를 유지합니다. 각 회상은 실패 모드와 자연어로 된 교정적 통찰을 기록합니다. 버퍼는 동일한 작업 클래스의 다음 시도에 선행되어 추가됩니다.

생성할 것:

1. 회상 캡처. 평가자 점수가 임계값 미만으로 시도가 종료되면, "X를 Y 때문에 실패했습니다. 다음에는 Z를 하세요." 형태의 한 줄 회상을 생성합니다. 외부적 실패(네트워크, 상류 500 오류)에 대한 회상은 재현 가능하지 않은 한 폐기합니다.
2. TTL 및 중복 제거. 회상은 기본적으로 N번의 시도 후 만료됩니다(10번 권장). 완전한 중복은 병합됩니다. 유사한 중복(소규모 임베딩 모델에서 코사인 유사도 >0.9, 또는 공유 부분 문자열 >= 80%)은 가장 최근 항목만 유지합니다.
3. 범위 정책. 세 가지 범위: 작업 클래스(작업 이름별), 사용자(동일 사용자의 모든 작업), 에이전트(모든 사용자). 기본값은 작업 클래스입니다. 회상이 사용자별 선호도를 참조하는 경우에만 사용자 범위로 격상하며, 에이전트 범위로 자동으로 격상하지는 않습니다.
4. 압축. 버퍼가 예산을 초과하면, 수면 시간(sleep-time) 압축을 실행합니다: 유사한 중복을 클러스터링하고, 요약하며, 병합합니다. 압축은 핫 경로(hot path) 밖에서 실행되므로, 주요 에이전트의 응답을 지연시키지 마세요.
5. 프롬프트 통합. "이전 시도에서 배운 점"이라는 제목의 단일 블록을 불릿 리스트로 생성합니다. 프롬프트 내 항목은 6개로 제한하며, 초과분은 별도 요약 항목("... 및 타임아웃에 대한 4개의 이전 회상")으로 처리합니다.

하드 리젝트(Hard rejects):

- "다음에는 더 주의하세요."와 같은 회상을 작성하는 것. 이는 실행 가능한 지시가 아닙니다. 구체적이고 실행 가능한 다음 지시를 강제하는 프롬프트로 리플렉터(reflector)를 다시 실행하세요.
- 시도 횟수 대신 벽시계 시간(wall-clock time)에 기반하여 회상을 만료시키는 것. 오프라인 재현 가능한 실행을 위해 TTL은 시간 범위(time-scoped)가 아닌 시도 범위(trial-scoped)여야 합니다.
- 비밀(API 키, 토큰, PII)을 참조하는 회상을 저장하는 것. 버퍼에 커밋하기 전에 "비밀 포함" 클래스의 특정 오류로 거부하세요.

거절 규칙:

- 평가자가 연결되어 있지 않으면 거절하고 05강 (Self-Refine/CRITIC)을 권장하세요. 반성은 직관적인 판단이 아닌 신호를 필요로 합니다.
- 작업 유형이 일회성(절대 반복되지 않음)인 경우 거절하세요. 반복되지 않는 작업에 대해선 에피소드 메모리가 아무런 역할을 하지 못합니다.

출력: 구조화된 버퍼 파일(JSON 형식의 반성 객체: trial id, task class, scope, text, created_at, ttl_remaining), 다음 시도를 위한 프롬프트 블록, 그리고 곧 만료될 항목을 나열한 "만료된 반성(stale reflections)" 보고서를 생성합니다.

버퍼가 상한에 계속 도달하는 경우 06강(컨텍스트 압축)을, 컴팩션을 핫 패스(hot path)에서 벗어나게 하려면 08강(Letta sleep-time compute)을 가리키는 "다음에 읽을 내용" 노트로 마무리하세요.
