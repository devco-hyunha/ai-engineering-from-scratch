작업, 반복 예산, 그리고 사용 가능한 검증기(도구 기반 또는 자체 평가 전용)가 주어지면, 평가자-최적화자 루프를 위한 프롬프트와 중단 정책을 생성합니다.

생성할 항목:

1. 생성자 프롬프트. 첫 번째 출력을 위한 결정적 생성자입니다. 작업, 출력 형식, 제약 조건을 명시적으로 기술합니다.
2. 평가자/검증기 프롬프트. 도구(검색, 코드 실행, 테스트, 계산기, 타입 체크)가 사용 가능한 경우, 호출 방법과 구조화된 비판(JSON 형식: pass/fail, violations[], suggested_fixes[])을 생성하는 방법을 지정합니다. 자체 평가만 사용 가능한 경우, Self-Refine의 형식적 승인(rubber-stamp) 위험을 명시적으로 경고하고, 구조적으로 다른 프롬프트 스타일(예: "최소 하나의 결함을 찾아라"와 같은 적대적 프롬프트)을 사용합니다.
3. 리파이너 프롬프트. 이전 출력과 비판(이력)을 반드시 참조해야 합니다. "이전 반복에서 지적된 실패 유형을 반복하지 마세요"는 필수 조건입니다.
4. 중단 정책. 다음 조건들의 결합: 검증기 통과 OR (자체 평가가 통과하고 반복 횟수 >= 2) OR 반복 횟수 >= max_iterations. 단일 조건만으로는 절대 중단하지 않습니다.
5. 관측 가능성 훅. 각 반복을 OpenTelemetry GenAI 스팬(evaluate, optimize)으로 로깅하여 23강강에 따라 전체 refine 궤적이 감사 가능하도록 합니다.

하드 리젝트(Hard rejects):

- 생성자와 비판자에게 동일한 프롬프트를 사용. 형식적 승인(rubber-stamp) 위험 — 모델이 스스로와 동의합니다.
- 반복 상한 없음. 무한한 refine 루프는 토큰을 소진합니다. 기본값은 항상 4로 상한을 설정합니다.
- 자유 형식 산문 피드백을 요청하는 검증기 프롬프트. 구조화된 JSON만 허용 — pass/fail 및 항목별 위반 사항(violations)만 포함합니다.
- 리파이너 프롬프트에서 이력(history)을 제거. 논문은 이력이 없으면 품질이 붕괴됨을 보여줍니다.

거부 규칙:

- 작업에 검증기가 없고 검증기를 만들 방법도 없다면, CRITIC을 거부하고 Self-Refine이 사용 가능한 더 약한 옵션임을 명시하며, 형식적 승인(rubber-stamp) 위험에 대해 사용자에게 경고합니다.
- max_iterations가 10 이상이면 거부하고 작업 재설계를 권장합니다. 3~4번 이상의 반복으로 수렴하지 않는다면 생성 프롬프트가 잘못된 신호인 경우가 많습니다.
- 검증자가 파괴적인 도구(shell, git 쓰기)를 호출하면 거부하고 샌드박스 경계를 요구합니다(12강).

출력: 모든 프롬프트, 중단 정책, 도구 목록을 포함한 단일 구성 블록과 배포 대상에 따라 16강(OpenAI Agents SDK 가드레일), 12강(Anthropic 평가자-최적화자), 30강(평가 기반 에이전트 개발)을 가리키는 "다음에 읽을 내용" 노트를 포함합니다.
