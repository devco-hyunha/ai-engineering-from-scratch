과제 형태(단일 답변 / 다중 답변 / 자유 형식), 토큰 예산, 사용 가능한 평가자(스칼라 테스트 / 휴리스틱 / 자기 평가)가 주어지면, 구체적인 매개변수를 포함한 검색 전략 권장안을 생성해 보세요.

산출물:

1. 결정. 다음 중 하나: 선형 ReAct, 빔 ToT (빔 폭 k), BFS ToT (최대 깊이), 가지치기를 포함한 DFS ToT, 반복 횟수와 UCT c를 포함한 MCTS LATS, 진화적 탐색 (평가기가 프로그래밍 방식으로 검증 가능한 경우에만).
2. 매개변수(Parameter). 모든 전략에 대해 구체적인 기본값: 빔 너비, 깊이 상한, 분기 계수 K, 레벨당 롤아웃 수, UCT c (기본값 1.4), 타임아웃.
3. 가치 함수. 노드의 점수를 산정하는 기준을 정확히 지정합니다. 옵션: 단위 테스트 통과율, 목표까지의 수치적 거리, 형식 지정된 프롬프트 LLM 점수(확실/가능/불가능 또는 1..10 또는 투표), 또는 환경 보상입니다.
4. 토큰 예산 추정. 최악의 경우 토큰 수 = branching_factor ^ depth * avg_prompt_tokens. 이 숫자를 표시하세요. 사용자의 예산을 초과하는 경우, 더 저렴한 전략을 권장하세요.
5. 실패 모드. 선택한 각 전략에 대해 상위 두 가지 실패 모드와 그 완화 방안을 나열해 보세요 (예: LATS + 잡음 있는 평가자 -> CRITIC의 도구 기반 검증 추가, 05강).

하드 거절:

- 평가자가 신뢰할 수 없는 경우 검색을 권장합니다 (자기 평가만 있고, 정답이 없는 경우). ReAct + CRITIC으로 폴백하세요.
- compelling한 이유 없이 분기 계수 K를 5보다 높게 설정하는 것. K=3-5는 논문 기본값이며, K=10은 비용을 급증시킵니다.
- 채팅형 작업에 LATS를 적용해 보세요. 프로그래밍 대상이 없는 대화형 Q&A에서는 검색이 도움이 되지 않습니다.
- 기계적으로 검증 가능한 적합도가 없는 진화적 탐색. AlphaEvolve는 적합도가 프로그래밍 방식으로 정의될 때(테스트 실행, 속도 측정, 정리 검증)에만 의미가 있습니다.

거부 규칙:

- 토큰 예산이 단일 궤적 비용의 5배 미만이면 검색을 거부하고 ReAct + Reflexion을 권장하세요 (03강).
- 월클럭 지연 시간 예산이 10초 미만인 경우, LATS를 거부하고 ReAct를 권장합니다.
- 과제가 순수한 정보 검색이라면 검색을 거부하고 ReWOO (02강)를 권장하세요.

출력: 선택된 전략, 매개변수, 가치 함수, 예산 추정치를 포함하는 권장 블록과 평가자 신뢰성을 위한 05강(CRITIC), 진화적 변형을 위한 11강(AlphaEvolve), 벤치마크급 검증을 위한 30강(평가 주도 개발)을 가리키는 "다음에 읽을 내용" 노트를 포함합니다.
