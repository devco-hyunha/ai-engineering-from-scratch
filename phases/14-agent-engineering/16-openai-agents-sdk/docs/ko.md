# OpenAI Agents SDK: 핸드오프, 가드레일, 추적

> OpenAI Agents SDK는 Responses API 위에 구축된 경량 멀티 에이전트 프레임워크입니다. 다섯 가지 기본 요소: Agent, Handoff, Guardrail, Session, Tracing. 핸드오프는 `transfer_to_<agent>`라는 이름의 도구입니다. 가드레일은 입력이나 출력에서 트리거됩니다. 추적은 기본적으로 켜져 있습니다.

**유형:** Learn + Build
**언어:** Python (stdlib)
**선수 요건:** 14단계 · 01강 (에이전트 루프), 14단계 · 06강 (도구 사용)
**시간:** 약 75분

## 학습 목표

- OpenAI Agents SDK의 다섯 가지 기본 요소를 나열해 보세요.
- 핸드오프를 설명해 보세요: 왜 도구로 모델링되는지, 모델이 보는 이름 형식은 무엇인지, 컨텍스트가 어떻게 전달되는지.
- 입력 가드레일, 출력 가드레일, 도구 가드레일을 구분하고 `run_in_parallel`와 차단 모드의 차이를 설명해 보세요.
- 핸드오프 + 가드레일 + 스팬 스타일 추적을 갖춘 stdlib 런타임을 구현해 보세요.

## 문제점

명확하게 위임할 수 없는 에이전트는 모든 것을 하나의 프롬프트에 넣게 됩니다. 가드레일이 없는 에이전트는 개인 식별 정보(PII), 정책 위반 출력, 또는 무한 루프를 발생시킵니다. OpenAI의 SDK는 멀티 에이전트 작업을 관리 가능하게 만드는 세 가지 기본 요소를 규정합니다.

## 개념

### 다섯 가지 기본 요소

1. **Agent.** LLM + 지침 + 도구 + 핸드오프.
2. **Handoff.** 다른 에이전트로의 위임. 모델에는 `transfer_to_<agent_name>`라는 이름의 도구로 표현됩니다.
3. **Guardrail.** 입력(첫 번째 에이전트만), 출력(마지막 에이전트만), 또는 도구 호출(각 함수 도구)에 대한 검증.
4. **Session.** 턴에 걸친 자동 대화 기록.
5. **Tracing.** LLM 생성, 도구 호출, 핸드오프, 가드레일에 대한 내장 스팬.

### 도구로서의 핸드오프

모델은 도구 목록에서 `transfer_to_billing_agent`를 봅니다. 이를 호출하면 런타임이 다음을 수행하도록 신호를 보냅니다:

1. 대화 컨텍스트를 복사합니다(또는 `nest_handoff_history` 베타를 통해 압축합니다).
2. 목표 에이전트를 지침으로 초기화합니다.
3. 목표 에이전트로 실행을 계속합니다.

이는 감독자 패턴(13강 / 28강)을 제품화한 것입니다.

### 가드레일

세 가지 유형:

- **입력 가드레일.** 첫 에이전트의 입력에 대해 실행합니다. LLM 호출 전에 안전하지 않거나 범위를 벗어난 요청을 거부합니다.
- **출력 가드레일.** 마지막 에이전트의 출력에 대해 실행합니다. PII 유출, 정책 위반, 형식이 잘못된 응답을 포착합니다.
- **도구 가드레일.** 함수 도구별로 실행합니다. 인자를 검증하고, 권한을 확인하며, 실행을 감사합니다.

모드:

- **병렬** (기본값). 가드레일 LLM이 메인 LLM과 병렬로 실행됩니다. 꼬리 지연이 낮습니다. 트리핑되면 메인 LLM의 작업이 폐기됩니다(토큰 낭비).
- **차단** (`run_in_parallel=False`). 가드레일 LLM이 먼저 실행됩니다. 트리핑되면 메인 호출에 토큰이 낭비되지 않습니다.

트리와이어가 `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered`를 발생시킵니다.

### 추적

기본적으로 켜져 있습니다. 모든 LLM 생성, 도구 호출, 핸드오프, 가드레일이 스팬을 방출합니다. `OPENAI_AGENTS_DISABLE_TRACING=1`는 옵트아웃합니다. `add_trace_processor(processor)`는 OpenAI의 백엔드와 함께 스팬을 자체 백엔드로 전송합니다.

### 세션

`Session`는 대화 이력을 백엔드(SQLite, Redis, 커스텀)에 저장합니다. `Runner.run(agent, input, session=session)`는 자동으로 로드하고 추가합니다.

### 이 패턴이 잘못되는 지점

- **핸드오프 드리프트.** 에이전트 A가 에이전트 B에게 핸드오프하고, B가 다시 A에게 핸드오프합니다. 홉 카운터를 추가하세요.
- **가드레일 우회.** 도구 가드레일은 함수 도구에서만 발동합니다. 내장 도구(파일 리더, 웹 페치)는 별도의 정책이 필요합니다.
- **과도한 추적.** 스팬에 민감한 콘텐츠가 포함됩니다. OTel GenAI 콘텐츠 캡처 규칙(23강)과 함께 사용하세요. 외부에 저장하고 ID로 참조합니다.

```figure
ae-agent-handoff
```

## 구현하기

`code/main.py`는 SDK 형태를 표준 라이브러리에서 구현합니다:

- `Agent`, `FunctionTool`, `Handoff` (전송 시맨틱을 가진 함수 도구로).
- 입력/출력/도구 가드레일, 핸드오프 디스패치, 홉 카운터를 포함한 `Runner`.
- 추적 형태를 보여주기 위한 간단한 스팬 방출기.
- 사용자의 쿼리에 따라 청구나 지원으로 핸드오프하는 트리아지 에이전트. 하나의 입력에서 가드레일이 트리핑됩니다.

실행:

```
python3 code/main.py
```

추적은 두 번의 성공적인 핸드오프, 한 번의 입력 가드레일 트리핑, 그리고 실제 SDK가 방출하는 스팬 트리를 반영합니다.

## 사용하기

- OpenAI 우선 제품에는 **OpenAI Agents SDK**를 사용하세요.
- **Claude Agent SDK** (17강)는 Claude 우선 제품용입니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 에이전트(Agent) | "LLM + 지침" | SDK의 에이전트 타입; 도구와 핸드오프를 소유합니다 |
| 핸드오프(Handoff) | "전송" | 모델이 다른 에이전트에게 위임하기 위해 호출하는 도구 |
| 가드레일(Guardrails) | "정책 검사" | 입력 / 출력 / 도구 호출에 대한 검증 |
| 트리프와이어(Tripwire) | "가드레일 트리핑" | 가드레일이 거부할 때 발생하는 예외 |
| 세션(Session) | "이력 저장소" | 실행 간에 지속되는 대화 메모리 |
| 추적(Tracing) | "스팬(Spans)" | LLM + 도구 + 핸드오프 + 가드레일에 대한 내장 관측 가능성 |
| 차단형 가드레일 | "순차적 검사" | 가드레일이 먼저 실행됩니다; 트리핑 시 토큰 낭비 없음 |
| 병렬 가드레일 | "동시 검사" | 가드레일이 병렬로 실행됩니다; 지연 시간이 낮지만, 트리핑 시 토큰을 낭비합니다 |
