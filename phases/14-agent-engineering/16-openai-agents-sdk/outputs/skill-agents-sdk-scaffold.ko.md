제품 도메인과 전문가 에이전트 목록이 주어지면 OpenAI Agents SDK 앱을 스캐폴딩합니다.

다음 내용을 생성합니다:

1. 각 전문가에 대해 `Agent` 하나와 핸드오프만 가진 `triage` 에이전트 하나(도메인 도구 없음).
2. 각 도메인 도구에 대해 타입이 지정된 입력 스키마, 명확한 설명(모델이 언제 사용해야 하는지 알려줌), 실행 샌드박스를 가진 `FunctionTool`.
3. 트리아지에서 각 전문가로 가는 `Handoff`. 도구 이름이 `transfer_to_<agent>` 규칙을 따르는지 확인합니다.
4. PII, 정책, 범위에 대한 `InputGuardrail`. 가드레일 LLM이 메인 모델에 비해 크지 않은 한 병렬 모드를 기본으로 사용하며, 크다면 블로킹을 사용합니다.
5. 길이, PII, 정책에 대한 `OutputGuardrail`. 안전이 중요한 출력의 경우 프로덕션에서는 항상 블로킹을 사용합니다.
6. 네트워크나 파일 시스템을 건드리는 함수 도구에 대한 도구별 가드레일.
7. `Session` 저장소(기본은 SQLite; 프로덕션은 Redis).
8. OpenAI의 추적 UI와 함께 백엔드에 스팬을 연결하는 `add_trace_processor`.

하드 리젝트:

- 도메인 도구를 가진 트리아지 에이전트. 트리아지는 핸드오프만 수행해야 합니다. 혼합하면 라우터의 결정이 희석됩니다.
- 입력/출력을 변형하는 가드레일. 가드레일은 승인하거나 거부할 뿐, 재작성하지 않습니다.
- 침묵하는 핸드오프 루프. 호프 카운터(기본 최대 3)를 요구합니다.

거부 규칙:

- 사용자가 "가드레일 없이, 빠르게 진행하자"를 원한다면, 유료 사용자나 PII를 다루는 모든 제품에 대해 거부합니다.
- 제품에 전문가가 2명뿐이라면, 트리아지+핸드오프 대신 직접 분류기를 사용하는 `Agents` 라우팅(12강)을 제안합니다. 토큰 비용이 더 적습니다.
- 프로덕션에서 추적이 비활성화되어 있다면 출시를 거부합니다. 추적 없이는 다단계 실패를 디버깅할 수 없습니다.

출력: `agents.py`, `tools.py`, `guardrails.py`, `app.py`, `README.md`와 함께 triage-agent 근거, 가드레일 모드, 추적 처리기, 세션 백엔드를 포함합니다. 23강 (OTel GenAI), 24강 (관측성 백엔드) 또는 Claude Agent SDK 번역을 위한 17강을 가리키는 "다음에 읽을 내용"으로 마무리해 보세요.
