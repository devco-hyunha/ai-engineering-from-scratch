# 상태 유지 그래프 오케스트레이션 — 내구성 있는 실행과 체크포인트

> 에이전트(Agent)는 상태 머신이며, 노드는 함수이고, 엣지는 전이이며, 각 노드 실행 후 상태는 체크포인트로 저장됩니다. 실패 시 마지막 성공한 체크포인트에서 재개할 수 있습니다. LangGraph는 2026년 저수준 상태 유지 오케스트레이션 모델의 표준입니다.

**유형:** Learn + Build
**언어:** Python (stdlib)
**선수 요건:** 14단계 · 01강 (에이전트 루프), 14단계 · 12강 (워크플로우 패턴)
**시간:** 약 75분

## 학습 목표

- LangGraph의 핵심 모델인 타입이 지정된 상태, 함수 노드, 조건부 엣지, 노드 후 체크포인트를 설명할 수 있습니다.
- 문서에서 강조하는 네 가지 기능인 내구성 있는 실행(Durable Execution), 스트리밍(Streaming), 인간 개입 루프 (HITL)(Human-in-the-Loop (HITL)), 포괄적인 메모리를 나열할 수 있습니다.
- LangGraph가 지원하는 세 가지 오케스트레이션 토폴로지인 슈퍼바이저, 피어 투 피어 (스웜)(Peer-to-Peer (Swarm)), 계층적 (중첩 서브그래프)(Hierarchical (Nested Subgraphs))을 설명할 수 있습니다.
- 타입이 지정된 상태, 조건부 엣지, 체크포인트/재개 사이클을 포함하는 stdlib 상태 그래프를 구현할 수 있습니다.

## 문제점

에이전트와 워크플로우가 공통적으로 겪는 문제가 있습니다. 40단계 실행 중 38단계에서 실패하면, 처음부터 다시 시작하는 것이 아니라 38단계에서 재개하길 원합니다. 상태 모델이 이차적인 경우, 운영자는 새로 실행된다고 가정하는 라이브러리 주위에 재시도 로직을 직접 구현해야 합니다.

LangGraph의 설계 해답은 상태가 일급 타입 객체이고, 변경이 명시적이며, 모든 노드 실행 후 체크포인트가 저장된다는 것입니다. 재개는 `load_state(session_id)` 호출입니다.

## 개념

### 그래프

그래프는 다음으로 정의됩니다:

- **상태 타입.** 모든 노드가 읽고 변경하는 타입이 지정된 dict (또는 Pydantic 모델).
- **노드.** 순수 함수 `(state) -> state_update`. 반환 후 업데이트가 상태에 병합됩니다.
- **엣지.** 노드 간의 조건부 또는 직접 전이.
- **진입 및 종료.** `START` 및 `END` 센티널 노드가 경계를 표시합니다.

예시: `classify`, `refund`, `bug`, `sales`, `done` 노드를 가진 에이전트 — 그래프로서의 라우팅 워크플로우.

### 내구성 있는 실행

각 노드가 반환한 후, 런타임은 상태를 직렬화하여 체크포인터(SQLite, Postgres, Redis, 사용자 정의)에 기록합니다. N단계에서 실패가 발생하면 런타임은 `resume(session_id)`하여 N+1단계부터 정확한 상태로 이어갈 수 있습니다.

LangGraph 문서에서는 이 기능이 중요한 생산 환경 사용자로 Klarna, Uber, J.P. Morgan을 명시적으로 강조합니다. 핵심 주장은 그래프의 형태가 아니라, 그래프 형태와 체크포인팅이 결합되어 복구 비용을 낮춘다는 점입니다.

### 스트리밍

모든 노드는 부분적인 출력을 생성할 수 있습니다. 그래프는 노드별 델타 이벤트를 호출자에게 스트리밍하여, 그래프가 실행되는 동안 UI가 업데이트되도록 합니다.

### 인간 개입 루프 (HITL)(Human-in-the-Loop (HITL))

노드 간에 상태를 검사하고 수정합니다. 구현 방식: 중요한 노드 전에 일시 중지하고, 상태를 인간에게 표시하며, 수정을 수락하고, 재개합니다. 체크포인터는 상태가 이미 직렬화되어 있으므로 이 작업을 쉽게 만듭니다.

### 메모리

단기 메모리(실행 내 — 상태 내 대화 기록)와 장기 메모리(실행 간 — 체크포인터와 별도의 장기 저장소를 통해 지속)가 있습니다. LangGraph는 도구를 통해 외부 메모리 시스템(Mem0, 사용자 정의)과 통합합니다.

### 세 가지 토폴로지

1. **슈퍼바이저.** 중앙 라우터 LLM이 전문가 하위 에이전트에게 작업을 분배합니다. `langgraph-supervisor`에서 `create_supervisor()`을 수행합니다(2026년 LangChain 팀은 더 많은 컨텍스트 제어를 위해 도구 호출을 통해 직접 수행하는 것을 권장합니다).
2. **스웜 / 피어 투 피어.** 에이전트가 공유된 도구 인터페이스를 통해 직접 핸드오프합니다. 중앙 라우터가 없습니다.
3. **계층적.** 중첩된 하위 그래프로 구현된 하위 슈퍼바이저를 관리하는 슈퍼바이저입니다.

### 이 패턴이 잘못되는 지점

- **체크포인트가 너무 작음.** 대화 턴만 체크포인팅하면 도구 상태와 메모리 기록이 복구 불가능해집니다. 전체 상태가 직렬화되어야 합니다.
- **비결정적 노드.** 재개는 노드 입력이 동일한 상태 업데이트를 생성한다고 가정합니다. 랜덤 시드, 벽시계 시간, 외부 API는 반드시 캡처해야 합니다.
- **조건부 엣지의 과용.** 모든 엣지가 조건부인 그래프는 추론할 수 없는 상태 기계가 됩니다. 가끔 분기가 있는 선형 체인을 선호하세요.

```figure
langgraph-state
```

## 구현하기

`code/main.py`은 표준 라이브러리 상태 그래프를 구현합니다:

- `State` — `messages`, `step`, `route`, `output`, `human_approval`을 포함하는 타입 지정된 dict입니다.
- `Node` — 상태를 받아 업데이트 dict를 반환하는 callable입니다.
- `StateGraph` — 노드 + 엣지 + 조건부 엣지 + 실행 + 재개.
- `SQLiteCheckpointer` (메모리 내 가짜) — 모든 노드 실행 후 상태를 직렬화합니다. `load(session_id)`이 복원합니다.
- 데모 그래프: 분류 -> 분기(환불 / 버그 / 영업) -> 인간 게이트 -> 전송.

실행해 보세요:

```
python3 code/main.py
```

추적은 첫 실행이 인간 게이트에서 실패하고, 지속성(persistence)이 유지된 후, 재개가 최종 출력을 생성하는 과정을 보여줍니다.

## 사용하기

- **LangGraph** — 참고 자료, 프로덕션 준비 완료. `create_react_agent`, `create_supervisor`을 사용하거나 자체 그래프를 구축해 보세요.
- **AutoGen v0.4** (14강) — 높은 동시성 시나리오를 위한 액터 모델 대안입니다.
- **Claude Agent SDK** (17강) — 내장 세션 스토어를 갖춘 관리형 하네스입니다.
- **Custom** — 상태 형태나 체크포인터 백엔드에 대한 정확한 제어가 필요할 때 사용합니다.

## 출시하기

`outputs/skill-state-graph.md`은 체크포인팅과 재개가 연결된 LangGraph 형태의 상태 그래프를 모든 대상 런타임에서 생성합니다.

## 연습 문제

1. 분류 신뢰도가 임계값 미만일 때 `classify`에서 `end`로 조건부 엣지를 추가하세요. 인간이 `route`를 수동으로 설정한 후 실행을 재개하세요.
2. SQLite 유사 가짜를 실제 SQLite 체크포인터로 교체하세요. 단계별 직렬화 오버헤드를 측정하세요.
3. 병렬 엣지를 구현하세요: 두 노드가 동시에 실행되고, 커스텀 리듀서로 병합됩니다. 여기서 불변 상태가 무엇을 가져다주는지 생각해 보세요.
4. `langgraph-supervisor` 참고 자료를 읽어보세요. 장난감(toy)을 `create_supervisor`로 포팅(porting)하세요. 추적 형태를 비교하세요.
5. 스트리밍을 추가하세요: 각 노드가 실행 중 부분 상태를 생성(yield)합니다. 도착하는 델타를 출력하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 상태 그래프 | "에이전트(Agent)를 상태 기계로 보기" | 타입 지정된 상태 + 노드 + 엣지 + 리듀서 |
| 체크포인터(Checkpointer) | "지속성 백엔드" | 모든 노드 실행 후 상태를 직렬화; 재개 가능하게 함 |
| 리듀서(Reducer) | "상태 병합기" | 현재 상태와 노드의 업데이트를 결합하는 함수 |
| 조건부 엣지 | "브랜치" | 상태의 함수에 따라 선택되는 엣지 |
| 서브그래프 | "중첩 그래프" | 다른 그래프 내부의 노드로 사용되는 그래프 |
| 내구성 있는 실행(Durable Execution) | "실패 후 재개" | 정확한 상태로 마지막 성공한 노드에서 재시작 |
| 슈퍼바이저 | "라우터 LLM" | 전문가 서브에이전트를 위한 중앙 디스패처 |
| 스웜(Swarm) | "P2P 에이전트" | 에이전트가 공유 도구를 통해 핸드오프(Handoff)하며, 중앙 라우터가 없음 |
