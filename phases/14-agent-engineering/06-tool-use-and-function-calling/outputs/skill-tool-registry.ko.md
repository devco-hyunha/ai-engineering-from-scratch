작업 도메인이 주어지면, 에이전트가 BFCL V4 축(에이전트형, 다중 턴, 라이브, 비라이브, 환각) 전반에 걸쳐 신뢰할 수 있게 사용할 수 있는 도구 카탈로그를 생성합니다.

생성 대상:

1. 도구 정의. 각 도구마다 `name` (snake_case), `description` (언제 사용해야 하는지, 언제 사용해서는 안 되는지 모델에 알려줌), 타입이 지정된 속성, 필수 필드, 해당되는 경우의 enum, 숫자의 최소/최대값, 도구별 타임아웃, 도구별 샌드박스 정책(fs 표면, 네트워크, 메모리 상한)을 포함한 JSON Schema 입력을 정의합니다.
2. 설명 품질 점검. 각 설명을 "이 도구를 다른 도구보다 선택해야 하는 이유를 모델에 전달하는가?"라는 기준으로 검토합니다. 두 도구의 설명이 겹치면 거부하고 다시 작성합니다.
3. 병렬 디스패치 계획. 각 현실적인 작업에 대해, 독립적인 도구 호출(병렬화 가능)과 순차적으로 실행해야 하는 도구 호출을 식별합니다. 예상 디스패치 그래프를 생성합니다.
4. 검증 정책. enum 검사, 타입 강제 변환 규칙(예: "int-as-string은 허용, float-as-string은 거부"), 필수 필드 강제 적용. 모든 실패는 구조화된 관측 문자열을 반환하며, 루프로 예외를 발생시키지 않습니다.
5. 관측 가능성. 각 도구는 OpenTelemetry GenAI `tool_call` 스팬을 방출하며, 속성 `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result` (콘텐츠 정책이 요구할 경우 참조로만 포함, 인라인 아님)를 포함합니다.

거부 대상:

- 범용 셸/명령 실행 도구. 거부하고 구체적인 동사(`git_status`, `fs_read`, `npm_test`)로 분해합니다.
- 매개변수가 닫힌 값 집합을 가질 때 enum 누락. enum 검증은 드리프트를 잡는 가장 저렴한 방법입니다.
- 두 개의 서로 다른 도구에 동일한 설명. 모델이 두 도구 사이에서 신뢰할 수 있게 선택할 수 없습니다.
- 도구 이름만 명시하는 `description` ("두 수를 더합니다"). 대안보다 이 도구를 선택해야 하는 WHEN을 포함합니다.
- 타임아웃 없음. 모든 도구 호출에는 상한이 있어야 합니다.

거부 규칙:

- 단일 에이전트의 도구 목록이 30개를 초과하면 거부하고 하위 에이전트 위임을 권장합니다(17강).
- 도구가 확인 게이트 없이 파괴적 작업을 수행하면 거부하고 09강(권한, 샌드박스)을 참조하세요.
- 작업이 컴퓨터 사용(클릭, 입력, 스크린샷)인 경우 거부하고 21강을 참조하세요. 이는 비전 기반 작업을 수행하는 별도의 도구 형태입니다.

출력: Anthropic / OpenAI / Gemini SDK 호출에 바로 붙여넣을 수 있는 JSON 도구 카탈로그, 디스패치 그래프 다이어그램, 검증 정책 문서, 레지스트리가 통과해야 하는 BFCL 스타일 미니 평가.
