# HTN과 진화적 탐색을 활용한 계획

> 기호적 계획은 계획이 증명 가능하게 정확해야 하는 경우를 처리합니다. 진화적 코드 탐색은 적합도 함수가 기계적으로 검증 가능한 경우를 처리합니다. ChatHTN (2025)과 AlphaEvolve (2025)는 각각 LLM과 결합했을 때 어떤 가능성을 열어주는지 보여줍니다.

**유형:** Build
**언어:** Python (stdlib)
**선수 요건:** 14단계 · 02강 (ReWOO 및 Plan-and-Execute)
**시간:** 약 75분

## 학습 목표

- 계층적 작업 네트워크(Hierarchical Task Networks): 작업, 방법, 연산자, 전제 조건, 효과를 설명합니다.
- ChatHTN의 하이브리드 루프 — 기호적 탐색과 LLM 기반 분해 폴백을 설명합니다.
- AlphaEvolve의 진화적 루프와 왜 프로그램 가능한 평가자(programmatic evaluator)와만 작동하는지 설명합니다.
- stdlib에서 장난감 HTN 계획기와 장난감 진화적 탐색을 구현합니다.

## 문제점

ReWOO (02강), Plan-and-Execute, ReAct는 대부분의 에이전트 계획을 다루지만, 두 가지 경우를 잘 다루지 못합니다:

1. **증명 가능한 정확성을 가진 계획.** 스케줄링, 비행 경로 설정, 컴플라이언스 워크플로 — 계획은 구성 자체로 타당해야 합니다. 때때로 단계를 환각(Hallucination)하는 유창한 LLM 계획은 허용되지 않습니다.
2. **기계적으로 검증 가능한 적합도 함수를 가진 최적화.** 행렬 곱셈, 스케줄링 휴리스틱, 컴파일러 패스 — 목표는 "정확한 계획"이 아니라 "최고의 계획"입니다.

HTN 계획과 AlphaEvolve는 두 가지 다른 문제를 해결합니다. 둘 다 LLM을 대체재가 아닌 증폭기(amplifier)로 사용합니다.

## 개념

### 계층적 작업 네트워크(Hierarchical Task Networks)

HTN은 다음과 같습니다:

- **작업(Tasks)** — 복합 작업(분해해야 함) 및 원시 작업(직접 실행 가능).
- **방법(Methods)** — 전제 조건을 포함하여 복합 작업을 하위 작업으로 분해하는 방법.
- **연산자(Operators)** — 전제 조건과 효과를 가진 원시 작업.
- **상태(State)** — 팩트(fact)의 집합.

계획: 목표 작업과 초기 상태가 주어지면, 전제 조건이 순서대로 충족되는 원시 연산자로의 분해를 찾습니다.

HTN은 LLM보다 오래되었으며, 여전히 증명 가능하게 정확한 계획의 기준입니다.

### ChatHTN (Gopalakrishnan et al., 2025)

ChatHTN (arXiv:2505.11814)은 기호 HTN과 LLM 쿼리를 교대로 수행합니다:

1. 기존 방법들을 사용하여 현재 복합 작업을 분해해 보세요.
2. 적용할 방법이 없다면 LLM에게 "`s` 상태에서 `task`을 어떻게 분해하시겠습니까?"라고 물어보세요.
3. LLM 응답을 후보 하위 작업으로 변환합니다.
4. 연산자 스키마에 대해 검증하고, 유효하지 않은 분해를 거부합니다.
5. 재귀적으로 수행합니다.

이 논문의 핵심 주장: 생성된 모든 계획은 LLM 제안이 후보 분해로만 입력되고, 직접적인 계획 편집으로는 절대 입력되지 않으므로 증명 가능한 타당성을 가집니다. 기호 레이어가 정확성을 담당하며, LLM은 방법 라이브러리를 확장합니다.

온라인 방법 학습 (OpenReview `gwYEDY9j2x`, 2025 후속 연구)은 회귀 분석을 통해 LLM이 생성한 분해를 일반화하는 학습기를 추가하여 LLM 쿼리 빈도를 최대 75%까지 줄입니다.

### AlphaEvolve (Novikov et al., 2025)

AlphaEvolve (arXiv:2506.13131, DeepMind, 2025년 6월)는 Gemini 2.0 Flash/Pro 앙상블이 오케스트레이션하는 진화적 코드 검색이라는 완전히 다른 접근법입니다.

루프:

1. 시드 프로그램 + 프로그램 평가기(피트니스 점수를 반환)로 시작합니다.
2. LLM 앙상블이 변이를 제안합니다.
3. 변이를 평가기를 통해 실행합니다.
4. 최고의 결과를 유지하고 다시 변이를 수행합니다.

공개된 성과:

- 56년 만에 Strassen 알고리즘보다 4x4 복소 행렬 곱셈을 개선 (48개의 스칼라 곱셈).
- Borg 스케줄링 휴리스틱을 통해 Google 컴퓨팅 자원의 0.7%를 회수했습니다.
- 프론티어 워크로드에서 FlashAttention의 속도를 32% 향상시켰습니다.

하드 제약 조건: 피트니스 함수는 기계가 검증할 수 있어야 합니다. 산문 형식의 답변에 대한 진화적 검색은 수렴하지 않습니다.

### 언제 무엇을 사용해야 하는가

| 문제 유형 | 사용 | 이유 |
|---------------|-----|-----|
| 하드 제약 조건이 있는 스케줄링 | HTN + ChatHTN | 증명 가능한 타당성 |
| 컴파일러 최적화 | AlphaEvolve | 기계가 검증 가능한 피트니스 |
| 다단계 작업 실행 | ReAct / ReWOO | 루프 내 LLM, 형식적 보장 없음 |
| 테스트를 통한 코드 개선 | AlphaEvolve | 테스트가 평가자입니다 |
| 정책 기반 자동화 | HTN | 전제 조건이 정책을 인코딩합니다 |

### 이 패턴이 실패하는 지점

- **연산자 없는 HTN.** 전제 조건/효과 스키마가 없으면 건전성 주장이 무너집니다. ChatHTN의 "LLM이 분해를 제안"은 스키마가 유효하지 않은 이동(moves)을 거부해야 합니다.
- **실제 평가자 없는 AlphaEvolve.** "LLM에게 코드가 더 나은지 물어보는 것"은 적합도 함수가 아닙니다. 평가자는 결정적(deterministic)이고 빠해야 합니다.
- **과도한 엔지니어링.** 대부분의 에이전트 작업은 둘 중 어느 것도 필요하지 않습니다. 먼저 ReAct나 ReWOO를 사용해 보세요.

## 구현하기

`code/main.py`는 두 개의 장난감(toys)을 구현합니다:

- 연산자, 메서드, 전제 조건, 효과, 그리고 복합 작업에 메서드가 매칭되지 않을 때 작동하는 `LLMFallback`를 갖춘 표준 라이브러리 HTN 플래너입니다. "LLM"은 스크립트화된 분해기(decomposer)이므로 플래너는 오프라인으로 실행됩니다.
- 산술 프로그램에 대한 표준 라이브러리 진화적 탐색: 테스트 세트에 대해 `|f(x) - target|`를 최소화하는 표현식을 성장시킵니다. 평가자는 결정적입니다.

실행해 보세요:

```
python3 code/main.py
```

추적(trace)은 HTN 플래너가 복합 작업을 분해하는 과정(계획 중반에 LLM 폴백(fallback) 포함)과 진화 루프가 목표 표현식으로 수렴하는 과정을 보여줍니다.

## 사용하기

- **HTN 플래너** — `pyhop`, `SHOP3`, 또는 도메인 특화 정책 강제를 위해 직접 구축해 보세요.
- **ChatHTN** — 연구 코드; 이 패턴(기호적 + LLM 폴백)은 모든 HTN 플래너로 깔끔하게 이식됩니다.
- **AlphaEvolve** — DeepMind 논문; 이 패턴(앙상블 + 평가자)은 재현 가능합니다. OpenEvolve 및 유사한 오픈소스 포크가 등장하고 있습니다.
- **에이전트 프레임워크** — 일급(first-class) HTN이나 AlphaEvolve를 제공하는 것은 아직 없습니다. 서브 에이전트나 백그라운드 워커로 구축해 보세요.

## 연습 문제

1. HTN 플래너를 백트래킹(backtracking)으로 확장해 보세요: 연산자의 사후 조건(postcondition)이 런타임에 실패하면 롤백하고 다음 메서드를 시도합니다.
2. ChatHTN에 LLM 방식 캐시를 추가하세요: LLM이 `P` 상태 패턴에서 `T` 작업을 분해할 때 결과를 저장합니다. 다음 호출 시에는 먼저 메소드 라이브러리를 재확인하세요.
3. 진화적 탐색 평가기를 실제 테스트 스위트에 교체하세요. 20개 테스트 케이스를 통과하는 정렬 함수를 진화시키고, 수렴까지의 세대를 보고하세요.
4. AlphaEvolve의 평가기 설계 노트를 읽어보세요. 관심 있는 도메인(SQL 쿼리 최적화, 테스트 스위트 최소화, 배포 YAML)에 대한 평가기를 설계하세요.
5. 결합하세요: HTN을 사용하여 복합 작업을 하위 작업으로 분해한 후, 각 하위 작업의 원시 연산자에 진화적 탐색을 적용하세요. 어떤 부분에서 빛을 발하고, 어떤 부분에서 과잉 설계가 발생하나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| HTN | "계층적 계획기" | 연산자, 전제 조건, 효과를 포함한 작업 분해 |
| 메소드 | "분해 규칙" | 복합 작업을 하위 작업으로 나누는 방법 |
| 연산자 | "원시 동작" | 전제 조건과 효과를 가진 구체적 단계 |
| ChatHTN | "LLM + HTN" | 메소드가 일치하지 않을 때 기호적 계획기가 LLM에 요청 |
| AlphaEvolve | "진화적 코드 탐색" | 앙상블 LLM이 코드를 변이시키고, 결정론적 평가기가 선택 |
| 적합도 함수 | "평가기" | 출력에 대한 결정론적이고 기계적으로 검증 가능한 점수 |
| 온라인 메소드 학습 | "캐시된 LLM 분해" | 쿼리 비용을 줄이기 위해 LLM 계획을 저장하고 일반화 |
