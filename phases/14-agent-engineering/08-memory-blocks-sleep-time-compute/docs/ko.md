# 메모리 블록과 수면 시간 컴퓨팅

> 모델이 직접 편집할 수 있는 이산 기능 메모리 블록과, 주 에이전트가 유휴 상태일 때 메모리를 비동기적으로 통합하는 수면 시간 에이전트입니다. 이 두 가지 개념은 하나의 대화를 넘어 메모리를 확장하는 방법입니다.

**유형:** Build
**언어:** Python (stdlib)
**선수 요건:** 14단계 · 07강 (MemGPT)
**시간:** 약 75분

## 학습 목표

- Letta가 사용하는 세 가지 메모리 계층(코어, 리콜, 아카이브)과 각 계층의 역할을 나열해 보세요.
- 메모리 블록 패턴을 설명해 보세요: Human 블록, Persona 블록, 그리고 일급 타입 객체로서의 사용자 정의 블록.
- 수면 시간 컴퓨팅이 무엇인지, 왜 임계 경로(critical path) 밖에 위치하는지, 그리고 왜 주 에이전트보다 더 강력한 모델을 실행할 수 있는지 설명해 보세요.
- 주 에이전트가 응답을 처리하고 수면 시간 에이전트가 턴 사이에 블록을 통합하는 스크립트형 두 에이전트 루프를 구현해 보세요.

## 문제점

MemGPT (07강)는 가상 메모리 제어 흐름을 해결했습니다. 세 가지 생산 환경 문제가 발생했습니다:

1. **지연.** 모든 메모리 연산이 임계 경로(critical path)에 위치합니다. 사용자가 기다리는 동안 에이전트가 정리, 요약, 조정을 수행해야 한다면 꼬리 지연(tail latency)이 급증합니다.
2. **메모리 부패.** 쓰기 작업이 누적됩니다. 모순된 사실이 남습니다. 검색이 오래된 콘텐츠에 묻혀버립니다.
3. **구조 손실.** 평평한(flat) 아카이브 저장소는 "Human 블록은 항상 프롬프트에 포함되고, Persona 블록은 항상 프롬프트에 포함되며, Task 블록은 세션마다 교체된다"는 구조를 표현할 수 없습니다.

Letta (letta.com)는 원본 MemGPT 프로젝트가 2024년에 채택한 플랫폼 이름입니다. 논문에서의 패턴은 MemGPT 이름을 유지하며, 2026년 Letta V1 재작성은 이후의 별도 단계입니다. 메모리 블록은 구조를 명시적으로 만들고, 수면 시간 컴퓨팅은 통합 작업을 임계 경로(critical path) 밖으로 이동시킵니다.

## 개념

### 세 가지 계층

| 계층 | 범위 | 위치 | 작성 주체 |
|------|-------|----------------|------------|
| 코어 | 항상 표시됨 | 메인 프롬프트 내부 | 에이전트 도구 호출 + 수면 시간 재작성 |
| 리콜 | 대화 기록 | 검색 가능 | 자동 턴 로깅 |
| 아카이브 | 임의의 사실 | 벡터 + KV + 그래프 | 에이전트 도구 호출 + 수면 시간 인제스트 |

코어는 MemGPT 코어입니다. 리콜은 제거된 꼬리를 가진 대화 버퍼입니다. 아카이브는 외부 저장소입니다. 이 분리는 MemGPT의 2단계 과부하 문제를 정리합니다.

### 메모리 블록

블록은 코어 계층의 타입이 지정된, 영구적인, 편집 가능한 섹션입니다. 원본 MemGPT 논문은 두 가지를 정의했습니다:

- **인간 블록** — 사용자에 대한 사실 (이름, 역할, 선호도, 목표).
- **페르소나 블록** — 에이전트의 자기 개념 (정체성, 톤, 제약 조건).

Letta는 임의의 사용자 정의 블록으로 일반화합니다: 현재 목표를 위한 `Task` 블록, 코드베이스 사실을 위한 `Project` 블록, 하드 제약 조건을 위한 `Safety` 블록. 각 블록은 `id`, `label`, `value`, `limit` (문자 수 제한), `description` (모델이 언제 편집해야 하는지 알 수 있도록)를 가집니다.

블록은 도구 인터페이스를 통해 편집 가능합니다:

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — 한계에 가까운 블록을 압축합니다.

### 수면 시간 컴퓨팅

2025년 Letta의 추가 사항: 백그라운드에서 두 번째 에이전트를 실행하며, 임계 경로에서 벗어납니다. 수면 시간 에이전트는 대화 기록과 코드베이스 컨텍스트를 처리하고, 공유 블록에 `learned_context`을 기록하며, 아카이브 레코드를 통합하거나 무효화합니다.

도출되는 특성:

- **레이턴시 비용 없음.** 주요 응답은 메모리 연산을 기다리지 않습니다.
- **더 강력한 모델 허용.** 수면 시간 에이전트는 레이턴시 제약이 없으므로 더 비싸고 느린 모델을 사용할 수 있습니다.
- **자연스러운 통합 창.** 사용자가 기다리지 않을 때 중복 제거, 요약, 모순된 사실의 무효화를 수행합니다.

이 형태는 인간의 작동 방식과 일치합니다: 작업을 수행하고, 잠을 자면, 장기 기억이 밤새 정립됩니다.

### 네이티브 추론

Letta V1 (`letta_v1_agent`, 2026)은 `send_message`/heartbeat 및 인라인 `Thought:` 토큰을 폐기하고 네이티브 추론(reasoning)을 채택했습니다. Responses API (OpenAI)와 확장된 thinking을 지원하는 Messages API (Anthropic)는 reasoning을 별도의 채널로 방출하며, 턴(turn)을 통해 전달됩니다 (프로덕션 환경에서는 공급자 간에 암호화됨). 제어 루프는 여전히 ReAct입니다. 사고 추적(thought trace)은 구조적이며 프롬프트 형태가 아닙니다.

### 이 패턴이 잘못되는 지점

- **블록 팽창.** 무한한 `block_append`는 한도에 빠르게 도달합니다. 한도를 초과하는 쓰기 전에 블록 요약기를 연결해 보세요.
- **조용한 드리프트.** Sleep-time 에이전트가 블록을 재작성하면 주 에이전트가 이를 전혀 감지하지 못합니다. 블록을 버전화하고 추적(trace)에 diff를 표시해 보세요.
- **오염된 통합.** Sleep-time 에이전트가 공격자가 접근 가능한 콘텐츠를 코어에 처리합니다. 27강은 sleep-time 표면에도 적용됩니다.

## 구현하기

`code/main.py`는 다음을 구현합니다:

- `Block` — id, label, value, limit, description.
- `BlockStore` — CRUD + `near_limit(label)` 헬퍼.
- 두 개의 스크립트된 에이전트 — `PrimaryAgent`는 턴을 처리하고, `SleepTimeAgent`는 턴 사이에 통합합니다.
- 블록 쓰기가 포함된 3턴 대화와 블록을 요약하고 오래된 사실을 무효화하는 sleep-time 패스를 보여주는 추적(trace).

실행해 보세요:

```
python3 code/main.py
```

트랜스크립트는 분리를 보여줍니다: 주 턴은 빠르고 원시(raw) 쓰기를 생성하며, sleep 패스는 압축하고 정리합니다.

## 사용하기

- **Letta** (letta.com)는 참조 구현을 위한 것입니다. 셀프 호스트하거나 관리형 클라우드를 이용하세요.
- **Claude Agent SDK skills**는 블록 형태의 지식으로 사용하세요 — skill은 에이전트가 필요할 때 로드하는 이름 지정된, 버전화된, 검색 가능한 지침 블록입니다.
- 저장소 백엔드에 대한 제어권을 원하는 팀을 위한 **커스텀 빌드**. 나중에 마이그레이션할 수 있도록 Letta API 계약을 사용하세요.

## 연습 문제

1. `near_limit`이 true를 반환할 때 블록 값을 모델 생성 요약으로 대체하는 `block_summarize` 도구를 추가하세요. 요약 호출과 블록 오버플로우를 모두 최소화하는 트리거 임계값은 무엇인가요?
2. 아카이브에 대한 수면 시간 중복 제거를 구현하세요: 텍스트의 토큰 겹침이 90% 이상인 두 레코드는 하나로 병합됩니다. 이는 수면 패스에서만 수행하고, 임계 경로(critical path)에서는 절대 수행하지 마세요.
3. 블록을 버전화하세요. 모든 쓰기 시 이전 값과 diff를 기록하세요. `block_history(label)`을 노출하여 운영자가 "에이전트가 X를 왜 잊었는지"를 디버깅할 수 있게 하세요.
4. 수면 시간 에이전트를 신뢰할 수 없는 작성자로 취급하세요. Persona 또는 Safety 블록을 수정할 경우, 커밋하기 전에 두 번째 에이전트의 검토를 요구하세요.
5. 예제를 Letta API (`letta_v1_agent`)를 사용하도록 포팅하세요. 블록 스키마에는 어떤 변경이 있으며, 네이티브 추론은 추적(trace)의 형태를 어떻게 변경하나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 메모리 블록 | "편집 가능한 프롬프트 섹션" | 코어 메모리의 타입이 지정된, 영속적인, LLM이 편집 가능한 세그먼트 |
| 인간 블록 | "사용자 메모리" | 코어에 고정된, 사용자에 대한 사실 |
| Persona 블록 | "에이전트 정체성" | 코어에 고정된, 자기 개념, 톤, 제약 조건 |
| 수면 시간 컴퓨팅 | "비동기 메모리 작업" | 임계 경로(off the critical path)에서 통합을 수행하는 두 번째 에이전트 |
| Core / Recall / Archival | "계층(Tiers)" | 세 가지 계층 메모리 분할: 항상 보이는 것 / 대화 / 외부 |
| 블록 제한 | "상한(Cap)" | 블록당 문자 수 제한; 요약(summarization)을 강제함 |
| 네이티브 추론 | "사고 채널" | 프롬프트 레벨의 `Thought:`가 아닌, 제공자(provider) 레벨의 추론 출력 |
| 학습된 컨텍스트 | "수면 출력" | 수면 시간 에이전트가 공유 블록에 작성하는 사실 |
