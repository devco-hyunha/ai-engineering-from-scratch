사용자 요청과 도구 카탈로그(이름, 입력 스키마, 설명)가 주어지면 ReWOO 계획을 생성하세요: 도구 호출과 증거 참조(`#E1`, `#E2`, ...)를 포함하는 단계의 DAG입니다. 실행자에게 전달하기 전에 계획을 검증하세요.

생성할 항목:

1. 계획 DAG. 각 노드에는 id(`E1`, `E2`, ...), 도구 이름, 인자 사전(문자열에 `#E<k>` 참조가 포함될 수 있음), 선택적 `parallel_group` 레이블이 있습니다.
2. 검증 출력. 위상 정렬을 통한 비순환성 검사; 참조 해결 검사(모든 `#E<k>`는 선행하는 생성자가 있음); 도구 존재 검사(모든 도구 이름이 카탈로그에 있음); 인자 스키마 검사(각 인자가 도구의 입력 스키마와 일치함).
3. 병렬 처리 힌트. 모든 위상 레벨에 대해 동시 실행이 가능한 노드를 나열하세요.
4. Planner/Solver 분리 권장. 계획이 3단계 미만이면 ReAct를 권장하세요. 계획에 무제한 루프 요구 사항(모든 단계에서 재계획)이 있으면 재계획자(replanner)가 있는 Plan-and-Execute를 권장하세요. 계획이 30단계를 초과하거나 웹/모바일을 목표로 하면 합성 계획 데이터를 사용하는 Plan-and-Act를 권장하세요.

하드 거부:

- 순환이 있는 계획. ReWOO는 DAG를 가정합니다. 순환은 ReAct 또는 LATS의 관심사입니다.
- 위상 순서에서 `k`이 아직 존재하지 않는 `#E<k>`을 참조하는 계획. 실패하는 특정 엣지를 출력하세요.
- 카탈로그에 없는 도구를 호출하는 계획. 계획을 작동시키기 위해 도구를 임의로 만들지 마세요.
- 참조에 대한 인자 유형이 도구의 스키마와 일치하지 않는 계획(예: `#E1`이 문자열을 대체하지만 도구가 int를 기대하는 경우).

거부 규칙:

- 작업이 개방형 탐색(알 수 없는 도구 필요, 알 수 없는 단계)인 경우, 거부하고 ReAct 또는 LATS(04강)를 권장하세요.
- 도구 카탈로그에 게이트 승인 도구 없이 파괴적인 도구가 포함된 경우, 거부하고 09강(권한, 샌드박스)을 참조하세요.

출력: 구조화된 계획(JSON 또는 YAML), 검증 보고서, 병렬화 맵, 그리고 실행기(ReWOO Worker), 재계획기(Plan-and-Execute), 또는 더 큰 궤적 샘플링 루프(Plan-and-Act)를 가리키는 후속 조치입니다.

작업 유형이 이전에 시도된 경우 03강(Reflexion)을, 계획이 검색의 이점을 얻을 수 있는 경우 04강(LATS)를 가리키는 "다음에 읽을 내용" 노트로 마무리해 보세요.
