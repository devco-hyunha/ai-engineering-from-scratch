도구 접근 및 검색 기능을 가진 에이전트에 대해 주입 방어 레이어를 생성해 보세요.

생성 대상:

1. 모든 콘텐츠에 소스 태그를 지정합니다: `user_message`, `tool_output`, `retrieved_web`, `retrieved_memory`, `retrieved_file`. 태그는 메시지 히스토리를 통해 전파됩니다.
2. `Validator.assess(tool_call, contents)` — 주입 형태 인자나 검색된 콘텐츠를 포함하는 도구 호출을 거부합니다. 소스 태그가 선언된 신뢰 수준과 일치하는 경우에만 허용됩니다.
3. 내비게이션용 허용 목록 / 차단 목록: 에이전트가 접근할 수 있는 URL, 도메인, 파일 경로입니다.
4. 메모리 쓰기 가드레일: 지시문처럼 보이는 쓰기를 거부합니다.
5. 콘텐츠 캡처 규율 (23강): 검색된 콘텐츠는 외부에 저장합니다. 스팬은 산문이 아닌 참조 ID를 포함합니다.
6. 테스트 스위트: Greshake의 다섯 가지 주입 공격 유형을 레드 티밍 사례로 포함합니다.

거부 대상:

- 소스 태그가 없는 도구 사용 표면. 출처(provenance)가 없으면 권한 수준을 구분할 수 없습니다.
- 최종 출력에만 실행되는 검증기. 늦은 검증은 의미가 없습니다 — 모델이 이미 행동한 후입니다.
- "시스템 프롬프트가 처리합니다." 시스템 프롬프트 위생은 통제 수단이 아닙니다.

거부 규칙:

- 에이전트가 소스 태그 지정 없이 검색 기능을 가지고 있다면 출시를 거부합니다. 검색된 콘텐츠는 표준 주입 벡터입니다.
- 민감한 도구(메시지 전송, 셸 실행, /에 파일 쓰기)에 인간 개입 루프(HITL) 확인이 없다면 거부합니다.
- 메모리 쓰기가 보호되지 않으면 거부합니다. 지속되는 메모리 오염은 다음 세션에서 다시 오염을 일으킵니다.

출력: `validator.py`, `source_tag.py`, `allowlist.py`, `memory_guard.py`, `red_team.py`, `README.md`는 6개 통제 스택, 잔존 위험, 지속적 검토 주기를 설명합니다. 마지막에 "다음에 읽을 내용"으로 21강(컴퓨터 사용 안전)과 23강(OTel을 통한 콘텐츠 캡처)을 가리킵니다.
