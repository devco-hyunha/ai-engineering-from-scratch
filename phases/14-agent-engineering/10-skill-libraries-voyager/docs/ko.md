# 스킬 라이브러리와 평생 학습(Voyager)

> Voyager (Wang et al., TMLR 2024)는 실행 가능한 코드를 스킬로 취급합니다. 스킬은 이름이 지정되고, 검색 가능하며, 조합할 수 있으며, 환경 피드백을 통해 정제됩니다. 이는 Claude Agent SDK 스킬, skillkit 및 2026년 스킬 라이브러리 패턴의 참조 아키텍처입니다.

**유형:** Build
**언어:** Python (stdlib)
**선수 요건:** 14단계 · 07강 (MemGPT), 14단계 · 08강 (Letta Blocks)
**시간:** 약 75분

## 학습 목표

- Voyager의 세 가지 구성 요소인 자동 커리큘럼, 스킬 라이브러리, 반복적 프롬프팅을 나열하고 각각의 역할을 설명해 보세요.
- Voyager가 행동 공간을 원시 명령이 아닌 코드로 만드는 이유를 설명해 보세요.
- 등록, 검색, 조합 및 실패 기반 정제를 지원하는 stdlib 스킬 라이브러리를 구현해 보세요.
- Voyager의 패턴을 2026년 Claude Agent SDK 스킬 및 skillkit 생태계에 매핑해 보세요.

## 문제점

매 세션마다 모든 기능을 처음부터 재구축하는 에이전트는 세 가지 문제를 일으킵니다:

1. **토큰 낭비.** 모든 작업이 동일한 추론을 다시 유도합니다.
2. **진행 상황 손실.** 세션 A에서 학습한 수정 사항이 세션 B로 전달되지 않습니다.
3. **장기적 조합 실패.** 복잡한 작업은 기능 계층이 필요하며, 원샷 프롬프트는 이를 표현할 수 없습니다.

Voyager의 해답: 각 재사용 가능한 기능을 라이브러리에 저장된 이름 지정된 코드 청크로 취급하고, 유사성에 따라 검색하며, 다른 스킬과 조합하고, 실행 피드백을 통해 정제하는 것입니다.

## 개념

### 세 가지 구성 요소

Voyager (arXiv:2305.16291)는 에이전트를 다음 세 가지로 구조화합니다:

1. **자동 커리큘럼.** 호기심 기반 제안자가 에이전트의 현재 스킬 세트와 환경 상태에 따라 다음 작업을 선택합니다. 탐색은 하향식(bottom-up)입니다.
2. **스킬 라이브러리.** 각 스킬은 실행 가능한 코드입니다. 작업이 성공하면 새로운 스킬이 추가됩니다. 스킬은 쿼리-설명 유사성에 따라 검색됩니다.
3. **반복적 프롬프팅 메커니즘.** 실패 시 에이전트는 실행 오류, 환경 피드백 및 자체 검증 출력을 수신한 후 스킬을 정제합니다.

Minecraft 평가(Wang et al., 2024): 기준선 대비 고유 아이템이 3.3배 더 많고, 돌 도구는 8.5배 더 빠르며, 철 도구는 6.4배 더 빠르고, 지도 이동은 2.3배 더 길었습니다. 수치는 Minecraft에 특화되어 있지만, 패턴은 전이됩니다.

### 행동 공간 = 코드

대부분의 에이전트(Agent)는 원시적인 명령을 출력합니다. Voyager는 JavaScript 함수를 출력합니다. 스킬은 다음과 같습니다:

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

하위 스킬로 구성됩니다. 설명과 임베딩(Embedding)을 키로 저장합니다. 프롬프트가 아닌 프로그램으로 검색됩니다.

이것은 2026년 Claude Agent SDK 스킬입니다: 에이전트(Agent)가 필요할 때 로드하는, 이름이 지정되고 검색 가능한 코드 조각과 지침입니다.

### 스킬 검색

새로운 작업 "다이아몬드 곡괭이 만들기". 에이전트(Agent):

1. 작업 설명을 임베딩(Embedding)합니다.
2. 상위 k개의 유사한 스킬을 찾기 위해 스킬 라이브러리를 쿼리합니다.
3. `craftIronPickaxe`, `mineDiamond`, `placeCraftingTable` 등을 검색합니다.
4. 검색된 원시 요소와 새로운 로직으로 새로운 스킬을 구성합니다.

이것은 MCP 리소스(13단계)와 Agent SDK 스킬이 구현하는 패턴입니다: 현재 작업에 범위를 정한 지식/코드 표면에서의 검색입니다.

### 반복적 정제

Voyager의 피드백 루프:

1. 에이전트(Agent)가 스킬을 작성합니다.
2. 스킬이 환경에 대해 실행됩니다.
3. 세 가지 신호 중 하나가 반환됩니다: `success`, `error` (스택 트레이스 포함), `self-verification failure`.
4. 에이전트(Agent)는 신호를 컨텍스트로 사용하여 스킬을 다시 작성합니다.
5. 성공할 때까지 또는 최대 라운드까지 반복합니다.

이것은 환경 기반 검증으로 코드 생성에 적용된 Self-Refine (05강)입니다. CRITIC (05강)은 외부 도구를 검증자로 사용하는 동일한 패턴입니다.

### 커리큘럼 및 탐색

Voyager의 커리큘럼 모듈은 에이전트(Agent)가 가진 것과 아직 하지 않은 것에 기반하여 "호수 근처에 은신처를 짓기"와 같은 작업을 제안합니다. 제안자는 환경 상태와 스킬 인벤토리를 사용하여 현재 능력 바로 위의 작업을 선택합니다. 이것이 탐색의 최적 지점입니다.

프로덕션 에이전트(Agent)의 경우, 이것은 "누락된 것" 연산자로 변환됩니다: 현재 스킬 라이브러리와 도메인이 주어졌을 때, 아직 다루지 않는 스킬은 무엇입니까? 팀은 일반적으로 이를 커리큘럼 리뷰로 수동 구현합니다.

### 이 패턴이 실패하는 지점

- **스킬 라이브러리 부패.** 동일한 스킬이 설명이 약간 다른 상태로 10번 추가됩니다. 쓰기 시 중복 제거를 적용하고, 검색 시 하나만 반환하도록 하세요.
- **복합 스킬 드리프트.** 부모 스킬이 개선된 자식 스킬에 의존합니다. 스킬을 버전화하세요. v1에 고정된 부모 스킬은 v3을 자동으로 가져오지 않습니다.
- **검색 품질.** 스킬 설명에 대한 벡터 검색은 라이브러리가 수백 개를 넘으면 성능이 저하됩니다. 태그 필터와 하드 제약 조건("`category=tooling`을 가진 스킬만")으로 보완하세요.

```figure
voyager-skills
```

## 구현하기

`code/main.py`은 스킬 라이브러리 표준 라이브러리를 구현합니다:

- `Skill` — 이름, 설명, 코드(문자열), 버전, 태그, 의존성.
- `SkillLibrary` — 등록, 검색(토큰 겹침), 구성(의존성의 위상 정렬), 개선(업데이트 시 버전 상향).
- 세 개의 기본 스킬을 등록하고, 네 번째 스킬을 구성하며, 실패에 직면하고, 개선하는 스크립트화된 에이전트.

실행하세요:

```
python3 code/main.py
```

추적은 라이브러리 쓰기, 검색, 구성, 실행 실패, v2 개선을 보여줍니다 — Voyager의 루프를 처음부터 끝까지 확인할 수 있습니다.

## 사용하기

- **Claude Agent SDK 스킬**(Anthropic) — 2026년 참고 자료: 각 스킬은 설명, 코드, 지침을 포함하며, 에이전트 세션 중 필요할 때 로드됩니다.
- **skillkit**(npm: skillkit) — 32개 이상의 AI 코딩 에이전트를 위한 교차 에이전트 스킬 관리.
- **사용자 정의 스킬 라이브러리** — 도메인 특화(데이터 에이전트용 SQL 스킬, 인프라 에이전트용 Terraform 스킬). Voyager 패턴은 축소되어 적용됩니다.
- **OpenAI Agents SDK `tools`** — 저수준; 각 도구는 경량 스킬입니다.

## 연습 문제

1. `compose()`에 의존성 순환 감지기를 추가하세요. 스킬 A가 B에 의존하고 B가 A에 의존하면 어떻게 됩니까? 오류 vs 경고?
2. 스킬별 버전 고정(pinning)을 구현하세요. 부모 스킬이 자식 `crafting@1`을 구성할 때, `crafting@2`에 대한 개선이 부모 스킬을 조용히 업그레이드해서는 안 됩니다.
3. 토큰 겹침 검색을 sentence-transformers 임베딩(또는 BM25 표준 라이브러리 구현)으로 교체해 보세요. 50개 스킬을 가진 장난감 라이브러리에서 retrieval@5를 측정해 보세요.
4. "커리큘럼" 에이전트를 추가해 보세요. 현재 라이브러리와 도메인 설명을 입력으로 받아 누락된 스킬 5개를 제안합니다. 주간 단위로 호출해 보세요.
5. Anthropic의 Claude Agent SDK 스킬 문서를 읽어 보세요. 장난감 라이브러리를 SDK의 스킬 스키마로 이식해 보세요. 발견 가능성(discoverability)에 어떤 변화가 생기는지 확인해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 스킬(Skill) | "재사용 가능한 기능" | 유사성으로 검색 가능한, 이름이 지정된 코드 청크 + 설명 |
| 스킬 라이브러리(Skill library) | "에이전트의 방법 메모리" | 검색 및 조합이 가능한 스킬의 영구 저장소 |
| 커리큘럼(Curriculum) | "작업 제안자" | 현재 역량 격차에 기반한 상향식 목표 생성기 |
| 조합(Composition) | "스킬 DAG" | 스킬이 스킬을 호출하는 구조; 실행 시 위상 정렬 |
| 반복적 정제(Iterative refinement) | "자기 수정 루프" | 환경 피드백 + 오류 + 자기 검증이 다음 버전으로 되돌아감 |
| 코드로 표현된 행동 공간(Action-space-as-code) | "프로그래밍된 행동" | 시간적으로 확장된 행동을 위해 원시 명령이 아닌 함수를 방출 |
| 쓰기 시 중복 제거(Dedup on write) | "스킬 붕괴" | 거의 중복된 설명이 하나의 표준 스킬로 붕괴됨 |
