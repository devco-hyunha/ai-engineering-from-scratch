목표 런타임, 벡터 백엔드 (Qdrant, pgvector, Chroma, sqlite-vec), KV 백엔드 (Postgres, Redis, dict), 그래프 백엔드 (Neo4j, 메모리 내 엣지)가 주어지면 융합된 메모리 시스템을 생성합니다.

생성 대상:

1. `add(text, user_id, session_id, scope, importance, tags)` 퍼사드 뒤에 있는 세 가지 저장소 클래스입니다. 쓰기 시 추출기가 `text`를 레코드, KV 삼중항, 그래프 삼중항으로 분해합니다. 어떤 저장소도 선택 사항이 아닙니다.
2. 융합 스코어 `score = w_rel * relevance + w_imp * importance + w_rec * recency`입니다. 세 가지 가중치를 모두 설정으로 노출합니다. 호출마다 조정하지 말고 제품별로 조정하세요.
3. 범위 분류 체계: `user`, `session`, `agent`. 검색은 범위를 반드시 준수해야 합니다. 사용자 쿼리가 다른 사용자의 레코드를 유출해서는 안 됩니다.
4. 시간적 무효화입니다. 모순이 발생하면 이전 엣지/레코드를 무효로 표시하며, 절대 삭제하지 않습니다. 역사적 쿼리를 위해 `search(query, as_of=timestamp)`를 노출하세요.
5. 추출기 인터페이스입니다. 기본값은 LLM 기반일 수 있으며, 테스트를 위해 결정적인 정규식 폴백을 허용합니다. 폭발을 방지하기 위해 `add()`당 그래프 엣지 수를 제한하세요.

하드 리젝트:

- "Mem0형"으로 설명되는 단일 저장소 메모리입니다. 벡터 전용, KV 전용, 그래프 전용 제품은 괜찮지만 하이브리드 메모리가 아닙니다. 이름을 잘못 붙이지 마세요.
- 범위별 가중치나 명시적인 `scope=` 필터 없이 이루어지는 범위 간 검색입니다. 범위 유출은 규정 준수 및 개인정보 보호 사고입니다.
- 모순 시 삭제하는 것입니다. 무효화하고 타임스탬프를 찍으세요. 삭제는 버그를 숨기고 감사(audit)를 깨뜨립니다.

거부 규칙:

- 사용자가 "중요도 가중치 없음"을 요청하면 거부하세요. 백만 개의 레코드에 대한 평평한 관련성 순위는 발생하기 전부터 실패할 검색입니다.
- 그래프 백엔드에 충돌 감지기가 없다면, resulting system을 "Mem0형"이라고 부르는 것을 거부하세요. 이름을 격하하세요.
- 제품이 PII (의료, 법률, HR)를 포함한다면, 제품 소유자가 감사하지 않은 추출기를 사용하여 출시하는 것을 거부하세요.
