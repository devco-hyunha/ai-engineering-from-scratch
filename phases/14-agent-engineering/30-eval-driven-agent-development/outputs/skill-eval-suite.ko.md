에이전트 제품용 CI에 연결된 3계층 평가 스위트를 구축해 보세요.

다음 항목을 생성합니다:

1. **정적 벤치마크 계층** — 관련 벤치마크가 최소 하나 포함됩니다 (코드는 SWE-bench Verified, 도구 사용은 BFCL V4, 웹은 WebArena, 데스크톱은 OSWorld, 범용은 GAIA). 항상 +-감사 점수를 함께 보고합니다.
2. **커스텀 오프라인 계층** — 도메인 특화 차원(사실성, 톤, 범위, 거절 품질)에 대해 LLM-judge 루브릭으로 채점한 항목이 최소 하나 포함됩니다. 에이전트 실행 후 실제 상태를 탐지하는 실행 기반 케이스가 최소 하나 포함됩니다. 골드 경로(gold path)가 있는 궤적 기반 케이스가 최소 하나 포함됩니다.
3. **온라인 평가 계층** — 세션 리플레이, 가드레일 트리거된 알림, OTel GenAI 스팬을 통한 단계별 비용/지연 추적 (23강).
4. **평가자-최적화 러너** — 에이전트를 제안 / 판정 / 정제 루프로 감싸며 라운드 상한을 설정합니다.
5. **CI 게이트** — 기준선 대비 >=5%의 회귀가 발생하면 빌드를 실패시킵니다. 기준선을 시간에 따라 추적합니다.
6. **케이스 매핑** — 14단계 강의의 모든 가드레일과 학습된 규칙에 대해 최소 하나의 케이스가 매핑됩니다.

하드 리젝트:

- 기준선이 없는 평가 스위트. 참조가 없으면 회귀를 감지할 수 없습니다.
- 사실성 작업에서 외부 그라운딩이 없는 LLM-judge. CRITIC 패턴 (05강)이 필요합니다.
- 고정된 시드나 스냅샷 상태가 없는 불안정한 테스트. 오탐은 팀의 평가 신뢰도를 떨어뜨립니다.

거절 규칙:

- 사용자가 "해피 패스만"을 원하면 거절합니다. 모든 실패 모드 (26강)에 대해 케이스가 있어야 합니다.
- 사용자가 "CI 게이트 없음"을 원하면 유료 사용자에게 도달하는 제품에 대해 거절합니다. 그렇지 않으면 평가 드리프트가 보이지 않게 됩니다.
- 사용자가 "모두 LLM-judge"를 원하면 사실성 및 컴플라이언스 작업에서 거절합니다. 해당 작업에는 실행 기반이나 프로그램matic 평가자가 필요합니다.

출력: `cases/benchmarks/`, `cases/custom/`, `cases/online/`, `runner.py`, `ci_gate.py`, `README.md`는 평가 기준, 기준선, 그리고 14단계 매핑 표를 설명합니다. "다음에 읽을 내용"으로 마무리하며, 기반 구조를 위해 24강(관측 가능성), 26강(실패 모드), 또는 23강(OTel)을 가리킵니다.
