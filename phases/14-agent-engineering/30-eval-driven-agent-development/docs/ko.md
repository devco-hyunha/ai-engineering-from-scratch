# 평가 주도 에이전트 개발

> Anthropic의 가이드라인: "단순한 프롬프트로 시작하고, 종합적인 평가를 통해 최적화하며, 다단계 에이전트 시스템은 필요할 때만 추가하세요." 평가는 마지막 단계가 아닙니다. 14단계의 모든 선택을 주도하는 외부 루프입니다.

**유형:** Learn + Build
**언어:** Python (stdlib)
**선수 요건:** 14단계 전체.
**시간:** 약 60분

## 학습 목표

- 세 가지 평가 계층 — 정적 벤치마크, 커스텀 오프라인, 온라인 프로덕션 — 을 나열하고 각각의 용도를 설명해 보세요.
- 평가자-최적화자(tight loop)의 긴밀한 루프를 설명해 보세요.
- 2026년 모범 사례를 설명해 보세요: 평가는 코드 옆에 위치하고, CI에서 실행되며, PR을 게이트합니다.
- 14단계의 모든 강의를 생성하는 평가 사례와 연결해 보세요.

## 문제점

에이전트는 데모에서는 통과합니다. 데모가 예측할 수 없는 방식으로 프로덕션에서 실패합니다. 벤치마크는 "이 모델이 전반적으로 유능한가?"에 답하지, "이 에이전트가 내 제품에 맞는 패치를 출시하고 있는가?"에는 답하지 않습니다. 해답은 세 계층에서의 평가이며, 연속적으로 실행되고, 모든 가드레일과 학습된 규칙이 평가 사례에 매핑됩니다.

## 개념

### 세 가지 평가 계층

1. **정적 벤치마크** — 코드를 위한 SWE-bench Verified (19강), 브라우징/데스크톱을 위한 WebArena/OSWorld (20강), 범용을 위한 GAIA (19강), 도구 사용을 위한 BFCL V4 (06강). 모델 간 비교 및 회귀 게이트에 사용하세요. 오염은 실재합니다: SWE-bench+는 32.67%의 솔루션 누수를 발견했습니다. 항상 Verified / +-audited 점수를 보고하세요.

2. **커스텀 오프라인 평가** — 제품 형태:
   - LLM-as-judge (Langfuse, Phoenix, Opik — 24강).
   - 실행 기반 (패치를 실행하고 테스트를 확인하세요).
   - 궤적 기반 (골드와 행동 시퀀스를 비교하세요; OSWorld-Human은 상위 에이전트가 골드의 1.4-2.7배임을 보여줍니다).

3. **온라인 평가** — 프로덕션:
   - 세션 리플레이 (Langfuse).
   - 가드레일 트리거된 알림 (16강, 21강).
   - 단계별 비용/지연 추적 (23강 OTel spans).

### 평가자-최적화자 (Anthropic)

긴밀한 루프:

1. 제안자가 출력을 생성합니다.
2. 평가자가 판단합니다.
3. 평가자가 통과할 때까지 정제합니다.

이것은 Self-Refine (05강)의 일반화된 형태입니다. 관심 있는 모든 에이전트(Agent) 흐름은 신뢰성을 위해 평가자-최적화자 패턴으로 감쌀 수 있습니다.

### 2026년 모범 사례

- 평가(Evaluation (Eval))는 코드 옆에 위치합니다.
- 모든 PR에서 CI로 실행합니다.
- 평가 점수에 따라 병합을 게이트합니다 (예: "main 대비 5% 이상의 회귀 없음").
- 모든 가드레일(Guardrails)은 평가 사례에 매핑됩니다.
- 모든 학습된 규칙 (Reflexion, pro-workflow learn-rule)은 실패 사례에 매핑됩니다.

### 14단계 전체를 연결하기

14단계의 모든 강은 평가 사례를 생성합니다:

| 강 | 생성되는 평가 사례 |
|--------|------------------------|
| 01강 에이전트 루프(Agent Loop) | 예산 소진, 무한 루프 방지 |
| 02강 ReWOO | 도구 실패 시 플래너가 올바르게 재계획함 |
| 03강 Reflexion | 학습된 반성이 재시도 시 적용됨 |
| 05강 Self-Refine/CRITIC | 평가자가 정제된 출력을 통과시킴 |
| 06강 도구 사용 | 인자 강제 변환이 작동하며, 알 수 없는 도구는 거부됨 |
| 07-10강 메모리(Memory) | 검색 인용이 출처와 일치하며, 오래된 사실은 무효화됨 |
| 12강 워크플로우 패턴 | 각 패턴이 올바른 출력을 생성함 |
| 13강 LangGraph | 재개 시 상태를 정확히 재현함 |
| 14강 AutoGen 액터 | DLQ가 충돌한 핸들러를 포착함 |
| 16강 OpenAI Agents SDK | 가드레일(Guardrails)이 올바른 입력에서 작동함 |
| 17강 Claude Agent SDK | 하위 에이전트(Agent) 결과가 오케스트레이터(Orchestration)로 반환됨 |
| 19-20강 벤치마크 | SWE-bench Verified 점수, WebArena 성공률, OSWorld 효율성 |
| 21강 컴퓨터 사용 | 단계별 안전 장치가 주입된 DOM을 포착함 |
| 23강 OTel | 스팬이 필수 속성을 방출함 |
| 26강 실패 모드 | 감지기가 알려진 실패를 태그함 |
| 27강 프롬프트 인젝션(Prompt Injection) | PVE가 오염된 검색을 거부함 |
| 28강 오케스트레이션(Orchestration) | 감독자가 올바른 전문가로 라우팅함 |
| 29강 런타임 형태 | DLQ가 N% 실패를 처리함 |

평가 스위트에 각각에 대한 사례가 있다면, 14단계를 모두 커버한 것입니다.

### 평가 주도 개발이 실패하는 지점

- **기준선 없음.** 마지막에 알려진 좋은 상태(last-known-good)가 없는 평가는 읽을 수 없습니다. 기준선을 저장하세요.
- **그라운딩 없는 LLM 판정자.** 판정자도 환각(Hallucination)을 일으킵니다. CRITIC 패턴(05강) — 판정자가 외부 도구에 기반하여 그라운딩합니다.
- **평가에 과적합(Overfitting).** 평가에 최적화하면 실제 생산 환경의 유용성과 멀어집니다. 케이스를 순환하세요.
- **불안정한 테스트(Flaky Test) 평가.** 비결정적인 케이스가 오탐을 유발합니다. 시드를 고정하고 상태를 스냅샷하세요.

```figure
ae-eval-three-layers
```

## 구현하기

`code/main.py`은 표준 라이브러리 평가 하네스입니다:

- 카테고리(벤치마크, 커스텀, 온라인)가 있는 케이스 레지스트리.
- 테스트 중인 스크립트형 에이전트.
- 평가자-최적화 루프: 제안, 판정, 통과하거나 최대 라운드까지 개선.
- CI 게이트: 통과율 집계 + 기준선 대비 회귀 테스트(Regression Test).

실행하세요:

```
python3 code/main.py
```

출력: 케이스별 통과/실패, 회귀 테스트 플래그, CI 게이트 판정.

## 사용하기

- 에이전트 코드와 같은 저장소에 평가 케이스를 작성하세요.
- CI를 통해 모든 PR에서 실행하세요.
- 회귀 테스트가 발생하면 빌드를 실패시키세요.
- 시간에 따른 통과율을 추적하세요.
- 모든 생산 환경 실패를 새로운 케이스와 연결하세요.

## 출시하기

`outputs/skill-eval-suite.md`은 CI 게이트와 회귀 테스트 추적을 갖춘 에이전트 제품용 3계층 평가 스위트를 구축합니다.

## 연습 문제

1. 생산 환경 실패 중 하나를 선택하세요. 이를 재현하는 평가 케이스를 작성하세요. 에이전트가 현재 이를 통과하나요?
2. 도메인용 LLM 판정자 루브릭을 세 가지 차원(사실성, 톤, 범위)으로 구축하세요. 50개 세션을 채점하세요.
3. 평가 스위트를 CI에 연결하세요. 5% 이상 회귀 테스트가 발생하면 빌드를 실패시키세요.
4. 궤적 효율성 지표(trajectory-efficiency metric)를 추가하세요: 에이전트가 골드 궤적(gold trajectory) 대비 몇 단계를 수행했나요?
5. 14단계의 모든 강을 평가 스위트의 평가 케이스와 매핑하세요. 누락된 것이 있나요? 이는 메워야 할 공백입니다.
