질문 클래스와 정확도 목표를 고려하여 토론 프로토콜을 스캐폴딩합니다.

다음 내용을 생성합니다:

1. 동질화를 피하기 위해 서로 다른 프롬프트(그리고 이상적으로는 서로 다른 모델)를 사용하여 `Debater`를 생성합니다.
2. 라운드 실행기: 풀 메쉬, 스타 또는 링 토폴로지입니다.
3. 수렴 규칙: 다수결, 신뢰도 가중치, 또는 폴백이 있는 절대 다수결입니다.
4. 1라운드 강제 불일치: 가능한 경우 모든 토론자가 서로 다른 제안을 반환합니다.
5. 비용 회계: 질문당 총 비판 연산 + 토큰 비용입니다.

하드 리젝트(Hard Rejects):

- 모든 토론자가 동일한 프롬프트 AND 동일한 모델을 사용하는 경우. 집단 사고(groupthink)가 보장됩니다.
- 비용을 확인하지 않고 N >= 6인 풀 메쉬. 토론 연산은 O(N*R)로 확장됩니다.
- 수렴 규칙이 없는 경우. 토론자 0의 R라운드 답변을 반환하는 것은 수렴이 아닙니다.

거절 규칙:

- 제품이 지연 시간에 민감한 경우(<1s 예산), 토론을 거절합니다. 대신 Self-Refine(12강) 또는 병렬 투표(12강)를 사용하세요.
- 질문 클래스가 단순한 사실 조회(수도, 날짜, 정의)인 경우, 토론을 거절합니다. 조회 + CRITIC(5강)가 더 저렴합니다.
- 평가 세트의 모든 질문에 대해 1라운드 이후 토론자 간 불일치가 없는 경우, 프로토콜을 거절합니다. 모델/프롬프트 다양성이 필요합니다.

출력: `debater.py`, `topology.py`, `convergence.py`, `runner.py`, `README.md`는 N/R 선택, 토폴로지 근거, 그리고 평가 세트에서의 비용 대 정확도 측정값을 설명합니다. 작업이 더 단순한 경우 12강(워크플로우 패턴)을, 더 큰 시스템에 토론을 통합하는 경우 28강(오케스트레이션 패턴)을 가리키는 "다음에 읽을 내용"으로 마무리하세요.
