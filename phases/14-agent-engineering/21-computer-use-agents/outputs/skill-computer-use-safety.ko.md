컴퓨터 사용 에이전트와 대상 앱 목록이 주어졌을 때, 실행 전에 모든 작업을 분류하는 안전 계층을 생성해 보세요.

생성 대상:

1. `SafetyClassifier.assess(action, screen) -> SafetyVerdict` 필드 `allow`, `reason`, `needs_confirmation`를 포함합니다.
2. 에이전트가 클릭할 수 있는 요소 레이블의 허용 목록; 그 외의 경우 거절합니다.
3. 에이전트가 이동할 수 있는 URL의 허용 목록; 목록 밖으로 리디렉션되는 경우 거절합니다.
4. DOM 텍스트, 검색된 콘텐츠, 입력된 텍스트에 대한 주입 마커 필터. 매칭이 발생하면 작업을 차단합니다.
5. 민감한 작업(로그인, 구매, 삭제, 게시)에 대한 확인 게이트. 인간 개입 루프(HITL) 콜백 인터페이스를 사용합니다.
6. 추적 생성기: 모든 결정이 (작업, 판정, 이유)와 함께 기록됩니다.

하드 거절 조건:

- 첫 번째 작업에만 실행되는 안전 분류기. 모든 작업은 분류되어야 합니다.
- 형식 `*`의 허용 목록. 모든 것을 허용하는 허용 목록은 허용 목록이 아닙니다.
- 모델이 "확신하는 것처럼 보인다는" 이유로 확인을 건너뛰는 것. 확신은 안전이 아닙니다.

거절 규칙:

- 에이전트가 단계별 안전 기능 없이 컴퓨터 사용 접근 권한을 가지고 있다면 출시를 거절하세요.
- 에이전트가 임의의 URL로 이동할 수 있다면 거절하세요. 허용 목록 또는 차단 목록을 요구하세요.
- 민감한 작업이 어떤 모드에서도 확인 게이트를 우회한다면 거절하세요.

출력: `classifier.py`, `allowlist.py`, `confirmation.py`, `trace.py`, `README.md`. 게이트 정책, 주입 마커, 허용 목록 유지 관리 프로세스를 설명하세요. "다음에 읽을 내용"으로 27강(프롬프트 주입)과 23강(안전 결정에 대한 OTel 스팬 속성)을 가리키며 마무리하세요.
