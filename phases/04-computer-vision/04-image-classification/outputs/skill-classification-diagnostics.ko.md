# 분류 진단

혼동 행렬을 읽는 렌즈입니다. 집계된 정확도는 분류기가 작동한다는 것을 알려줍니다. 혼동 행렬은 *아직 모르는 것*을 알려줍니다.

## 사용 시점

- 훈련된 분류기의 검증 성능을 처음 확인할 때.
- 훈련 실행 간에 다음에 무엇을 변경할지 결정할 때.
- 모델 출시 전: 중요한 클래스가 조용히 실패하지 않았는지 확인할 때.
- 전체 정확도가 1포인트 떨어지고 그 이유를 알아야 하는 프로덕션 회귀를 디버깅할 때.

## 입력

- `cm`: CxC 혼동 행렬 (행 = 실제, 열 = 예측).
- `labels`: C개의 클래스 이름 목록, 동일한 순서로.
- 선택적 `class_priors`: 클래스별 훈련 빈도 (기본값은 `cm`의 행 합).

## 단계

1. **클래스별 지표 계산.** 0으로 나누는 경우 해당 클래스에 대해 지표가 정의되지 않은 것으로 간주하고 `n/a`으로 보고하세요. 0으로 조용히 대체하지 마세요.
   - precision_i = cm[i,i] / sum(cm[:, i])   (클래스가 예측된 적이 없을 때 정의되지 않음)
   - recall_i    = cm[i,i] / sum(cm[i, :])   (클래스에 정답 샘플이 없을 때 정의되지 않음)
   - f1_i        = 2 * p * r / (p + r)        (두 구성 요소 중 하나가 정의되지 않을 때 정의되지 않음)

2. **F1 기준으로 최악의 클래스 최대 3개 순위를 매기세요.** 혼동 행렬의 클래스가 3개 미만이면 존재하는 개수만큼 순위를 매기세요. 모든 지표가 정의되지 않은 클래스는 제외하세요.

3. **각 행의 최상위 비대각선 셀 찾기** — 이 클래스에서 가장 흔하게 훔쳐가는 하나의 클래스입니다. `true -> predicted`으로 보고하세요.

4. **각 최악의 클래스에 대해 실패 모드 분류.** 라벨이 재현 가능하도록 다음 정량적 임계값을 사용하세요:
   - `ambiguity` — 다른 클래스와의 양방향 혼동: `cm[i,j] / sum(cm[i, :]) >= 0.15` 및 `cm[j,i] / sum(cm[j, :]) >= 0.15` 모두.
   - `imbalance` — 클래스가 최상위 혼동 대상의 훈련 개수보다 `< 0.5x` 적습니다.
   - `label_noise` — `|precision_i - recall_i| >= 0.2`이며, 해당 클래스는 불균형/모호성 경로에 있지 않습니다.
   - `systematic` — 단일 혼동 요인이 이 클래스 오류의 0.2 이상을 차지하지 않으며, 오류가 세 개 이상의 다른 클래스에 분산됩니다.

5. **가장 영향력 있는 단일 다음 조치를 권장합니다**:
   - `ambiguity` -> 구별되는 예제를 수집하거나 합성하고, 구별 특성을 보존하는 타겟 증강을 추가합니다.
   - `imbalance` -> 소수 클래스를 과표본화하거나 클래스 가중 손실을 적용합니다.
   - `label_noise` -> 해당 클래스의 층화 샘플을 감사하고, 다른 변경 전에 오라벨을 수정합니다.
   - `systematic` -> 해당 클래스의 데이터를 늘리거나, 이 클래스의 손실에 더 높은 가중치를 부여하여 미세 조정합니다.

## 보고서

```
[diagnostics]
  aggregate accuracy: X.XX
  macro F1:           X.XX

[top-3 worst classes]
  1. class <name>  F1 = X.XX  prec = X.XX  rec = X.XX
     top confusion: <name> -> <other>  (N cases)
     failure mode:  ambiguity | imbalance | label_noise | systematic
     action:        <one sentence>

  2. ...
  3. ...

[recommendation]
  single biggest lever: <one sentence naming the class and the fix>
```

## 규칙

- 최대 세 개의 클래스만 반환합니다. 더 많은 클래스는 신호를 가립니다.
- 각 최악의 클래스에 대해 지배적인 혼동 요인을 명시합니다. "다수의 클래스와 혼동"으로 요약하지 마세요.
- 모든 권장 사항을 혼동 행렬 증거에 근거합니다. 어떤 클래스인지 지정하지 않은 채 "데이터를 더 추가하라"는 식의 일반적 권장 사항은 금지합니다.
- 정밀도와 재현율이 0.2 이상 차이가 날 경우, 항상 라벨 노이즈를 후보로 표시합니다. 실제 클래스는 학습 후 정밀도와 재현율이 일반적으로 일치합니다.
