# 프롬프트 캐싱 및 시맨틱 캐싱의 경제학

> **가격 스냅샷은 2026-04 기준입니다.** 아래 수치 주장은 이 강의가 게시된 시점에 수집된 공급업체의 요금표에 기반합니다. downstream에서 인용하기 전에 연결된 문서를 통해 확인해 보세요.

> 캐싱은 두 계층에서 발생합니다. L2 (공급업체 수준) 프롬프트/접두어 캐싱은 반복되는 접두어에 대해 어텐션 KV를 재사용합니다. Anthropic의 프롬프트 캐싱 문서는 긴 프롬프트에서 최대 90% 비용 절감 및 85% 지연 시간 감소를 홍보합니다. Claude 3.5 Sonnet의 경우 캐시 읽기는 $0.30/M vs $3.00/M이며, 5분 TTL과 1시간 TTL 옵션에 대해 2배의 쓰기 프리미엄이 적용됩니다 (docs.anthropic.com, 2026-04). OpenAI 프롬프트 캐싱은 ≥1024 토큰인 프롬프트에 자동으로 적용되며, 캐시된 입력은 신선한 입력 대비 약 90% 할인된 가격으로 책정됩니다 (platform.openai.com, 2026-04). 모델별 정확한 캐시된 요금은 실시간 요금표에 따라 달라집니다. L1 (앱 수준) 시맨틱 캐싱은 임베딩 유사성 히트 시 LLM을 완전히 건너뜁니다. 공급업체의 "95% 정확도"는 매칭 정확도를 의미하며 히트율을 의미하지는 않습니다. 보고된 프로덕션 히트율은 10% (개방형 채팅)에서 70% (구조화된 FAQ)까지 다양합니다. 두 공급업체 모두 공식 기준선을 공개하지 않으므로, 이를 보장된 값이 아닌 커뮤니티 텔레메트리로 취급하세요. 프로덕션 함정으로는 병렬화가 캐싱을 죽이는 것 (첫 캐시 쓰기 전에 N개의 병렬 요청이 발행되면 지출이 몇 배로 팽창할 수 있음)과 접두어 내의 동적 콘텐츠가 캐시 히트를 완전히 방지하는 것이 있습니다. ProjectDiscovery는 캐시 가능한 접두어에서 동적 텍스트를 제거하여 히트율을 7%에서 74%로 높였다고 보고했습니다 (2025-11).

**유형:** Learn
**언어:** Python (표준 라이브러리, 장난감 2계층 캐시 시뮬레이터)
**선수 요건:** 17단계 · 04강 (서빙 엔진 내부 구조), 17단계 · 06강 (SGLang RadixAttention)
**시간:** 약 60분

## 학습 목표

- L2 프롬프트/접두어 캐싱 (공급업체에서의 KV 재사용)과 L1 시맨틱 캐싱 (유사한 프롬프트에서의 LLM 우회)을 구분하세요.
- Anthropic의 `cache_control` 명시적 마킹과 두 가지 TTL 옵션 (5분 vs 1시간) 및 그 가격 배수를 설명하세요.
- 히트율, 프롬프트/응답 구성, 토큰 가격을 고려하여 예상 월간 절감액을 계산하세요.
- 청구서를 5-10배로 팽창시키는 병렬화 안티 패턴과 히트율을 붕괴시키는 동적 콘텐츠 안티 패턴을 나열하세요.

## 문제점

RAG 서비스에 프롬프트 캐싱을 추가했습니다. 비용은 그대로입니다. 적중률을 측정해 보니 7%입니다. 프롬프트는 정적으로 보이지만 실제로는 그렇지 않습니다. 시스템 프롬프트에 분 단위까지 포맷된 현재 날짜, 요청 ID, 다양성을 위한 무작위 예제 순서 재배치가 포함됩니다. 모든 요청이 새로운 캐시 항목을 기록하고, 읽기는 0입니다.

또한, 에이전트가 사용자 질문당 10개의 병렬 도구 호출을 실행합니다. 10개 모두 첫 번째 캐시 기록이 완료되기 전에 제공자에게 도착합니다. 기록은 10번, 읽기는 0번입니다. 비용은 "캐싱 적용 시" 예상 비용의 5-10배입니다.

캐싱은 플래그가 아니라 프로토콜입니다. 두 계층, 두 가지 다른 실패 모드입니다.

## 개념

### L2 — 제공자 프롬프트/접두어 캐싱

제공자는 캐싱 가능한 접두어에 대한 어텐션 KV를 저장하고, 접두어가 일치하는 다음 요청에서 이를 재사용합니다. 기록 비용은 한 번만 지불하며, 읽기는 거의 무료입니다.

**Anthropic (Claude 3.5 / 3.7 / 4 시리즈)**: 요청에 명시적인 `cache_control` 마커를 사용합니다. 캐싱 가능한 블록을 태그합니다. TTL: 5분 (기록 비용은 기본 비용의 1.25배) 또는 1시간 (기록 비용은 기본 비용의 2배). 캐시 읽기: $0.30/M on Claude 3.5 Sonnet vs $3.00/M 신규 — 10배 저렴합니다 (docs.anthropic.com, 2026-04 기준). 모델별(Opus/Haiku는 별도로 공개)로 요율이 다르므로, 항상 실시간 가격 페이지를 확인하세요.

**OpenAI**: 1024 토큰 이상의 프롬프트에 대해 자동 캐싱을 적용합니다 (platform.openai.com, 2026-04). 명시적인 플래그가 없습니다. 현재 gpt-4o/gpt-5 가격표 기준, 캐시된 입력은 신규 입력보다 약 10배 저렴합니다. 공식 적중률 기준은 문서나 릴리스 노트에 공개되지 않으며, 커뮤니티 보고서는 신중한 프롬프트 설계 시 30–60%에 집중되어 있습니다. `usage.cached_tokens`을 모니터링하여 자체 적중률을 측정해 보세요.

**Google (Gemini)**: 명시적인 API를 통한 컨텍스트 캐싱; 100만 토큰 컨텍스트는 캐싱의 가치를 더욱 높입니다.

**셀프 호스트 (vLLM, SGLang)**: 17단계 · 06강은 RadixAttention를 다루며, 자체 컴퓨팅 환경에서 동일한 패턴을 적용합니다.

### L1 — 앱 수준 시맨틱 캐싱

LLM을 호출하기 전에 프롬프트를 해싱하고 임베딩하여 유사한 캐시된 요청을 검색합니다 (코사인 유사도(Cosine Similarity)가 임계값, 일반적으로 0.95 이상). 적중 시 캐시된 응답을 반환합니다. 미스 시 LLM을 호출하고 결과를 캐시합니다.

오픈 소스: Redis Vector Similarity, GPTCache, Qdrant. 상용: Portkey Cache, Helicone Cache.

벤더의 정확성 주장은 반환된 캐시된 응답이 의미적으로 적절했던 빈도를 의미합니다 — 적중(hit) 빈도가 아닙니다. 실제 적중률:

- 개방형 채팅: 10-15%.
- 구조화된 FAQ / 지원: 40-70%.
- 코드 질문: 20-30% (작은 변형이 적중을 죽입니다).
- 프롬프트를 반복하는 음성 에이전트: 50-80% (음성 정규화 고정 세트).

### 병렬화 안티 패턴

에이전트가 10개의 도구 호출을 병렬로 수행합니다. 모든 10개 호출이 동일한 4K 토큰 시스템 프롬프트를 가집니다. Anthropic 캐시 쓰기는 요청 단위로 이루어지며, 첫 번째 캐시 쓰기는 제공자가 프롬프트를 본 후 약 300 ms에 완료됩니다. 요청 2-10은 동일한 밀리초 윈도우에 도착하며 각각 캐시 미스를 봅니다. 10개의 쓰기 프리미엄을 지불하고, 0개의 읽기 할인을 받습니다.

해결: 순차적 우선 배치로 처리하세요 — 요청 1을 단독으로 실행한 후, 요청 1의 캐시가 채워지면 요청 2-10을 실행합니다. 첫 번째 도구 호출에 300 ms가 추가되지만, 청구서를 5-10배 절감합니다.

### 동적 콘텐츠 안티 패턴

시스템 프롬프트가 다음과 같이 생겼습니다:

```
You are a helpful assistant. The current time is 14:32:17.
User ID: abc123. Today is Tuesday...
```

모든 요청이 고유합니다. 모든 요청이 씁니다. 적중은 0입니다.

해결: 진정으로 정적인 모든 것을 캐시 가능한 접두어로 이동하고, 캐시 경계 이후에 동적 콘텐츠를 추가하세요:

```
[cacheable]
You are a helpful assistant. [rules, examples, instructions]
[/cacheable]
[dynamic, not cached]
Current time: 14:32:17. User: abc123.
```

ProjectDiscovery는 이 방식으로 캐시 적중률을 7%에서 74%로 높였고, 그 구조를 공개했습니다.

### 야간 작업 부하를 위해 배치 + 캐시를 스택하세요

배치 API (17단계 · 15강)는 24시간 처리로 50% 할인을 제공합니다. 그 위에 캐시된 입력을 얹으면 추가로 약 10배 절감됩니다. 야간 분류, 라벨링 및 보고서 생성 작업 부하는 스택을 통해 동기식 비캐시 비용의 약 10%까지 떨어질 수 있습니다.

### 기억해야 할 수치

가격 포인트는 2026-04에 연결된 벤더 문서에서 캡처되었으며, 몇 달마다 변동합니다 — 의존하기 전에 재확인하세요.

- Anthropic 캐시 읽기: Claude 3.5 Sonnet에서 $0.30/M, 새로운 입력보다 약 10배 저렴합니다 (docs.anthropic.com).
- Anthropic 캐시 쓰기 프리미엄: 1.25배 (5분 TTL) 또는 2배 (1시간 TTL).
- OpenAI 자동 캐시: ≥1024 토큰인 프롬프트에 적용됩니다; 캐시된 입력은 현재 요금표에서 새로운 입력의 약 10% 가격으로 책정됩니다 (platform.openai.com).
- 시맨틱 캐시 적중률(커뮤니티 보고 기준): 오픈 채팅 약 10%; 구조화된 FAQ는 최대 약 70%. 벤더가 문서화한 기준값이 아닙니다.
- ProjectDiscovery: 동적 요소를 접두어에서 제거하여 적중률을 7%에서 74%로 향상(프로젝트 블로그, 2025-11).
- 병렬화 안티 패턴: N개의 병렬 요청이 첫 캐시 기록에 실패할 경우 청구 금액이 5~10배 증가한다는 일반적인 보고.

## 연습 문제

1. `code/main.py`를 실행하세요. 병렬화 플래그를 토글해 보세요. 청구 금액이 얼마나 변합니까?
2. 시스템 프롬프트에 날짜가 있습니다. 이를 밖으로 이동하세요. 전후 적중률 계산식을 보여주세요.
3. 요청 도착률을 고려하여 1시간 TTL(2배 기록)과 5분 TTL(1.25배 기록)의 손익분기점을 계산하세요.
4. 시맨틱 캐시가 0.95 임계값에서 20% 적중합니다. 0.85에서는 50% 적중하지만 부정확한 캐시 응답이 보입니다. 올바른 임계값을 선택하고 정당화하세요.
5. 사용자 질문당 10개의 병렬 하위 질의를 배치합니다. 엔드투엔드 지연을 추가하지 않고 캐시 친화적으로 재작성하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| L2 프롬프트 캐시 | "접두어 캐시" | 제공자가 반복되는 접두어에 대해 KV를 저장 |
| `cache_control` | "Anthropic 캐시 마커" | 캐시 가능한 블록을 표시하는 명시적 속성 |
| 캐시 기록 프리미엄 | "기록 세금" | 첫 미스-투-캐시(miss-to-cache)에 대한 추가 비용(1.25배 또는 2배) |
| L1 시맨틱 캐시 | "임베딩 캐시" | LLM 호출 전 앱 수준에서 해시 및 임베딩 |
| GPTCache | "LLM 캐싱 라이브러리" | 인기 있는 OSS L1 캐시 라이브러리 |
| 캐시 적중률 | "적중 / 총 요청" | 캐시에서 처리된 요청의 비율 |
| 병렬화 안티 패턴 | "N-기록 함정" | N개의 병렬 요청이 캐시를 N번 미스 |
| 동적 콘텐츠 함정 | "프롬프트 내 시간 함정" | 접두어 내 동적 바이트가 적중률을 죽임 |
| RadixAttention | "replica 내 캐시" | SGLang의 접두어 캐시 구현 |
