모델 크기, SLA (TTFT P99), 트래픽 형태 (안정적 vs 버스트), 예산 태도를 고려하여 콜드 스타트 완화 계획을 작성합니다.

다음 내용을 생성합니다:

1. 콜드 스타트 예산. 콜드 스타트 원시 경로(노드 프로비저닝, 이미지 풀, 가중치를 HBM으로 전송, 엔진 초기화, 첫 번째 순방향)를 세부적으로 분석합니다. 명시된 모델 크기에 대해 2026년 명목 초(seconds)를 사용합니다.
2. 레이어 선택. 총 시간을 SLA 미만으로 줄이는 최소한의 레이어 수를 선택합니다: 사전 시드 이미지(L1), 모델 스트리머(L2), GPU 스냅샷(L3), 웜 풀(L4), 계층적 로딩(L5). 각 레이어가 공격하는 특정 단계에 대해 정당화합니다.
3. 웜 풀 크기. 주요 경로에 대해 `min_workers`를 명시합니다. 70B+ 모델에서 TTFT P99 SLA가 60초 미만인 경우, 비용에 관계없이 웜 풀을 필수로 지정합니다.
4. 비용 추정. 선택한 웜 풀의 월간 GPU 비용과 예상되는 일일 콜드 스타트 횟수.
5. 꼬리 정책. 새로운 복제본의 첫 번째 사용자에게는 어떤 일이 일어나나요? 웜 복제본으로 큐잉되나요, 아니면 콜드 스타트 비용을 지불하나요? 특정 정책(예: "10초 내의 웜 복제본으로 첫 요청을 라우팅; 콜드로 폴스루")를 명시합니다.
6. 실패 모드. 세션 중 웜 복제본이 죽으면 어떤 일이 일어나나요? 복구(라이브 마이그레이션)는 자동인가요, 아니면 다음 요청에서 콜드 스타트가 발생하나요?

하드 거부:
- 월간 비용을 계산하지 않고 "웜 풀만 추가"를 제안하는 것.
- 공격하는 특정 단계를 명시하지 않고 완화 전략을 주장하는 것(예: "Bottlerocket 사용"이라고 말하면서 180초 이미지 풀을 제거한다고 언급하지 않는 것).
- GPU 스냅샷에 대한 GPU 토폴로지별 제약 조건을 무시하는 것 — 플랫폼이 SKU를 마이그레이션하면 스냅샷이 무효화됩니다.

거부 규칙:
- 웜 풀 없이 새로운 70B 콜드 스타트에서 TTFT P99 SLA가 5초 미만인 경우, 거부합니다 — 2026년 인프라 속도에서는 수학적으로 불가능합니다.
- 예산이 워름 풀(warm pool)을 허용하지 않지만 SLA가 30초 미만의 콜드 스타트를 요구하는 경우, 플랫폼 특유의 해결책(Modal GPU 스냅샷, Baseten 사전 워밍)을 명시하고, 해당 해결책이 없는 다른 플랫폼에서는 SLA를 약속하지 마세요.
- 운영자가 버스트 트래픽과 70B 모델을 고려한 스케일 투 제로(scale-to-zero)를 요청하는 경우, SLA를 약속하지 마세요. 스냅샷이나 워름 풀(warm pool) 없이는 계산이 성립하지 않습니다.

출력: 단계, 계층, `min_workers`, 월간 비용, 꼬리 정책, 실패 모드를 나열한 한 장짜리 계획. 마지막에는 경보해야 할 단일 지표로 최근 롤링 시간 동안의 P99 콜드 스타트 지속 시간을 제시하세요.
