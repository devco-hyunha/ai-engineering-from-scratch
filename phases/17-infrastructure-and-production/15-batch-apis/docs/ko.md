# 배치 API — 업계 표준인 50% 할인

> 모든 주요 제공업체는 50% 할인과 약 24시간 처리 시간을 보장하는 비동기 배치 API를 제공합니다. OpenAI, Anthropic, Google 및 대부분의 추론 플랫폼(Fireworks 배치 티어, Together 배치)은 동일한 패턴을 구현합니다. 배치와 프롬프트 캐싱을 결합하고 야간 파이프라인을 사용하면 동기식 비캐시 비용의 약 10%까지 떨어집니다. 규칙은 매우 단순합니다: 인터랙티브하지 않은 작업은 배치로 처리해야 합니다. 콘텐츠 생성 파이프라인, 문서 분류, 데이터 추출, 보고서 생성, 대량 라벨링, 카탈로그 태깅 — 24시간 지연을 허용하는 모든 작업은 배치로 이동하기 전까지 비용 낭비가 발생합니다. 2026년 생산 패턴은 모든 새로운 LLM 워크로드를 세 가지 레인으로 분류하는 것입니다: 인터랙티브(캐싱을 포함한 동기식), 준인터랙티브(폴백을 포함한 비동기 큐), 배치(야간, 캐시된 입력 결합). 인터랙티브인 척하지만 몇 분의 지연을 허용하는 워크로드가 가장 큰 낭비를 유발합니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 배치 대 동기식 비용 시뮬레이터)
**선수 요건:** 17단계 · 14강 (프롬프트 및 시맨틱 캐싱)
**시간:** 약 45분

## 학습 목표

- 세 가지 제공업체 배치 API(OpenAI, Anthropic, Google)와 공통적인 50% 할인 + 24시간 처리 보장 사항을 나열해 보세요.
- 야간 분류 워크로드에 배치 + 캐시된 입력을 결합한 비용을 계산하고 동기식 비캐시 기준선과 비교해 보세요.
- 워크로드를 인터랙티브 / 준인터랙티브 / 배치로 분류하고 레인 선택의 근거를 설명해 보세요.
- 두 가지 함정인 부분적 인터랙티브(사용자가 24시간보다 빠른 응답을 기대함)와 출력 스키마 드리프트(배치 파일 형식이 제공업체마다 다름)를 나열해 보세요.

## 문제점

팀이 야간 보고서 생성 파이프라인을 출시합니다. 50,000개의 문서를 각각 요약하고, 요약본을 클러스터링하며, 경영진 브리프를 작성합니다. 동기식으로 실행하면 4시간이 걸리고 $2,000/야간의 비용이 발생합니다. 배치 API에 대해 듣게 됩니다.

배치를 사용하면 50% 할인을 받을 수 있습니다. 또한 시스템 프롬프트에 프롬프트 캐싱을 활성화합니다(50,000번 호출 전체에 공유됨). 결합하면 비용이 $180/야간으로 떨어집니다 — 기준선의 약 9%. 동일한 파이프라인, 세 가지 설정 변경으로 달성됩니다.

배치는 LLM 비용 도구 키트에서 가장 저렴한 레버이지만 아무도 당기지 않는 레버입니다. 그 이유는 대부분 조직적인 것입니다. 팀은 SLA가 실제로 "아침까지"임에도 "실시간"이라고 생각합니다. 이 강의는 청구서의 90%를 테이블 위에 남겨두지 않는 것에 대한 것입니다.

## 개념

### 세 가지 배치 API

**OpenAI Batch API**: 요청 목록이 포함된 JSONL 파일 업로드. 24시간 내 처리를 약속합니다(실제로는 보통 ~2-8시간). 입력 및 출력 토큰에 대해 50% 할인. `/v1/batches` 엔드포인트. 캐시 대상 입력은 캐시 입력 가격도 추가로 적용됩니다.

**Anthropic Message Batches**: JSONL 업로드. 24시간 내 처리. 50% 할인. `cache_control`를 지원합니다 — 캐시 쓰기는 명시적이며, 읽기는 배치 내에서 자동으로 발생합니다.

**Google Vertex AI Batch Prediction**: BigQuery 또는 GCS 입력. Gemini에 대해 유사한 50% 할인. Vertex 파이프라인과 통합됩니다.

### 시맨틱: 비동기, 느림이 아님

배치는 "24시간 내에 반환하겠습니다"라는 약속이지, "24시간이 걸릴 것입니다"라는 의미가 아닙니다. 일반적인 P50은 2-6시간입니다. 제공자는 GPU 재고가 충분히 활용되지 않는 오프피크 윈도우 동안 배치를 스케줄링합니다.

### 캐싱과 스택하기

동일한 4K 토큰 시스템 프롬프트를 사용하는 50,000개 문서 요약 작업:

- 동기식 비캐시: 전체 요금으로 50000 × ($input × 4000 + $output × 200).
- 동기식 캐시: 첫 번째 쓰기 후 시스템 프롬프트가 캐시되며, 나머지 49999개는 입력 비용이 10배 저렴해집니다.
- 배치 캐시: 위의 모든 사항에 더해 읽기와 쓰기 모두에 대해 50% 할인.

스택: 배치 + 캐시 = 동기식 비캐시 청구서의 약 10%. 밤새 실행되고 공유 시스템 프롬프트가 있는 모든 워크로드가 이 방식을 사용해야 합니다.

### 워크로드 분류

**인터랙티브** — 사용자가 응답을 기다립니다. TTFT가 중요합니다. 프롬프트 캐싱을 사용하는 동기식 호출. 배치할 수 없습니다.

**세미-인터랙티브** — 사용자가 작업을 제출하고 몇 분 후 확인합니다. 배치가 사용 불가능할 경우 동기식으로 폴백하는 비동기 큐. 중량 RAG 인덱싱을 생각해 보세요.

**배치** — 사용자가 "아침까지" 또는 "다음 시간까지" 결과를 기대합니다. 콘텐츠 파이프라인, 대규모 분류, 오프라인 분석. 항상 배치하고, 항상 캐싱을 스택하세요.

공통 실수: 파이프라인이 프로덕션 환경에 있다는 이유로 모든 것을 인터랙티브로 분류하는 것입니다. 프로덕션은 지연 시간 사양이 아닙니다. SLA가 지연 시간 사양입니다.

### 부분 인터랙티브 함정

일부 기능은 인터랙티브처럼 보이지만 5~10분의 지연을 허용합니다. 예: '새로고침' 버튼이 있는 야간 고객 건강 보고서. 사용자가 새로고침을 클릭하면 10분 대기하는 것은 문제가 없습니다. 팀은 이를 동기식으로 출시합니다. 50개의 동시 새로고침은 배치 처리 후 이메일로 전달하는 방식보다 비용이 10배 더 많이 듭니다.

물어야 할 질문: "이 사용자에게 24시간이란 무엇을 의미합니까?" 답이 "눈치채지 못할 것이다"라면 배치 처리하세요.

### 출력 스키마 함정

배치 파일 형식은 제공자마다 다릅니다:

- OpenAI: JSONL, 한 줄에 하나의 요청.
- Anthropic: JSONL, 한 줄에 하나의 메시지; 응답 형식이 내장되어 있습니다.
- Vertex: BigQuery 테이블 또는 GCS 접두어에 TFRecord 포함.

제공자 간에 '하나의 배치 클라이언트'를 작성하려면 제공자별 어댑터 코드가 필요합니다. 다중 제공자 배치(Portkey, LiteLLM 일부 티어)를 홍보하는 게이트웨이도 여전히 원시 형식을 얇게 래핑합니다.

### 기억해야 할 수치

- 제공자 간 배치 할인: 입력 + 출력에 대해 평평한 50% 할인.
- 처리 완료 SLA: 24시간 보장, P50은 일반적으로 2~6시간.
- 배치 + 캐시된 입력 스택: 동기식 비캐시 비용의 약 10%.
- 워크로드 분류 규칙: 24시간 지연이 허용된다면 항상 배치 처리하세요.

## 연습 문제

1. `code/main.py`를 실행하세요. 3K 토큰 시스템 프롬프트와 500 토큰 출력을 가진 100k 문서 파이프라인에 대해, 전체 스택(배치 + 캐시)의 절감액을 동기식 기준선과 비교하여 계산하세요.
2. 알고 있는 실제 제품에서 세 가지 기능을 선택하세요. 각각을 인터랙티브/반자동/배치로 분류하세요.
3. 사용자가 보고서가 3시간 걸렸다고 불평합니다. 이는 배치 처리 오판이었습니까, 아니면 정당한 인터랙티브 처리였습니까? 결정 기준을 작성하세요.
4. 배치 API의 반환 SLA는 24시간이지만 P99는 20시간입니다. 이를 사용자에게 어떻게 전달하시겠습니까? 엣지 케이스에서 다운스트림 시스템의 동작은 어떻게 되나요?
5. 손익분기점 계산: 공유 접두어 길이가 어느 정도일 때 배치 + 캐시가 예약된 GPU에서 밤새 실행하는 것보다 저렴해지나요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| Batch API | "비동기 할인" | 24시간 처리 보장으로 50% 할인 |
| JSONL | "배치 형식" | 한 줄에 하나의 JSON 요청; OpenAI/Anthropic 표준 |
| Message Batches | "Anthropic batch" | Anthropic의 배치 API 제품명 |
| Batch prediction | "Vertex batch" | Vertex AI의 배치 API 제품 |
| Turnaround SLA | "24h 약속" | 보장, 전형적인 값이 아님; 전형적인 값은 2-6h |
| Workload triage | "인터랙티브 결정" | 인터랙티브 / 준인터랙티브 / 배치 라우팅 결정 |
| Output schema | "응답 형식" | 제공자별 JSONL 레이아웃; 이식 불가능 |
| Stacked discount | "batch + cache" | 둘 다 적용될 때 캐시되지 않은 동기 청구의 약 10% |
