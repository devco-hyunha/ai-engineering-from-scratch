작업 부하(모델, 하드웨어, 목표 동시성, 사용자 상호작용 유형 — 스트리밍 채팅 / 원샷 / 음성 / 에이전트)가 주어지면, CI/CD용 순수 처리량(goodput) 기반 SLO 게이트를 생성해 보세요.

생성할 항목:

1. SLO 사양. 세 가지 임계값: TTFT P99 상한, TPOT P99 상한, E2E P99 상한. 상호작용 유형에 따라 방어 가능한 값을 선택하세요(스트리밍 채팅: TTFT 500 ms, TPOT 25 ms, E2E 3 s; 음성: TTFT 300 ms로 더 엄격하게; 에이전트: E2E 5 s로 더 느슨하게).
2. 벤치마킹 레시피. 도구 선택(LLMPerf 또는 GenAI-Perf — 선택한 도구와 이유를 명시하세요). 프롬프트 분포(입력 및 출력 토큰의 평균 + 표준 편차). 동시성 스윕(목표의 25%, 50%, 100%, 150%).
3. 순수 처리량(goodput) 계산. 공식: 세 가지 제약 조건을 동시에 충족하는 요청의 비율. 프로덕션은 >= 99%, 카나리 릴리스(Canary Release)는 >= 95%를 목표로 하세요.
4. 백분위수 보고. 모든 지표에 대해 P50, P90, P99를 보고하세요(평균만 보고하지 마세요). 평균은 Sanity Check 용도로만 주석 처리하세요.
5. 도구 함정 주의. 도구가 ITL에 TTFT를 포함하는지 제외하는지 명시하세요. 팀 간 비교 전에 정의를 고정하세요.
6. 게이트 로직. 목표 동시성에서 순수 처리량(goodput) >= 목표이면 CI가 통과합니다. 동시성 100%와 150% 사이에서 순수 처리량(goodput)이 5 포인트 이상 저하되면 플래그를 지정하세요 — 이는 부하 테스트 여유(headroom)가 부족함을 나타냅니다.

거부 조건:
- 처리량(throughput)만으로 게이트하는 경우. 거부하고 순수 처리량(goodput)을 요구하세요.
- P99 없이 평균만 보고하는 경우. 거부하세요.
- 도구 이름과 도구 버전을 생략하는 경우. 거부하세요.
- 목표 동시성에서만 벤치마킹하는 경우. 항상 스윕을 수행하세요.

거부 규칙:
- 사용자가 SLO를 작성하지 않은 경우, 거부하고 먼저 상호작용 유형에 기반하여 SLO를 작성하세요.
- 프롬프트 분포가 "반복되는 동일한 프롬프트"인 경우, 거부하세요 — 이는 프롬프트 균일성 함정입니다. 현실적인 합성 데이터를 요구하세요.
- 벤치마킹이 30회 미만 실행이거나 실행당 요청이 100개 미만인 경우, 통계적으로 불충분하므로 거부하세요.

출력: 임계값, 벤치마크 레시피, 도구 선택, 백분위수 보고서 템플릿, CI 통과/실패 규칙을 나열한 한 페이지 분량의 SLO 게이트 사양입니다. 알려진 약점에 따라 순수 처리량(Goodput) 대 동시성 곡선, 프롬프트 분포 민감도, 청크 프리필(Chunked Prefill) 켜짐/꺼짐 꼬리 지연(Tail Latency) 비교 중 하나를 지정하는 "다음에 측정할 것" 단락으로 마무리하세요.
