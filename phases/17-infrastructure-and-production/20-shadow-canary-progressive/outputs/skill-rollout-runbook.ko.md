후보 변경 사항(새로운 모델, 새로운 프롬프트 템플릿, 새로운 라우터 정책), 기준 생산 지표, 위험 허용도를 고려하여 롤아웃 런북을 작성해 보세요.

다음 내용을 작성합니다:

1. 섀도 계획. 기간(24-72시간). 기록할 지표: 출력, 토큰 수, 지연 시간, 거절, 오류. 알림 조건: 비용 변화 >20%, 출력 길이 변화 >30%, 스키마 위반 발생 시.
2. 카나리 진행. 단계(1% → 10% → 25% → 50% → 75% → 100%). 각 단계의 기간(트래픽 볼륨에 따라 30분~24시간; 각 단계가 통계적 신뢰도를 확보할 만큼 충분한 데이터를 갖도록 보장).
3. 5개의 게이트. 지연 시간 P99, 요청당 비용, 오류/거절, 출력 길이 P99, 부정적 피드백(thumbs-down) 비율에 대한 정확한 임계값을 지정합니다. 노이즈 바닥 이상으로 설정합니다(15%의 불가피한 변동성을 고려).
4. 도구. 롤아웃 컨트롤러(Argo Rollouts, Flagger, KServe)와 즉각적인 롤백을 위한 기능 플래그 시스템을 지정합니다.
5. 롤백 경로. 세 가지 작업을 문서화합니다: 플래그 전환 → 고정된 다이제스트로 되돌리기 → 검증. 목표 시간: 전체 과정이 60초 이내.
6. A/B 생략 여부? 정당화. 개선된 변형 변경은 A/B를 생략할 수 있습니다. distinctly different changes (new behavior, new cost curve)는 A/B가 필요합니다.

거부 조건:
- 섀도 모드 생략. 거부 — 비용 급증과 길이 후퇴가 오프라인 평가를 통과해 버립니다.
- 15% 변동성보다 엄격한 게이트. 거부 — 오탐이 합법적인 롤아웃을 중단시킵니다.
- 재배포가 필요한 롤백. 거부 — 이는 롤백이 아니라 피해 보고서입니다.

거절 규칙:
- 변경 사항이 안전에 치명적인 경우(예: PII 처리 변경), 카나리 시작 전 섀도 샘플에서 PII 유출이 0건이어야 하는 추가 게이트를 요구합니다.
- 트래픽 볼륨이 시간당 100 요청 미만인 경우, 카나리 단계를 연장해야 합니다. 그렇지 않으면 게이트 노이즈가 신호를 압도합니다.
- 팀이 5개 카나리 게이트의 기준선 지표를 제공하지 못하면 롤아웃을 거부하세요. 기준선은 필수 전제 조건입니다.

출력: 섀도 트래픽, 카나리, 게이트, 도구, 롤백, A/B 태세를 포함한 한 장의 런북. 첫 실제 배포 전에 롤백을 한 번 연습하는 롤백 훈련 요구 사항으로 마무리하세요.
