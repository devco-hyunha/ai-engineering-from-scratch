# AI를 위한 SRE — 다중 에이전트 인시던트 대응, 런북, 예측 감지

> AI SRE는 인프라 데이터(로그, 런북, 서비스 토폴로지)에 기반한 LLM을 RAG를 통해 활용하여 조사, 문서화, 조정 단계를 자동화합니다. 2026년 아키텍처 패턴은 다중 에이전트 오케스트레이션입니다. 전문화된 에이전트(로그, 메트릭, 런북)가 감독자(supervisor)에 의해 조정되며, AI는 가설과 쿼리를 제안하고 인간은 판단을 승인합니다. Datadog Bits AI와 Azure SRE Agent는 이를 관리형 제품으로 출시했습니다. 런북은 진화하고 있습니다. NeuBird Hawkeye는 적대적 평가(adversarial evaluation)를 사용합니다. 두 모델이 동일한 인시던트를 분석하며, 일치하면 신뢰도, 불일치하면 불확실성으로 간주합니다. 운영 메모리는 팀 변화에 걸쳐 지속됩니다. 자동 복구(auto-remediation)는 신중하게 유지됩니다. AI가 제안하고 인간이 승인합니다. 완전한 자율적 행동은 좁은 범위(팟 재시작, 특정 배포 롤백)로 제한되며 엄격한 가드레일(guardrails)이 적용됩니다. "설치하고 잊어버리는(set it and forget it)" 방식을 판매하는 것은 과장입니다. 새로운 프론티어는 인시던트 전 예측입니다. MIT 연구에 따르면, 과거 로그 + GPU 온도 + API 오류 패턴으로 학습된 LLM이 장애의 89%를 10-15분 전에 예측했습니다. 전망: 2026년 말까지 기업용 LLM의 95%가 자동 페일오버(failover)를 갖출 것입니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 장난감 다중 에이전트 인시던트 분류 시뮬레이터)
**선수 요건:** 17단계 · 13강 (관측 가능성), 17단계 · 24강 (카오스 엔지니어링)
**시간:** 약 60분

## 학습 목표

- 다중 에이전트 AI SRE 아키텍처를 다이어그램으로 표현해 보세요. 감독자 + 전문화된 에이전트(로그, 메트릭, 런북) + 인간 승인 게이트를 포함합니다.
- 자동 복구가 좁은 범위(팟 재시작, 배포 되돌리기)인 이유를 설명해 보세요. 서비스 재설계와 같은 넓은 범위가 아닌 이유를 포함합니다.
- 적대적 평가 패턴(NeuBird Hawkeye)을 명명해 보세요. 두 모델이 일치하면 신뢰도, 불일치하면 에스컬레이션합니다.
- MIT의 89% 조기 감지 결과와 운영적 제약 조건을 인용해 보세요. 실행(actuation) 없는 예측은 단순한 대시보드일 뿐입니다.

## 문제점

온콜(on-call) 엔지니어가 새벽 3시에 호출을 받습니다. "체크아웃에서 높은 오류율 발생." 엔지니어는 Datadog, Loki, 세 개의 런북, 배포 로그를 확인합니다. 30분 후, 근본 원인이 KV 캐시 급증으로 인한 vLLM OOM임을 깨닫습니다. 팟을 재시작하면 오류가 해소됩니다.

2026년에는 해당 조사 과정의 첫 20분은 자동화할 수 있습니다. 로그를 서비스별로 그룹화하고, 최근 배포와 상관관계를 분석하며, 런북과 대조하는 작업은 모두 RAG (검색 증강 생성)(RAG (Retrieval-Augmented Generation)) 및 도구 사용으로 처리됩니다. 감독형 에이전트(Agent)는 인간이 Datadog를 열기 전에 1차 분류(triage)를 수행하고 가설을 제시할 수 있습니다.

완전 자율적인 복구(remediation)는 다른 문제입니다. Pod 재시작은 안전합니다. GPU 풀을 확장하는 것은 정책이 허용한다면 안전합니다. 서비스 아키텍처를 재설계하는 것은 절대적으로 안전하지 않습니다. 중요한 것은 좁은 경계를 설정하는 것입니다.

## 개념

### 멀티 에이전트 아키텍처

```
          Incident
             │
             ▼
        Supervisor
        /    |    \
       ▼     ▼     ▼
  Log agent  Metric agent  Runbook agent
       │     │     │
       └─────┴─────┘
             │
             ▼
        Hypothesis + evidence
             │
             ▼
        Human approval
             │
             ▼
        Action (narrow set)
```

슈퍼바이저(Supervisor)는 인시던트(Incident)를 하위 쿼리로 분해합니다. 전문화된 에이전트(Agent)는 도구 접근 권한(로그 검색, PromQL, 문서 검색)을 가집니다. 슈퍼바이저는 결과를 종합하여 가설과 증거를 인간에게 제시합니다. 인간은 승인하거나 방향을 수정합니다.

### 자동 복구 범위

**안전 (좁은 범위)**: Pod 재시작, 특정 배포 롤백(Rollback), 사전 승인된 범위 내에서 풀 확장, 사전 승인된 기능 플래그 활성화.

**안전하지 않음 (넓은 범위)**: 서비스 토폴로지 변경, 리소스 한계 수정, 새 코드 배포, IAM 변경, 데이터베이스 변경.

"한번 설정하면 잊어버려도 된다(set it and forget it)"라고 판매하는 사람은 과장하고 있습니다. AI SRE가 성숙해짐에 따라 안전한 범위는 확장되지만, 경계는 실재합니다.

### 적대적 평가(NeuBird Hawkeye)

두 모델이 독립적으로 동일한 인시던트(Incident)를 분석합니다. 두 모델이 근본 원인(root cause)에 대해 일치하면 신뢰도가 높습니다. 일치하지 않으면 두 가설을 모두 표시하여 인간에게 에스컬레이션합니다. 단순한 패턴이지만, 환각(Hallucination)된 근본 원인에 대한 효과적인 필터입니다.

### 운영 메모리

팀 이직은 전통적인 SRE의 조용한 치명타입니다 — 부족 지식(tribal knowledge)이 사라집니다. AI SRE는 런북과 사후 분석(Postmortem)을 벡터 데이터베이스(Vector Database)에 저장하며, 에이전트(Agent)는 모든 새로운 인시던트(Incident)에서 이를 검색합니다. 새로운 엔지니어가 합류하면 AI는 전체 역사를 가지고 있습니다.

### 사전 인시던트 예측

MIT 2025 연구: 역사적 로그, GPU 온도, API 오류 패턴으로 학습된 LLM (대규모 언어 모델)(LLM (Large Language Model))은 테스트 세트에서 장애가 발생하기 10-15분 전에 89%의 장애를 예측했습니다.

현실 점검: 실행(actuation) 없는 예측은 대시보드일 뿐입니다. 운영상의 질문은 "예측했을 때, 무엇을 하는가?"입니다. 사전 드레인(drain)? 페이지(Pager)? 자동 확장? 답은 정책별로 다릅니다.

### 2026년 제품

- **Datadog Bits AI** — Datadog 내부의 관리형 SRE 코파일럿입니다.
- **Azure SRE Agent** — Azure 네이티브입니다.
- **NeuBird Hawkeye** — 적대적 평가 + 운영 메모리입니다.
- **PagerDuty AIOps** — 트리아지 + 중복 제거입니다.
- **Incident.io Autopilot** — 인시던트 커맨더 + 조정입니다.

### 코드화된 런북

런북은 Confluence 페이지에서 구조화된 섹션(증상, 가설, 검증, 조치)을 가진 버전 관리된 마크다운으로 진화합니다. 구조화된 런북은 더 나은 RAG (검색 증강 생성)(RAG (Retrieval-Augmented Generation)) 검색을 가능하게 합니다. AI-SRE 롤아웃은 비구조화된 런북을 구조화된 형태로 변환하는 것부터 시작해 보세요.

### 기억해야 할 수치

- MIT 조기 탐지: 장애의 89%, 10-15분 리드 타임.
- 멀티 에이전트 트리아지: 슈퍼바이저 + (로그, 메트릭, 런북) + 인간.
- 안전한 자동 복구 세트: 포드 재시작, 배포 롤백, 범위 내 스케일링.
- 적대적 평가: 두 모델이 독립적; 일치 = 신뢰도.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 로그 에이전트와 메트릭 에이전트가 불일치하면 어떻게 되나요? 슈퍼바이저는 이를 어떻게 해결하나요?
2. 서비스에 대해 세 가지 "안전한" 자동 복구 작업을 정의해 보세요. 각각을 정당화해 보세요.
3. 구조화된 런북 템플릿을 작성해 보세요: 섹션, 필수 필드, 검증 명령어.
4. 예측 탐지가 12분 리드 타임에 발동합니다. 정책은 어떻게 되나요 — 페이지 호출, 사전 드레인, 또는 둘 다?
5. 3인 팀이 2026년에 AI SRE를 도입해야 하는지, 아니면 기다려야 하는지 논증해 보세요. 성숙도, 볼륨, 위험을 고려해 보세요.
