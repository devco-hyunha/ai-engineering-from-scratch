# LLM 기능 A/B 테스트 — GrowthBook, Statsig, 그리고 바이브 문제

> 전통적인 A/B 테스트는 비결정적(non-deterministic) LLM을 위해 설계되지 않았습니다. 중요한 구분은 다음과 같습니다: 평가(evals)는 "모델이 작업을 수행할 수 있는가?"에 답하고, A/B 테스트는 "사용자가 신경 쓰는가?"에 답합니다. 둘 다 필수이며, 바이브 체크(vibe checks)만으로 출시하는 시대는 끝났습니다. 2026년에 테스트해야 할 항목: 프롬프트 엔지니어링(프롬프트 엔지니어링)(wording), 모델 선택(GPT-4 vs GPT-3.5 vs OSS; 정확성 vs 비용 vs 지연), 생성 매개변수(생성 매개변수)(temperature, top-p). 실제 사례: 챗봇 보상 모델 변형은 대화 길이를 +70%, 유지율을 +30% 개선했습니다. Nextdoor AI의 제목 실험은 보상 함수 개선 후 CTR을 +1% 개선했습니다. Khan Academy Khanmigo는 지연 시간 대 수학 정확성 축에서 반복 개선을 진행했습니다. 플랫폼 구분: **Statsig** (2025년 9월 OpenAI에 $1.1B에 인수됨) — 순차 테스트, CUPED, 올인원. **GrowthBook** — 오픈소스, 웨어하우스 네이티브, 베이지안 + 빈도론 + 순차 엔진, CUPED, SRM 체크, Benjamini-Hochberg + Bonferroni 보정. 웨어하우스-SQL 선호도와 조직에서 "OpenAI에 인수됨"이 중요한지 여부에 따라 선택하세요.

**유형:** Learn
**언어:** Python (stdlib, toy sequential test simulator)
**선수 요건:** 17단계 · 13강 (관측 가능성(Observability)), 17단계 · 20강 (점진적 배포(Progressive Deployment))
**시간:** 약 60분

## 학습 목표

- 평가(evals)("모델이 작업을 수행할 수 있는가")와 A/B 테스트("사용자가 신경 쓰는가")를 구분해 보세요.
- 세 가지 테스트 가능한 축(프롬프트, 모델, 매개변수)을 나열하고 각각에 대한 지표(metric)를 선택해 보세요.
- CUPED, 순차 테스트, Benjamini-Hochberg 다중 비교 보정을 설명해 보세요.
- 웨어하우스-SQL 태세와 기업 인수 입장을 바탕으로 Statsig 또는 GrowthBook을 선택해 보세요.

## 문제점

시스템 프롬프트(System Prompt)를 수동으로 조정했습니다. 더 좋아진 것 같습니다. 출시했습니다. 전환율이 노이즈로 인해 변했습니다. 지표(metric)를 탓합니다. 또는 새로운 모델을 출시했는데 전환율이 변하지 않았습니다 — 모델이 성능이 저하된 것일까요, 아니면 변화가 감지하기 너무 작은 것일까요? A/B 테스트 없이 출시했기 때문에 알 수 없습니다.

평가는 모델이 레이블이 지정된 세트에서 작업을 수행할 수 있는지를 답합니다. 사용자가 출력물을 선호하는지는 답하지 않습니다. 이를 답하는 것은 통제된 온라인 실험뿐이며, 실험이 충분한 검정력을 가지고, 비결정성을 통제하며, 다중 비교를 보정하는 경우에만 가능합니다.

## 개념

### 평가 vs A/B 테스트

**평가** — 오프라인, 레이블이 지정된 세트, 판정자(루브릭 또는 LLM-as-judge 또는 인간). 답: "이 고정된 분포에서 출력물이 정확/유용/안전한가요?"

**A/B 테스트** — 온라인, 실제 사용자, 랜덤화. 답: "새로운 변형이 중요한 사용자 수준 지표에 영향을 미치나요?"

둘 다 필요합니다. 평가는 노출 전에 회귀를 포착하고, A/B는 이후 제품 영향을 확인합니다.

### 테스트할 대상

1. **프롬프트 엔지니어링(Prompt Engineering)** — 문구, 시스템 프롬프트(System Prompt) 구조, 예시. 지표: 작업 성공, 사용자 유지, 요청당 비용.
2. **모델 선택** — GPT-4 vs GPT-3.5-Turbo vs Llama-OSS. 지표: 정확도(작업) + 요청당 비용 + P99 지연. 다목적.
3. **생성 매개변수(Parameter)** — 온도(Temperature), top-p, max_tokens. 지표: 작업별(출력 다양성 vs 결정성).

### CUPED — 분산 감소

실험 전 데이터를 사용하는 통제 실험(CUPED). 사후 기간 비교 전에 사전 기간 분산을 제거합니다. 일반적인 분산 감소: 30-70%. 유효 표본 크기가 무료로 증가합니다.

구현: Statsig와 GrowthBook 모두 구현합니다.

### 순차적 테스트

고전적 A/B는 고정된 표본 크기를 가정합니다. 순차적 테스트("peek-and-decide")는 반복적인 확인 하에서 오탐율을 통제합니다. 항상 유효한 순차적 절차(mSPRT, Howard의 신뢰 구간)를 사용하면 명확한 승자가 있을 때 조기 종료할 수 있습니다.

### 다중 비교 보정

95% 신뢰도로 20개의 A/B 테스트를 실행하면 우연히 오탐이 하나 발생합니다. Bonferroni 보정은 테스트별 α를 강화하고, Benjamini-Hochberg는 오탐율을 통제합니다. GrowthBook은 둘 다 구현합니다.

### SRM — 표본 비율 불일치

할당 해시는 사용자를 변형에 랜덤화합니다. 50/50 분할이 47/53을 전달하면 무언가 고장 난 것입니다. SRM 체크가 이를 플래그합니다. 두 플랫폼 모두 구현합니다.

### Statsig vs GrowthBook

**Statsig**:
- 2025년 9월 OpenAI에 11억 달러에 인수되었습니다. 호스팅형 SaaS입니다.
- 순차적 테스트, CUPED, 홀드아웃 인구를 지원합니다.
- 올인원 제품: 기능 플래그 + 실험 + 관측 가능성을 통합했습니다.
- 최적의 선택: 팀이 번들된 제품을 원하며 OpenAI 소유권은 중요하지 않은 경우입니다.

**GrowthBook**:
- 오픈소스(MIT); 웨어하우스 네이티브로 Snowflake/BigQuery/Redshift에서 직접 읽습니다.
- 다양한 엔진: 베이지안, 빈도론, 순차적 테스트를 지원합니다.
- CUPED, SRM, Bonferroni, BH 보정 기능을 제공합니다.
- 셀프 호스트 또는 관리형 클라우드를 선택할 수 있습니다.
- 최적의 선택: 웨어하우스 SQL 환경, 데이터 팀이 지표 계층을 통제하며 오픈소스를 선호하는 경우입니다.

### 비결정성이 검정력을 복잡하게 만듭니다

동일한 프롬프트가 다양한 출력을 생성합니다. 전통적인 검정력 계산은 IID 관측을 가정합니다. LLM의 비결정성으로 인해 유효 표본 크기가 명목상 표본 크기보다 낮아집니다. 안전 마진으로 필요한 표본 크기를 약 1.3~1.5배로 늘려 보세요.

### 실제 사례 결과

- 챗봇 보상 모델 변형: 대화 길이가 70% 증가하고, 유지율이 30% 증가했습니다.
- Nextdoor의 제목: 보상 함수 개선 후 CTR이 1% 증가했습니다.
- Khan Academy Khanmigo: 지연 시간과 수학 정확도 간의 반복적인 트레이드오프를 수행했습니다.

### 안티 패턴: 감으로 출시하기

모든 시니어 엔지니어는 "느낌이 더 좋다"는 이유로 A/B 테스트 없이 출시된 기능을 나열할 수 있습니다. 그 대부분은 팀이 몇 달 동안 눈치채지 못한 제품 지표의 후퇴를 초래했습니다. A/B 테스트는 강제 기능입니다.

### 기억해야 할 숫자

- Statsig는 OpenAI에 인수되었습니다: 11억 달러, 2025년 9월.
- GrowthBook: 오픈소스 MIT; 베이지안 + 빈도론 + 순차적 테스트를 지원합니다.
- CUPED 분산 감소: 30~70%.
- LLM 비결정성 → 표본 크기 버퍼 +30~50%.

## 연습 문제

1. `code/main.py`을 실행해 보세요. 기준 전환율이 3%이고 예상 상승분이 5%일 때, 80%의 검정력을 확보하려면 표본 크기는 얼마여야 합니까?
2. 의료 규제 대상 온프레미스 고객에 Statsig 또는 GrowthBook 중 하나를 선택해 보세요.
3. GPT-4와 GPT-3.5를 해결된 티켓당 비용 기준으로 테스트하는 A/B 테스트를 설계해 보세요. 주요 지표, 가드레일 지표, 보조 지표는 각각 무엇입니까?
4. 카나리 릴리스는 통과했지만 A/B 테스트에서 전환율이 -1.2% 감소했습니다. 출시하시겠습니까? 에스컬레이션 기준을 작성해 보세요.
5. 사후 기간 분산의 60%를 차지하는 사전 기간에 CUPED를 적용해 보세요. 유효 표본 크기 증가분을 계산해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 평가(Eval) | "오프라인 테스트" | 모델 능력을 레이블이 지정된 세트에서 평가하는 것 |
| A/B 테스트 | "실험" | 사용자를 대상으로 한 라이브 랜덤 비교 |
| CUPED | "분산 감소" | 사전 기간 회귀 분석을 통해 분산을 줄이는 기법 |
| 순차 테스트 | "피킹 허용 테스트" | 조기 중지를 허용하는 항상 유효한 절차 |
| 다중 비교 | "가족 오류" | 많은 테스트를 수행하면 오탐이 증가함 |
| Bonferroni | "엄격한 보정" | α를 테스트 수로 나누는 것 |
| Benjamini-Hochberg | "BH FDR" | 오탐률 제어, 더 보수적이지 않음 |
| SRM | "잘못된 분할" | 표본 비율 불일치; 할당 버그 |
| Statsig | "OpenAI 소유" | 올인원 상용 제품, 2025년 인수됨 |
| GrowthBook | "오픈소스 제품" | MIT의 웨어하우스 네이티브 플랫폼 |
| mSPRT | "순차 확률비 검정" | 고전적인 순차 절차 |
