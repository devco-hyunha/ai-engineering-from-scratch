규제 범위(SOC 2, HIPAA, GDPR), 현재 자격 증명 상태, 네트워크/아웃바운드 태세를 고려하여 보안 계획을 작성해 보세요.

다음 내용을 작성합니다:

1. 볼트 마이그레이션. 볼트(HashiCorp, AWS Secrets Manager, Azure Key Vault, GCP Secret Manager)를 선택합니다. 게이트웨이 패턴: 애플리케이션 → 게이트웨이 → 런타임 시 볼트. 하드코딩된 환경 변수 및 구성 파일 자격 증명을 폐기합니다.
2. 시크릿 스캐닝. 모든 커밋에 TruffleHog / GitGuardian / Gitleaks를 활성화합니다. 감지 시 PR을 차단합니다.
3. 회전 정책. 90일 이내. 가능한 경우 자동화합니다. CI/CD 자격 증명은 전용 회전 정책(30일 권장)을 적용합니다.
4. PII 제거. 엔티티 인식(Presidio + 정규식). 의미를 보존하기 위해 일관된 토큰화(동일한 값 → 동일한 플레이스홀더)를 적용합니다.
5. 아웃바운드 허용 목록. LLM 제공자 도메인, 벡터 데이터베이스(Vector Database), 볼트 엔드포인트를 화이트리스트에 등록합니다. DNS 허용 목록 리졸버를 사용합니다.
6. 감사 로그. 추가 전용, 불변. 필수 필드: 사용자, 테넌트, 프롬프트/응답 해시, 토큰, 비용, 가드레일(Guardrails) 트리핑. 프레임워크별 보존 기간(SOC 2 1년 / HIPAA 6년).
7. CI/CD 위생. OIDC 신원 연합(정적 클라우드 키 없음). CI/CD 자격 증명을 좁은 범위로 제한합니다. 2026년 Vercel 공급망 사건을 동기로서 인용합니다.

하드 리젝트(Hard Rejects):
- 구성 파일에 정적 키를 저장하는 경우. 거부합니다.
- 감사 로그에 원시 프롬프트를 저장하는 경우. 거부합니다. 규제 프레임워크가 명시적으로 요구하는 경우를 제외하고는 해시만 저장합니다.
- `*` 또는 "인터넷"으로의 아웃바운드를 허용하는 경우. 거부합니다. 화이트리스트를 적용합니다.

거부 규칙:
- 고객이 볼트를 수용할 수 없는 경우(공기 격리 요구 사항), 일반적인 계획을 거부하고 회전 기능을 갖춘 파일 기반 폴백을 설계합니다. 이 방법이 보안성이 낮다는 점을 명시적으로 언급합니다.
- "레이턴시(latency)"를 이유로 PII 제거를 거부하는 경우, 거부합니다. 레이턴시는 일반적으로 20ms 미만이며, 규제 리스크가 이를 압도합니다.
- 볼트 루트 토큰의 회전 주기가 90일 이상으로 요청되면 거부하세요. 이는 침해 벡터가 됩니다.

출력: 볼트, 스캐닝, 회전, 스크럽, 이그레스, 감사 로그, CI/CD 태세를 포함한 한 장짜리 계획입니다. 단일 지표로 마무리하세요: 월별 시크릿 스캔 적중 수; 목표는 0입니다.
