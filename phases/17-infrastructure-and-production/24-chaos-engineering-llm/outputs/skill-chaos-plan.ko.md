스택 (Kubernetes / VM / 관리형), SLI/SLO 성숙도, 관측 가능성 품질, 팀 온콜 성숙도를 고려하여 카오스 계획을 작성해 보세요.

다음 내용을 작성합니다:

1. 선수 요건 점검. SLI/SLO가 정의되어 있는지, 관측 가능성이 연결되어 있는지, 롤백이 자동화되어 있는지, 런북이 구조화되어 있는지, 온콜 로테이션이 있는지 확인합니다. 하나라도 누락된 경우 프로덕션 카오스 실행을 거부합니다.
2. 4개 평면. 각 평면(제어, 대상, 안전, 관측 가능성)의 도구를 지정합니다. 관측 가능성은 17단계 · 13강을 참조합니다.
3. 세 가지 초기 실험. 포드 죽이기로 시작합니다. 그 다음 제공자 429 오류, 메모리 과부하 순서로 진행합니다. 각 실험에는 폭발 반경 상한, 지속 시간, 성공 기준을 설정합니다.
4. 안전 게이트. 소진율 (> 예상의 2배), 폭발 반경 (< 플릿의 30%), 추적 ID 태깅, 억제 윈도우.
5. 주기. 주간 작은 카나리 릴리스. 월간 게임 데이 (팀 간). 분기별 복원력 감사.
6. 도구. LitmusChaos (OSS, CNCF 졸업), Chaos Mesh (OSS, CNCF 샌드박스), Harness Chaos (상용 AI 지원), AWS FIS / Azure Chaos Studio (관리형 클라우드 네이티브).

거부 조건:
- 5가지 선수 요건 없이 프로덕션에서 카오스를 실행하는 경우. 거부합니다 — 실제 인시던트로 발전할 것입니다.
- 폭발 반경 상한이 없는 실험. 거부합니다.
- 추적 ID 태깅이 없는 실험. 거부합니다 — 알람 중복 제거가 불가능합니다.

거부 규칙:
- 팀이 스테이징에서 성공적인 실험을 한 번도 수행하지 않은 경우, 스테이징에서 하나를 성공적으로 완료할 때까지 프로덕션 카오스를 거부합니다.
- 인시던트 볼륨이 이미 높은 경우 (> 주당 2건), 추가 카오스를 거부합니다 — 먼저 안정화합니다.
- 팀에 SLO가 없는 경우, 모든 실험 전에 SLO를 요구합니다.

출력: 선수 요건 점검, 4개 평면 도구, 세 가지 초기 실험, 안전 게이트, 주기를 포함한 한 장짜리 계획. 분기별 의존성 맵 업데이트 약속으로 마무리합니다.
