작업 부하(엔드포인트, TTFT/TPOT/오류에 대한 SLA), 목표 규모(동시성, RPS), CI 태세(PR 게이트 또는 릴리스 전용)가 주어지면 부하 테스트 계획을 작성합니다.

다음 내용을 생성합니다:

1. 도구. 기본 실행에는 LLMPerf, CI 게이트에는 k6 + 스트리밍 확장, NVIDIA 참조 실행에는 GenAI-Perf, 대규모 합성 테스트에는 guidellm을 사용합니다. 이미 Locust를 사용 중이라면 LLM-Locust만 고려합니다.
2. 프롬프트 분포. 실제 트래픽(가능한 경우) 또는 공개된 분포(ShareGPT / HumanEval)에서 입력 토큰의 평균 + 표준 편차를 가져옵니다. 단일 프롬프트 반복 루프는 금지합니다.
3. 네 가지 패턴. 스테디, 램프, 스파이크, 소크. 각 패턴에 대해: 목표 RPS, 지속 시간, 예상 실패 모드.
4. CI 게이트. 특정 임계값: TTFT P95 < X, 5xx < 5%, TPOT < Y. PR당 실행 시간: 3-5분.
5. 메트릭 정합성. 보고 도구가 GenAI-Perf 스타일(ITL이 TTFT를 제외함)인지 LLMPerf 스타일(ITL이 TTFT를 포함함)인지 확인합니다. 하나를 선택하고 일관성을 유지합니다.
6. 출력. 저장소에 커밋된 스크립트 파일(k6 JS, LLMPerf CLI).

하드 리젝트:
- 균일한 프롬프트로 부하 테스트. 거부 — 수치가 거짓말을 합니다.
- 스트리밍 지원 없이 부하 테스트. 거부 — LLM 엔드포인트는 기본적으로 스트리밍합니다.
- 메트릭 정의 차이를 인정하지 않고 도구 간 수치를 비교. 거부.

거부 규칙:
- 팀이 LLM-Locust 확장 없이 Locust 스톡으로 실행하려는 경우 거부 — GIL 함정입니다.
- PR당 CI 게이트 예산이 60초 미만인 경우 전체 소크 테스트를 거부 — 빠른 스테디 상태와 별도의 나이트 소크 테스트를 제안합니다.
- 프롬프트 분포 데이터가 없는 경우, 문서화된 공개 분포(ShareGPT)를 요구하고 가정을 명시합니다.

출력: 도구, 프롬프트 분포, 목표가 있는 네 가지 패턴, CI 게이트 임계값, 메트릭 정합성을 포함한 한 페이지 계획. 모든 임계값을 충족하고 3회 실행 안정성이 확보될 때만 PR이 녹색이 되는 단일 CI 출력으로 마무리합니다.
