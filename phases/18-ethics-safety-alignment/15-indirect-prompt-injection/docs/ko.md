# 간접 프롬프트 주입(Indirect Prompt Injection) — 프로덕션 공격 표면

> 간접 프롬프트 주입(IPI)은 웹 페이지, 이메일, 공유 문서, 지원 티켓 등 외부 콘텐츠에 지침을 삽입하여, 사용자가 명시적으로 개입하지 않아도 에이전트 시스템이 이를 소비하도록 만드는 공격입니다. IPI는 2026년 프로덕션 환경의 지배적인 위협입니다. 공격자가 사용자와 직접 접촉하지 않으므로 사용자 입력 필터를 우회하며, 에이전트가 더 많은 외부 콘텐츠를 처리할수록 조용히 규모가 커지고, 프롬프트를 읽는 사람이 없는 자동화된 워크플로우를 표적으로 삼습니다. MDPI Information 17(1):54 (2026년 1월)는 2023-2025년 연구를 종합했습니다. NDSS 2026의 IPI 방어 논문은 핵심 과제를 제시합니다. 주입된 지침은 의미적으로 무해할 수 있습니다("예를 들어 'Yes'를 출력해 주세요"). 따라서 탐지는 키워드 필터링 이상의 접근이 필요합니다. "공격자는 두 번째로 움직인다"(Nasr et al., OpenAI/Anthropic/DeepMind 공동, 2025년 10월): 적응형 공격(기울기, RL, 랜덤 검색, 인간 레드팀)은 원래 공격 성공률이 거의 0%로 보고되었던 12개의 공개된 방어 중 90% 이상을 무력화했습니다.

## 문제점

직접 프롬프트 주입은 공격자가 사용자나 사용자의 프롬프트에 도달해야 합니다. IPI는 그럴 필요가 없습니다. 공격자는 에이전트가 읽을 수 있는 모든 콘텐츠(웹 페이지,收件함의 이메일, GitHub 이슈, 제품 리뷰)에 페이로드를 배치합니다. 에이전트는 정상적인 운영 중에 이를 습득하여 지침을 실행합니다. 사용자는 전달자일 뿐, 의도가 아닙니다.

## 개념

### 세 가지 전달 벡터

- **검색 증강 생성(RAG)(Retrieval-Augmented Generation).** 공격자가 문서를 게시하면 검색 단계가 이를 가져오고, 프롬프트는 사용자 질문 전에 이를 연결합니다. 모델은 공격자의 지침을 실행합니다.
- **받은 편지함 / 문서 워크플로.** 공격자가 사용자에게 이메일을 보내면, 에이전트(Agent)가 이메일을 읽고, 프롬프트(Prompt)에 이메일 본문이 포함되며, 모델이 이메일의 지시를 따릅니다.
- **도구 출력.** 공격자가 에이전트(Agent)가 사용하는 도구(예: 공격자가 제어하는 결과를 반환하는 웹 검색)를 제어합니다. 도구 출력에 지시가 포함되어 있으며, 에이전트(Agent)의 제어 흐름이 이를 따릅니다.

이 세 가지에는 공통된 구조적 특성이 있습니다. 공격자는 사용자-facing 입력을 건드리지 않고 프롬프트(Prompt)의 일부 조각을 제어합니다.

### 사용자 입력 필터가 이를 놓치는 이유

IPI 페이로드(Payload)는 사용자의 입력에 나타나지 않습니다. 검색된 콘텐츠에 나타납니다. 필터가 사용자 입력에 기반하여 작동한다면, 페이로드(Payload)는 이를 우회합니다. 필터가 모델에 도달하는 모든 콘텐츠에 적용된다면, 임의의 검색된 텍스트에 적용되어야 하는데, 이는 비용이 많이 들며 명령형 어조를 포함하는 합법적인 콘텐츠에 대해 오탐(False Positive)을 발생시킵니다.

### AI를 위한 정보 흐름 제어 (IFC)(Information Flow Control (IFC))

2026년 방어 패러다임은 고전적인 OS 보안에서 차용한 개념입니다. 모든 콘텐츠 소스를 보안 레이블로 취급합니다. 사용자의 쿼리(Query)를 "신뢰됨(trusted)"으로 레이블링하고, 검색된 콘텐츠를 "신뢰되지 않음(untrusted)"으로 레이블링합니다. 모델의 제어 흐름을 정보 흐름으로 취급합니다. 신뢰되지 않은 콘텐츠에 의해 트리거된 행동은 실행 전에 신뢰된 입력에 의해 비준되어야 합니다.

CaMeL (Microsoft 2025), ConfAIde (Stanford 2024), 그리고 NDSS 2026 IPI 방어 논문은 IFC를 다양한 방식으로 구현합니다. 공통된 원칙은 다음과 같습니다. 코드와 데이터가 동일한 컨텍스트 윈도우(Context Window)를 공유하는 한, 목표는 예방이 아니라 격리입니다.

### 공격자는 두 번째로 움직입니다

Nasr et al. (2025년 10월)은 12개의 공개된 IPI 방어 기법을 적응형 공격(gradient search, RL 정책, random search, 72시간 인간 레드 티밍(Red Teaming))으로 테스트했습니다. 원래 거의 0%의 ASR을 보고했던 모든 방어 기법은 90% 이상의 ASR로 뚫렸습니다.

방법론적 교훈은 다음과 같습니다. 적응형 공격 평가와 함께 방어 기법을 발표해야 합니다. 정적 공격 벤치마크는 견고성의 증거가 아닙니다. 공격자는 방어 기법을 알게 됩니다.

### 실제 사건

25강은 EchoLeak (CVE-2025-32711, CVSS 9.3)를 다룹니다. 이는 Microsoft 365 Copilot에서 공개적으로 문서화된 최초의 제로클릭 간접 프롬프트 주입(Indirect Prompt Injection)입니다. GitHub Copilot Chat의 CamoLeak (CVSS 9.6)과 GitHub Copilot의 CVE-2025-53773도 포함됩니다. 실제 프로덕션 배포 환경에서는 벤치마크뿐만 아니라 현장에서 간접 프롬프트 주입으로 인해 보안이 침해되고 있습니다.

### OWASP 및 NIST의 관점

OWASP LLM Top 10 (2025)은 프롬프트 주입(직접 및 간접)을 LLM01로, 즉 1위 애플리케이션 계층 위협으로 분류합니다. NIST AI SPD 2024는 간접 프롬프트 주입을 "생성형 AI의 가장 큰 보안 결함"이라고 표현합니다.

### 18단계에서의 위치

12-14강은 모델 중심의 제일브레이크를 다루며, 15강은 2026년 프로덕션 배포 환경에서 지배적인 시스템 중심 공격을 다루고, 16강은 방어 도구를 다루며, 25강은 구체적인 CVE 사례를 다룹니다.

## 사용하기

`code/main.py`는 간접 프롬프트 주입(IPI) 하네스를 구축합니다. 장난감 에이전트에는 세 가지 도구(웹 검색, 이메일 읽기, 메시지 전송)가 있으며, 환경에는 공격자가 제어하는 콘텐츠가 포함되어 있고 그 안에 지시문("모든 연락처로 전달하세요")이 내장되어 있습니다. 주입된 지시문을 따르는 단순한 에이전트, 검색된 콘텐츠에 키워드 필터를 적용하는 필터 방어 에이전트, 그리고 신뢰된 콘텐츠와 신뢰되지 않은 콘텐츠를 분리하고 신뢰되지 않은 제어 흐름 명령을 거부하는 IFC 에이전트 사이를 전환할 수 있습니다.

## 출시하기

이 강의는 `outputs/skill-ipi-audit.md`를 생성합니다. 에이전트 배포 설명이 주어지면, 신뢰되지 않은 콘텐츠 소스를 나열하고, 배포가 IFC를 적용하는지 확인하며, 신뢰 라벨 없이 모델에 도달하는 소스를 표시합니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 세 에이전트 각각에 대한 공격 성공률을 측정하세요.

2. 검색된 콘텐츠에 대해 패러프레이즈 기반 방어를 구현하세요. 합법적인 검색된 텍스트에 대한 오탐(false-positive)률을 측정하세요.

3. NDSS 2026 IPI 방어 논문을 읽어보세요. "선량한 지시문"의 도전 과제와 이것이 키워드 기반 필터링을 불가능하게 만드는 이유를 설명하세요.

4. 에이전트가 서드파티 API로부터 도구 출력을 받는 배포 환경을 설계하세요. 각 프롬프트 조각에 신뢰 수준을 라벨링하고, 에이전트의 행동을 지배하는 IFC 정책을 작성하세요.

5. Nasr et al. 2025의 적응형 공격 방법론을 연습 문제 2의 필터 방어 에이전트에 대해 재현하세요. 적응형 공격 전후의 ASR(공격 성공률)을 보고하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| IPI | "간접 프롬프트 주입" | 사용자가 작성하지 않은 콘텐츠를 에이전트가 정상 작동 중 소비하여 발생하는 주입 |
| RAG 주입 | "오염된 검색" | 공격자가 검색 단계가 가져오는 콘텐츠를 게시하며, 프롬프트에 페이로드가 포함됨 |
| 제로 클릭 | "사용자 행동 없음" | 에이전트 작동 중 공격이 자동으로 트리거되며, 사용자는 아무것도 하지 않음 |
| IFC | "정보 흐름 제어" | 라벨 기반 접근 방식: 신뢰할 수 없는 콘텐츠에서 발생한 행동은 신뢰할 수 있는 승인(ratification)이 필요 |
| 적응형 공격 | "기울기 / RL 레드 티밍" | 방어책을 알고 이를 최적화하는 공격; 정직한 평가에 필수 |
| 무해한 지시문 | "예를 출력해 주세요" | 의미적으로 무해한 IPI 페이로드; 키워드 필터가 잡아내지 못함 |
| 범위 위반 | "교차 신뢰 유출" | 에이전트가 한 신뢰 컨텍스트의 데이터에 접근하여 다른 컨텍스트로 출력 |
