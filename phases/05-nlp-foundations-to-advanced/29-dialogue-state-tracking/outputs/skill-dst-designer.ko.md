사용 사례(도메인, 언어, 어휘 개방성, 컴플라이언스 요구 사항)가 주어지면 다음을 출력합니다:

1. 스키마. 도메인 목록, 도메인별 슬롯, 슬롯별 개방형 vs 폐쇄형 어휘.
2. 추출기. 규칙 기반 / seq2seq / LLM-with-Pydantic. 이유.
3. 업데이트 정책. 전체 상태 재생성 / 증분 업데이트; 수정 처리; 부정 처리.
4. 평가. 보존된 대화 세트에 대한 Joint Goal Accuracy, 슬롯 수준 정밀도/재현율, 가장 어려운 슬롯에서의 혼동.
5. 확인 흐름. 사용자에게 명시적으로 확인을 요청해야 하는 시점(파괴적 작업, 낮은 신뢰도의 추출).

규칙 기반의 보조 검사가 없는 경우, 컴플라이언스에 민감한 슬롯에 대해 LLM 전용 DST를 거부합니다. 사용자가 수정할 때 슬롯을 롤백할 수 없는 DST는 거부합니다. 버전 태그가 없는 스키마는 플래그를 지정합니다.
