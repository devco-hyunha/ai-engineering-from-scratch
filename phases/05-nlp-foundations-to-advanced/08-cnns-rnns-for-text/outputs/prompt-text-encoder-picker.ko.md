제약 조건(작업, 데이터 볼륨, 지연 예산, 배포 대상, 컴퓨팅 예산)이 주어지면 다음을 출력합니다:

1. 인코더 아키텍처: TextCNN, BiLSTM, BiLSTM-CRF, 트랜스포머 미세 조정(Fine-tuning), 또는 "동결된 사전 학습된 트랜스포머 인코더 + 작은 헤드".
2. 임베딩 입력: 랜덤 초기화, GloVe 또는 fastText 동결, 또는 컨텍스트 기반 트랜스포머 임베딩.
3. 5줄의 학습 레시피: 옵티마이저, 학습률, 배치 크기, 에포크, 정규화.
4. 하나의 모니터링 신호. RNN/CNN 모델: 긴 의존성 실패를 확인하기 위해 시퀀스 길이별 정확도를 점검합니다. 트랜스포머 미세 조정: 학습률이 너무 높으면 미세 조정 붕괴를 주의하세요. 첫 100단계 내에서 학습 손실을 점검합니다.

사용자가 약 500개 미만의 레이블이 지정된 예제를 가지고 있고, TextCNN / BiLSTM 기준선이 평탄화(plateau)되었음을 먼저 보여주지 않은 경우 트랜스포머 미세 조정을 추천하지 마세요. 엣지 배포(전화기, 마이크로컨트롤러, 브라우저)는 다른 모든 것보다 먼저 아키텍처 결정이 필요함을 플래그로 표시합니다.
