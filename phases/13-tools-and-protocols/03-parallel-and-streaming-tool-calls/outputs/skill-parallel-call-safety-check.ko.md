도구 레지스트리(이름, 설명, 실행기가 포함된 도구 목록)가 주어지면 `parallel_safe: bool`, `ordering_deps: [tool_name]`, `rate_limit_group: name` 필드가 추가된 주석 처리된 복사본을 반환합니다.

다음 내용을 생성합니다:

1. 도구별 분류. 각 도구에 대해 결정하세요: 같은 턴 내에서 병렬 실행이 안전한지(순수 읽기, 서로 다른 자원), 안전한지 아닌지(변경, 공유 자원, 외부 속도 제한).
2. 의존성 그래프. 한 도구의 출력이 다른 도구의 입력으로 전달되어야 하는 쌍을 식별합니다. 같은 턴 내에서 병렬화할 수 없습니다. `ordering_deps`로 표시하세요.
3. 속도 제한 그룹화. 동일한 다운스트림 API를 호출하는 도구는 하나의 그룹을 공유합니다. 호스트는 도구별이 아닌 그룹별 동시성을 제한해야 합니다.
4. 안전 권장 사항. 각 안전하지 않은 도구에 대해 해당 턴의 병렬 실행을 비활성화할지, 큐에 넣을지, 자원에 따라 샤딩할지 명시하세요.
5. 제공자별 플래그. 안전하지 않은 도구가 세트에 포함된 경우 OpenAI에서는 `parallel_tool_calls=false`, Anthropic에서는 `disable_parallel_tool_use=true`를 권장합니다.

하드 거부:
- 감사 후 분류가 없는 레지스트리는 거부합니다. 기본 거부 정책; 알 수 없는 것은 안전하지 않은 것으로 간주합니다.
- 공유 자원에서의 쓰기 경로 도구가 `parallel_safe: true`로 표시된 경우 거부합니다. 경쟁 조건(Race conditions)이 발생합니다.
- 속도 제한이 있는 외부 API를 호출하는 도구가 `rate_limit_group` 없이 존재하는 경우 거부합니다.

거부 규칙:
- 검토 없이 모든 도구를 병렬 안전(parallel-safe)으로 표시하라는 요청을 받으면 거부하세요.
- 레지스트리에 동일한 자원에서의 중대한 도구(동일 경로에서의 `delete_file` 및 `write_file`)가 포함된 경우, 병렬화를 거부하고 샌드박스 수준의 직렬화를 위해 14단계 · 09강으로 안내하세요.
- 사용자가 자신의 도구는 절대 경쟁 조건이 발생하지 않는다고 주장하면 거부하고 증거(테스트, 로그, 또는 형식적 논증)를 요청하세요. 경쟁 조건은 프로덕션 환경에서 조용히 발생합니다.

출력: 각 도구에 세 개의 새 필드가 포함된 JSON 형식의 수정된 레지스트리, 그 뒤에 가장 위험한 병렬화 선택과 권장 완화 조치를 명시한 짧은 요약이 따라옵니다. 현재 턴에 대한 권장 `tool_choice` 재지정(override)으로 마무리하세요.
