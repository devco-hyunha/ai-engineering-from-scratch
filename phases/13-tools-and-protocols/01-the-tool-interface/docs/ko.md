# 도구 인터페이스 — 에이전트가 구조화된 입출력을 필요로 하는 이유

> 언어 모델은 토큰을 생성합니다. 프로그램은 행동을 취합니다. 이 둘 사이의 간극이 바로 도구 인터페이스입니다. 모델이 행동을 요청하고 호스트가 이를 실행할 수 있게 해주는 계약입니다. 2026년 스택 — OpenAI, Anthropic, Gemini의 함수 호출; MCP의 `tools/call`; A2A의 작업 부분 — 모두 동일한 4단계 루프의 다른 인코딩입니다. 이 강의에서는 루프를 정의하고 이를 실행하기 위한 최소한의 메커니즘을 보여줍니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, LLM 없음)
**선수 요건:** 11단계 (LLM 완료 API)
**시간:** 약 45분

## 학습 목표

- 텍스트만 생성할 수 있는 LLM이 왜 그 자체로 실제 세계에 대한 행동을 취할 수 없는지 설명해 보세요.
- 4단계 도구 호출 루프(설명 → 결정 → 실행 → 관찰)를 그리고 각 단계를 누가 담당하는지 지정해 보세요.
- 도구 설명을 세 부분으로 작성해 보세요: 이름, JSON Schema 입력, 결정론적 실행 함수.
- 순수 도구와 사이드 이펙트 도구를 구분하고, 이 구분이 안전성에 왜 중요한지 설명해 보세요.

## 문제점

LLM은 다음 토큰에 대한 확률 분포를 방출합니다. 이것이 전체 출력 표면입니다. 채팅 모델에게 "지금 벵갈루루의 날씨는 어떤가요?"라고 물으면, 그럴듯한 문장을 작성할 수 있지만 날씨 API에 연결할 수는 없습니다. 그 문장은 우연히 맞을 수도 있고, 3일 지난 정보일 수도 있습니다.

이 간극을 메우는 것이 도구 인터페이스의 목적입니다. 호스트 프로그램 — 에이전트 런타임, Claude Desktop, ChatGPT, Cursor, 또는 커스텀 스크립트 — 모델에게 호출 가능한 도구 목록을 광고합니다. 모델은 행동이 필요하다고 결정하면 도구와 그 인수를 지정하는 구조화된 페이로드를 방출합니다. 호스트는 그 페이로드를 파싱하여 도구를 실제로 실행하고 결과를 피드백합니다. 모델이 더 이상의 호출이 필요 없다고 결정할 때까지 루프가 계속됩니다.

이 계약의 첫 번째 버전은 2023년 6월 OpenAI의 "functions" 매개변수로 출시되었습니다. Anthropic은 Claude 2.1에서 `tool_use` 블록을 따랐습니다. Gemini는 몇 달 후 `functionDeclarations`을 추가했습니다. 모든 제공자는 이제 동일한 형태를 노출합니다: JSON-Schema 타입의 도구 목록이 입력되고, JSON 페이로드 도구 호출이 출력됩니다. Model Context Protocol (2024년 11월)은 계약이 일반화되어 하나의 도구 레지스트리가 모든 모델을 서비스하도록 했습니다. A2A (2026년 4월, v1.0)는 에이전트 간 위임에 동일한 프리미티브를 계층화했습니다.

4단계 루프는 이 모든 것의 밑에 있는 불변 조건입니다. 13단계의 나머지 모든 내용은 이를 상세화한 것입니다.

## 개념

### 1단계: 설명

호스트는 각 도구를 세 가지 필드로 선언합니다.

- **이름.** 안정적이고 기계가 읽을 수 있는 식별자. `get_weather`, "weather thing"가 아닙니다.
- **설명.** 한 단락의 자연어 요약. "사용자가 특정 도시의 현재 조건에 대해 물어볼 때 사용하세요. 역사적 데이터에는 사용하지 마세요."
- **입력 스키마.** 도구의 인수를 설명하는 JSON Schema 객체 (draft 2020-12).

모델은 목록을 받습니다. 현대의 제공자들은 제공자별 템플릿을 사용하여 이 선언들을 시스템 프롬프트로 직렬화하므로, 호출자로서는 구조화된 형태만 다루면 됩니다.

### 2단계: 결정

사용자의 메시지와 사용 가능한 도구가 주어지면, 모델은 세 가지 행동 중 하나를 선택합니다.

1. **텍스트로 직접 답변.** 도구 호출 없음.
2. **하나 이상의 도구를 호출.** 구조화된 호출 객체를 방출합니다. `parallel_tool_calls: true` (OpenAI와 Gemini에서 기본 활성화, Anthropic에서 선택적 활성화) 하에서는 모델이 한 턴에서 여러 호출을 방출할 수 있습니다.
3. **거부.** 엄격 모드 구조화된 출력은 호출 대신 타입이 지정된 `refusal` 블록을 생성할 수 있습니다.

도구 호출 페이로드에는 세 가지 안정적 필드가 있습니다: 호출 `id`, 도구 `name`, 그리고 JSON `arguments` 객체. id는 호스트가 나중에 결과를 특정 호출과 상관관계 지을 수 있도록 존재하며, 병렬 호출이 순서대로 돌아오지 않을 때 중요합니다.

### 3단계: 실행

호스트는 호출을 수신하고, 선언된 스키마와 인자를 검증한 뒤 실행기를 실행합니다. 인자가 유효하지 않다는 것은 모델이 필드를 환각(Hallucination)하거나 잘못된 타입을 사용했다는 뜻이며, 이는 약한 모델에서 매우 흔한 실패 모드입니다. 프로덕션 호스트는 유효하지 않은 인자에 대해 세 가지 중 하나를 수행합니다: 즉시 실패하여 오류를 모델에 노출하거나, 제약 디코딩(제약 디코딩) 파서로 JSON을 복구하거나, 검증 오류를 프롬프트에 포함하여 모델을 재시도합니다.

실행기 자체는 일반적인 코드입니다. Python, TypeScript, 셸 명령, 데이터베이스 쿼리 등입니다. 실행기는 결과를 생성하며, 이 결과는 보통 문자열이지만 JSON 값이나 구조화된 콘텐츠 블록(MCP의 텍스트, 이미지, 리소스 참조)일 수도 있습니다. 결과는 직렬화 가능해야 합니다.

### 4단계: 관찰하기

호스트는 도구 결과를 대화에 추가합니다(일치하는 `id`를 가진 `tool` 역할 메시지로)하고 모델을 다시 호출합니다. 모델은 이제 컨텍스트에 도구 출력을 포함하고 있으며, 최종 답변을 생성하거나 추가 호출을 요청할 수 있습니다. 모델이 호출을 더 이상 생성하지 않거나 호스트가 반복 횟수에 대한 안전 게이트(안전 게이트) 한도에 도달할 때까지 이 과정이 계속됩니다.

### 신뢰 경계(Trust Boundary) 분리

도구는 안전에 중요한 두 가지 유형이 있습니다.

- **순수(Pure).** 읽기 전용, 결정적, 사이드 효과 없음. `get_weather`, `search_docs`, `get_current_time`. 추론적으로 호출해도 안전합니다.
- **결과적(Consequential).** 상태를 변경하고, 비용을 지출하며, 사용자 데이터를 건드립니다. `send_email`, `delete_file`, `execute_trade`. 게이트가 필요합니다.

Meta의 2026년 에이전트 보안 "Rule of Two"는 단일 턴이 신뢰할 수 없는 입력, 민감한 데이터, 결과적 행동 중 최대 두 가지만 결합할 수 있다고 규정합니다. 도구 인터페이스는 이 규칙을 강제하는 지점입니다 — 호출을 거부하거나, 사용자 확인을 요구하거나, 범위를 격상하는 방식으로요. 전체 보안 장은 13단계 · 15강을, 에이전트 수준 권한 정책은 14단계 · 09강을 참조하세요.

### 루프가 존재하는 위치

| 컨텍스트 | 누가 설명하는가 | 누가 결정하는가 | 누가 실행하는가 |
|---------|---------------|-------------|--------------|
| 단일 턴 함수 호출(Function Calling) (OpenAI/Anthropic/Gemini) | 앱 개발자 | LLM (대규모 언어 모델)(LLM (Large Language Model)) | 앱 개발자 |
| MCP (모델 컨텍스트 프로토콜)(MCP (Model Context Protocol)) | MCP 서버 | MCP 클라이언트를 통한 LLM (대규모 언어 모델)(LLM (Large Language Model)) | MCP 서버 |
| A2A | 에이전트 카드 발행자 | 호출하는 에이전트(Agent) | 호출된 에이전트(Agent) |
| 웹 브라우저 (함수 호출(Function Calling) 에이전트(Agent)) | 브라우저 확장 프로그램 / WebMCP | LLM (대규모 언어 모델)(LLM (Large Language Model)) | 브라우저 런타임 |

어디서나 동일한 네 단계입니다. 열 이름은 바뀌지만, 구조는 변하지 않습니다.

### 왜 모델에게 JSON을 출력하도록 프롬프트하지 않을까요?

"모델이 JSON으로 응답하도록 요청하는 것"은 함수 호출(function calling) 이전의 패턴이었습니다. 프론티어 모델에서는 약 5~15%의 확률로 실패하며, 더 작은 모델에서는 훨씬 더 자주 실패합니다. 실패 모드에는 중괄호 누락, 후행 쉼표, 환각된 필드, 잘못된 타입 등이 포함됩니다. 이후 JSON 복구 패스, 재시도, 또는 제약 디코딩(제약 디코딩)이 필요합니다.

네이티브 함수 호출(native function calling)은 세 가지 이유로 더 좋습니다. 첫째, 제공자는 모델이 정확한 호출 형태에 대해 엔드투엔드(end-to-end)로 학습하므로, 엄격 모드(strict mode)에서 유효 JSON 비율이 98~99%로 상승합니다. 둘째, 호출 페이로드(payload)는 자유 텍스트(free-text) 내부가 아닌 자체 프로토콜 슬롯에 위치하므로, 도구 호출(tool call)이 사용자 가시 응답(user-visible reply)으로 유출되지 않습니다. 셋째, 제공자는 제약 디코딩(제약 디코딩)을 통해 스키마 준수를 강제합니다 (OpenAI의 strict mode, Anthropic의 `tool_use`, Gemini의 `responseSchema`). 출력은 검증이 보장됩니다.

13단계 · 02강은 세 제공자 API를 나란히 살펴봅니다. 13단계 · 04강은 구조화된 출력(structured outputs)에 대해 깊이 있게 다룹니다.

### 서킷 브레이커(Circuit breakers)

루프(loop)는 모델이 호출을 더 이상 생성하지 않거나 호스트가 최대 턱(turn) 수에 도달하면 종료됩니다. 프로덕션 호스트는 이를 5~20 턱으로 설정합니다. 그 이상은 모델이 벗어날 수 없는 루프에 거의 확실히 빠져 있습니다. Claude Code는 기본값이 20, OpenAI Assistants는 10, Cursor의 에이전트 모드(agent mode)는 25입니다.

대안인 무한 루프(unbounded loops)는 "에이전트가 밤새 API 호출에 $400를 사용했다"는 사후 분석(post-mortem)으로 6개월마다 나타납니다. 상한(bound) 없이 출시하지 마세요.

14단계 · 12강은 오류 복구(error recovery)와 자가 치유(self-healing)를 깊이 다루며, 17단계는 프로덕션 속도 제한(rate limits)을 다룹니다.

### 13단계의 다음 방향

- 02강부터 05강은 제공자 수준의 도구 호출(tool-call) 표면을 다듬습니다.
- 06강부터 14강은 루프(loop)를 MCP로 일반화합니다.
- 15강부터 18강은 루프(loop)를 적대적 서버, 적대적 사용자, 인증되지 않은 원격 인증 표면(remote auth surfaces)에 대해 방어합니다.
- 19강부터 22강은 에이전트 간 협업(agent-to-agent collaboration), 관측 가능성(observability), 라우팅(routing), 패키징(packaging)으로 패턴을 확장합니다.
- 23강은 모든 프리미티브(primitive)를 사용하여 완전한 생태계(ecosystem)를 출시합니다.

나머지 모든 강의는 이 4단계 루프의 상세한 설명입니다. 이 루프를 불변 조건으로 염두에 두세요.

## 사용하기

`code/main.py`는 LLM 없이 4단계 루프를 실행합니다. 가짜 "결정자(decider)" 함수가 사용자 메시지의 패턴 매칭으로 모델을 시뮬레이션하며, 실행기(executor), 스키마 검증기, 관찰 단계 하네스는 실제 구현입니다. 이를 실행하여 인쇄 가능한 중간 상태와 함께 전체 요청/응답 흐름을 확인한 후, 이후 강의에서 가짜 결정자를 실제 제공자로 교체하세요.

확인할 사항:

- 도구 레지스트리는 각 도구마다 세 필드를 가집니다: 이름, 설명, 스키마, 실행기 참조.
- 검증기는 표준 라이브러리만으로 작성된 최소한의 JSON Schema 하위 집합(타입, 필수 필드, enum, min/max)입니다. 13단계 · 04강에서는 더 완전한 검증기를 제공합니다.
- 루프는 반복 횟수를 5로 제한합니다. 프로덕션 에이전트에는 정확히 이런 종류의 서킷 브레이커가 필요합니다.

## 출시하기

이 강의는 `outputs/skill-tool-interface-reviewer.md`을 생성합니다. 초안 도구 정의(이름 + 설명 + 스키마 + 실행기 개요)가 주어지면, 이 스킬은 루프 적합성을 감사합니다: 이름이 기계적으로 안정적인지, 설명이 완전한 사용 지침인지, 스키마가 JSON Schema 2020-12를 올바르게 사용하는지, 순수(pure) 대 순차적(consequential) 분류가 명시적인지 확인합니다.

## 연습 문제

1. `code/main.py`에 `get_stock_price(ticker)`라는 네 번째 도구를 추가하세요. 그 설명을 "사용자가 티커로 현재 주가를 요청할 때 사용하세요. 역사적 주가나 시장 요약에는 사용하지 마세요."로 작성하세요. 하네스를 실행하고 가짜 결정자가 티커를 언급하는 쿼리를 새 도구로 라우팅하는지 확인하세요.

2. 스키마 검증기를 망가뜨리세요. `arguments` 객체가 필수 필드를 누락한 호출을 전달하고, 실행 전에 호스트가 이를 거부하는지 확인하세요. 그런 다음 알 수 없는 추가 필드가 있는 호출을 전달하세요. 결정하세요: 호스트가 거부해야 할까요, 무시해야 할까요? 안전 논거로 선택을 정당화하세요.

3. 하네스의 각 도구를 순수(pure) 또는 순차적(consequential)으로 분류하세요. `consequential: true` 플래그가 필요한 레지스트리 항목에 이를 추가하고, 순차적 도구가 선택될 때마다 "사용자 확인이 필요합니다"라는 라인을 출력하도록 루프를 수정하세요. 이는 모든 프로덕션 호스트가 필요로 하는 확인 게이트의 형태입니다.

4. 위 제공자 열 표에 선호하는 클라이언트(Claude Desktop, Cursor, ChatGPT 또는 맞춤형 스택)의 내용을 채워 네 단계 루프를 종이에 그려 보세요. 13단계 · 06강의 MCP 전용 변형과 교차 참조해 보세요.

5. OpenAI의 함수 호출 가이드를 처음부터 끝까지 읽어 보세요. 여기서 제시된 네 단계 루프에는 포함되지 않지만 요청에는 있는 필드 하나를 식별해 보세요. 그 필드가 무엇을 더하는지, 그리고 필수적인 요소가 아닌 편리한 요소인 이유를 설명해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 도구 | "모델이 호출할 수 있는 것" | 이름 + JSON-Schema 타입 입력 + 실행 함수의 삼중 구조 |
| 함수 호출 | "네이티브 도구 사용" | 산문 대신 구조화된 도구 호출을 방출하기 위한 제공자 수준의 API 지원 |
| 도구 호출 | "모델의 행동 요청" | 모델이 방출하는 `id`, `name`, `arguments`을 포함하는 JSON 페이로드 |
| 도구 결과 | "도구가 반환한 것" | 일치하는 id를 가진 `tool` 역할 메시지로 감싼 실행자의 출력 |
| 병렬 도구 호출 | "한 번에 여러 호출" | 하나의 모델 턴에서 독립적이며 id로 순서화할 수 있는 여러 호출 객체 |
| 엄격 모드 | "보장된 JSON" | 모델의 출력이 선언된 스키마를 검증하도록 강제하는 제약 디코딩 |
| 순수 도구 | "읽기 전용 도구" | 사이드 효과가 없음; 안전하게 재실행 가능 |
| 결과 도구 | "행동 도구" | 외부 상태를 변경함; 게이트, 감사 또는 사용자 확인이 필요 |
| 네 단계 루프 | "도구 호출 사이클" | describe → decide → execute → observe |
| 호스트 | "에이전트 런타임" | 도구 레지스트리를 유지하고, 모델을 호출하며, 실행자를 실행하는 프로그램 |
