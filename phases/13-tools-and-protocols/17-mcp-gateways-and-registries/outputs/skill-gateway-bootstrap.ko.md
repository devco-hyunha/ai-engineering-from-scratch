클라이언트, 백엔드, 인증 요구 사항 및 컴플라이언스 제약 조건을 고려하여 게이트웨이 설계를 작성해 보세요.

## 필수 입력

- 공개 게이트웨이 리소스 URI, 허용된 프로토콜 개정 및 전송 방식.
- 인증된 주체 및 역할 모델.
- 백엔드 엔드포인트, 발급자, 리소스, 레지스트리 레코드, 게시자 증거 및 승인된 설명자.
- 도구 가시성, 인자 정책, 비용 클래스 및 데이터 민감도.
- 스트리밍, 변경 알림, MRTR (다중 왕복 요청)(Multi Round-Trip Request) 및 Tasks 요구 사항.
- 감사, 보존, 추적 및 편집(redaction) 요구 사항.

## 산출물

1. 상태 비저장 진입점. 하나의 POST 엔드포인트, 요청별 버전 및 기능, 일치하는 method 및 name 헤더, JSON 또는 요청 범위 SSE, 그리고 최신 GET 및 DELETE에 대한 405 응답. 버전 지원 전에 헤더 일치성을 검증하세요. HTTP 400 `-32020`, 지원 및 요청된 데이터가 포함된 정확한 HTTP 400 `-32022`, HTTP 404 `-32601`, 선택적 오류 데이터 직렬화 및 202 빈 본문 알림 처리를 지정하세요.
2. 발견 계획. 게이트웨이 `server/discover`을 구현하고, 각 백엔드를 발견하며, 안전한 종단 간 기능 교집합만 노출하고, 현재 `resultType`, `ttlMs`, `cacheScope` 및 서버 식별자 메타데이터를 포함하세요.
3. 수용 테이블. 공식 레지스트리 `server.json` 게시 형식과 `com.example/*` 스타일 이름을 보안 수용과 별도로 검증하세요. 모든 백엔드에 대해, 레코드를 외부 검증된 게시자 네임스페이스, 출처 소스, 엔드포인트, 버전 정책, 설명자 다이제스트, 발급자, 리소스, 승인 및 만료 상태와 결합하세요.
4. 네임스페이스 맵. 모든 백엔드 도구에 안정적인 자격이 부여된 공개 이름을 부여하고, 모든 `tools/list` 설명자에서 유효한 객체 루트 `inputSchema`을 유지하세요. 순서에 의한 충돌을 거부하세요.
5. 인증 매트릭스. 주체와 역할을 공개 도구, 리소스, 인자 및 범위에 매핑하세요. 외부 및 백엔드 자격 증명을 분리하고 발급자 바인딩을 유지하세요.
6. 전송 계약. 새로운 독립적인 백엔드 요청을 구축하고, 중개된 클라이언트 기능만 광고하며, 백엔드 결과를 검증하고, 추적 상관관계를 유지합니다.
7. 캐시 계획. 주체별 발견 및 목록을 비공개로 설정합니다. 제한된 TTL 및 무효화 동작을 설정합니다.
8. 속도 및 감사 정책. 주체, 발급자, 리소스, 도구, 비용 클래스 및 시간별로 제한을 설정합니다. 자격 증명 및 불필요한 민감한 인수를 마스킹합니다.
9. 인터랙션 라우팅. 요청 범위 SSE, `subscriptions/listen` 확인 및 재연결 동작, 바이트 단위 정확한 MRTR 상태 전송, `Mcp-Name`의 작업 ID별 Tasks 라우팅을 설명합니다.
10. 전송 어댑터. 게이트웨이가 파싱된 요청 및 헤더를 수신하는 경우, 이를 프로세스 내 프로토콜 모델로 지정하고 JSON Content-Type 및 JSON 및 SSE Accept 강제 적용을 위해 09강과 연결합니다.
11. 호환성 어댑터. 이전 초기화, 세션 ID, GET 스트림, 리소스 구독 및 실험적 작업 메서드를 최신 게이트웨이 코어와 분리합니다.

## 하드 거부

- 2026-07-28에 필수인 것으로 제시되는 세션 친화성, 세션 저장소 또는 세션 ID 재작성.
- 수입 증거 없이 레지스트리 존재 여부나 표시 이름을 신뢰하는 것.
- 재승인 없이 조용한 도구 충돌이나 설명자 고정 업데이트.
- 백엔드에서 외부 베어러 토큰을 재사용하거나 다른 발급자나 리소스에서 백엔드 토큰을 사용하는 것.
- 주체 필터링된 목록의 공개 캐싱.
- 독립적인 최신 GET 이벤트 스트림, Last-Event-ID 재생 또는 리소스 구독 메서드.
- 새로운 `tasks/list` 또는 `tasks/result` 동작.
- 제거된 프로토콜 세션만으로 키가 지정된 속도 제한.
- 분리된 검증된 수입 및 출처 상태 대신 `server.json` 내부에서 발명된 보안 검증.
- `inputSchema`를 생략한 네임스페이스 도구 설명자.

## 출력 형식

Ingress, Discovery, Admission, Namespace Map, Authorization, Forwarding, Cache, Rate Limits, Audit, Interactions 및 Legacy Adapter라는 섹션을 반환합니다. 가장 강력한 수용 테스트가 필요한 단일 라우트로 마무리합니다.
