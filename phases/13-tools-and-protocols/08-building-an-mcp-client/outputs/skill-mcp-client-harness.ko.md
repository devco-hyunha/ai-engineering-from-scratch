MCP 서버 전송 목록이 주어지면, MCP `2026-07-28`를 선호하고 레거시 호환성을 격리하는 클라이언트 하네스를 생성합니다.

생성 대상:

1. 피어 구성. 안정적인 서버 이름을 고정된 명령이나 엔드포인트, 인자, 환경 허용 목록, 인증 컨텍스트, 전송 유형 및 기본값이 false인 명시적인 `allow_legacy` 플래그에 매핑합니다.
2. 최신 요청 빌더. 직렬화 직전에 모든 `params._meta`에 프로토콜 버전, 현재 클라이언트 기능 및 권장되는 클라이언트 식별자를 포함합니다.
3. stdio 시대 프로브. `server/discover`를 먼저 전송합니다. 유효한 DiscoverResult를 수락하고, 상호 지원되는 최신 버전으로 `-32022`를 재시도하며, `-32020`와 `-32021`를 수정 가능한 최신 오류로 취급합니다.
4. 레거시 호환성 프로브. 인식되지 않는 오류, 시간 초과, 연결 종료 또는 빈 응답을 모호한 상태로 취급합니다. 해당 피어가 정확히 `allow_legacy: true`를 가진 경우에만 마감 시간이 지정된 `initialize`를 한 번 전송합니다. 구성된 레거시 개정판, 객체 기능 및 비어 있지 않은 서버 식별자를 포함하는 상관된 JSON-RPC 성공이 확인된 후에만 레거시를 선택합니다. 그렇지 않으면 안전하게 실패합니다(fail closed).
5. 도구 캐시. 협상된 인증 컨텍스트에서 `ttlMs`와 `cacheScope`를 준수합니다. 누락된 레거시 `resultType`는 `"complete"`로 취급합니다.
6. 네임스페이스 병합. 피어와 도구를 정렬합니다. 충돌에 대해 접두사를 붙이거나 거부합니다. 조용한 덮어쓰기를 금지합니다.
7. 라우터. 표준 도구 이름을 피어 및 로컬 이름에 매핑하고, 새로운 요청 ID를 생성하며, 시대별 올바른 요청을 전송하고, 응답 ID를 검증합니다.
8. 복구. 전송 손실 시 진행 중인 작업을 실패 처리하고, 재시작하거나 재연결하며, 발견 및 목록을 반복하고, 구독을 다시 열며, 안전 정책에 허용된 작업만 재시도합니다.

하드 거부:

- 현재 `_meta` 없이 최신 요청을 전송하는 것.
- 인식된 최신 오류 후 초기화로 폴백하는 것.
- 레거시 호환성을 위해 명시적으로 허용 목록에 포함되지 않은 피어에 `initialize`를 전송하는 것.
- 타임아웃, 연결 종료, 빈 응답, 인식되지 않는 오류, 형식이 잘못된 결과, 지원되지 않는 리비전을 레거시 동작의 증거로 취급하는 것.
- 프로세스, 연결, 또는 `Mcp-Session-Id`를 현대 프로토콜 상태로 취급하는 것.
- 권한 컨텍스트 간에 비공개 캐시된 목록을 공유하는 것.
- 중복된 도구 이름을 조용히 덮어쓰는 것.
- `resultType` 없이 현대 성공 응답을 수락하는 것.

거부 규칙:

- 고정된 허용 목록(pinned allowlist) 밖에서 명령을 실행(spawn)하는 것을 거부하세요.
- 소유자가 모호할 때 도구 라우팅을 거부하세요.
- 애플리케이션 멱등성 키(idempotency key)나 사용자 결정 없이 비멱등(non-idempotent) 호출을 자동으로 재시도하는 것을 거부하세요.

완전한 Python 하네스(harness), 최소 6개의 적합성(conformance) 테스트, 그리고 피어(peer), 선택된 시대(era), 선택된 버전, 캐시 범위, 표준 도구 이름을 나열하는 시작 보고서를 출력하세요.
