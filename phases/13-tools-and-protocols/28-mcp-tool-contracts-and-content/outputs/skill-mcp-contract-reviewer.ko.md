제공된 MCP 도구 표면을 프로토콜 버전 `2026-07-28`에 대해 검토합니다.

이러한 입력이 없는 경우 요청하세요:

1. 모든 `nextCursor` 필드를 포함한 완전한 `tools/list` 설명자 페이지.
2. 각 도구당 최소한 하나의 성공적인 결과와 하나의 실패 결과.
3. 사용된 경우 Streamable HTTP 매개변수 헤더 매핑.
4. 완료 참조, 호출자 클래스 및 예시 제안.
5. 가시 도구 집합을 변경할 수 있는 인증 컨텍스트.

이러한 섹션을 포함한 간결한 보고서를 작성하세요.

## 설명자 수용

각 도구마다:

- 비어 있지 않은 안정적인 이름을 확인하세요;
- 객체 `inputSchema`을 요구하세요;
- JSON Schema 방언을 식별하고, 생략된 경우 2020-12를 기본값으로 설정하세요;
- 존재하는 경우 `outputSchema`을 검증하세요;
- 주석은 정책이 아닌 신뢰할 수 없는 힌트로 취급하세요;
- 정확한 이유와 함께 `ADMIT`, `REJECT` 또는 `CONDITIONAL`을 반환하세요.

잘못된 설명자 하나를 거부하되, 관련 없는 유효한 도구들은 거부하지 마세요.

## 결과 계약

`isError: true`을 포함하여 모든 완전한 결과에 대해:

- `resultType: complete`을 요구하세요;
- 유형별로 모든 콘텐츠 블록을 검증하세요;
- `structuredContent`을 객체 전용이 아닌 모든 JSON 값으로 취급하세요;
- 존재하는 경우 `structuredContent`과 `outputSchema`에 대한 준수를 요구하세요;
- 구조화된 결과에 대해 호환성 텍스트 블록을 요구하세요;
- 리소스 링크와 내장된 리소스를 구분하세요;
- 크기 및 미디어 유형 제한을 명시하세요.

잘못된 요청은 JSON-RPC 오류로 분류하세요. 실행 가능한 실행 실패는 공개된 출력 계약을 우회하지 않고 `isError: true`을 포함한 완전한 결과로 분류하세요.

## 매개변수 헤더

모든 `x-mcp-header`에 대해:

- 유효하고 비어 있지 않은 HTTP 필드 이름 토큰을 요구합니다;
- 대소문자를 구분하지 않는 고유성을 요구합니다;
- 문자열, 정수 또는 불리언 타입을 요구합니다;
- 중첩된 속성, 조합자,
배열 항목 및 `$ref`이 사용하는 정의를 포함하여 전체 입력 스키마를 순회합니다;
- 직접 `inputSchema.properties` 멤버에만 주석을 허용하고
다른 위치나 `outputSchema`에서 발견된 모든 주석을 거부합니다;
- `number` 및 `-9007199254740991`부터
`9007199254740991`까지의 범위를 벗어난 정수 값을 거부합니다;
- 배포 정책에 따라 자격 증명, 토큰, 시크릿, 비밀번호, 인증 및 PII 필드를 거부합니다;
- 값이 비어 있지 않은 가시 ASCII 문자이며
`=?base64?`로 시작하지 않을 때만 평문으로 전송합니다;
- 그 외의 경우 원본 값을 트리밍하거나 `=?base64?{Base64UTF8}?=`
원본 값을 정규화합니다;
- 유니코드, 빈 문자열, 공백, 제어 문자, CR 또는 LF, 패딩된 문자열 및
센티널처럼 보이는 문자열을 인코딩하고, 불리언은 소문자 텍스트로 렌더링합니다;
- HTTP 경계에서 인식된 `Mcp-Param-*` 값을 디코딩하고, 헤더
  이름을 대소문자를 구분하지 않고 비교하며, 디코딩된 값을 JSON 본문과 정확히 비교하고
  누락, 중복, 예상치 못한, 형식이 잘못된, 또는 불일치하는 복사본을
  HTTP `400` 및 JSON-RPC `-32020`으로 거부합니다;
- 최종 헤더 이름과 거부 범주만 기록하고, 인자 값이나
인코딩된 페이로드를 기록하지 않습니다.

## 페이지네이션

모든 목록 요청을 추적합니다. `nextCursor`이 존재하고 비어 있지 않은 경우, 빈 문자열인 경우에도 계속 진행합니다. 커서를 절대 디코딩, 수정, 증분, 정렬하거나 의미를 파생하지 마세요. 중복된 도구, 누락된 페이지 및 불안정한 순서를 보고하세요.

## 완료

각 프롬프트 또는 리소스 참조에 대해:

- 참조와 인자를 검증합니다;
- 호출자의 권한을 통해 제안 사항을 필터링합니다;
- 결과를 100개 값으로 제한합니다;
- 클라이언트 디바운스 및 서버 속도 제한을 정의합니다;
- 숨겨진 테넌트, 리소스 및 환경 이름이 유출되지 않는지 테스트합니다.

## 검증 매트릭스

다음 검사를 최소한 포함하여 반환하세요:

| 검사 | 픽스처 | 예상 결과 |
|------|---------|-----------------|
| 비객체 구조화 출력 | 유효한 배열, 스칼라, 또는 null 스키마 | 준수하는 경우 허용 |
| 출력 불일치 | 잘못된 JSON 타입 또는 누락된 속성 | 모델 사용 전에 거부 |
| 오류 출력 불일치 | `isError: true`의 누락되거나 유효하지 않은 구조화된 콘텐츠 | 모델 사용 전에 거부 |
| 빈 커서 | `nextCursor: ""` | 후속 요청이 정확한 커서를 전송 |
| 안전하지 않은 헤더 | 토큰 또는 유효하지 않은 필드 이름 | 디스크립터 거부 |
| 중첩 헤더 주석 | `oneOf`, `items`, 중첩 객체, 또는 `$ref` 정의 | 전체 트리 수용 중 디스크립터 거부 |
| 인코딩된 헤더 값 | 유니코드, 줄바꿈, 패딩, 또는 센티널처럼 보이는 텍스트 | 정확한 base64 UTF-8 센티널이 원본 값을 왕복 |
| 정수 헤더 값 | 안전한 경계와 각 경계를 초과하는 값 하나 | 안전한 경계는 통과; 안전하지 않은 값은 거부 |
| 헤더 및 본문 일치 | 대소문자 변형, 누락된 복사본, 및 디코딩 불일치 | 대소문자 변형은 통과; 누락되거나 불일치하면 HTTP 400 및 JSON-RPC -32020 반환 |
| 혼합 콘텐츠 | 텍스트, 미디어, 링크, 임베드된 리소스 | 각 블록이 독립적으로 검증 |
| 완료 격리 | 낮은 권한 호출자 | 권한 있는 제안이 반환되지 않음 |
| 오류 계층화 | 알 수 없는 도구 및 비즈니스 실패 | JSON-RPC 오류와 `isError: true`가 구분 유지 |

증거가 성공적인 도구 호출만 포함하는 경우 승인을 거부하세요. 발견 페이지, 수용 결정, 및 검증된 결과 픽스처를 요구하세요.
