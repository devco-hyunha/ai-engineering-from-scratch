# MCP 도구 계약 및 콘텐츠

> 도구 자동화가 안전하려면 발견, 인자, 결과, 페이지네이션, 전송 메타데이터가 하나의 계약에 일치해야 합니다.

**유형:** Build
**언어:** Python
**선수 요건:** 13단계, 07강, 09강, 10강
**시간:** 약 120분

## 학습 목표

- JSON Schema 2020-12로 도구 입력과 출력을 정의해 보세요.
- 결과가 JSON 객체라고 가정하지 않고 구조화된 결과를 검증해 보세요.
- 텍스트, 이미지, 오디오, 리소스 링크, 임베드된 리소스 중 하나를 선택해 보세요.
- 도구가 모델에 도달하기 전에 안전하지 않은 `x-mcp-header` 정의를 거부해 보세요.
- 매개변수 헤더 값을 인코딩하고 헤더와 본문의 정확성을 확인해 보세요.
- 커서 값을 해석하지 않고 커서 페이지네이션을 탐색해 보세요.
- `completion/complete` 제안을 제한하고 승인해 보세요.

## 문제점

Python 함수를 호출하는 것은 쉽습니다. AI 호스트를 통해 원격 기능을 호출하는 것은 계약 문제입니다.

서버는 설명자를 게시합니다. 클라이언트는 그 설명자를 모델 컨텍스트와 사용자 인터페이스로 변환합니다. 모델은 인자를 생성합니다. 게이트웨이는 미러링된 헤더에서 요청을 라우팅할 수 있습니다. 서버는 도구를 실행합니다. 클라이언트는 결과를 모델에 반환할 만큼 안전하고 유효한지 결정합니다.

약한 경계 하나가 전체 체인을 손상시킵니다.

다섯 가지 실패 사례를 고려해 보세요:

- 설명자는 결과가 객체라고 말하지만, 서버는 배열을 반환합니다.
- 클라이언트는 `nextCursor`가 빈 문자열일 때 페이지네이션을 중단합니다.
- 토큰 매개변수가 HTTP 헤더에 미러링되어 중간자에게 노출됩니다.
- 유니코드 라우팅 값이 원시 헤더로 전송되면 게이트웨이와 원점이 서로 다른 바이트를 해석합니다.
- 완료 엔드포인트가 접근할 수 없는 호출자에게 프로덕션 환경을 제안합니다.

이러한 실패는 더 나은 프롬프트로 해결되지 않습니다. 명시적인 프로토콜 및 애플리케이션 계약이 필요합니다.

## 계약 파이프라인

각 도구 호출을 다섯 개의 게이트로 취급해 보세요:

1. **발견.** 결정적이고 페이지화된 도구 목록을 읽어 보세요.
2. **수용.** 각 설명자를 검증하고 로컬 보안 정책을 적용하세요.
3. **호출.** 인자를 검증하고 전송 메타데이터를 빌드하세요.
4. **실행.** 핸들러를 실행하고 실패를 올바르게 분류하세요.
5. **소비.** 모델 사용 전에 콘텐츠 블록과 구조화된 출력을 검증하세요.

```figure
mcp-contract-pipeline
```

호스트는 수용 및 소비 게이트를 소유합니다. 서버는 클라이언트가 자신의 주석, 스키마, 또는 출력에 신뢰를 강요할 수 없습니다.

## JSON Schema는 런타임 경계입니다

MCP `2026-07-28`에서는 `inputSchema`과 `outputSchema`가 JSON Schema를 사용합니다. `$schema`이 없을 경우, 기본 방언은 2020-12입니다.

입력 스키마는 스키마 객체여야 합니다. 인자가 없는 도구도 정확히 무엇을 허용하는지 명시해야 합니다:

```json
{
  "type": "object",
  "additionalProperties": false
}
```

이것은 임의의 속성을 허용하는 `{ "type": "object" }`보다 더 엄격합니다.

출력 스키마는 선택적입니다. 서버가 하나를 게시하면, 모든 완전한 도구
결과는 `isError: true`을 포함하여, 준수하는 `structuredContent`를 반환하는 것에
커밋합니다. 에러 플래그는 실행 결과를 분류합니다; 게시된 출력 계약을
면제하지 않습니다. 클라이언트는 설명자를 신뢰하는 대신 결과를
검증해야 합니다.

### 구조화된 콘텐츠는 모든 JSON 값입니다

`structuredContent`를 사전으로 하드 코딩하지 마세요. 이것은 다음이 될 수 있습니다:

- 객체;
- 배열;
- 문자열;
- 숫자;
- 불리언;
- `null`.

이 도구는 배열을 반환합니다:

```json
{
  "name": "tag_catalog",
  "inputSchema": {
    "type": "object",
    "additionalProperties": false
  },
  "outputSchema": {
    "type": "array",
    "items": {"type": "string"}
  }
}
```

그의 성공적인 결과는 유효합니다:

```json
{
  "resultType": "complete",
  "content": [
    {
      "type": "text",
      "text": "[\"contracts\", \"mcp\", \"stateless\"]"
    }
  ],
  "structuredContent": ["contracts", "mcp", "stateless"],
  "isError": false
}
```

호환성을 위해, 구조화된 결과는 텍스트 블록에 직렬화된 JSON도 포함해야 합니다. 텍스트는 검증 소스가 아닙니다. `structuredContent`가 소스입니다.

### 작은 검증기는 여전히 경계를 가르쳐 줍니다

이 강의는 Python 표준 라이브러리 안에 머물러 있도록 의도적으로 JSON Schema의 하위 집합을 사용합니다. 이것은 샘플 도구가 사용하는 메커니즘을 확인합니다:

- object, array, string, integer, number, boolean, null 타입;
- 필수 속성;
- `additionalProperties: false`;
- 배열 항목;
- enum 값;
- 최소 문자열 길이입니다.

이것은 완전한 프로덕션 검증기를 대체하는 것이 아닙니다. 재사용 가능한 교훈은 검증이 일어나는 위치입니다: 디스크립터의 경우 발견 후, 인수의 경우 실행 전, 구조화된 결과의 경우 소비 전입니다.

## 콘텐츠 블록은 각각 다른 비용을 가집니다

`content` 배열은 여러 콘텐츠 유형을 결합할 수 있습니다.

| 유형 | 사용 목적 | 주요 경계 |
|------|------------|---------------|
| `text` | 사람과 모델이 읽을 수 있는 요약 | 텍스트를 신뢰할 수 없는 출력으로 취급 |
| `image` | base64로 인코딩된 시각적 증거 | 미디어 유형 및 크기 검증 |
| `audio` | base64로 인코딩된 음성 또는 녹음 출력 | 미디어 유형 및 지속 시간 제한 검증 |
| `resource_link` | 클라이언트가 나중에 가져올 수 있는 URI | 이후의 리소스 읽기 재인증 |
| `resource` | 결과에 직접 포함된 데이터 | 현재 페이로드 및 콘텐츠 제한 강제 |

리소스 링크는 리소스가 `resources/list`에 나타난다는 증거가 아닙니다. 이것은 이 도구 호출이 반환한 참조입니다. 클라이언트는 URI를 따를 때 리소스 정책을 적용합니다.

임베디드 리소스는 추가 왕복을 피하지만 현재 응답 크기를 증가시킵니다. 크기가 크거나 독립적으로 변경되는 아티팩트에는 링크를 사용하세요. 결과와 원자적으로 이동해야 하는 작은 증거에는 임베디드 리소스를 사용하세요.

이 교훈의 `evidence_bundle` 결과는 모든 다섯 가지 유형을 포함합니다. 클라이언트는 결과를 수락하기 전에 각 블록을 검증합니다.

## `x-mcp-header`는 라우팅 메타데이터입니다

`inputSchema` 내부의 속성은 `x-mcp-header`을 선언할 수 있습니다. Streamable HTTP를 통해 클라이언트는 그 인수를 `Mcp-Param-{name}`에 미러링합니다.

```json
{
  "region": {
    "type": "string",
    "x-mcp-header": "Region"
  }
}
```

`region: "eu-west"`를 사용하면 트랜스포트는 다음을 방출할 수 있습니다:

```http
Mcp-Param-Region: eu-west
```

이 애노테이션은 JSON 본문을 파싱하지 않고 라우팅할 수 있도록 로드 밸런서, 게이트웨이 또는 정책 엔진이 존재합니다. 자격 증명을 넣는 위치가 아닙니다.

프로토콜은 애노테이션을 제한합니다:

- 헤더 이름은 비어 있지 않으며 HTTP 필드 이름 토큰 문법을 따릅니다;
- 헤더 이름은 대소문자를 구분하지 않고 고유합니다;
- 속성 유형은 문자열, 정수 또는 부울입니다;
- `number`는 허용되지 않습니다;
- 주석은 `inputSchema.properties`의 직접 멤버에만 나타납니다;
- 정수 값은 `-9007199254740991`부터 `9007199254740991`까지의 범위를 벗어나지 않습니다.

위치 규칙은 구문적이며 실패 시 차단(fail-closed)됩니다. 검증기가 이해하는 속성만 보는 것이 아니라, 전체 스키마 트리를 순회하세요. 중첩된 객체의 `properties` 아래, `oneOf` 분기, `items`, `$ref`을 통해 도달한 정의, 또는 모든 출력 스키마 아래에 있는 주석은 거부하세요. 참조를 해석한다고 해서 참조된 노드가 직접적인 최상위 속성이 되지는 않습니다.

이 강의는 배포 정책을 추가합니다: `password`, `secret`, `token`, `api_key`, `authorization`와 같은 이름을 반영하는(describe) 기술자(descriptor)는 거부하세요. 공식 사양은 서버 작성자가 민감한 매개변수를 반영하지 않도록 권고합니다. 클라이언트는 이 권고를 엄격한 수용(admission) 규칙으로 만들 수 있습니다.

값이 아닌 헤더 이름을 감사하세요. 샘플 코드는 `Mcp-Param-Region`를 기록하면서 `eu-west`는 감사 이벤트에서 제외합니다.

### HTTP 헤더를 만들기 전에 값을 인코딩하세요

매개변수 값은 `!`부터 `~`까지의 가시 ASCII 문자로 구성된 비어 있지 않은 문자열이며 인코딩 센티넬(sentinel)과 유사하지 않을 때만 평문으로 전송될 수 있습니다. 그 외의 모든 값은 이 정확한 형식을 사용합니다:

```text
=?base64?{Base64UTF8}?=
```

`Base64UTF8`는 정확한 UTF-8 바이트에 대한 표준 base64입니다. 값을 먼저 잘라내거나, 정규화하거나, 대체하지 마세요. 유니코드, 빈 문자열, 공백, 탭, 제어 문자, CR 또는 LF, 선행 또는 후행 공백, `=?base64?`로 시작하는 모든 값을 인코딩하세요. 센티넬처럼 보이는 값을 다시 인코딩하는 것은 수신자가 전송 구문으로 디코딩하는 대신 문자 그대로의 원본 텍스트를 복원할 수 있게 해줍니다.

부울(Boolean) 값은 소문자 `true` 또는 `false`로 렌더링됩니다. 정수는 10진수로 렌더링되며 JavaScript의 안전한 정수 범위 안에 있어야 합니다. 그 범위를 벗어난 값은 중간 단계에서 반올림되지 않고 거부됩니다.

### 서버는 반영된(mirrored) 복사본을 확인합니다

헤더 생성은 클라이언트 쪽의 절반만입니다. Streamable HTTP 경계에서 서버는 다음을 수행해야 합니다:

1. 헤더 이름의 대소문자를 고려하지 않고 인식된 `Mcp-Param-*` 이름을 찾습니다;
2. 존재하는 경우 정확한 base64 센티넬 형식을 디코딩합니다;
3. 디코딩된 텍스트를 해당 JSON 본문 인자와 정확히 비교합니다;
4. 누락, 중복, 예상치 못한, 형식이 잘못된, 또는 불일치하는
인식된 헤더를 디스패치 전에 거부합니다.

거부는 HTTP `400`이며 JSON-RPC 오류 코드 `-32020`입니다. 본문 값이나 인코딩된 헤더 형식은 감사 기록에 포함되지 않습니다. 인식된 헤더 이름과 거부 범주만 기록하세요.

`code/main.py`는 이 경계를 직접 모델링합니다. [09강](../../09-mcp-transports/)는 메서드 및 프로토콜 버전 일치성을 포함하여 더 넓은 Streamable HTTP 검증 순서를 다루

## 페이지네이션 커서는 불투명합니다

MCP 목록 작업은 커서 페이지네이션을 사용합니다. 서버가 페이지 크기와 커서 형식을 선택합니다. 클라이언트는 하나의 결정만 내립니다:

```python
if result.get("nextCursor") is None:
    break
cursor = result["nextCursor"]
```

이렇게 작성하지 마세요:

```python
if not result.get("nextCursor"):
    break
```

빈 문자열은 유효한 커서입니다. 진위(truthiness) 체크는 너무 일찍 멈추게 됩니다.

클라이언트는 커서를 디코딩하거나, 증가시키거나, 순서를 위해 이전 커서와 비교하거나, 페이지 번호를 추론해서는 안 됩니다. 서버는 커서에 서명하거나, 카탈로그 버전에 바인딩하거나, 비공개 상태에 매핑할 수 있습니다. 이는 서버의 구현 세부 사항입니다.

샘플 서버는 첫 번째 페이지 이후에 의도적으로 `""`를 반환합니다. 클라이언트는 두 번째 요청에서 그 정확한 값을 보내야 합니다. 그 추적은 다음과 같습니다:

```text
<first request with no cursor>
<second request with cursor "">
```

유효하지 않은 커서는 JSON-RPC 유효하지 않은 매개변수, 코드 `-32602`를 생성합니다.

## 완성은 권한 부여 표면입니다

`completion/complete`는 프롬프트 인자 및 리소스 템플릿 인자에 대한 제안(suggestions)을 제공합니다. 이는 인터랙티브 양식에 유용하지만, 일반적인 목록 메서드가 보호하는 이름을 유출할 수 있습니다.

완성 요청은 참조와 완성 중인 인자를 지정합니다:

```json
{
  "method": "completion/complete",
  "params": {
    "ref": {
      "type": "ref/prompt",
      "name": "deployment_review"
    },
    "argument": {
      "name": "environment",
      "value": "st"
    }
  }
}
```

결과는 최대 100개의 값을 반환하며 `total` 및 `hasMore`을 보고할 수 있습니다.

참조된 프롬프트나 리소스가 사용하는 것과 동일한 권한 부여 경계를 적용하세요. 샘플의 분석가는 `development` 및 `staging`를 받습니다. 운영자만 `production`를 받을 수 있습니다.

프로덕션 완성에는 다음도 필요합니다:

- 입력 검증;
- 호출자 인식 필터링;
- 클라이언트에서의 요청 디바운싱;
- 서버에서의 속도 제한;
- 제한된 결과 개수;
- 민감한 제안 값을 노출하지 않는 로그.

완성은 보조 기능이며, 발견 우회가 아닙니다.

## 두 개의 오류 계층

프로토콜 오류와 도구 실행 오류를 분리해 유지하세요.

MCP 요청이 올바르게 전달될 수 없는 경우 JSON-RPC 오류를 사용하세요:

- 알 수 없는 도구 이름;
- 잘못된 요청 형식;
- 요청 메타데이터 누락;
- 잘못된 커서.

호출이 도구에 도달했고 도구가 조치 가능한 실패를 보고하는 경우 `isError: true`을 포함한 완전한 도구 결과를 사용하세요:

- 보고 소스가 사용 불가능한 경우;
- 날짜가 지원 범위를 벗어난 경우;
- 비즈니스 규칙이 요청된 작업을 거부하는 경우.

모델은 도구 실행 오류를 복구할 수 있는 경우가 많습니다. 그러나 자체 출력 스키마를 위반한 서버는 복구할 수 없습니다.

도구가 출력 스키마를 선언하는 경우, 해당 스키마 내에서 조치 가능한 실패를 모델링하세요. 샘플 `route_report` 실패는 `accepted: false`과 함께 요청된 영역을 반환하며, 사람이 읽을 수 있는 오류 텍스트와 `isError: true`를 포함합니다.

## 구현하기

`code/main.py`은 Python 표준 라이브러리를 사용하여 경계의 양쪽을 모두 구축합니다.

서버는 다음을 구현합니다:

- 요청별 MCP 메타데이터 검증;
- 도구 및 완성(capabilities) 기능을 포함한 `server/discover`;
- 결정론적 `tools/list` 페이지네이션;
- 거부되어야 하는 하나를 포함하여 네 개의 도구 설명자;
- 배열 구조화된 출력;
- 현재 모든 도구 콘텐츠 블록 유형;
- 인식된 매개변수 헤더를 디코딩하고 불일치 시 HTTP 및 JSON-RPC를 반환하는 Streamable HTTP 정합성 게이트;
HTTP `400` 및 JSON-RPC `-32020`를 반환합니다;
- 권한이 부여되고 속도 제한이 적용된 완성.

클라이언트는 다음을 구현합니다:

- 설명자 허용(admission);
- 전체 트리 `x-mcp-header` 배치 검증 및 민감 필드 정책;
- 정확한 평문 가시 ASCII 또는 base64 UTF-8 값 인코딩;
- 빈 문자열을 따르는 불투명 커서 루프;
- 인수 및 결과 검증;
- 콘텐츠 블록 검증;
- 값은 포함하지 않고 이름만 포함하는 헤더 감사 이벤트.

의도적으로 안전하지 않은 설명자는 교육용 데이터입니다. 하나의 거부된 도구가 유효한 도구의 로딩을 방지하지 않는다는 것을 증명합니다.

## 인터랙티브 랩

`code/main.py`을 열고 `TOOLS`을 찾으세요.

1. `tag_catalog.outputSchema.type`을 `array`에서 `object`으로 변경하세요.
2. 데모를 실행하세요. 클라이언트가 반환된 배열을 거부해야 합니다.
3. 스키마를 복원하세요.
4. 첫 페이지의 `nextCursor`을 `""`으로 유지한 후, 마지막 페이지가 필드를 생략하는 대신

5. 테스트를 실행하고 커서 추적을 비교하세요.
6. 문자열 속성에 `x-mcp-header: "Authorization"`을 추가하세요.
7. 설명자 승인 절차가 호출 전에 이를 거부하는지 확인하세요.
8. 유니코드, 줄 바꿈, 주변 공백, 그리고 `region`
 리터럴 텍스트 `=?base64?SGVsbG8=?=`을 포함하는 값을 시도하세요. 각 방출된 헤더를 디코딩하고
원본 값이 정확히 살아남는지 증명하세요.
9. 주석을 `oneOf`, `items`, 또는 `$ref` 정의 아래로 이동하세요. 각 설명자가
데모가 해당 분기를 사용하지 않더라도 거부되는지 확인하세요.
10. 인식된 헤더를 제거하거나 디코딩된 값을 변경하세요. HTTP
경계가 상태 `400` 및 JSON-RPC 코드 `-32020`을 반환하는지 확인하세요.

핵심은 JSON 형태를 암기하는 것이 아닙니다. 각 게이트가 소유한 경계에서 실패하는 것을 관찰하는 것입니다.

## 연습 랩

계약 랩을 `search_evidence` 도구로 확장하세요.

요구 사항:

1. 입력 스키마는 `query`, `limit`, 그리고 안전한 `region` 라우팅 필드를 허용합니다.
2. 출력 스키마는 `uri`, `title`, `score`를 포함하는 객체 배열입니다.
3. 결과에는 각 항목에 대한 호환성 텍스트와 리소스 링크가 포함됩니다.
4. 인수는 알 수 없는 속성을 거부합니다.
5. `limit`는 애플리케이션 유효성 검사에 의해 제한됩니다.
6. 하나의 URI에 대한 접근 권한이 없는 호출자는 완료(complete)나 도구 출력(tool output)을 통해 해당 URI를 볼 수 없습니다.
7. 테스트에는 비준수(nonconforming) 점수, 유효하지 않은 헤더 주석(annotation), 그리고 두 페이지 목록이 포함됩니다.
8. 헤더 값 테스트는 가시 ASCII, 유니코드, 제어 문자,
공백, 센티널(sentinel)처럼 보이는 텍스트, 그리고 JavaScript 안전 정수 경계 양쪽을 모두 포함합니다.
9. HTTP 픽스처(fixture)는 대소문자를 구분하지 않는 헤더 이름을 허용하지만, 인식된 값이 누락되거나
일치하지 않는 경우 상태 `400` 및 코드 `-32020`로 거부합니다.

`outputs/skill-mcp-contract-reviewer.md`는 평평(flat)하고 재사용 가능한 리뷰 스킬입니다. 도구 설명자(descriptor), 샘플 결과, 페이지네이션 동작, 완료(complete) 정책을 입력하세요. 이 스킬은 수용(admission) 결정, 결과 유효성 검사 계획, 헤더 정책, 그리고 구체적인 실패 테스트를 반환합니다.

## 검증하기

다음 문장들이 참일 때 이 강은 완료됩니다:

- `tools/list`는 반복 호출 시 동일한 논리적 순서를 반환합니다.
- `nextCursor`가 `""`일 때 클라이언트는 두 번째 요청을 수행합니다.
- 안전하지 않은 민감 헤더(sensitive-header) 설명자는 제외되지만, 다른 도구들은 계속 사용 가능합니다.
- 배열은 배열 출력 스키마를 통과합니다.
- 객체는 동일한 배열 스키마에서 실패합니다.
- 오류 결과는 게시된 출력 스키마를 생략하거나 위반할 수 없습니다.
- 텍스트, 이미지, 오디오, 리소스 링크, 그리고 임베드된 리소스 블록이 유효성 검사를 통과합니다.
- 헤더 감사(audit) 이벤트는 이름을 포함하지만 값은 포함하지 않습니다.
- 평범한 가시 ASCII는 평범한 상태로 유지되며, 유니코드, 제어 문자, 패딩된 값, 빈 값, 그리고
센티널처럼 보이는 값은 정확한 base64 UTF-8 인코딩을 통해 왕복(round-trip)합니다.
- JavaScript 안전 범위를 벗어난 미러링된 정수는 거부됩니다.
- `oneOf`, `items`, 중첩된 객체, `$ref` 정의, 또는
출력 스키마 하의 주석(annotation)은 수용(admission) 중에 거부됩니다.
- 대소문자를 구분하지 않는 인식된 헤더 이름은 디코딩된 값이
  본문과 정확히 일치해야 합니다. 누락되거나 불일치하는 복사본은 HTTP `400`
  및 JSON-RPC `-32020`를 생성합니다.
- 분석가 완료는 `production`를 반환하지 않습니다.
- 도구 실패는 `isError: true`를 사용하며, 형식이 잘못된 프로토콜 호출은 JSON-RPC `error`를 사용합니다.

## 캡스톤 연결

13단계 캡스톤 프로젝트에는 여러 서버의 도구를 병합할 수 있는 게이트웨이가 필요합니다. 이 강의는 해당 게이트웨이의 수용(admission) 코어를 제공합니다.

이 산출물을 사용하여 캡스톤 증거의 네 가지 요소를 평가해 보세요:

- 결정적이고 완전한 페이지 분할(paginated) 발견;
- 모델 노출 전의 descriptor 검증;
- 검증된 구조화된 출력 및 제한된 content block;
- 권한 경계를 보존하는 완료 및 라우팅 메타데이터.

성공적인 `tools/call`만으로 게이트웨이 호환성을 주장하지 마세요. descriptor, 페이지 추적(trace), 수용된 도구 세트, 거부된 도구 세트, 그리고 검증된 결과 하나를 캡처하세요.

## 핵심 용어

| 용어 | 의미 |
|------|---------|
| `inputSchema` | 허용된 도구 인수를 정의하는 JSON Schema 객체 |
| `outputSchema` | `structuredContent`를 정의하는 선택적 JSON Schema |
| `structuredContent` | 도구 결과에 의해 생성된 모든 JSON 값 |
| Content block | 타입이 지정된 텍스트, 이미지, 오디오, 리소스 링크, 또는 임베드된 리소스 |
| `x-mcp-header` | 원시(primitive) 인수를 Streamable HTTP 메타데이터에 반영하는 Schema annotation |
| Opaque cursor | 서버가 발급한 페이지 분할(pagination) 토큰으로, 클라이언트가 값을 해석하지 않음 |
| Completion reference | 인수가 완성되고 있는 prompt 이름 또는 resource URI/template |
| Admission | 발견된 descriptor를 노출하거나 거부하는 클라이언트의 결정 |
