# LLM 라우팅 계층 — LiteLLM, OpenRouter, Portkey

> 프로바이더 종속(lock-in)은 비용이 많이 듭니다. 도구 호출(tool-calling) 워크로드에 따라 적합한 모델이 다릅니다. 라우팅 게이트웨이는 하나의 API 표면, 재시도, 페일오버, 비용 추적, 가드레일(guardrails)을 제공합니다. 2026년에는 세 가지 아키타입이 지배적입니다: LiteLLM (오픈소스 셀프 호스트), OpenRouter (관리형 SaaS), Portkey (프로덕션급, 2026년 3월 오픈소스화). 이 강의에서는 결정 기준을 명시하고 표준 라이브러리(stdlib) 라우팅 게이트웨이를 단계별로 진행합니다.

**유형:** Learn
**언어:** Python (stdlib, 라우팅 + 페일오버 + 비용 추적기)
**선수 요건:** 13단계 · 02강 (함수 호출), 13단계 · 17강 (게이트웨이)
**시간:** 약 45분

## 학습 목표

- 셀프 호스트, 관리형, 프로덕션급 라우팅 옵션을 구분해 보세요.
- 정의된 우선순위 순서로 프로바이더 장애 시 재시도하는 폴백(fallback) 체인을 구현해 보세요.
- 프로바이더 간 요청별 비용 및 토큰 사용량을 추적해 보세요.
- 주어진 프로덕션 제약 조건에 따라 LiteLLM, OpenRouter, Portkey 중 하나를 결정해 보세요.

## 문제점

프로바이더 라우팅이 중요한 시나리오:

1. **비용.** Claude Sonnet은 Haiku보다 비용이 3배 높습니다. 분류(triage) 작업에는 Haiku가 충분하고, 합성(synthesis) 작업에는 Sonnet가 가치 있습니다. 요청별로 라우팅하세요.

2. **페일오버.** OpenAI에 문제가 있는 시간대가 있습니다. 모든 요청이 실패합니다. 재배포 없이 Anthropic으로 자동 폴백(fallback)을 원합니다.

3. **지연.** 라이브 채팅 UI는 빠른 첫 토큰까지의 시간(TTFT)이 필요합니다. 배치 요약기는 필요하지 않습니다. 지연 SLA에 따라 라우팅하세요.

4. **컴플라이언스.** EU 사용자는 EU 지역에 머물러야 합니다. 지역에 따라 라우팅하세요.

5. **실험.** 동일한 워크로드에서 두 모델을 A/B 테스트합니다. 테스트 버킷에 따라 라우팅하세요.

이 모든 것을 통합마다 수동으로 코딩하는 것은 반복적입니다. 라우팅 게이트웨이는 하나의 OpenAI 호환 API를 제공하며 나머지를 처리합니다.

## 개념

### OpenAI 호환 프록시 형태

모두 OpenAI 형태를 따릅니다. 라우팅 게이트웨이는 `/v1/chat/completions`을 노출하고, OpenAI 스키마를 수용하며, 내부적으로 Anthropic / Gemini / Cohere / Ollama / 기타로 프록시(proxy)합니다. 클라이언트는 신경 쓰지 않습니다.

### 모델 별칭

고정된 스냅샷 ID 대신, 코드가 `our_smart_model`를 사용합니다. 게이트웨이는 별칭을 실제 모델에 매핑합니다. 제공자가 새로운 세대를 출시하면 서버 측에서 별칭을 변경하며, 코드는 아무것도 건드리지 않습니다.

### 폴백 체인

```
primary: openai/gpt-4o
on 5xx: anthropic/claude-3-5-sonnet
on 5xx: google/gemini-1.5-pro
on 5xx: refuse
```

게이트웨이는 이를 설정(config)에서 정의합니다. 재시도는 예산에 포함되므로 폴백 캐스케이드가 비용을 폭증시키지 않습니다.

### 시맨틱 캐싱

동일하거나 거의 동일한 프롬프트는 제공자 대신 캐시를 조회합니다. 반복적인 에이전트 루프에서 절약되는 비용은 30~60%에 달할 수 있습니다. 키는 임베딩 기반으로 생성되며, 거의 동일한 프롬프트는 캐시 슬롯을 공유합니다.

### 가드레일

게이트웨이 수준:

- **PII 마스킹.** 프롬프트 전송 전 정규식 또는 ML 기반 처리를 수행합니다.
- **정책 위반.** 금지된 내용이 포함된 프롬프트를 거부합니다.
- **출력 필터.** 완결(completions)에서 유출을 제거합니다.

Portkey와 Kong은 모두 특화된 가드레일을 제공합니다. LiteLLM은 이를 선택적으로 설정할 수 있습니다.

### 키별 속도 제한

하나의 API 키는 하나의 팀에 해당합니다. 키별 예산은 한 팀이 공유 할당량을 소진하는 것을 방지합니다. 대부분의 게이트웨이가 이를 지원합니다.

### 셀프 호스트 vs 관리형 트레이드오프

| 요소 | LiteLLM (셀프 호스트) | OpenRouter (관리형) | Portkey (프로덕션) |
|--------|----------------------|----------------------|----------------------|
| 코드 | 오픈 소스, Python | 관리형 SaaS | 오픈 소스 (2026년 3월) + 관리형 |
| 설정 | 프록시 배포 | 가입 | 둘 중 하나 |
| 제공자 | 100+ | 300+ | 100+ |
| 청구 | 자체 키 | OpenRouter 크레딧 | 자체 키 |
| 관측 가능성 | OpenTelemetry | 대시보드 | 완전한 OTel + PII 마스킹 |
| 최적 용도 | 완전한 제어권을 원하는 팀 | 빠른 프로토타이핑 | 컴플라이언스가 필요한 프로덕션 |

SRE 팀이 있고 데이터 주권을 원한다면 LiteLLM이 유리합니다. 단일 구독으로 인프라 없이 운영하려면 OpenRouter가 유리합니다. 가드레일과 컴플라이언스를 즉시 필요로 한다면 Portkey가 유리합니다.

### 비용 추적

모든 요청은 `provider`, `model`, `input_tokens`, `output_tokens`를 포함합니다. 게이트웨이가 유지하는 가격표에서 가져온 모델별 토큰 단가 곱합니다. 사용자별 / 팀별 / 프로젝트별 집계.

### MCP와 라우팅

게이트웨이는 LLM 호출과 MCP 샘플링 요청 모두를 라우팅할 수 있습니다. 샘플링 요청의 modelPreferences가 특정 모델을 선호할 경우, 게이트웨이는 적절한 백엔드로 변환합니다. 이 지점에서 13단계 · 17강 (MCP 게이트웨이)과 이 강의의 라우팅 게이트웨이가 하나의 서비스로 통합되는 경우가 있습니다.

### 라우팅 전략

- **정적 우선순위.** 목록의 첫 번째를 사용하며, 오류 발생 시 폴백합니다.
- **로드 밸런싱.** 라운드 로빈 또는 가중치 방식.
- **비용 인식.** 지연 시간 / 품질을 충족하는 가장 저렴한 모델을 선택합니다.
- **지연 시간 인식.** 최근 N분 동안 가장 빠른 모델을 선택합니다.
- **작업 인식.** 프롬프트 분류기가 코딩은 한 모델로, 요약은 다른 모델로 라우팅합니다.

```figure
tp-router-failover
```

## 사용하기

`code/main.py`는 약 150줄로 라우팅 게이트웨이를 구현합니다. OpenAI 형식의 요청을 받아 각 제공자 스텁으로 변환하고, 우선순위 폴백 체인을 실행하며, 요청별 비용을 추적하고, 입력에 PII 마스킹 처리를 적용합니다. 세 가지 시나리오로 실행해 보세요: 정상 요청, 폴백을 유발하는 주요 제공자 장애, 마스킹으로 잡힌 PII 유출.

확인할 사항:

- `ROUTES` dict: 별칭 -> 우선순위가 지정된 구체적 제공자 목록.
- 폴백 루프는 5xx 오류 시 재시도합니다.
- 비용 추적기는 토큰 사용량을 모델별 단가로 곱합니다.
- PII 마스커는 SSN 형식 패턴을 제거한 후 전달합니다.

## 연습 문제

1. `code/main.py`을 실행하세요. 장애 시나리오를 트리거하여 폴백이 두 번째 제공자로 이어지고 비용이 올바르게 귀속되는지 확인하세요.

2. 시맨틱 캐싱을 추가하세요: 프롬프트의 SHA256이 조회 키가 되며, 캐시 적중 시 즉시 반환됩니다. 반복 호출에서 비용 절감을 측정하세요.

3. 프롬프트 분류기를 추가하여 "code ..." 프롬프트는 지능을 선호하는 별칭으로, "summarize ..." 프롬프트는 속도를 선호하는 별칭으로 라우팅하세요.

4. 팀별 예산을 설계하세요: 각 팀은 월간 지출 상한을 가지며, 상한에 도달하면 게이트웨이가 요청을 거부합니다. 강제 적용 세분화 (요청별 또는 윈도우 단위)를 선택하세요.

5. LiteLLM, OpenRouter, Portkey 문서를 나란히 읽어 보세요. 각 서비스가 제공하는 기능 중 다른 두 서비스가 제공하지 않는 기능을 하나씩 나열해 보세요.
