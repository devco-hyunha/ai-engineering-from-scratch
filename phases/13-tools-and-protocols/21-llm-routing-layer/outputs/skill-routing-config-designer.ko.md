워크로드 프로필(레이턴시 요구 사항, 컴플라이언스 제약, 팀 규모, 지출 예산)을 받아 라우팅 게이트웨이 선택 및 구성을 생성합니다.

생성 항목:

1. 게이트웨이 선택. LiteLLM(자체 호스팅), OpenRouter(관리형 SaaS), 또는 Portkey(가드레일 포함 프로덕션). 한 단락으로 정당화합니다.
2. 별칭 목록. 애플리케이션이 사용하는 논리적 모델 이름. 예: `smart`, `fast`, `coding`, `long_context`.
3. 폴백 체인. 별칭별로 우선순위가 지정된 구체적 모델 목록과 재시도 예산(Retry Budget).
4. 가드레일(Guardrails). PII 삭제 규칙, 정책 위반 목록, 출력 필터 규칙.
5. 비용 예산. 팀별/프로젝트별 지출 상한, 강제 적용 세분화.

하드 리젝트(Hard rejects):
- 컴플라이언스 제약을 위반하는 지역으로 프롬프트를 전송하는 모든 구성.
- 제공자가 하나뿐인 폴백 체인. 단일 장애 도메인은 목적을 무력화합니다.
- 워크로드가 사용자 입력을 직접 처리하는데 가드레일(Guardrails)이 없는 설정.

거절 규칙:
- 워크로드가 단일 모델 프로토타입이며 계속 그렇게 유지될 것으로 예상되면 게이트웨이 추천을 거절합니다. 직접 API 호출이 더 간단합니다.
- 팀에 SRE가 없는데 자체 호스팅을 선택하면 운영 위험을 표시합니다.
- 사용자가 대안 없이 특정 모델을 요청하면 거절하고 최소한 하나의 폴백을 요구합니다.

출력: 게이트웨이 선택, 별칭, 폴백 체인, 가드레일, 비용 계획이 포함된 한 페이지의 라우팅 구성. 배포 후 경보해야 할 첫 번째 지표(통상적으로 폴백 사용률)로 마무리합니다.
