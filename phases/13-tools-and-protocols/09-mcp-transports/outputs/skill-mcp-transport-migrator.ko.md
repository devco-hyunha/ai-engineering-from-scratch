세션 기반 Streamable HTTP 또는 HTTP+SSE 서버가 주어지면, MCP `2026-07-28`에 대한 마이그레이션 런북을 작성해 보세요.

다음 내용을 작성합니다:

1. 엔드포인트 맵. POST를 허용하는 현대적인 MCP 엔드포인트를 하나 정의합니다. 각 JSON-RPC 요청 또는 알림은 새로운 POST를 받습니다.
2. 응답 맵. 하나의 응답에는 `application/json`을, 최종 응답에 이어지는 관련 알림에는 요청 범위 `text/event-stream`을 사용하세요.
3. 제거된 동작. 현대적인 GET 및 DELETE에는 `405`을 반환합니다. `Mcp-Session-Id`과 `Last-Event-ID`는 무시하며, 절대 생성, 에코, 폐기, 재개하지 마세요.
4. 요청 메타데이터. 모든 본문 `_meta`에 프로토콜 버전과 클라이언트 기능을 필수로 포함하고, 권장되는 클라이언트 식별자를 포함하세요.
5. 헤더 검증. `MCP-Protocol-Version`, `Mcp-Method` 및 조건부 `Mcp-Name`를 필수로 요구합니다. Base64 센티넬을 디코딩하여 헤더를 본문과 비교합니다. 불일치 시 `-32020`을 반환합니다. 지원되지 않는 일치하는 버전의 경우 정확한 데이터 키 `supported`와 `requested`를 포함하여 `-32022`을 반환합니다.
6. 구독 마이그레이션. 독립적인 GET, `resources/subscribe`, `resources/unsubscribe`를 POST `subscriptions/listen`로 대체합니다. 청취 요청 id와 동일한 `io.modelcontextprotocol/subscriptionId`으로 승인, 모든 알림, 최종 결과를 태깅하세요.
7. 상태 마이그레이션. 연결 친화성을 인증된 주체에 바인딩된 명시적이고 불투명한 애플리케이션 핸들로 대체하세요.
8. 호환성 기간. 이전 엔드포인트는 분리하고 명확히 라벨링하세요. 레거시 폴백 전에 현대적인 POST 오류를 반드시 검사해야 합니다. 메서드와 본문 보존이 안전하지 않으므로 `301` 또는 `302`로 POST를 리디렉션하지 마세요.
9. 검증. Origin 거부, POST 미디어 협상, 본문 메타데이터, 미러링된 헤더, JSON 응답, 본문 없는 승인된 알림 `202`, 범위 지정된 SSE 구독 메타데이터, GET 및 DELETE `405`, 무시된 제거된 헤더, 새로운 id를 사용한 끊어진 스트림 재시도를 테스트하세요.

하드 거부:

- 세션 id, 독립적인 GET, DELETE, 재생을 현대적인 동작으로 제시하는 것.
- 프로세스 또는 연결 메모리를 통해 요청별 기능을 공유합니다.
- 서버가 시작하는 JSON-RPC 요청을 전송합니다.
- `Last-Event-ID`을 사용하여 최신 SSE 스트림을 재개합니다.
- 인식된 최신 오류 발생 후 레거시로 폴백합니다.
- 마이그레이션 중 JSON-RPC POST를 이동하기 위해 리디렉트를 사용합니다.

거부 규칙:

- 인증, 권한 부여 및 정확한 Origin 정책 없이 공개 노출을 거부합니다.
- 명시적 워크플로 상태의 대체 수단으로 숨겨진 스티키 라우팅을 거부합니다.
- 애플리케이션 멱등성 제어 없이 비멱등적 작업의 자동 재시도를 거부합니다.

이전 및 이후 엔드포인트 표, 단계적 롤아웃, 롤백 경계 및 실행 가능한 적합성 체크리스트를 출력합니다. 레거시 라우트가 제거될 정확한 날짜로 마무리합니다.
