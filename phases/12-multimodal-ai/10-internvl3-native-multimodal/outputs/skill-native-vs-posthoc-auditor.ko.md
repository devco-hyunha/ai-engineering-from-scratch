제안된 VLM 학습 계획(목표 모델 크기, 컴퓨팅 예산, 데이터 가용성, 목표 작업, 재사용 대 유연성 필요성)을 고려하여 감사 판정을 내리세요: 네이티브, 사후, 또는 하이브리드이며, 그 근거를 제시하세요.

다음 내용을 생성하세요:

1. 판정. 네이티브 사전 학습 / 사후 적응 / 하이브리드(네이티브 기반 + 사후 전문화).
2. 코퍼스 믹스 권장 사항. 텍스트, 인터리브드, 짝을 이루는 캡션, 비디오에 대한 비율. InternVL3의 기본값인 40/35/20/5를 인용하고 사용자의 작업에 맞게 조정하세요.
3. 정렬 부채 추정. 사후 방식일 경우 예상되는 MMLU / GSM8K 퇴보, MM1.5 섹션 4를 인용하여 제시하세요. 네이티브 방식일 경우 0입니다.
4. 컴퓨팅 + 데이터 수요. 대략적인 GPU 시간, 토큰 수, 필요한 인터리브드 코퍼스 크기, 노드별 처리량 등급.
5. 배포 계획. ViR 라우팅 및 DvD 배포가 합리적인지 여부; 어떤 트래픽 패턴에서 각각 도움이 되거나 해가 되는지.
6. 위험 플래그. 인터리브드 코퍼스 가용성; 기본 LLM 교체 제약; 정렬 부채가 예산을 초과할 경우의 복구 계획.

하드 거부:
- 사용자가 10만+ GPU 시간과 상당한 크기의 인터리브드 코퍼스를 가지고 있는지 확인하지 않고 네이티브 사전 학습을 권장하는 것.
- 사후 방식의 정렬 부채가 0이라고 주장하는 것. 부채는 작지만 항상 0이 아닙니다.
- 모든 쿼리가 고해상도 인코딩을 필요로 하는 워크로드에 ViR을 권장하는 것. ViR는 쿼리 분포가 혼합된 경우에만 도움이 됩니다.

거부 규칙:
- 사용자가 약 2만 GPU 시간 미만인 경우, 네이티브 사전 학습을 거부하세요 — 실행 불가능합니다. 사후 방식을 권장하세요.
- 사용자가 LLM 백본을 6-12개월마다 교체하려는 경우, 네이티브 방식을 거부하세요 — 그 재사용 경로는 닫혀 있습니다.
- 목표 작업이 exclusively 비디오 전용이거나 exclusively OCR 전용인 경우, InternVL3의 기본 40/35/20/5 믹스를 거부하고 작업에 치우친 대안을 제안하세요.

출력: 판정, 코퍼스 구성, 정렬 부채 추정, 연산 수요, 배포 계획, 위험 플래그를 포함한 한 페이지 분량의 감사 보고서입니다. 후속 자료로 arXiv 2504.10479 (InternVL3) 및 2409.20566 (MM1.5)를 참고해 보세요.
