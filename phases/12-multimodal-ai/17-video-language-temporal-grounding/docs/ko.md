# 비전-언어 모델: 시간적 토큰과 그라운딩

> 비디오는 사진의 단순한 쌓임이 아닙니다. 5초 클립에는 인과적 순서, 동작 동사, 이벤트 타이밍이 있으며, 이는 이미지 모델이 표현할 수 없는 요소입니다. Video-LLaMA (Zhang et al., 2023년 6월)는 오디오-비주얼 그라운딩을 갖춘 최초의 오픈 비디오 LLM을 출시했습니다. VideoChat와 Video-LLaVA는 이 패턴을 확장했습니다. 2025년 Qwen2.5-VL의 TMRoPE는 프런티어 독점 모델과의 격차를 좁혔습니다. 각 시스템은 시간적 토큰을 서로 다른 방식으로 해결했습니다. Q-former는 클립 단위, concat-pool은 프레임 단위, TMRoPE는 토큰 단위입니다. 이 강의에서는 이러한 패턴을 읽고, 균일 대 동적 프레임 샘플러를 구축하며, 시간적 그라운딩 작업에서 평가합니다.

**유형:** Build
**언어:** Python (표준 라이브러리, 프레임 샘플러 + 시간적 그라운딩 평가기)
**선수 요건:** 12단계 · 08강 (LLaVA-OneVision)
**시간:** 약 180분

## 학습 목표

- 비전 인코더와 독립적으로 시간적 위치 인코딩이 비디오 VLM 성능을 변화시키는 이유를 설명합니다.
- 초당 토큰 수와 그라운딩 정확도 측면에서 균일, 동적 FPS, 이벤트 기반 프레임 샘플링을 비교합니다.
- Q-former-per-clip (Video-LLaMA) 대 pooled-per-frame (Video-LLaVA) 대 M-RoPE-per-token (Qwen2.5-VL) 설계를 설명합니다.
- 네 가지 비디오 벤치마크의 이름을 나열합니다: VideoMME, TempCompass, EgoSchema, Video-MMMU.

## 문제점

30 FPS의 1분 비디오는 1800개의 프레임입니다. 프레임당 196개의 시각적 토큰 (ViT-B, 224)이 있다면, 이는 352k 토큰으로, 2024년대의 모든 LLM 컨텍스트보다 큽니다.

세 가지 감소 전략이 존재합니다:

1. 프레임을 하위 샘플링합니다 (콘텐츠에 따라 1-8 FPS).
2. 각 프레임의 패치 토큰을 aggressively 풀링합니다 (3x3 또는 4x4 바이리니어 풀링).
3. 16프레임 클립을 입력하여 64개 토큰을 출력하는 Q-former를 통해 압축합니다.

각 트레이드오프는 다릅니다. 하위 샘플링은 시간적 세부 정보를 잃습니다. 풀링은 공간적 세부 정보를 잃습니다. Q-former는 둘 다 조금 잃지만 토큰을 절약합니다.

시간적 위치 인코딩은 다른 축입니다: 모델은 프레임 5가 프레임 6보다 먼저 왔다는 것을 어떻게 알까요? 옵션에는 단순한 1D 시간적 RoPE (Video-LLaMA), 학습된 시간적 임베딩 (Video-LLaVA), TMRoPE (Qwen2.5-VL, 완전한 3D)가 포함됩니다.

## 개념

### Video-LLaMA: 클립별 Q-former + 오디오 브랜치

Video-LLaMA (2023)는 최초의 오픈 소스 비디오 LLM이었습니다. 아키텍처:

- 2 FPS로 16프레임 클립 (즉, 8초).
- 프레임별 ViT 특징 -> 모든 16프레임에 대해 교차 어텐션(Cross-Attention)하는 Video Q-former -> 32개의 학습된 쿼리 -> LLM.
- 병렬 오디오 브랜치: 파형 -> ImageBind 오디오 인코더 -> Audio Q-former -> 32개의 쿼리 -> LLM.

장점: 오디오-비주얼 결합 추론. 단점: 고정된 클립 길이, 임의의 시간 접지(grounding) 불가.

### VideoChat 및 Video-LLaVA

VideoChat은 Video-LLaMA의 아이디어를 유지하되 오디오를 제거하고 단순화했습니다. Video-LLaVA (Lin et al., 2023)는 이미지와 비디오 프레임 모두에 대해 단일 시각 인코더를 학습("투영 전 정렬(alignment before projection)")하여 통합된 표현을 제공했습니다. 둘 다 고정된 CLIP 인코더 + MLP + LLM 구조입니다.

둘 다 긴 비디오를 처리하지 못합니다. 둘 다 8-16프레임 시스템입니다.

### Qwen2.5-VL 및 TMRoPE

Qwen2.5-VL은 TMRoPE — 시간-모달리티 로터리 위치 임베딩(Temporal-Modality Rotary Position Embedding)을 도입했습니다. 각 패치 토큰은 실제 타임스탬프(프레임 인덱스가 아님)인 (t, h, w) 위치를 가집니다.

단순한 시간 임베딩과의 주요 차이점:

- 인덱스가 아닌 절대 시간. 모델은 "프레임 15"가 아닌 "4.2초 시점"을 봅니다.
- 클립별 회전(rotation)이 아닌 토큰별 회전. 각 시각 토큰은 자신의 타임스탬프에 따라 독립적으로 회전합니다.
- 동적 FPS와 호환됩니다. 여기서 2 FPS로 샘플링하고 저기서 4 FPS로 샘플링하더라도, TMRoPE는 불균등한 간격을 기본적으로 처리합니다.

TMRoPE는 "고양이가 몇 초에 점프합니까?"라는 쿼리를 가능하게 합니다. 모델은 "4.2초 시점"이라고 출력할 수 있습니다. Video-LLaMA는 "클립 초반"이라고만 말할 수 있었습니다.

### 프레임 샘플링 전략

균일(Uniform): 기간에 걸쳐 N개의 프레임을 고르게 샘플링합니다. 간단하지만 움직임의 정점을 놓칩니다.

동적 FPS: 움직임 강도에 기반하여 적응적으로 샘플링합니다. 광학 흐름(optical flow)이나 프레임 차이를 통해 고움직임 구간을 더 밀집하게 샘플링합니다. Qwen2.5-VL은 이를 기반으로 학습합니다.

이벤트 기반: 경량 검출기를 실행하여 행동이 일어나는 곳에서 더 많이 샘플링합니다. VideoAgent가 사용합니다.

키 프레임 + 컨텍스트: 샷 경계와 몇몇 인접 프레임을 샘플링합니다. 시네마틱 콘텐츠에 사용됩니다.

### 프레임별 풀링(Pooling)

1 FPS, 프레임당 576 토큰이면 5분 클립은 172,800 토큰입니다. Qwen2.5-VL-72B의 128k 컨텍스트 윈도우로 처리 가능하지만 비용이 높습니다.

3x3 바이리니어 풀링(pooling)으로 프레임당 64 토큰으로 줄이면 5분은 19,200 토큰이 됩니다. 대부분의 작업에 적합한 균형점입니다.

공간적 세부 정보가 덜 중요한 에이전트 워크플로우에서는 더 공격적으로 풀링(6x6 -> 프레임당 16 토큰)하세요.

### 네 가지 비디오 벤치마크

- VideoMME: 짧은 + 중간 + 긴 비디오의 종합적인 비디오 이해.
- TempCompass: 세밀한 시간적 추론, "이전" / "이후" 질문.
- EgoSchema: 장시간 1인칭 시점 비디오.
- Video-MMMU: 멀티모달 다학제 비디오 질문.

완전한 비디오-VLM 평가는 이 네 가지를 모두 포함합니다. 각각 다른 축을 강조합니다. TempCompass는 순서에, EgoSchema는 3분 이상의 추론에, VideoMME는 다양한 길이에 초점을 맞춥니다.

### 그라운딩 출력 형식

시간적 그라운딩을 위한 출력 형식:

- 자유 텍스트: "고양이가 4초 지점에서 점프한다." 파싱은 쉽지만 부정확합니다.
- 구조화된 JSON: `{"event": "jump", "start": 4.1, "end": 4.3}`. Qwen2.5-VL은 이 형식으로 학습됩니다.
- 토큰 기반: 답변과 교대로 배치되는 특수 `<time>4.1</time>` 토큰. Qwen2.5-VL의 내부 형식입니다.

토큰 기반은 다운스트림 사용에 가장 정확합니다. Qwen2.5-VL의 JSON 출력 형식은 직접 파싱됩니다.

### 2026년 모범 사례

2026년 비디오 VLM을 위한 권장 사항:

- 인코더: SigLIP 2와 M-RoPE 또는 TMRoPE(Qwen2.5-VL).
- 프레임 샘플링: 동적 FPS(움직임에 따라 1-4) 및 최대 프레임 제한.
- 프레임별 풀링: 3x3 바이리니어.
- 출력: 시간 + 이벤트 필드를 포함한 구조화된 JSON.
- 벤치마크: 일반용은 VideoMME + TempCompass, 장시간용은 EgoSchema.

## 사용하기

`code/main.py`에는 다음이 포함됩니다:

- 균일 및 동적 FPS 프레임 샘플러.
- 장난감(temporal-grounding) 평가기: 시간 T의 "정답" 이벤트와 모델 출력이 주어지면 허용 오차로 정확도를 점수화합니다.
- Video-LLaMA(16 프레임, Q-former), Video-LLaVA(8 프레임, MLP), Qwen2.5-VL(동적 FPS + TMRoPE)의 비교.

## 출시하기

이 강의는 `outputs/skill-video-vlm-frame-planner.md`를 생성합니다. 비디오 작업(모니터링, 행동 인식, 시간적 접지, 요약)이 주어지면, 프레임 샘플러, 풀링 계수, 출력 형식 및 예상 정확도 등급을 선택합니다.

## 연습 문제

1. 3분 요리 시연에 대해 균일 FPS와 동적 FPS 중 하나를 선택하세요. 토큰 수를 근거로 정당화해 보세요.

2. TMRoPE는 단순한 시간 임베딩 테이블이 할 수 없는 것을 구체적으로 무엇을 추가합니까?

3. VLM이 생성하도록 학습할 수 있는 시간적 접지용 JSON 스키마를 작성하세요. 오류 케이스를 포함해야 합니다.

4. Video-LLaVA의 "투영 전 정렬" 섹션 3을 읽어 보세요. 왜 이것이 이미지 및 비디오 인코더를 별도로 학습하는 것보다 더 나은가요?

5. VideoMME 리더보드를 기준으로, 2026년 현재 최고 오픈 모델과 최고 독점 모델 간의 격차는 얼마입니까? 그 격차 중 시간 인코딩과 기본 LLM 규모에 기인한 부분은 각각 얼마나 됩니까?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| 시간적 접지 | "시간이 국소화된 답변" | VLM이 이벤트가 발생하는 특정 타임스탬프 범위를 출력합니다 |
| TMRoPE | "시간-멀티모달 RoPE" | Qwen2.5-VL이 사용하는 절대 타임스탬프를 포함한 3D 회전 위치 |
| 동적 FPS | "모션 인식 샘플링" | 고모션 구간에서는 더 많은 프레임을 샘플링하고, 정적 구간에서는 더 적게 샘플링합니다 |
| 프레임 풀링 | "프레임별 공간 압축" | LLM에 전달하기 전에 프레임별 패치를 이중선형 보간으로 줄입니다 |
| 비디오 Q-former | "클립 압축기" | N개의 프레임을 K개의 학습된 쿼리에 매핑하는 교차 어텐션 병목 |
| VideoMME | "비디오 벤치마크" | 짧은/중간/긴 비디오를 포괄하는 벤치마크로, 2500개 이상의 샘플을 포함합니다 |
