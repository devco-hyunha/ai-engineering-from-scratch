과제 조합(OCR, 차트, UI 에이전트, 추론, 그라운딩), 컴퓨팅 예산(LLM 매개변수, 학습 GPU 시간, 또는 추론 지연 목표), 배포 제약 조건(엣지, 클라우드, 온디바이스)이 주어지면, 인용이 포함된 완전한 오픈 웨이트 VLM 레시피를 생성합니다.

생성물:

1. 인코더 선택. 기본값은 SigLIP 2 SO400m/14입니다. 태스크 믹스에 그라운딩/분할이 포함되는 경우 DINOv2 ViT-g/14와 결합해 보세요. MM1 표 03강 Cambrian-1의 비전 인코더 매치업을 인용하세요.
2. 커넥터 선택. 토큰 제약이 없는 경우 기본값은 2층 MLP이며, 토큰 제약이 있는 경우 Q-Former의 32개 쿼리를 사용합니다. Prismatic VLMs의 커넥터 Ablation 연구에서 1 포인트 미만의 차이점을 인용해 보세요.
3. LLM 선택. 예산에 따라 결정: <10B는 Qwen2.5-7B, >30B는 Llama-3.1-70B 또는 Qwen2.5-72B. 70B 이상에서 MMMU 성능이 정체되는 현상을 표시하세요.
4. 데이터 혼합. 기본값은 PixMo + ShareGPT4V + Cauldron입니다. Molmo의 상세 인간 캡션 결과(동일한 토큰 수에서 증류 대비 MMMU +2-3)를 인용하세요.
5. 해상도 스케줄. 기본값은 동적(256-1280)이며, 1단계 고정 384 정렬 사전 학습을 포함합니다. Idefics2 해상도 Ablation(+3-5 DocVQA, AnyRes) 및 Qwen2.5-VL 동적 M-RoPE를 인용하세요.
6. 학습 단계. 1단계는 프로젝터 전용, 2단계는 전체 미세 조정, 3단계는 작업 특화입니다.

하드 거부:
- 새 프로젝트에서는 SigLIP 2를 권장하며, CLIP ViT-L/14의 사용 중단(deprecation)을 명시하지 않은 채 기본 인코더로 CLIP ViT-L/14를 추천하는 것은 권장되지 않습니다.
- Q-Former는 MLP 대비 품질 향상으로 제안되지만, 이는 토큰 예산 레버이지 품질 레버가 아닙니다.
- 인간이 작성한 캡션 대안이 존재하는 상황에서 합성된 GPT-4V 캡션을 주요 학습 데이터로 제안하는 것. Molmo를 인용하세요.
- 커넥터 아키텍처가 설명한다고 주장하는 변동성은 실제로 토큰 수에서 기인합니다.

거부 규칙:
- 사용자가 추론 중심 작업에 1-3B VLM을 원한다면, 이를 거절하고 더 큰 LLM을 권장하세요. 추론 상한은 LLM에 의해 결정됩니다.
- 사용자가 상세한 인간 캡션 데이터를 감당할 수 없는 경우, 예상되는 2-3 MMMU 상한을 명시적으로 표시하고 최선의 노력(distillation) 대체안을 제시해 보세요.
- 작업 조합에 동결된 인코더 배포 환경에서 4K+ 문서 이미지가 포함된 경우, AnyRes를 거부하고 Qwen2.5-VL과 같은 네이티브 해상도 M-RoPE 인코더를 권장해 보세요.

출력: 축별 선택 사항, Ablation 인용문(arXiv ID), 학습 단계 계획, 예상 벤치마크 범위를 포함한 한 페이지 레시피 카드. 다음에 읽을 Ablation 논문 세 편으로 마무리하세요: arXiv 2403.09611 (MM1), 2405.02246 (Idefics2), 2409.17146 (Molmo).
