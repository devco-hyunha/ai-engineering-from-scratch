# 오픈 웨이트 VLM 레시피: 실제로 중요한 것

> 2024-2026년 오픈 웨이트 VLM 문헌은 어블레이션(ablation) 표의 숲입니다. Apple의 MM1은 이미지 인코더, 커넥터, 데이터 믹스의 13가지 조합을 테스트했습니다. Allen AI의 Molmo는 상세한 인간 캡션이 GPT-4V 증류(distillation)보다 우수함을 증명했습니다. Cambrian-1은 20개 이상의 인코더 비교를 수행했습니다. Idefics2는 5축 설계 공간을 공식화했습니다. Prismatic VLMs는 통제된 벤치마크에서 27가지 훈련 레시피를 비교했습니다. 이 모든 잡음 속에서, 몇 가지 결과가 논문 전반에 걸쳐 일관되게 유지됩니다: 이미지 인코더가 커넥터 아키텍처보다 중요하고, 데이터 믹스가 둘 다보다 중요하며, 상세한 인간 캡션이 증류된 합성 데이터를 능가합니다. 이 강의는 이러한 표들을 읽어, 여러분이 직접 읽지 않아도 되도록 합니다.

**유형:** 학습 + 실습
**언어:** Python (표준 라이브러리, 어블레이션 표 파서 + 레시피 선택기)
**선수 요건:** 12단계 · 05강 (LLaVA 기준선)
**시간:** 약 180분

## 학습 목표

- 5축 VLM 설계 공간을 나열하세요: 이미지 인코더, 커넥터, LLM, 데이터 믹스, 해상도 스케줄.
- MM1 / Idefics2 / Cambrian-1 어블레이션 표를 읽고, 주어진 벤치마크에서 어떤 조절 변수(knob)가 성능을 변화시키는지 예측하세요.
- 컴퓨팅 예산과 작업 믹스를 고려하여 새로운 VLM에 대한 레시피(인코더, 커넥터, 데이터, 해상도)를 선택하세요.
- 동일한 토큰 수에서 상세한 인간 캡션이 GPT-4V 증류(distillation)보다 우수한 이유를 설명하세요.

## 문제점

수백 개의 오픈 웨이트 VLM이 존재합니다. "좋은" 모델과 "최신(state-of-the-art)" 모델 간의 대부분의 격차는 아키텍처가 아닙니다. 데이터, 해상도 스케줄, 인코더 선택입니다. 모델 성능이 저하될 때 먼저 어떤 조절 변수(knob)를 조정해야 하는지 아는 것은 500만 GPU 시간의 실수를 피하는 데 도움이 됩니다.

2023년 물결(LLaVA-1.5, InstructBLIP, MiniGPT-4)은 캡션 쌍 사전 훈련 + LLaVA-Instruct-150k를 사용했습니다. 좋은 기준선입니다. MMMU 35% 부근에서 한계에 도달했습니다.

2024년 물결(MM1, Idefics2, Molmo, Cambrian-1, Prismatic VLMs)은 포괄적인 어블레이션(ablation)을 수행했습니다. 결과는 놀랍고 실용적이었습니다.

## 개념

### 5축 설계 공간

Idefics2 (Laurençon et al., 2024)는 축(axis)을 다음과 같이 명명했습니다:

1. 이미지 인코더. CLIP ViT-L/14, SigLIP SO400m/14, DINOv2 ViT-g/14, InternViT-6B. 인코더는 패치 크기, 해상도, 사전 학습 목적에 따라 다릅니다.
2. 커넥터. MLP (2-4 레이어), Q-Former (32 쿼리 + 교차 어텐션), Perceiver Resampler (64 쿼리), C-Abstractor (합성곱 + 바이리니어 풀링).
3. 언어 모델. Llama-3 8B / 70B, Mistral 7B, Phi-3, Gemma-2, Qwen2.5. LLM 크기가 매개변수 비용의 지배적인 요인입니다.
4. 학습 데이터. 캡션 쌍 (CC3M, LAION), 인터리브드 (OBELICS, MMC4), 지시문 (LLaVA-Instruct, ShareGPT4V, PixMo, Cauldron).
5. 해상도 스케줄. 고정 224/336/448, AnyRes, 네이티브 동적. 학습 중 램프업하거나 상수로 유지합니다.

모든 프로덕션 VLM은 각 축에 대해 선택을 합니다. MMMU 점수의 대부분의 분산은 축 1, 4, 5로 설명됩니다. 커넥터를 무엇을 선택했는지가 아닙니다.

### 축 1: 인코더 > 커넥터

MM1 섹션 3.2는 다음을 보여 주었습니다: CLIP ViT-L/14에서 SigLIP SO400m/14로 교체하면 MMMU 점수가 3점 이상 증가했습니다. 커넥터를 MLP에서 Perceiver Resampler로 교체하면 1점 미만 증가했습니다. Idefics2는 이를 복제했습니다: SigLIP > CLIP, Q-Former ≈ MLP ≈ Perceiver는 동일한 토큰 수에서 유사합니다.

Cambrian-1의 "Cambrian Vision Encoders Match-Up" (Tong et al., 2024)은 비전 중심 벤치마크 (CV-Bench)에서 20개 이상의 인코더를 실행했습니다. 리더보드 상위는 DINOv2와 SigLIP의 혼합입니다. CLIP은 중간 순위입니다. ImageBind와 ViT-MAE는 하위입니다. CLIP ViT-L에서 DINOv2 ViT-g/14까지의 차이는 CV-Bench에서 약 5-7점입니다.

2026년 오픈 VLM의 기본 인코더는 시맨틱 + 밀집 특징을 위한 SigLIP 2 SO400m/14입니다. 때로는 DINOv2 ViT-g/14 특징과 연결합니다 (Cambrian의 "Spatial Vision Aggregator"가 이를 수행합니다).

### 축 2: 커넥터 설계는 무의미합니다

MM1, Idefics2, Prismatic, MM-Interleaved는 모두 동일한 결론에 도달했습니다: 고정된 시각 토큰 수에서 커넥터 아키텍처는 거의 중요하지 않습니다. 평균 풀링된 패치에 대한 2레이어 MLP는 동일한 토큰 예산에서 32 쿼리 Q-Former와 1점 이내의 성능을 보입니다.

중요한 것은 토큰 수입니다. 더 많은 시각 토큰 = 더 많은 LLM 연산 = 더 나은 성능, 어느 시점까지, 그 후 수확 체감이 있습니다. 이미지당 64 토큰은 OCR에는 너무 적습니다. 576-1024 토큰은 대부분의 오픈 VLM에 대한 최적점입니다. 2048+는 문서와 차트에만 도움이 됩니다.

Q-Former와 MLP의 선택은 품질 문제가 아니라 비용 문제입니다. Q-Former는 이미지 해상도와 무관하게 토큰 수를 32-64개로 제한하는 반면, MLP는 모든 패치 토큰을 출력합니다. 고해상도 입력에서는 Q-Former가 LLM 컨텍스트를 절약하지만, 저해상도에서는 차이가 잡음 수준에 불과합니다.

### 축 3: LLM 크기가 상한선을 결정합니다

LLM을 7B에서 13B로 두 배로 늘리면 모든 VLM 논문에서 MMMU 점수가 안정적으로 2-4점 상승합니다. 70B에서는 대부분의 벤치마크가 포화 상태에 도달합니다. VLM의 멀티모달 추론 상한선은 LLM의 텍스트 추론 상한선과 같으며, 시각 인코더는 LLM에 정보를 공급할 뿐 LLM을 대신해 추론할 수 없습니다.

Qwen2.5-VL-72B와 Claude Opus 4.7이 MMMU-Pro와 ScreenSpot-Pro에서 압도적인 성능을 보이는 이유는 언어 처리 능력이 매우 크기 때문입니다. 7B VLM은 영리한 커넥터 설계만으로 70B VLM을 대체할 수 없습니다.

### 축 4: 데이터 — 상세한 인간 캡션이 증류(distillation)를 능가합니다

Molmo + PixMo (Deitke et al., 2024)는 모든 사람이 읽어야 할 2024년 결과입니다. Allen AI는 인간 annotator가 이미지를 1-3분간의 밀도 높은 음성-텍스트 변환 과정으로 설명하여 712K개의 밀도 높은 캡션이 달린 이미지를 확보했습니다. 학습 데이터 어디에도 GPT-4V 증류(distillation)는 사용되지 않았습니다.

Molmo-72B는 11개 벤치마크 중 11개 모두에서 Llama-3.2-90B-Vision을 능가했습니다. 성능 차이는 아키텍처가 아니라 캡션 품질입니다. 상세한 인간 캡션은 짧은 웹 캡션보다 이미지당 5-10배 더 많은 정보를 담고 있으며, GPT-4V 증류(distillation)가 환각(hallucination)을 일으키는 부분에서도 사실에 기반합니다.

ShareGPT4V (Chen et al., 2023)와 Cauldron (Idefics2)은 인간 캡션과 GPT-4V 캡션을 혼합하는 동일한 전략을 따랐습니다. 추세는 명확합니다. 2026년 최전선에서는 캡션 밀도 > 캡션 수량 > 증류(distillation)의 편의성입니다.

### 축 5: 해상도와 그 스케줄

Idefics2의 ablation 연구에 따르면, 384에서 448로 늘리면 1-2점 상승합니다. 이미지 분할(AnyRes)을 적용해 448에서 980으로 늘리면 OCR 벤치마크에서 추가로 3-5점 상승합니다. 고정 해상도 학습은 중간 정확도에서 정체되는 반면, 해상도를 점진적으로 높이는 방식(224에서 시작해 448 또는 네이티브 해상도로 마무리)은 더 빠르게 학습되고 더 높은 최종 성능을 달성합니다.

Cambrian-1은 해상도와 토큰 수의 트레이드오프를 실험했습니다. 고정된 연산량에서는 저해상도로 더 많은 토큰을 사용하거나, 고해상도로 더 적은 토큰을 사용할 수 있습니다. OCR에는 고해상도가 유리하고, 일반적인 장면 이해에는 저해상도-다량 토큰이 유리합니다.

2026년 생산 레시피는 Stage 1을 고정 384 해상도로 학습하고, Stage 2는 OCR 중심 작업에 대해 동적 해상도를 최대 1280까지 적용하는 것입니다.

### Prismatic의 통제된 비교

Prismatic VLMs (Karamcheti et al., 2024)는 모든 축을 통제한 논문입니다. 동일한 13B LLM, 동일한 지시 데이터, 동일한 평가 — 한 번에 하나의 축만 변합니다. 결과:

- 이미지별 시각 토큰 개수가 분산의 약 60%를 설명합니다.
- 인코더 선택이 약 20%를 설명합니다.
- 커넥터 아키텍처가 약 5%를 설명합니다.
- 나머지 약 15%는 기타 요소(데이터 혼합, 스케줄러, 학습률)가 설명합니다.

이는 대략적인 분해이지만, 문헌에서 "무엇을 먼저 제거(ablate)해야 하는가"에 대한 가장 명확한 답변입니다.

### 2026년용 선택 가이드

증거를 바탕으로, 2026년 신규 프로젝트의 기본 오픈 VLM 레시피는 다음과 같습니다:

- 인코더: NaFlex를 사용하여 SigLIP 2 SO400m/14를 네이티브 해상도로 적용하고, 세그멘테이션/그라운딩이 필요할 경우 밀집 특징을 위해 DINOv2 ViT-g/14와 연결합니다.
- 커넥터: 패치 토큰에 2층 MLP를 적용합니다. 토큰 제약이 없는 한 Q-Former는 건너뛰세요.
- LLM: Qwen2.5 / Llama-3.1 / Gemma 2, 비용은 7B, 품질은 70B, 목표 지연 시간에 따라 선택합니다.
- 데이터: PixMo + ShareGPT4V + Cauldron, 작업별 지시 데이터로 보충합니다.
- 해상도: 동적 (긴 변당 최소 256, 최대 1280 픽셀).
- 스케줄: 1단계 정렬 (프로젝터 전용), 2단계 전체 미세 조정, 3단계 작업별 미세 조정.

이러한 기본값 각각은 이 강의 끝에 인용된 논문들의 측정된 제거(ablation) 실험에 기반합니다.

## 사용하기

`code/main.py`는 제거(ablation) 표 파서 및 레시피 선택 도구입니다. MM1 및 Idefics2의 제거 표(축약본)를 인코딩하며, 다음을 쿼리할 수 있습니다:

- "예산 X와 작업 Y가 주어졌을 때, 어떤 레시피가 승리하는가?"
- "7B Llama에서 SigLIP을 CLIP으로 교체하면 MMMU 델타는 얼마인가?"
- "80% 신뢰도 답변을 위해 먼저 제거(ablate)해야 할 축은 무엇인가?"

출력은 예상 벤치마크 델타와 "먼저 제거(ablate)할 항목" 권장 사항이 포함된 순위가 매겨진 레시피 목록입니다.

## 출시하기

이 강의는 `outputs/skill-vlm-recipe-picker.md`를 생성합니다. 목표 작업 조합, 컴퓨팅 예산, 지연 시간 목표가 주어지면 전체 레시피(인코더, 커넥터, LLM, 데이터 조합, 해상도 스케줄)를 각 선택을 정당화하는 애블레이션(ablation)에 대한 인용과 함께 출력합니다. 새로운 VLM 프로젝트가 시작될 때마다 엔지니어가 Idefics2 애블레이션 테이블을 매번 새로 만들지 않도록 방지합니다.

## 연습 문제

1. MM1 섹션 3.2를 읽어 보세요. 고정된 2B LLM에서 예산이 50M 이미지일 때, 어떤 인코더가 승리합니까? 13B LLM에서는 답이 뒤집히겠습니까? 왜 그렇습니까?

2. Cambrian-1은 DINOv2 + SigLIP을 연결(concatenating)하는 것이 비전 중심 벤치마크에서는 각각 단독으로 사용하는 것보다 성능이 좋지만, MMMU에서는 신호를 추가하지 않는다고 발견했습니다. 어떤 벤치마크는 성능이 향상되고 어떤 벤치마크는 평평(flat)하게 유지될지 예측해 보세요.

3. 목표는 2B LLM 기반의 모바일 UI 에이전트입니다. 인코더, 커넥터, 해상도, 데이터 조합을 선택하세요. 각 선택을 특정 애블레이션 테이블로 정당화하세요.

4. Molmo는 4B 및 72B 모델을 출시합니다. 4B는 폐쇄형 7B VLM과 경쟁력이 있으며, 72B는 11/11 벤치마크에서 Llama-3.2-90B-Vision을 능가합니다. 이것이 LLM 크기 플래토(plateau) 가설에 대해 무엇을 말합니까?

5. 7B VLM에서 인코더 품질과 데이터 조합 품질을 분리하는 애블레이션 테이블을 설계하세요. 최소한 몇 번의 학습 실행이 필요합니까? 네 가지 축 설정을 제안하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| 애블레이션(Ablation) | "하나의 노브를 돌리기" | 디자인 공간 축 중 정확히 하나만 다른 여러 학습 실행을 수행하며, 나머지 모든 것은 일정하게 유지하는 것 |
| 커넥터(Connector) | "브리지" / "프로젝터" | 비전 인코더의 출력을 LLM의 토큰 공간으로 매핑하는 학습 가능한 모듈(MLP, Q-Former, Perceiver) |
| 상세한 인간 캡션(Detailed human caption) | "밀집 캡션(Dense caption)" | 웹 alt 텍스트보다 더 풍부한 다문장 인간 작성 설명(일반적으로 80-300 토큰) |
| 증류(Distillation) | "GPT-4V 캡션" | 더 강력한 비공개 VLM이 생성한 학습 데이터; 편리하지만 상속된 환각(Hallucination)에 취약함 |
| AnyRes / 동적 해상도(dynamic res) | "고해상도 경로" | 테일링(tiling)이나 M-RoPE를 통해 인코더의 네이티브 해상도보다 큰 이미지를 입력하는 전략 |
| 해상도 램프(Resolution ramp) | "커리큘럼(Curriculum)" | 낮은 해상도로 시작하여 점차 높이는 학습 스케줄로, 정렬(Alignment) 학습을 가속화함 |
| 비전 중심 벤치마크 | "CV-Bench / BLINK" | 언어 중심 추론이 아닌 세밀한 시각 인지를 강조하는 평가 |
| PixMo | "Molmo의 데이터" | Allen AI의 712K개 밀집 캡션 이미지 데이터셋; 인간 발화를 밀집 캡션으로 전사한 데이터 |
