# LLaVA와 시각 지시 튜닝

> LLaVA (2023년 4월)는 전 세계에서 가장 많이 복제된 멀티모달 아키텍처입니다. BLIP-2의 Q-Former를 2층 MLP로 대체하고, Flamingo의 게이트된 교차 어텐션을 단순한 토큰 연결로 대체했으며, 텍스트 전용 캡션에서 GPT-4가 생성한 158k개의 시각-지시 대화(turn)로 학습했습니다. 2023년에서 2026년 사이에 VLM을 구축한 실무자라면 누구나 LLaVA의 변형 중 하나를 구축했습니다. LLaVA-1.5는 AnyRes를 추가했습니다. LLaVA-NeXT는 해상도를 높였습니다. LLaVA-OneVision은 이미지, 다중 이미지, 비디오를 하나의 레시피로 통합했습니다. 이 강의는 레시피를 읽고, 프로젝터를 구현하며, 왜 "단순함이 승리했는지"를 설명합니다.

**유형:** Build
**언어:** Python (stdlib, 프로젝터 + 지시 템플릿 빌더)
**선수 요건:** 12단계 · 02강 (CLIP), 11단계 (LLM 엔지니어링 — 지시 튜닝)
**시간:** 약 180분

## 학습 목표

- ViT 패치 임베딩(차원 1024)을 LLM의 임베딩 차원(차원 4096)으로 매핑하는 2층 MLP 프로젝터를 구축해 보세요.
- LLaVA의 2단계 레시피를 따라가 보세요: (1) 558k개의 캡션 쌍에 대한 프로젝터 정렬, (2) GPT-4가 생성한 158k개의 대화(turn)에 대한 시각 지시 튜닝.
- 이미지 토큰 자리 표시자, 시스템 프롬프트, 사용자/어시스턴트 대화를 포함하는 LLaVA 형식의 프롬프트를 구성해 보세요.
- Q-Former의 토큰 예산 이점에도 불구하고 커뮤니티가 Q-Former에서 MLP로 이동한 이유를 설명해 보세요.

## 문제점

BLIP-2의 Q-Former (12.03강)는 이미지를 32개의 토큰으로 압축합니다. 깔끔하고 효율적이며 벤치마크에 좋습니다. 하지만 두 가지 문제가 있습니다.

첫째, Q-Former는 학습 가능하지만 그 손실은 최종 작업이 아닙니다. 1단계는 ITC+ITM+ITG를 학습합니다. 2단계는 LM 손실을 학습합니다. 쿼리들은 LLM이 디코딩해야 하는 중간 표현을 학습합니다. 정보 병목 현상에서 정보가 손실됩니다.

둘째, Q-Former는 188M개의 매개변수를 차지하며, LLaVA의 2023년 규모에서는 목표 LLM과 함께 공동 설계해야 했습니다. LLM을 변경하면 Q-Former를 재학습해야 합니다. 비전 인코더를 변경하면 재학습해야 합니다. 모든 조합은 별도의 R&D 프로젝트였습니다.

LLaVA의 답변는 단순함으로 인해 당혹스러울 정도였습니다. ViT의 576개 패치 토큰을 가져와 각각을 2층 MLP(`1024 → 4096 → 4096`)를 통해 전달하고, 모든 576개를 LLM의 입력 시퀀스에 덤프하는 방식입니다. 병목 현상이 없습니다. 이상한 목적 함수에 대한 1단계 사전 학습도 없습니다. 직접적인 LM 손실로 MLP를 학습하기만 하면 됩니다.

데이터는 어디서 오는 걸까요? LLaVA의 두 번째 통찰은 GPT-4(텍스트 전용)를 사용하여 지시 데이터를 생성하는 것입니다. GPT-4에 COCO 캡션과 이미지 바운딩 박스 데이터를 입력하고, 대화, 설명, 복잡한 추론 질문을 생성하도록 요청합니다. 158k개의 지시-응답 턴을 무료로 생성합니다. 인간 주석이 필요 없습니다.

결과: 8개의 A100 GPU로 하루 동안 실행된 VLM이 MMMU에서 Flamingo를 능가했으며, 커뮤니티가 확장할 수 있는 오픈 체크포인트를 출시했습니다. 2023년 말까지 50개 이상의 포크가 파생되었습니다.

## 개념

### 아키텍처

13B 크기의 LLaVA-1.5:
- 비전 인코더: CLIP ViT-L/14 @ 336 (1단계 동안 동결, 2단계에서 선택적으로 동결 해제).
- 프로젝터: GELU 활성화 함수를 사용하는 2층 MLP, `1024 → 4096 → 4096`.
- LLM: Vicuna-13B (나중에 Llama-3.1-8B).

이미지 + 텍스트 프롬프트에 대한 순방향 패스:

```
img -> ViT -> 576 patches of dim 1024
patches -> MLP -> 576 tokens of dim 4096
prompt: system + "<image>" placeholder + user question
replace <image> token with the 576 projected tokens
feed the full sequence to the LLM
decode response
```

이미지는 LLM 컨텍스트의 576개 토큰을 차지합니다. 2048 컨텍스트에서는 텍스트에 1472개 토큰이 남습니다. 32k 컨텍스트에서는 반올림 오차 수준입니다.

### 1단계: 프로젝트 정렬

ViT를 동결합니다. LLM을 동결합니다. 2층 MLP만 학습합니다. 데이터셋: 558k개의 이미지-캡션 쌍 (LAION-CC-SBU). 손실: 투사된 이미지 토큰을 조건으로 캡션에 대한 언어 모델링.

배치 크기 128으로 단일 에포크에서 몇 시간 안에 완료됩니다. 프로젝트는 ViT 공간을 LLM 공간으로 매핑하는 방법을 학습합니다. 작업별 감독이 없습니다.

### 2단계: 시각 지시 미세 조정

프로젝터를 동결 해제합니다 (학습 가능 상태 유지). LLM을 동결 해제합니다 (보통 전체, 때로는 LoRA). 158k개의 시각 지시 턴으로 학습합니다.

지시 데이터가 핵심입니다. Liu et al.는 이를 다음과 같이 생성했습니다:
1. COCO 이미지를 가져옵니다.
2. 텍스트 설명을 추출합니다 (5개의 인간 캡션 + 바운딩 박스 목록).
3. 세 가지 프롬프트 템플릿과 함께 GPT-4에 전송합니다:
   - 대화: "이 이미지에 대해 사용자와 어시스턴트 간의 왕복 대화를 생성하세요."
   - 상세한 설명: "이미지에 대해 풍부하고 상세한 설명을 해 보세요."
   - 복잡한 추론: "이미지에 대해 추론이 필요한 질문을 하고, 그 질문에 답해 보세요."
4. GPT-4의 출력 결과를 (지시문, 응답) 쌍으로 파싱합니다.

이 과정은 이미지를 직접 다루지 않으며, 오직 텍스트 설명에만 의존합니다. GPT-4는 그럴듯한 이미지 내용을 환각(Hallucination)합니다. 일부 잡음이 있었지만, 효과는 있었습니다: 158k 턴(turn)은 대화 기능을 활성화하기에 충분했습니다.

### 커뮤니티가 이 방식을 채택한 이유

- 1단계 전용 손실 함수를 조정할 필요가 없습니다. 전체 과정에서 LM 손실(LM loss)을 사용합니다.
- 프로젝터(Projector)는 며칠이 아닌 몇 시간 안에 학습됩니다.
- 프로젝터만 재학습하면 LLM을 교체할 수 있습니다 (LLaVA-Llama2, LLaVA-Mistral, LLaVA-Llama3).
- 시각-지시문 데이터 파이프라인은 GPT-4를 사용하며, 새로운 도메인에 대해 재생성하는 비용이 저렴합니다.

### LLaVA-1.5 및 LLaVA-NeXT

LLaVA-1.5 (2023년 10월)에서 추가된 사항:
- 학술적 작업 데이터 (VQA, OKVQA, RefCOCO)가 지시문 미세 조정(instruction tuning)에 혼합되었습니다.
- 더 나은 시스템 프롬프트(System Prompt).
- 컨텍스트 윈도우(Context Window)가 2048에서 32k로 확장되었습니다.

LLaVA-NeXT (2024년 1월)에서 추가된 사항:
- AnyRes: 고해상도 이미지를 336x336 크롭(crop)의 2x2 또는 1x3 그리드로 분할하고, 하나의 전역 저해상도 썸네일을 추가합니다. 각 크롭은 576개의 토큰이 되며, 이미지당 총 약 2880개의 시각 토큰이 됩니다. OCR 및 차트 작업 성능이 급격히 향상되었습니다.
- ShareGPT4V (고품질 GPT-4V 캡션)를 포함한 더 나은 지시문 데이터 혼합.
- 더 강력한 기반 LLM (Mistral-7B, Yi-34B).

### LLaVA-OneVision

12.08강에서는 OneVision을 심층적으로 다룹니다. 요약하자면: 동일한 프로젝터(Projector)를 사용하지만, 단일 이미지, 다중 이미지, 비디오를 하나의 모델에서 공유된 시각 토큰 예산으로 다루는 커리큘럼으로 학습합니다.

### Q-Former와의 비교

| | Q-Former (BLIP-2) | MLP (LLaVA) |
|---|---|---|
| 이미지당 시각 토큰 | 32 | 576 (기본) 또는 2880 (AnyRes) |
| 학습 가능한 매개변수 | 188M + LM | 40M + LM |
| 1단계 손실 | ITC+ITM+ITG | LM만 |
| LLM 교체 | 재학습 필요 | 최소한의 재학습으로 교체 가능 |
| 다중 이미지 | 어색함 | 자연스러움 (연결) |
| 비디오 | 어색함 | 자연스러움 (프레임별 연결) |
| 토큰 예산 | 작음 | 큼 |

MLP는 단순성과 토큰 유연성에서 우위를 점합니다. Q-Former는 토큰 예산에서 우위를 점합니다. 2023년 후반에는 토큰 예산이 더 이상 구속 조건이 아니게 되었고(LLM 컨텍스트가 32k-128k+로 증가), 단순성이 지배적이게 되었습니다.

### 프롬프트 형식

```
A chat between a curious human and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the human's questions. USER: <image> Describe this image in detail. ASSISTANT: The image shows ...
```

`<image>`는 플레이스홀더 토큰입니다. 토큰화 전에, 이 토큰은 576개의 시각 토큰(또는 AnyRes를 사용할 경우 2880개)으로 대체됩니다. 토크나이저는 학습된 시퀀스보다 약간 더 긴 시퀀스를 보게 되지만, LLM은 1단계에서 이를 학습했으므로 새로운 입력을 처리할 수 있습니다.

### 매개변수 경제성

LLaVA-1.5-7B 구성 breakdown:
- CLIP ViT-L/14 @ 336: 303M (1단계에서 동결, 2단계에서 종종 동결 해제).
- 프로젝터 (2x 선형): ~22M 학습 가능.
- Llama-7B: 7B.
- 총계: 7.3B 매개변수. 2단계에서 학습 가능한 부분: 전체 7B + 22M 프로젝트.

2단계 학습 비용: 8xA100에서 약 20시간. 이것이 핵심 수치입니다 — 하루, 한 노드, 재현 가능. 이것이 LLaVA가 확산된 이유입니다.

```figure
mm-llava-projector
```

## 사용하기

`code/main.py`는 다음을 구현합니다:

1. 순수 Python으로 작성된 2층 MLP 프로젝트 (토이 스케일에서 dim 16 → 32 → 32).
2. 프롬프트 빌딩 파이프라인: 시스템 프롬프트 + N개의 투사된 토큰으로 대체된 `<image>` + 사용자 턴 + 어시스턴트 생성 플레이스홀더.
3. LLM 컨텍스트에서 576-토큰 시각 블록이 어떻게 보이는지 시각화하는 도구 (2k / 32k / 128k 컨텍스트의 소비 비율).

## 출시하기

이 강의는 `outputs/skill-llava-vibes-eval.md`를 생성합니다. LLaVA 계열 체크포인트가 주어지면, 10-프롬프트 바이브스 평가 스위트(3개 캡셔닝, 3개 VQA, 2개 추론, 2개 거부)를 실행하고 사람이 읽기 쉬운 스코어카드를 보고합니다. 벤치마크가 아닙니다; 프로젝트와 LLM이 잘 연결되어 있는지 확인하는 스모크 테스트입니다.

## 연습 문제

1. `1024 → 4096 → 4096`에서 2층 MLP 프로젝트의 학습 가능 매개변수 수를 계산하세요. GELU와 편향을 포함하면, LLaVA-13B의 몇 비율을 차지합니까?

2. "거부" 케이스에 대한 LLaVA 프롬프트를 구성하세요 — 이미지에는 개인이 포함되어 있습니다. 예상되는 어시스턴트 응답을 작성하세요. LLaVA가 제로샷으로 이를 거부해야 하는 이유는 무엇이며, 거부를 강화하기 위해 어떤 학습 데이터가 필요합니까?

3. LLaVA-NeXT 블로그의 AnyRes 섹션을 읽어 보세요. AnyRes에서 1344x672 이미지의 시각적 토큰 수를 계산해 보세요. 336x336에서의 기본 576 토큰과 비교해 보세요.

4. LLaVA의 stage-1 프로젝터는 캡션에 대해 LM 손실로 학습됩니다. stage 1을 건너뛰고 바로 stage 2 (시각적 지시 조정)로 진행하면 어떤 일이 발생할까요? Prismatic VLMs의 ablation 연구(arXiv:2402.07865)를 인용하여 답해 보세요.

5. LLaVA-Instruct-150k는 COCO 캡션을 사용하여 GPT-4로 지시문을 생성합니다. 새로운 도메인(의료 X-ray, 위성 이미지)의 경우, 도메인 지시문을 생성하기 위한 4단계 데이터 파이프라인을 설명해 보세요. 각 단계에서 어떤 문제가 발생할 수 있을까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 프로젝터 | "MLP 브리지" | ViT 차원을 LLM 차원으로 매핑하는 GELU가 포함된 2층 MLP |
| 이미지 토큰 | "<image> 자리표시자" | 추론 전 N개의 투사된 시각적 토큰으로 대체되는 프롬프트 마커 |
| 시각적 지시 조정 | "LLaVA stage 2" | GPT-4가 생성한 (이미지, 지시문, 응답) 삼중항(triplet)에 대한 학습 |
| Stage 1 정렬 | "프로젝터 사전 학습" | ViT와 LLM을 동결하고, 캡션에 대해 LM 손실로 프로젝터를 학습 |
| AnyRes | "멀티 크롭 타일링" | 고해상도 이미지를 타일 그리드로 분할하고 각 타일의 시각적 토큰을 연결(concatenate) |
| LLaVA-Instruct | "GPT-4 생성" | COCO 캡션 + GPT-4로 합성된 158k개의 지시문-응답 쌍 |
| 시각 인코더 동결 | "백본 잠금" | CLIP 가중치가 stage 1에서 업데이트되지 않으며, stage 2에서도 업데이트되지 않는 경우가 있음 |
| ShareGPT4V | "더 나은 캡션" | GPT-4V가 생성한 100만 개의 밀집 캡션으로, 더 높은 품질의 정렬에 사용 |
| VQA | "시각적 질문 답변" | 이미지에 대한 자유 형식 질문에 답하는 작업 |
| Prismatic VLMs | "설계 공간 논문" | Karamcheti 2024 ablation 연구로, 프로젝터 및 데이터 선택을 체계적으로 테스트 |
