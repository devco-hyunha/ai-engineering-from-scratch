컴퓨터 사용 제품 사양(도메인, 액션 세트, 평가 대상)이 주어지면 에이전트 루프, 메모리 전략, 그라운딩 모드, 평가를 설계해 보세요.

다음 내용을 생성합니다:

1. 액션 스키마. 지원되는 액션(클릭, 입력, 스크롤, 드래그, 선택, 이동, 완료, 시각적 도구 포함)의 JSON 정의입니다.
2. 입력 모드. 스크린샷 전용, 접근성 트리, 또는 하이브리드입니다. 브라우저는 하이브리드가 기본이며, 접근성 훅이 없는 데스크톱 앱은 스크린샷 전용을 사용합니다.
3. 모델 선택. Qwen2.5-VL-72B (오픈), Claude Opus 4.7 컴퓨터 사용 (클로즈드, 강력), GPT-5 (클로즈드, 더 강력)입니다. 벤치마크와 비용으로 정당화합니다.
4. 메모리 전략. 5단계마다 요약 체인을 생성하고 마지막 2개 스크린샷을 실시간으로 유지합니다. 매우 긴 워크플로우의 경우 로그 전용으로 처리합니다.
5. 오류 복구. 액션 실패 시 `element_desc` 시맨틱 힌트를 통해 그라운딩을 재수행합니다. 최대 2회까지 재시도하며, 실패 시 재계획(replanning)으로 폴백합니다.
6. 평가 계획. 그라운딩에는 ScreenSpot-Pro, 엔드투엔드에는 VisualWebArena, 어려운 다단계 워크플로우에는 AgentVista를 사용합니다. 예상 점수 티어를 설정합니다.

하드 리젝트(Hard Rejects):
- 자유 텍스트 액션 출력 사용은 금지합니다. 항상 명시적 스키마를 가진 JSON 구조로 출력해야 합니다.
- 오픈 7B 모델이 AgentVista에서 프론티어 모델과 동등하다고 주장하는 것은 금지합니다. 격차는 10-20점입니다.
- 스크린샷 간 좌표 메모리에 의존하는 것은 금지합니다. 캡처 간 좌표가 드리프트(drift)됩니다.

거절 규칙:
- 제품이 50단계 이상의 워크플로우를 요구한다면 단일 에이전트 루프를 거절하고 계층적 플래너(planner) + 실행자(executor) 분리를 권장합니다.
- 제품이 접근성 훅이 없는 규제 대상 플랫폼에서 작동한다면 스크린샷 전용의 신뢰성 한계를 표시하고 강력한 검증을 제안합니다.
- 작업 범주가 학습된 분포(특수 산업용 소프트웨어)를 벗어난다면 오프더셀프(off-the-shelf) 솔루션을 거절하고 도메인 스크린샷에 대한 미세 조정(fine-tuning)을 제안합니다.

출력: 한 페이지 에이전트 설계로, 행동 스키마, 입력 모드, 모델 선택, 메모리, 복구, 평가를 포함합니다. arXiv 2401.10935 (SeeClick), 2401.13649 (VisualWebArena), 2602.23166 (AgentVista)로 마무리하세요.
