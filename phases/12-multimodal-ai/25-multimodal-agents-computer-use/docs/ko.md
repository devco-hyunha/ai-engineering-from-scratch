# 멀티모달 에이전트와 컴퓨터 사용 (캡스톤)

> 2026년 최전선 제품은 스크린샷을 읽고, 버튼을 클릭하며, 웹 UI를 탐색하고, 양식을 작성하며, 워크플로우를 끝까지 완수하는 멀티모달 에이전트입니다. SeeClick과 CogAgent (2024)는 GUI 접지 원시 요소를 증명했습니다. Ferret-UI는 모바일을 추가했습니다. ChartAgent는 차트를 위한 시각적 도구 사용을 도입했습니다. VisualWebArena와 AgentVista (2026)는 최전선이 추격하는 벤치마크이며, Gemini 3 Pro와 Claude Opus 4.7조차 AgentVista의 어려운 작업에서 약 30%의 점수를 기록합니다. 이 캡스톤은 12단계의 모든 흐름을 통합합니다: 인식 (고해상도 VLM), 추론 (도구 사용이 포함된 LLM), 접지 (좌표 출력), 장기 기억, 그리고 평가.

**유형:** Capstone
**언어:** Python (표준 라이브러리, 액션 스키마 + 에이전트 루프 골격)
**선수 요건:** 12단계 · 05강 (LLaVA), 12단계 · 09강 (Qwen-VL JSON), 14단계 (에이전트 엔지니어링)
**시간:** 약 240분

## 학습 목표

- 멀티모달 에이전트 루프를 설계하세요: 인식 → 추론 → 행동 → 관찰 → 반복.
- VLM이 JSON으로 출력할 수 있는 GUI 접지 출력 스키마 (클릭 좌표, 텍스트 입력, 스크롤, 드래그)를 구축하세요.
- 스크린샷 전용 에이전트, 접근성 트리 에이전트, 하이브리드 에이전트를 비교하세요.
- 작은 VisualWebArena 슬라이스에 대한 멀티모달 에이전트 벤치마크 평가를 설정하세요.

## 문제점

예약 사이트 워크플로우: "4월 15일 도쿄행 항공권을 찾아주세요, 통로 좌석이고 $800 미만이어야 하며, 예약하세요."

멀티모달 에이전트는 다음을 수행해야 합니다:

1. 브라우저의 스크린샷을 찍습니다.
2. 스크린샷 + URL + 목표를 계획으로 파싱합니다.
3. 구조화된 액션을 출력합니다: 클릭 (x,y 위치), "Tokyo" 입력 (요소 E 위치), 아래로 스크롤, 선택 (라디오 버튼).
4. 브라우저에 액션을 적용합니다.
5. 새로운 상태를 관찰합니다 (다음 스크린샷).
6. 작업이 완료될 때까지 반복합니다.

각 단계는 멀티모달 VLM 호출입니다. VLM 출력은 파싱 가능한 JSON이어야 합니다. 오류는 단계에 걸쳐 누적되므로, 복구가 중요합니다.

## 개념

### GUI 접지 — 원시 요소

GUI 그라운딩은 스크린샷과 자연어 지시문을 입력으로 받아 클릭할 (x, y) 좌표(또는 다른 동작)를 출력하는 작업입니다.

SeeClick (arXiv:2401.10935)은 대규모로 공개된 최초의 결과입니다. 합성 및 실제 GUI 데이터로 VLM을 미세 조정하고, 좌표를 일반 텍스트 토큰으로 출력합니다. 잘 작동합니다.

CogAgent (arXiv:2312.08914)는 밀집된 UI를 위해 1120x1120 고해상도 인코딩을 추가했습니다. 점수: 웹 내비게이션에서 약 84%.

Ferret-UI (arXiv:2404.05719)는 모바일 UI에 집중하며 iOS 접근성 데이터와 통합합니다.

출력 형식은 보통 JSON입니다:

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc`는 복구를 돕습니다: 스크린샷 간에 좌표가 어긋나면, 시맨틱 힌트가 시스템이 다시 그라운딩할 수 있게 해줍니다.

### 동작 스키마

일반적인 동작 스키마는 6-10가지 동작 유형을 포함합니다:

- `click`: (x, y)
- `type`: (text, x?, y?)
- `scroll`: (direction, amount)
- `drag`: (x0, y0, x1, y1)
- `select`: (option_index)
- `hover`: (x, y)
- `navigate`: (url)
- `wait`: (ms)
- `done`: (success, explanation)

에이전트는 단계마다 하나의 동작을 방출합니다. 브라우저 래퍼가 이를 실행하고 새로운 상태를 반환합니다.

### 스크린샷 전용 vs 접근성 트리

두 가지 입력 모드:

- 스크린샷 전용: 전체 이미지, 구조적 정보 없음. 가장 범용적이며 모든 앱에서 작동합니다.
- 접근성 트리: 구조화된 DOM / iOS 접근성 정보. 그라운딩에 훨씬 더 신뢰할 수 있으며, 트리가 이용 가능한 곳에서 작동합니다.
- 하이브리드: 둘 다 사용하며, 트리는 원자적 동작을 위한 신뢰할 수 있는 그라운더로, 스크린샷은 시맨틱 컨텍스트로 사용합니다.

프로덕션 에이전트는 가능한 경우 하이브리드를 사용합니다. 브라우저 자동화(Selenium + 접근성)는 항상 트리를 가지고 있으며, 데스크톱 앱은 때때로 트리를 가집니다.

### 장기 기억

20단계 워크플로우는 20개의 스크린샷을 생성합니다. VLM의 컨텍스트는 빠르게 채워집니다. 세 가지 압축 전략:

- 요약 체인: 5단계마다 일어난 일을 요약하고, 오래된 스크린샷을 버립니다.
- 스킵 프레임: 첫 번째, 마지막, 그리고 3번째마다의 스크린샷을 유지합니다.
- 도구 기록 로그: 작업을 실행하고, 수행된 내용을 텍스트 로그로 유지합니다. 이전 스크린샷을 다시 보지 마세요.

Claude의 컴퓨터 사용 API는 로그 패턴을 사용합니다. 더 단순하고 신뢰성이 높습니다.

### 시각적 도구 사용

ChartAgent (arXiv:2510.04514)는 차트 이해를 위한 시각적 도구 사용을 도입합니다: 잘라내기(crop), 확대(zoom), OCR, 외부 감지 호출. 에이전트는 "영역 (100, 200, 300, 400)으로 잘라낸 후 OCR을 호출"과 같은 도구 호출을 출력할 수 있습니다. 도구는 텍스트를 반환하며, VLM은 추론을 계속합니다.

이 패턴은 일반화됩니다: 세트 오브 마크(set-of-mark) 프롬팅, 영역 주석, 외부 감지 도구는 모두 "도구 호출을 출력하고, 구조화된 응답을 받는다"라는 동일한 스키마에 부합합니다.

### 2026년 벤치마크

- ScreenSpot-Pro. 약 1,000개의 웹 스크린샷에 대한 GUI 접지(grounding). 오픈 소스 SOTA Qwen2.5-VL-72B는 약 85%. 프론티어 모델은 약 90%.
- VisualWebArena. 엔드투엔드 웹 작업 (쇼핑, 포럼, 분류 광고). 오픈 소스 SOTA는 약 20%. Gemini 3 Pro는 약 27%.
- AgentVista (arXiv:2602.23166). 2026년 가장 어려운 벤치마크. 12개 영역에 걸친 현실적인 워크플로우. 프론티어 모델은 27-40% 점수를 받으며, 오픈 모델은 10-20%입니다.
- WebArena / WebShop. 오래된 벤치마크이며, 프론티어 모델에 의해 포화(saturated) 상태입니다.

### 왜 여전히 어려운가

에이전트 성능 병목 현상:

1. 세밀한 규모의 시각적 접지. "작은 X를 클릭하세요"는 모바일 해상도에서 자주 실패합니다.
2. 장기적 계획(Long-horizon planning). 10번의 작업 후, 에이전트는 목표에서 벗어납니다.
3. 오류 복구. 클릭이 실패했을 때 (잘못된 버튼), 감지 및 복구는 거의 훈련 데이터에 포함되지 않습니다.
4. 교차 페이지 컨텍스트. 탭 간 이동이나 긴 양식에서 상태가 손실됩니다.

연구 방향: 메모리 아키텍처, 명시적 재계획, 멀티모달 검증 (작업 성공을 위한 스크린샷 매칭).

### 캡스톤 빌드 프로젝트

캡스톤 과제: 다음을 수행하는 컴퓨터 사용 에이전트를 구축합니다:

1. 예약 사이트 목업(mock) 페이지의 HTML과 스크린샷을 읽습니다.
2. 다단계 시퀀스를 계획합니다: 검색 → 선택 → 양식 작성 → 제출.
3. 작업 스키마와 일치하는 JSON 작업을 출력합니다.
4. 고정된 10개 작업 슬라이스(slice)에서 평가합니다.

이 강의는 실제 브라우저로 쉽게 확장할 수 있는 스캐폴드(scaffold) 코드를 제공합니다.

```figure
mm-agent-loop
```

## 사용하기

`code/main.py`는 캡스톤 스캐폴드입니다:

- 액션 스키마 JSON 정의 (10개 액션).
- 모의 브라우저 상태를 dict로 표현.
- 에이전트 루프 골격: 상태 수신, 액션 방출, 적용, 반복.
- 10개 작업 미니 벤치마크 (합성 페이지)로 엔드투엔드 성공률을 측정합니다.
- 액션이 실패했을 때의 오류 복구 훅.

## 출시하기

이 강의는 `outputs/skill-multimodal-agent-designer.md`를 생성합니다. 컴퓨터 사용 제품 (도메인, 액션 세트, 평가 대상)이 주어지면 전체 에이전트 루프, 메모리 전략, 그라운딩 모드 및 예상 벤치마크 점수를 설계합니다.

## 연습 문제

1. 액션 스키마에 `screenshot_region` 도구 (크롭 + 줌)를 추가하세요. 어떤 작업이 이점을 얻습니까?

2. AgentVista (arXiv:2602.23166)를 읽어보세요. 가장 어려운 작업 범주와 프론티어 모델이 여전히 실패하는 이유를 설명하세요.

3. 장기 메모리 압축: 4개 이하의 스크린샷만 라이브로 유지하고, 개수 제한 없이 기록하는 요약 체인을 설계하세요.

4. 오류 복구 훅을 구축하세요: 액션 실패 (버튼을 찾을 수 없음) 시 에이전트는 다음에 무엇을 합니까?

5. 10개 웹 작업에서 스크린샷 전용 Claude 4.07강 스크린샷 + 접근성 트리 하이브리드 Qwen2.5-VL을 비교하세요. 어떤 작업에서 누가 이깁니까?

|------|-----------------|------------------------|
