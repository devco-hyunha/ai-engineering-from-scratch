# Emu3: 이미지 및 비디오 생성을 위한 다음 토큰 예측

> BAAI의 Emu3 (Wang et al., 2024년 9월)는 확산 모델 대 자기회귀 논쟁을 종결해야 했던 2024년의 결과입니다. 단일 Llama 스타일 디코더 전용 트랜스포머는 텍스트 + VQ 이미지 토큰 + 3D VQ 비디오 토큰으로 구성된 통합 어휘에 대해 다음 토큰 예측 목표만으로 학습되었으며, 이미지 생성에서 SDXL을, 인식에서 LLaVA-1.6을 능가합니다. CLIP 손실은 없습니다. 확산 스케줄도 없습니다. 추론 시 품질을 위해 분류기 없는 가이드(classifier-free guidance)를 사용하지만, 핵심 학습 목표는 교사 강제(teacher forcing)를 포함한 다음 토큰 예측입니다. Nature에 게재되었습니다. 이 강의는 Emu3 논문을 읽어보며, 왜 더 나은 토크나이저와 스케일링이 필요한 전부인지 설명하고 확산 모델 접근법과 대조합니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 3D 비디오 토크나이저 수학 + 자기회귀 샘플러 골격)
**선수 요건:** 12단계 · 11강 (Chameleon)
**시간:** 약 120분

## 학습 목표

- 확산 모델이 이미지 품질에 필수적이라는 오래된 가정에도 불구하고, Emu3의 단일 손실 다음 토큰 목표가 왜 작동하는지 설명해 보세요.
- 3D 비디오 토크나이저를 설명해 보세요: 시공간 VQ 코드북이 어떤 모습인지, 왜 패치가 시간을 포함하는지 설명해 보세요.
- Emu3와 Stable Diffusion XL을 (학습 연산량, 추론 비용, 품질 상한) 측면에서 비교해 보세요.
- 동일한 Emu3 모델이 수행하는 세 가지 역할을 나열해 보세요: Emu3-Gen (이미지 생성), Emu3-Chat (인식), Emu3-Stage2 (비디오 생성).

## 문제점

2024년까지의 통념: 이미지 생성에는 확산 모델이 필요합니다. 논거: 이산 이미지 토큰은 세부 정보를 복원하기 위해 너무 많은 정보를 잃으며, 자기회귀 샘플링은 수천 개의 토큰에 걸쳐 오차를 누적합니다. Stable Diffusion, DALL-E 3, Imagen, Midjourney는 모두 어떤 형태의 확산 모델을 사용합니다. Chameleon (12.11강)은 작은 규모에서 이를 부분적으로 반증했지만, 품질 면에서 SDXL을 따라잡지 못했습니다.

Emu3는 이 논거를 정면으로 공격했습니다. 주장: 더 나은 시각 토크나이저 + 충분한 스케일 + 다음 토큰 손실 = 인식도 수행하는 동일한 모델에서 확산 모델을 능가하는 이미지 생성.

출간 당시 이 베팅은 논쟁을 불러일으켰습니다. 2년 후, 오픈소스 통합 생성 계열(Emu3, Show-o, Janus-Pro, Transfusion)은 연구의 기본 경로가 되었으며, 프로덕션 프론티어 모델은 일부 변형을 사용하는 것으로 보입니다.

## 개념

### Emu3 토크나이저

핵심 구성 요소는 시각 토크나이저입니다. Emu3는 토큰당 8x8 해상도 감소로 커스텀 IBQ 클래스 토크나이저(Inverse Bottleneck Quantizer, SBER-MoVQGAN 계열)를 훈련합니다. 512x512 이미지는 코드북 크기 32768에서 64x64 = 4096 토큰이 됩니다.

이것은 K=8192에서 512x512당 1024 토큰을 사용하는 Chameleon보다 크지만, 토큰당 비용은 더 저렴합니다(더 작은 코드북 조회, 더 단순한 코덱). 핵심 지표는 30.5 dB의 재구성 PSNR로, 32 dB의 Stable Diffusion 연속 잠재 공간과 경쟁할 수 있습니다.

비디오의 경우: 3D VQ 토크나이저는 시공간 패치(4x4x4 픽셀)를 하나의 정수로 인코딩합니다. 8 FPS의 4초 클립은 32 프레임을 가지며, 256x256에서 4x 공간 및 4x 시간 감소가 적용되면 토큰 개수는 (256/4) * (256/4) * (32/4) = 64 * 64 * 8 = 32,768 토큰입니다.

토크나이저 품질이 상한선입니다. Emu3의 기여는 부분적으로 "매우 좋은 토크나이저를 훈련했다"는 것입니다.

### 단일 손실 훈련

Emu3는 하나의 목적 함수를 사용합니다: 텍스트 토큰, 2D 이미지 토큰, 3D 비디오 토큰에 걸친 공유 어휘에서의 다음 토큰 예측. 훈련 중 가중치는 기여도를 균형 잡기 위해 모달리티별 계수 곱해지지만, 손실 함수는 동일합니다.

다음의 혼합으로 훈련합니다:
- 이미지 생성: `<text caption> <image> image_tokens </image>`
- 이미지 인식: `<image> image_tokens </image> <question> text_tokens`
- 비디오 생성: `<text caption> <video> video_tokens </video>`
- 비디오 인식: 유사합니다.
- 텍스트 전용: 표준 NTP.

모델은 데이터 분포에서 이미지 토큰과 텍스트 토큰 중 언제 방출할지 학습합니다. 생성은 `<image>` 태그 이후 모델이 이미지 토큰을 예측하는 것에서 emerges합니다.

### Classifier-free guidance와 온도

자기회귀 이미지 생성은 추론 시 classifier-free guidance(CFG)를 적용하면 훨씬 더 좋아집니다. Emu3는 이를 사용합니다: 한 번은 전체 캡션으로, 한 번은 빈 캡션으로 두 번 생성하고, 로짓을 guidance 가중치(일반적으로 3.0-7.0)로 혼합합니다. 이는 확산 모델이 사용하는 동일한 CFG 트릭을 자기회귀 설정에 차용한 것입니다.

온도(Temperature)가 중요합니다: 너무 높으면 아티팩트가 발생하고, 너무 낮으면 모드 붕괴(mode collapse)가 일어납니다. Emu3의 권장 온도는 인식(perception)의 경우 1.0, 이미지 생성의 경우 0.8입니다.

### 세 가지 역할, 하나의 모델

Emu3는 세 가지 기능적으로 구분된 API로 제공되지만, 하나의 기본 가중치(weight set)를 공유합니다:

- Emu3-Gen. 이미지 생성. 입력은 텍스트, 출력은 이미지 토큰(Token)입니다.
- Emu3-Chat. VQA 및 캡셔닝. 입력은 이미지(토큰), 출력은 텍스트입니다.
- Emu3-Stage2. 비디오 생성 및 비디오 VQA. 입력은 텍스트 또는 비디오, 출력은 텍스트 또는 비디오입니다.

태스크별 헤드(head)는 없습니다. 프롬프트 템플릿만 다릅니다. 동일한 체크포인트(Checkpoint)를 사용합니다.

### 벤치마크

Emu3 논문(2024년 9월)에서:

- 이미지 생성: MJHQ-30K FID에서 SDXL보다 우수(5.4 vs 5.6), GenEval 종합 점수에서 통계적으로 동률(0.54 vs 0.55), Deep-Eval의 종합 점수에서도 동등합니다.
- 이미지 인식: VQAv2에서 LLaVA-1.6보다 우수(75.1 vs 72.4)하며, MMMU에서는 대략적으로 동등한 성능을 보입니다.
- 비디오 생성: Sora 시대 공개 벤치마크 모델들과 경쟁력 있는 FVD로 4초 클립 품질을 달성합니다.

수치가 항상 승리하는 것은 아닙니다 — Emu3는 여기서 한 점을 양보하고 저기서 한 점을 얻습니다 — 그러나 "next-token prediction은 모든 것에 필요하다"라는 주장은 모든 모달리티(modality)에 걸쳐 방어 가능합니다.

### 컴퓨팅 비용

Emu3는 약 3,000억 개의 멀티모달(multimodal) 토큰으로 7B 매개변수(Parameter) 모델을 학습했습니다. GPU 시간은 Llama-2-7B 사전 학습과 대략적으로 유사합니다(A100급 실리콘에서 2k-4k GPU-years). Stable Diffusion 3와 같은 확산 모델(Diffusion Model)은 유사한 예산으로 학습되지만, 별도의 텍스트 인코더(Encoder)와 더 복잡한 파이프라인이 필요합니다.

추론(Inference) 시, Emu3는 이미지당 SDXL보다 느립니다: 30 tok/s로 4096개의 이미지 토큰을 생성하면 512x512 이미지당 약 2분이 소요되며, SDXL은 2-5초가 걸립니다. 추론적 디코딩(Speculative Decoding)과 KV 캐시(KV Cache) 최적화가 격차를 줄이지만 완전히 해소하지는 못합니다. 자기회귀(Autoregressive) 이미지 생성은 컴퓨팅이 많이 소모되며, 이는 고정된 트레이드오프(trade-off)입니다.

### 중요한 이유

Emu3의 깊은 기여는 개념적입니다. next-token prediction이 이미지 생성에서 확산 모델(Diffusion Model)과 동등한 수준으로 확장된다면, 통합 모델 경로(하나의 손실 함수(Loss Function), 하나의 백본(backbone), 모든 모달리티)가 실행 가능합니다. 미래의 모델은 별도의 텍스트 인코더(Encoder), 별도의 확산 스케줄러(scheduler), 별도의 VAE(Variational Autoencoder)가 필요하지 않습니다. 하나의 트랜스포머(Transformer), 모달리티(modality)당 하나의 토크나이저(Tokenization), 그리고 확장(scale)이 필요합니다.

Show-o, Janus-Pro, InternVL-U는 모두 이 논제를 구축하거나 도전합니다. 2025년까지 중국 연구소(BAAI, DeepSeek)는 미국 연구소보다 이 방향에서 더 공격적으로 발표하고 있습니다.

## 사용하기

`code/main.py`는 두 개의 장난감 요소를 구축합니다:

- 2D vs 3D VQ 토크나이저 개수 계산기: (해상도, 패치, 클립 길이, FPS)가 주어지면 이미지와 비디오의 토큰 개수를 계산합니다.
- 온도에서 분류기 없는 가이드(classifier-free guidance)를 사용하는 자기회귀 이미지 토큰 샘플러입니다.

CFG 구현은 Emu3의 레시피와 일치합니다 — 조건부 및 무조건부 로짓을 가이드 가중치로 혼합합니다.

## 연습 문제

1. Emu3는 8x8 감소로 512x512 이미지당 4096 토큰을 생성합니다. 1024x1024 및 2048x2048의 등가물을 계산하세요. 추론 지연은 어떻게 변합니까?

2. Emu3 섹션 3.3의 비디오 토크나이저를 읽으세요. 3D VQ 패치 형태를 설명하고 왜 4x4x4가 8x8x1이 아닌지 설명하세요.

3. 분류기 없는 가이드 가중치 5.0 vs 3.0: 시각적 효과는 무엇입니까? `code/main.py`에서 수식을 추적하세요.

4. 300B 토큰에서 Emu3-7B의 학습 FLOPs를 계산하고 Stable Diffusion 03강 비교하세요. 어느 쪽이 학습 비용이 더 높았습니까?

5. Emu3는 FID에서 SDXL을 이기지만, 전문화된 VLM과의 VQAv2에서는 이기지 못합니다. 통합 손실 접근 방식이 다른 벤치마크에서 전문가 모델과 다른 강점을 보이는 이유를 설명하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| 다음 토큰 예측 | "NTP" | 표준 자기회귀 손실: token[0..i]가 주어지면 token[i+1]을 예측; 토큰화되면 모든 모달리티에 적용 가능 |
| IBQ 토크나이저 | "역 병목 양자화기" | 더 큰 코드북(32768+)과 Chameleon보다 더 나은 재구성 성능을 가진 VQ-VAE의 한 클래스 |
| 3D VQ | "시공간 양자화기" | (시간, 행, 열)로 인덱싱된 코드북; 하나의 토큰이 4x4x4 픽셀 큐브를 커버 |
| 분류기 없는 가이드 | "CFG" | 조건부 및 무조건부 로짓을 가중치 gamma로 혼합; 추론 시 이미지 품질 향상 |
| 통합 어휘 | "공유 토큰" | 텍스트 + 이미지 + 비디오가 모두 동일한 정수 공간에서 토큰을 사용하며, 모델은 다음에 올 모달리티를 예측합니다 |
| MJHQ-30K | "이미지 생성 벤치마크" | 30k 프롬프트를 포함한 Midjourney 품질 벤치마크; Emu3는 여기서 FID를 보고합니다 |
