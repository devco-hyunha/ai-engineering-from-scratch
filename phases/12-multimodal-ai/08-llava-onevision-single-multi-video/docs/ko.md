# LLaVA-OneVision: 단일 이미지, 다중 이미지, 비디오를 하나의 모델로

> LLaVA-OneVision(Li et al., 2024년 8월) 이전의 오픈 VLM 세계에는 각각 별도의 계보가 있었습니다. 단일 이미지를 위한 LLaVA-1.5, Mantis와 VILA 같은 다중 이미지 모델, Video-LLaVA와 Video-LLaMA 같은 비디오 모델이 각각 존재했습니다. 각 모델은 자신의 벤치마크에서는 성공했지만 다른 벤치마크에서는 실패했습니다. LLaVA-OneVision은 하나의 커리큘럼이 세 가지 시나리오 모두를 지배하는 단일 모델을 훈련할 수 있으며, 단일 이미지 기술이 비디오로 전이되고 다중 이미지 추론이 단일 이미지로 전이되는 등 emergent task-transfer 효과가 전문가들의 합을 능가한다고 주장했습니다. 레시피는 단순해 보입니다. 모든 시나리오에서 일정한 시각 토큰 예산을 유지하고, 단일 이미지에서 OneVision(다중 이미지)을 거쳐 비디오로 이동하는 명시적인 커리큘럼을 사용하는 것입니다. 이 강의에서는 예산, 커리큘럼, emergent behaviors를 읽어 나갑니다.

**유형:** Build
**언어:** Python (stdlib, 토큰 예산 계산기 + 커리큘럼 플래너)
**선수 요건:** 12단계 · 05강 (LLaVA), 12단계 · 06강 (any-resolution)
**시간:** 약 180분

## 학습 목표

- 단일 이미지, 다중 이미지, 비디오 입력 전반에 걸쳐 일정한 시각 토큰 예산을 설계해 보세요.
- 치명적 망각(catastrophic forgetting) 없이 단일 이미지에서 비디오로 기술을 전이하는 훈련 커리큘럼을 순서대로 구성해 보세요.
- 커리큘럼이 올바르게 적용될 때, 동일한 매개변수 수의 단일 모델이 전문가 모델들을 능가하는 이유를 설명해 보세요.
- LLaVA-OneVision이 보고한 세 가지 emergent capabilities를 나열해 보세요: 다중 카메라 추론, set-of-mark 프롬팅, iPhone 스크린샷 에이전트.

## 문제점

이미지, 다중 이미지, 비디오는 각각 모델에 다른 방식으로 스트레스를 줍니다.

단일 이미지는 OCR 및 세밀한 디테일을 포착하기 위해 고해상도 토큰(AnyRes, 약 2880 시각 토큰)을 원합니다. 샘플당 예산: 이미지 1개, 2880 토큰.

다중 이미지는 이미지 간 추론이 컨텍스트에 Fits되도록 moderate resolution(~576 토큰)의 여러 이미지를 원합니다. 샘플당 예산: 이미지 4-8개, 각각 576 토큰, 총 2300-4600 토큰.

비디오는 temporal dynamics를 포착하기 위해 low resolution(pooling 후 frame당 약 196 토큰)의 많은 프레임을 원합니다. 샘플당 예산: 프레임 8-32개, 각각 196 토큰, 총 1600-6200 토큰.

별도 모델을 학습하면 하나의 예산을 선택합니다. 하나의 모델을 학습한다면, 컨텍스트를 초과하지 않으면서 시나리오 전반에 걸쳐 예산이 합리적으로 확장되도록 해야 합니다.

OneVision 이전에는 "하나의 시나리오만 학습하고 나머지는 무시한다"가 기본 답변이었습니다. Video-LLaVA는 추가 학습 단계를 통해 이미지 모델에 비디오를 retrofit했습니다. LLaVA-NeXT는 tiling을 통해 다중 이미지 지원을 추가했습니다. 세 가지를 모두 깔끔하게 처리한 모델은 없었습니다.

## 개념

### OneVision 토큰 예산

LLaVA-OneVision은 샘플당 약 3000-4000개의 통합 시각 토큰 예산을 선택하며, 시나리오별로 다르게 할당합니다:

- 단일 이미지: AnyRes-9 (3x3 타일 + 썸네일), 각 타일은 384 해상도에서 729개 패치, 공격적인 2x2 bilinear pooling → 타일당 182개. 총계: 9 * 182 + 182 = 1820 토큰. 또는 AnyRes-4에서 타일당 729개 = 2916 + 729.
- 다중 이미지: 각 이미지를 중간 해상도(384, tiling 없음)로 처리, pooling 없이 729 토큰. 예산 6개 이미지 → 4374 토큰.
- 비디오: 384 해상도의 32개 프레임에 공격적인 3x3 bilinear pool 적용 → 프레임당 81 토큰. 총계: 32 * 81 = 2592 토큰.

이 할당은 총 토큰 수를 대략 일정하게 유지합니다. LLM은 컨텍스트를 초과하는 배치를 보지 않습니다. 인코더는 시나리오별로 다른 기하학을 생성하지만, LLM은 동일한 예산을 소비합니다.

### 3단계 커리큘럼

LLaVA-OneVision은 3단계로 학습합니다:

1. 단일 이미지 SFT (단계 SI). 모든 데이터는 단일 이미지 + 텍스트입니다. 고해상도 AnyRes 입력으로 학습합니다. 이는 인식, OCR 및 세밀한 이해를 가르칩니다. LLaVA-NeXT 데이터와 OneVision 전용 단일 이미지 데이터를 사용합니다.
2. OneVision SFT (단계 OV). 단일 이미지 + 다중 이미지 + 비디오(균일하게 샘플링된 프레임)를 혼합합니다. 통합 토큰 예산으로 학습합니다. 이는 모델이 이질적인 배치 형태를 처리하도록 가르칩니다. 가중치 리셋 없음 — 단계 SI에서 계속 진행합니다.
3. 작업 전이 (단계 TT). 목표 작업 혼합으로 계속 진행하며, 제품에 따라 다중 이미지나 비디오에 더 비중을 둡니다. 배포를 위한 선택적 미세 조정.

중요: 커리큘럼 순서가 중요합니다. 비디오 우선이나 다중 이미지 우선으로 학습하면 동일한 데이터라도 단일 이미지 우선보다 이미지 성능이 더 나빠집니다. 논문은 이를 명시적으로 ablate했습니다.

### 커리큘럼이 작동하는 이유

단일 이미지 학습은 지각 기반을 구축합니다. 패치 토큰은 세밀한 시각적 특징을 담고 있으며, LLM은 이를 텍스트와 통합하는 방법을 학습합니다. 다중 이미지 및 비디오는 구조적 과제(어떤 이미지가 무엇인지, 무엇이 먼저 발생했는지)를 도입하는데, 이는 강력한 지각 기반 없이는 학습하기 어렵습니다.

모든 시나리오를 처음부터 함께 학습하면 모델은 지각이 과소 적합(배치당 단일 이미지 데이터가 제한됨)되고 구조가 과적합(다중 이미지/비디오 데이터가 많음)됩니다. 결과: 이미지 간 추론 패턴을 따르지만 시각적으로 얕은 모델이 됩니다.

커리큘럼 순서는 SI 단계에서 지각 강도를, OV 단계에서 구성적/시간적 추론을 제공하며, 둘 중 하나를 잃지 않습니다.

### emergent cross-scenario skills

LLaVA-OneVision 논문은 세 가지 emergent capabilities를 보고합니다:

1. 다중 카메라 추론. 다중 이미지 + 비디오로 별도로 학습되었으며, 추론 시 다중 카메라 운전 장면에 대해 추론하도록 요청받습니다. 모델은 학습에서 그 정확한 형식을 본 적이 없음에도 불구하고 뷰를 올바르게 통합합니다.
2. Set-of-mark prompting. 사용자가 이미지 내 객체에 번호가 매겨진 마크로 주석 달기; 모델은 "마크 7에 대해 마크 3이 무엇을 하고 있는지"에 대해 추론합니다. 마크나 주석으로 학습되지 않았으며, 공간적 그라운딩 + 다중 이미지 참조의 조합에서 학습되었습니다.
3. iPhone 스크린샷 에이전트. 사용자가 iPhone 화면의 스크린샷을 제공하고 다음 클릭을 계획하도록 요청합니다. UI 스크린샷, 사용자 워크플로 비디오 및 다중 이미지 before/after 쌍으로 학습되었습니다. 에이전트 사용 사례로 일반화됩니다.

이것들은 학습된 작업이 아닙니다; 커리큘럼의 구성적 구조에서 emergent합니다.

### 시각 토큰 풀링

토큰 예산은 풀링을 요구합니다. OneVision은 2D 패치 그리드에 이중 선형 보간을 사용합니다: 24x24 = 576 패치가 12x12 = 144 (2x 팩터) 또는 8x8 = 64 (3x 팩터)가 됩니다. 풀링은 지역성을 보존하기 위해 토큰 공간이 아닌 패치 그리드 공간에서 수행됩니다.

시나리오별 풀링 팩터 선택은 그 자체가 하이퍼파라미터입니다. 풀링이 적음 = 토큰이 많음 = 더 풍부한 표현. 풀링이 많음 = 토큰이 적음 = 더 많은 프레임/이미지가 들어갑니다.

### LLaVA-OneVision-1.5

2025년 후속 연구(LLaVA-OneVision-1.5, arXiv 2509.23661)는 학습 데이터, 모델 가중치, 코드가 "완전 오픈" 상태입니다. 일부 벤치마크에서는 독점 모델과의 격차를 줄이며 레시피를 민주화합니다. 동일한 커리큘럼, 더 많은 데이터, 더 나은 기본 LLM을 사용합니다. 아키텍처 변경은 없습니다.

### Qwen2.5-VL과의 비교

Qwen2.5-VL(12.09강)은 다른 선택을 합니다. 고정 풀링 대신 M-RoPE와 동적 FPS를 사용합니다. 예산은 입력에 따라 확장되므로, 1분 영상은 5초 영상보다 더 많은 토큰을 사용합니다. LLaVA-OneVision은 예산을 고정하고 풀링을 확장합니다. 두 방식 모두 작동하며, 구성 가능성과 예측 가능성을 서로 트레이드오프합니다.

## 사용하기

`code/main.py`는 OneVision 스타일 VLM을 위한 커리큘럼 및 예산 계획 도구입니다. 샘플당 토큰 예산과 목표 시나리오 구성(예: 단일 이미지 40%, 다중 이미지 30%, 영상 30%)이 주어지면 다음을 수행합니다:

- 시나리오별로 해상도, 풀링 팩터, 프레임 수를 할당합니다.
- 모든 시나리오가 공유 예산 내에 Fits하는지 확인합니다.
- 예상 토큰 수, LLM FLOPs, 토큰이 부족한 시나리오를 보고합니다.
- 단계별 학습 스케줄을 출력합니다.

OneVision 미세 조정을 계획하거나 VLM 배포의 요청당 비용을 점검하는 데 사용해 보세요.

## 출시하기

이 강의는 `outputs/skill-onevision-budget-planner.md`을 생성합니다. 목표 작업 분포와 샘플당 예산이 주어지면 AnyRes 팩터, 프레임별 풀링, 영상 프레임 수, 커리큘럼 단계 가중치를 출력합니다. 통합 시나리오 VLM을 학습하거나 미세 조정할 때 이 도구를 사용해 보세요.

## 연습 문제

1. 제품이 단일 이미지 80%, 다중 이미지(2-4장) 10%, 영상(8-16프레임) 10%를 지원합니다. 토큰 예산을 설계해 보세요. 무거운 다중 이미지를 수행하지 않아 절약한 추가 예산은 어디에 배치하시겠습니까?

2. LLaVA-OneVision 섹션 4.3(emergent capabilities)을 읽어 보세요. 논문이 보고하지 않았지만 커리큘럼이 잠금 해제할 가능성이 있는 네 번째 emergent skill을 제안해 보세요.

3. 커리큘럼 순서를 바꾸어 보세요. 다중 이미지를 먼저 학습한 후 단일 이미지, 영상을 학습합니다. 어떤 벤치마크가 저하되는지 예측하고 그 이유를 설명해 보세요.

4. 논문은 샘플당 8프레임으로 학습된 영상 벤치마크를 보고합니다. 이것이 추론 시 30초 영상으로 일반화될까요? 토큰 예산과 시간적 추론 중 무엇이 먼저 깨집니까?

5. 24x24 패치를 12x12로 이중 선형 풀링(bilinear pooling)하는 것은 각 차원에서 4배 감소입니다. 표준 라이브러리 Python으로 풀링을 구현하고, 각 2x2 블록의 평균이 이중 선형 출력과 일치하는지 확인해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| OneVision 시나리오 | "단일 이미지, 다중 이미지 또는 비디오" | 통합 VLM이 처리하는 세 가지 입력 형태 중 하나; 예산은 모든 시나리오에 걸쳐 일정하게 유지 |
| 토큰 예산 | "샘플당 토큰 수" | LLM이 학습/추론 샘플당 보는 총 시각 토큰 수, 일반적으로 3000-4000 |
| 커리큘럼 | "학습 순서" | 점진적 전이를 위해 선택된 단계 순서 (단일 이미지 → 다중 이미지 → 비디오) |
| 이중 선형 풀링 | "토큰 축소" | 토큰 수를 줄이면서 지역성을 보존하기 위해 패치 그리드(2D)에 이중 선형 보간을 적용 |
| 점진적 기술 | "학습되지 않았지만 작동함" | 커리큘럼 구성으로 인해 대응하는 학습 데이터 없이 추론 시 나타나는 능력 |
| AnyRes-k | "k-타일 설정" | 고정 해상도의 k개 하위 타일과 하나의 썸네일, 일반적인 k ∈ {4, 9} |
| 작업 전이 | "시나리오 간 일반화" | 공유 백본을 통해 단일 이미지에서 학습된 기술이 비디오에 적용되는 것 (그 반대도 포함) |
