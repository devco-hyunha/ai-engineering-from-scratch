# 문서 및 다이어그램 이해

> 문서는 사진이 아닙니다. PDF, 과학 논문, 청구서, 손으로 작성한 양식에는 레이아웃, 표, 다이어그램, 각주, 헤더, 의미론적 구조가 있으며, 단순한 이미지 이해로는 이를 포착할 수 없습니다. VLM 이전 스택은 파이프라인이었습니다: Tesseract OCR + LayoutLMv3 + 표 추출 휴리스틱. VLM 물결은 Donut (2022), Nougat (2023), DocLLM (2023) 같은 OCR 없는 모델로 이를 대체했으며, 이들은 구조화된 마크업을 직접 생성합니다. 2026년 현재 최전선에서는 "페이지 이미지를 Claude Opus 4.7에 2576px 원본 해상도로 입력"하는 것뿐이며, 구조화된 마크업 출력은 자동으로 따라옵니다. 이 강의는 문서 AI의 세 시대 흐름을 다룹니다.

**유형:** Build
**언어:** Python (표준 라이브러리, 레이아웃 인식 문서 파서 골격)
**선수 요건:** 12단계 · 05강 (LLaVA), 5단계 (NLP)
**시간:** 약 180분

## 학습 목표

- 문서 AI의 세 시대인 OCR 파이프라인, OCR 없는 방식, VLM 네이티브 방식을 설명해 보세요.
- LayoutLMv3의 세 입력 스트림인 텍스트, 레이아웃 (bbox), 이미지 패치를 통합 마스킹과 함께 설명해 보세요.
- Donut (OCR 없는 방식, 이미지 → 마크업), Nougat (과학 논문 → LaTeX), DocLLM (레이아웃 인식 생성형), PaliGemma 2 (VLM 네이티브)를 비교해 보세요.
- 새로운 작업 (청구서, 과학 논문, 손으로 작성한 양식, 중국어 영수증)에 적합한 문서 모델을 선택해 보세요.

## 문제점

"이 PDF를 이해해 주세요"는 겉보기에 간단하지만 실제로는 매우 어렵습니다. 정보는 다음에 있습니다:

- 텍스트 내용 (신호의 90%).
- 레이아웃 (헤더, 각주, 사이드바, 2단 형식).
- 표 (행, 열, 병합된 셀).
- 그림 및 다이어그램.
- 손으로 작성한 주석.
- 폰트 및 타이포그래피 (제목 대 본문).

원시 OCR은 텍스트만 덤프하고 나머지는 잃어버립니다. 청구서를 다루는 시스템은 "합계: $1,245"가 오른쪽 하단에서 나왔다는 것을 알아야 하며, 각주에서 나온 것이 아니라는 것을 알아야 합니다.

## 개념

### 1시대 — OCR 파이프라인 (2021년 이전)

클래식 스택은 다음과 같습니다:

1. PDF → 페이지별 이미지.
2. Tesseract (또는 상용 OCR)가 단어를 바운딩 박스(bounding box)와 함께 추출합니다.
3. 레이아웃 분석기가 블록(헤더, 표, 단락)을 식별합니다.
4. 표 구조 인식기가 표를 파싱합니다.
5. 도메인 규칙 + 정규식(Regex)으로 필드를 추출합니다.

깨끗한 인쇄 텍스트에는 잘 작동합니다. 손글씨, 기울어진 스캔, 복잡한 표, 비영어권 스크립트에서는 실패합니다. 모든 실패 모드에는 맞춤형 예외 경로가 필요합니다.

### TrOCR (2021)

TrOCR (Li et al., arXiv:2109.10282)은 Tesseract의 고전적인 CNN-CTC를 합성 및 실제 텍스트 이미지로 학습된 트랜스포머 인코더-디코더로 대체했습니다. 손글씨 및 다국어 텍스트에서 명확한 승리를 거두었습니다. 여전히 파이프라인(디텍터 → TrOCR → 레이아웃)이지만, OCR 단계가 극적으로 개선되었습니다.

### 2기 — OCR 프리 (2022-2023)

첫 번째 OCR 프리 모델은 다음과 같이 말했습니다: 탐지를 완전히 생략하고, 이미지 픽셀을 구조화된 출력으로 직접 매핑합니다.

Donut (Kim et al., arXiv:2111.15664):
- 인코더-디코더 트랜스포머이며, 인코더는 Swin-B입니다.
- 출력은 양식 이해를 위한 JSON, 요약용 마크다운, 또는 작업별 스키마입니다.
- OCR 없음, 레이아웃 없음, 탐지 없음.

Nougat (Blecher et al., arXiv:2308.13418):
- 과학 논문 전용으로 학습되었습니다.
- 출력은 LaTeX / 마크다운입니다.
- 수식, 다단 레이아웃, 그림을 처리합니다.
- 모든 arXiv 파서(Parser)가 호출하는 모델입니다.

이들은 전문가 모델이며, 범용 모델이 아닙니다. Donut는 과학 논문에서 실패하고, Nougat는 청구서에서 실패합니다.

### LayoutLMv3 (2022)

다른 트랙입니다. LayoutLMv3 (Huang et al., arXiv:2204.08387)는 OCR을 유지하면서 레이아웃 이해를 추가합니다:

- 세 가지 입력 스트림: OCR 텍스트 토큰, 토큰별 2D 경계 상자, 이미지 패치.
- 세 가지 모달리티(텍스트, 패치, 레이아웃)에 걸친 마스킹 학습 목표.
- 다운스트림: 분류, 엔티티 추출, 표 QA.

LayoutLMv3는 OCR 기반 문서 이해의 정점입니다. 양식 및 청구서에 강합니다. 상류 단계에 OCR이 필요합니다. 표준화된 문서 벤치마크에서 VLM 이전 최고의 정확도를 보여줍니다.

### DocLLM (2023)

DocLLM (Wang et al., arXiv:2401.00908)은 LayoutLM의 생성형 형제 모델입니다. 레이아웃 토큰을 조건으로 자유 형식의 답변을 생성합니다. 문서 QA에 더 적합하지만, 여전히 OCR 입력에 의존합니다.

### 3단계 — VLM 네이티브 (2024+)

2024년 VLM은 파이프라인 전체를 대체할 만큼 충분히 좋아졌습니다. 전체 페이지 이미지를 고해상도로 VLM에 입력하고, 질문을 하면 답변을 얻을 수 있습니다.

- LLaVA-NeXT의 336-타일 AnyRes는 작은 문서에 잘 작동합니다.
- Qwen2.5-VL의 동적 해상도는 2048+ 픽셀을 네이티브로 처리합니다.
- Claude Opus 4.7은 2576px 문서를 지원합니다.
- PaliGemma 2 (2025년 4월)는 문서 및 필기체 전용으로 훈련되었습니다.

VLM 네이티브와 OCR 파이프라인 간의 격차는 빠르게 좁혀졌습니다. 2026년 현재, VLM 네이티브는 다음 영역에서 승리합니다:

- 장면 텍스트 (필기체 + 인쇄체, 혼합 문자 스크립트).
- 병합된 셀이 포함된 복잡한 표.
- 텍스트에 내장된 수식.
- 텍스트 주석이 포함된 그림.

OCR 파이프라인은 다음 영역에서 여전히 승리합니다:

- 페이지당 지연 시간이 중요한 대규모 순수 스캔 작업.
- 파이프라인 신뢰성 (결정적 실패 vs VLM 환각).
- 감사 가능한 OCR 출력이 필요한 규제 환경.

### Claude 4.7 / GPT-5 프론티어

2576-픽셀 네이티브 입력에서, 프론티어 VLM은 인간에 가까운 정확도로 문서 이해를 수행합니다. 2026년 초의 벤치마크 수치:

- DocVQA: Claude 4.7 ~95.1, PaliGemma 2 ~88.4, Nougat ~77.3, 파이프라인 LayoutLMv3 ~83.
- ChartQA: Claude 4.7 ~92.2, GPT-4V ~78.
- VisualMRC: Claude 4.7 ~94.

폐쇄형 모델 간 격차는 주로 해상도와 기본 LLM 규모에 기인합니다. 7B 오픈 모델은 몇 포인트 뒤처져 있지만 빠르게 따라잡고 있습니다.

### 수식 및 LaTeX 출력

과학 논문은 수식에 정확한 LaTeX 출력이 필요합니다. Nougat은 이를 위해 훈련되었습니다. LaTeX 타겟으로 훈련된 VLM (Qwen2.5-VL-Math, Nougat 파생 모델)은 사용 가능한 LaTeX를 생성합니다. 명시적인 LaTeX 훈련이 없으면, VLM은 읽기 쉽지만 부정확한 전사(transcription)를 생성합니다.

2026년 과학 논문 파이프라인에서는: PDF에 Nougat을 체이닝한 후, 어려운 페이지에 VLM을 적용하세요.

### 필기체

가장 어려운 하위 작업입니다. 인쇄된 텍스트와 손글씨가 혼합된 경우(의사 노트, 작성된 양식)는 여전히 OCR 파이프라인이 VLM보다 비용 효율적입니다. 손글씨 전용 VLM은 개선되고 있습니다(Claude 4.7, PaliGemma 2).

### 2026 레시피

새로운 문서-AI 프로젝트의 경우:

- 대규모 순수 인쇄 청구서: LayoutLMv3 + 규칙, 비용 효율적.
- 혼합 문서(과학 + 손글씨 + 양식): VLM 네이티브(PaliGemma 2 또는 Qwen2.5-VL).
- 전체 arXiv 수집: 수식은 Nougat, 그림은 VLM 사용.
- 규제 관련: OCR 파이프라인 + 교차 검증을 위한 VLM 검증기.

## 사용하기

`code/main.py`:

- 레이아웃 인식 토이 토크나이저: (text, bbox) 쌍을 입력으로 받아 LayoutLMv3 스타일 입력을 생성합니다.
- Donut 스타일 작업 스키마 생성기: 양식용 JSON 템플릿.
- OCR 파이프라인, Donut, Nougat, VLM 네이티브 간 페이지별 토큰 예산 비교.

## 출시하기

이 강의는 `outputs/skill-document-ai-stack-picker.md`를 생성합니다. 문서-AI 프로젝트(도메인, 규모, 품질, 규제)가 주어지면 OCR 파이프라인, OCR 프리 전문화 모델, VLM 네이티브 중 하나를 선택합니다.

## 연습 문제

1. 프로젝트가 하루 1000만 건의 청구서라면, 정확도를 잃지 않으면서 페이지당 비용을 최소화하는 스택은 무엇인가요?

2. 왜 LayoutLMv3는 양식 QA에서 순수 CLIP-VLM보다 성능이 좋지만 장면 텍스트에서는 성능이 떨어지는가요? bbox 스트림은 무엇을 포기하나요?

3. Nougat은 LaTeX를 생성합니다. VLM 네이티브 출력의 LaTeX 충실도가 Nougat을 능가하는 테스트 케이스와 Nougat이 승리하는 케이스를 제안해 보세요.

4. PaliGemma 2 논문(Google, 2024)을 읽어 보세요. PaliGemma 1 대비 문서 정확도를 높인 주요 학습 데이터 추가는 무엇이었나요?

5. 규제 안전 하이브리드를 설계해 보세요: OCR 파이프라인을 주력으로, VLM을 보조 교차 검증으로 사용. 불일치를 어떻게 해결하나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| OCR 파이프라인 | "Tesseract 스타일" | 단계별 스택: 감지 -> OCR -> 레이아웃 -> 규칙; 결정적, 취약 |
| OCR 프리 | "Donut 스타일" | 명시적 OCR을 건너뛰는 이미지-출력 트랜스포머; 단일 모델 |
