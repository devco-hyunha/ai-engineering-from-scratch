# ColPali와 비전 기반 문서 RAG

> 전통적인 RAG는 PDF를 텍스트로 파싱하고, 청크로 분할하며, 청크를 임베딩하고, 벡터를 저장합니다. 모든 단계에서 신호가 손실됩니다: OCR은 차트 데이터를 드롭하고, 청킹은 표 행을 깨뜨리며, 텍스트 임베딩은 그림을 무시합니다. ColPali (Faysse et al., 2024년 7월)는 더 단순한 질문을 던졌습니다: 왜 텍스트를 추출해야 할까요? PaliGemma를 통해 페이지 이미지를 직접 임베딩하고, 검색을 위해 ColBERT 스타일의 늦은 상호작용(late interaction)을 사용하며, 문서가 담고 있는 레이아웃, 그림, 폰트, 서식 신호를 모두 유지합니다. 공개된 벤치마크에 따르면 시각적으로 풍부한 문서에서 텍스트-RAG 대비 엔드투엔드 정확도가 20-40% 더 높습니다. ColQwen2, ColSmol, VisRAG가 이 패턴을 확장했습니다. 이 강의는 비전 기반 RAG 논문을 읽고 작은 ColPali 유사 인덱서를 구축합니다.

**유형:** Build
**언어:** Python (stdlib, 다중 벡터 인덱서 + MaxSim 스코어)
**선수 요건:** 11단계 (LLM 엔지니어링 — RAG 기초), 12단계 · 05강 (LLaVA)
**시간:** 약 180분

## 학습 목표

- 바이인코더 검색(문서당 하나의 벡터)과 늦은 상호작용 검색(문서당 여러 벡터)의 차이를 설명해 보세요.
- ColBERT의 MaxSim 연산과 ColPali가 이를 텍스트 토큰에서 이미지 패치로 일반화하는 방식을 설명해 보세요.
- 작은 ColPali 유사 인덱서를 구축해 보세요: 페이지 → 패치 임베딩 → 쿼리 용어 임베딩에 대한 MaxSim → 상위 k개 페이지.
- 인보이스 / 재무 보고서 사용 사례에서 ColPali + Qwen2.5-VL 생성기와 텍스트-RAG + GPT-4를 비교해 보세요.

## 문제점

PDF에 대한 텍스트-RAG는 문서의 대부분을 버립니다. 재무 보고서의 Q3 매출 성장은 보통 차트에 있으며, 의료 보고서의 소견은 주석이 달린 이미지에 있고, 법적 계약의 서명 블록은 텍스트 사실이 아닌 레이아웃 사실입니다.

텍스트-RAG 파이프라인:

1. PDF → OCR / pdftotext를 통해 텍스트로 변환.
2. 텍스트 → 300-500 토큰 청크로 분할.
3. 청크 → 바이인코더 임베딩 (하나의 벡터).
4. 사용자 쿼리 → 임베딩 → 코사인 유사도 → 상위 k개 청크.
5. 청크 + 쿼리 → LLM.

손실 있는 5단계. 차트는 캡처되지 않습니다. 표는 청크 간에 깨집니다. 다중 열 레이아웃은 평탄화됩니다. 그림 주석은 사라집니다.

ColPali의 해결책: OCR을 건너뛰고 페이지 이미지를 직접 임베딩합니다. 검색 시 ColBERT 스타일의 후기 상호작용(late interaction)을 사용하여 모델이 쿼리 시점에 세밀한 패치에 집중할 수 있도록 합니다.

## 개념

### ColBERT (2020)

ColBERT (Khattab & Zaharia, arXiv:2004.12832)는 텍스트 검색 방법입니다. 문서당 하나의 벡터를 생성하는 대신, 토큰당 하나의 벡터를 생성합니다. 쿼리 시점에는:

- 쿼리 토큰은 자체 임베딩을 가집니다 (N_q 벡터).
- 문서 토큰은 임베딩을 가집니다 (N_d 벡터, 일반적으로 캐시됨).
- 점수 = 쿼리 토큰에 대한 합, 각 쿼리 토큰에 대해 문서 토큰 중 최대 코사인 유사도: Σ_i max_j cos(q_i, d_j).

이것이 MaxSim 연산입니다. 각 쿼리 토큰은 가장 잘 매칭되는 문서 토큰을 "선택"합니다. 최종 점수는 합입니다.

장점: 강력한 재현율, 토큰 수준 의미 처리. 단점: 문서당 N_d 벡터, 저장 비용이 높음.

### ColPali

ColPali (Faysse et al., arXiv:2407.01449)는 ColBERT 패턴을 이미지에 적용합니다.

- 각 페이지는 PaliGemma (ViT + 언어)에 의해 패치 임베딩으로 인코딩됩니다: 페이지당 N_p 벡터.
- 각 사용자 쿼리 (텍스트)는 쿼리 토큰 임베딩으로 인코딩됩니다: N_q 벡터.
- 점수 = Σ_i max_j cos(q_i, p_j), 즉 쿼리 텍스트 토큰과 페이지 이미지 패치에 대한 MaxSim.
- 총 점수에 따라 상위 k 페이지를 검색합니다.

문서 입력 시: 모든 페이지를 PaliGemma로 임베딩하고 모든 패치 임베딩을 저장합니다. 쿼리 시점: 쿼리 토큰을 임베딩하고 저장된 모든 페이지 임베딩에 대해 MaxSim을 계산하여 상위 k 페이지를 반환합니다.

장점: 시각적으로 풍부한 문서에서 텍스트-RAG 대비 엔드투엔드 성능이 20-40% 향상됩니다. 각 패치 벡터는 지역 레이아웃과 내용을 포착합니다.

단점: 페이지당 N_p 패치 × 4바이트 float × D차원 벡터 = 저장 공간이 빠르게 증가합니다. PQ / OPQ 양자화로 완화됩니다.

### ColQwen2 및 ColSmol

ColQwen2 (illuin-tech, 2024-2025)는 PaliGemma를 Qwen2-VL로 교체합니다. 더 나은 기본 인코더, 더 나은 검색 성능.

ColSmol은 로컬 / 엣지 사용을 위한 소형 변형입니다. 약 10억 파라미터의 ColSmol 리트리버는 소비자용 GPU에서 실행됩니다.

### VisRAG

VisRAG (Yu et al., arXiv:2410.10594)는 다른 변형입니다: 패치에 대한 MaxSim 대신, VLM으로 각 페이지를 단일 벡터로 풀링한 후 바이인코더(bi-encoder)로 검색합니다. 인덱싱이 더 빠르고 저장 공간이 작지만, 재현율(recall)이 약합니다.

품질 대 비용의 트레이드오프: 품질을 원한다면 ColPali, 규모(scale)를 원한다면 VisRAG를 선택하세요.

### M3DocRAG

M3DocRAG (Cho et al., arXiv:2411.04952)는 멀티모달 검색을 다중 페이지 및 다중 문서 추론으로 확장합니다. 문서 간에 페이지를 검색하고, VLM을 위해 다중 페이지 컨텍스트를 구성합니다.

### ViDoRe — 벤치마크

ColPali의 동반 벤치마크입니다. 시각적 문서 검색 평가(Visual Document Retrieval Evaluation)입니다. 작업에는 재무 보고서, 과학 논문, 행정 문서, 의료 기록, 매뉴얼이 포함됩니다. 지표: nDCG@5.

ColPali-v1은 ViDoRe에서 nDCG@5 약 80%를 기록합니다. 동일한 문서에 대해 텍스트-RAG는 nDCG@5 약 50-60%를 기록합니다.

### 엔드투엔드(end-to-end) RAG 파이프라인

비전 네이티브(vision-native) RAG의 경우:

1. 수입(Ingest): PDF → 페이지 이미지 → PaliGemma 인코딩 → 모든 패치 임베딩 저장.
2. 쿼리(Query): 사용자 텍스트 → 쿼리 토큰 임베딩 → 인덱싱된 모든 페이지에 대해 MaxSim 수행 → 상위 k개 페이지.
3. 생성(Generate): 상위 k개 페이지 이미지 + 쿼리 → VLM (Qwen2.5-VL 또는 Claude) → 답변.

어디에도 OCR이 없습니다. 그림, 차트, 폰트, 레이아웃이 모두 답변에 반영됩니다.

### 저장 공간 계산

페이지당 729개 패치와 128차원 임베딩을 가진 50페이지 재무 보고서의 경우:

- ColPali: 50 * 729 * 128 * 4 bytes = 원시(raw) 약 18 MB, PQ 적용 후 약 4 MB.
- Text-RAG: 50 chunks * 768-dim * 4 bytes = 약 150 kB.

ColPali는 문서당 저장 공간이 약 30배 더 많습니다. 대규모 환경에서는 OPQ / PQ를 적용하여 약 5-10배로 줄일 수 있으며, 보통 허용 가능한 수준입니다.

### 텍스트-RAG가 여전히 유리한 경우

- 레이아웃 신호가 없는 순수 텍스트 문서 (위키 기사, 채팅 로그). 텍스트-RAG는 더 단순하고 저장 비용이 저렴합니다.
- 저장 비용이 지배적인 수백만 페이지 아카이브.
- 검색과 함께 추출 가능한 OCR 텍스트를 요구하는 엄격한 규제 요건.

2026년의 나머지 모든 경우 — 재무 보고서, 과학 논문, 법률 계약, 의료 기록, UX 문서 — 비전 네이티브 RAG가 승리합니다.

## 사용하기

`code/main.py`:

- 장난감 패치 인코더: "페이지"(특징 벡터의 작은 격자)를 패치 임베딩 배열로 매핑합니다.
- MaxSim 스코어 계산기: 쿼리 토큰 임베딩 세트와 페이지 패치 세트 간의 ColBERT 스타일 점수를 계산합니다.
- 5개의 장난감 페이지를 인덱싱하고, 3개의 쿼리를 실행하며, 점수와 함께 상위 k개를 반환합니다.

## 연습 문제

1. 729개의 패치/페이지, 128차원 임베딩, 4바이트 floats를 사용하는 200페이지 연례 보고서가 있습니다. 원시 저장 용량과 PQ 압축(8배) 저장 용량을 계산해 보세요.

2. MaxSim은 Σ_i max_j cos(q_i, p_j)입니다. 이 합이 단순한 평균 유사도가 포착하지 못하는 것은 무엇인가요?

3. ColPali는 페이지를 패치 세트로 인덱싱합니다. 대신 단어 수준(ColBERT가 하는 방식)으로 인덱싱하면 무엇이 달라지나요? 트레이드오프는 무엇인가요?

4. 쿼리당 500ms의 지연 예산을 가진 100만 페이지 코퍼스에 대한 엔드투엔드 파이프라인을 설계해 보세요. ColQwen2 / VisRAG를 선택하고 그 이유를 정당화하세요.

5. M3DocRAG (arXiv:2411.04952)를 읽어 보세요. 다중 페이지 어텐션 패턴을 설명하고, 단일 페이지 ColPali 검색과 어떻게 다른지 서술하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| 후기 상호작용 | "ColBERT 스타일" | 단일 문서 벡터가 아닌, 토큰별 또는 패치별 임베딩 + MaxSim을 사용하는 검색 |
| MaxSim | "패치 간 최대값" | 각 쿼리 토큰에 대해 가장 높은 유사성을 가진 문서 토큰을 선택하고, 쿼리 전체에 대해 합산 |
| 바이인코더 | "단일 벡터" | 문서당 하나의 벡터; 더 빠르지만 세분성이 손실됨 |
| 다중 벡터 | "문서당 다수의 벡터" | 문서/페이지당 N_p개의 벡터를 저장; 저장 비용이 증가하지만 재현율이 개선됨 |
| 패치 임베딩 | "페이지 특징" | VLM 인코더에서 생성된 이미지 패치당 하나의 벡터, 페이지별로 캐시됨 |
| ViDoRe | "비전 문서 벤치마크" | 시각적 문서 검색을 위한 ColPali의 벤치마크 스위트 |
| PQ 양자화 | "제품 양자화" | 벡터 유사성을 유지하면서 저장 공간을 약 8배 줄이는 압축 |
