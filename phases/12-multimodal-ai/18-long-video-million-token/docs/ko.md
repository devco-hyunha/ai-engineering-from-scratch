# 백만 토큰 컨텍스트에서의 장시간 영상 이해

> 1시간 길이의 4K 영상을 24 FPS로 패치하고 임베딩하면 약 6,000만 토큰이 생성됩니다. 2시간 길이의 팟캐스트 에피소드를 전사하면 30,000 토큰이 됩니다. 풀 블루레이 장편 영화는 공격적인 풀링으로 압축하더라도 수십만 토큰이 됩니다. Google의 Gemini 1.5 (2024년 3월)는 1,000만 토큰 컨텍스트로 이 시대를 열었으며, 1시간 길이의 영상에서 신뢰할 수 있는 '건초 더미에서 바늘 찾기' 검색을 수행했습니다. LWM (Liu et al., 2024년 2월)은 링 어텐션의 확장 경로를 보여 주었습니다. LongVILA와 Video-XL은 입력 처리를 더 확장했습니다. VideoAgent는 원시 컨텍스트를 에이전트 검색으로 대체했습니다. 각 접근 방식은 연산, 검색, 엔지니어링 복잡성 측면에서 서로 다른 트레이드오프를 가집니다. 이 강의에서는 이러한 접근 방식을 나란히 비교합니다.

**유형:** Build
**언어:** Python (표준 라이브러리, 건초 더미에서 바늘 찾기 시뮬레이터 + 에이전트 검색 라우터)
**선수 요건:** 12단계 · 17단계 (영상 시간적 토큰)
**시간:** 약 180분

## 학습 목표

- 다양한 FPS와 풀링 조건에서 장시간 영상의 총 시각 토큰 수를 계산해 보세요.
- 세 가지 확장 경로를 설명해 보세요: 브루트 컨텍스트 (Gemini 1.5), 링 어텐션 (LWM), 토큰 압축 (LongVILA / Video-XL).
- 원시 컨텍스트 영상 VLM과 에이전트 검색 영상 VLM (VideoAgent)을 정확도와 지연 시간 측면에서 비교해 보세요.
- 30분 길이의 영상에 대한 '건초 더미에서 바늘 찾기' 테스트를 설계하고 특정 분에서의 검색률을 측정해 보세요.

## 문제점

Qwen2.5-VL 크기의 패치를 384 네이티브 해상도로 처리한 단일 프레임은 약 729 토큰입니다. 3x3 풀링을 적용하면 프레임당 81 토큰이 됩니다. 1 FPS의 30분 클립은 1,800 프레임 = 145,800 토큰입니다. 2025년 오픈 VLM으로 처리 가능하지만 여유가 없습니다. 2 FPS에서는 291,600 토큰이 되며, 가장 큰 컨텍스트를 가진 모델만 처리할 수 있습니다.

1 FPS의 2시간 영화는 583,000 토큰입니다. 대부분의 2026년 오픈 모델을 넘어서며, Gemini 2.5 Pro가 필요하거나 더 공격적으로 풀링해야 합니다.

세 가지 확장 경로가 등장했습니다.

## 개념

### 경로 1: 브루트 컨텍스트 (Gemini 1.5, Claude Opus)

하드웨어를 투입하여 문제를 해결합니다. 컨텍스트를 수백만 토큰으로 확장하고 모든 것을 단일 순전파로 처리합니다.

Gemini 1.5 Pro는 100만 토큰으로 출시되었으며, Gemini 1.5 Ultra는 1000만 토큰까지 확장되었습니다. Gemini 2.5 Pro는 2026년에 수 시간의 영상을 신뢰성 있게 처리합니다. 논문(arXiv:2403.05530)은 약 950만 토큰까지 건초 더미 속 바늘 찾기(recall)가 99.7%임을 문서화하고 있습니다.

엔지니어링: 메모리 계층(로컬 + 전역 + 희소)을 갖춘 맞춤형 어텐션 구현과 긴 컨텍스트 효율성을 위한 MoE (혼합 전문가)(MoE (Mixture of Experts)) 전문가 라우팅을 사용합니다. 전체 세부 사항은 공개되지 않았습니다. 오픈 소스가 아닙니다.

### 경로 2: 링 어텐션(Ring attention) (LWM, LongVILA)

링 어텐션은 긴 시퀀스를 각 디바이스가 청크를 보유하는 "링" 형태로 디바이스 간에 분산합니다. 전체 시퀀스에 대한 어텐션은 각 디바이스가 링 패턴에 따라 다음 디바이스로 청크를 전송하고, 부분 어텐션을 계산하며, 이를 집계하는 방식으로 수행됩니다.

LWM (Liu et al., 2024)은 이 방식으로 100만 토큰 컨텍스트 모델을 학습했습니다. 학습 연산량은 컨텍스트에 대해 선형적으로 증가하며, 2차적으로 증가하지 않습니다. 어텐션에서의 2차적 비용은 링의 디바이스들에 걸쳐 상각(amortized)됩니다.

LongVILA (arXiv:2408.10188)은 이 패턴을 비전-언어 모델 (VLM)(Vision-Language Model (VLM))에 적용했습니다. 프레임당 192 토큰인 1400프레임 영상은 268k 컨텍스트를 생성하며, 8방향 병렬화 across ring attention를 통해 학습되었습니다.

### 경로 3: 토큰 압축 (Video-XL, LongVA)

브루트 컨텍스트(brute context)보다 저렴합니다: LLM이 시퀀스를 보기 전에 aggressively 압축합니다.

Video-XL (arXiv:2409.14485)은 시각적 요약 토큰을 사용합니다: N개의 프레임으로 구성된 각 클립은 N에 대해 어텐션하는 단일 "요약" 토큰을 생성합니다. 추론 시 LLM은 클립당 하나의 요약 토큰을 보게 되며, 컨텍스트가 극적으로 축소됩니다.

LongVA는 "긴 컨텍스트 전이(long context transfer)" 기법을 통해 LLM 컨텍스트를 200k에서 2M으로 확장합니다. 긴 컨텍스트 텍스트로 학습하고, 공유된 표현을 통해 긴 컨텍스트 영상으로 전이합니다.

토큰 압축은 특정 타임스탬프에서의 재현율(recall)과 확장성(scalability) 간에 트레이드오프를 취합니다. 모델은 일반적으로 무슨 일이 일어났는지 알지만, 때로는 정확한 프레임을 놓칠 수 있습니다.

### 경로 4: 에이전트 기반 검색 (VideoAgent)

전체 영상을 LLM에 공급하지 마세요. 대신 영상을 데이터베이스로 취급하고 LLM을 사용하여 이를 쿼리하세요.

VideoAgent (arXiv:2403.10517):

1. LLM이 질문을 읽습니다.
2. LLM이 관련 클립을 검색 도구(retrieval tool)에 요청합니다 ("고양이가 있는 세그먼트를 보여 주세요").
3. 도구가 일치하는 클립 타임스탬프를 반환합니다.
4. LLM은 VLM을 통해 해당 클립을 읽습니다.
5. LLM은 답변을 구성하거나 후속 쿼리를 요청합니다.

이것은 LLM-as-agent 패턴을 긴 비디오에 적용한 것입니다. 더 저렴한 추론(관련된 클립만 인코딩)이 가능하지만, 더 어려운 엔지니어링이 필요합니다(검색 품질이 병목이 됩니다).

### Needle-in-a-haystack 벤치마크

표준 긴 컨텍스트 테스트: 비디오의 랜덤한 지점에 고유한 시각적 또는 텍스트 마커를 삽입한 후, 이를 기억해야 하는 쿼리를 요청합니다.

메트릭: 비디오 길이와 마커 위치에 따른 Recall@k.

Gemini 2.5 Pro는 최대 90분 길이의 비디오에서 99% 이상의 리콜 점수를 기록합니다. 오픈 72B 모델(Qwen2.5-VL-72B, InternVL3-78B)은 30분에서 약 85-90% 점수를 기록하며, 60분 이후에는 성능이 저하됩니다.

VideoAgent는 도구가 잘 작동하면 검색이 니들(needle)을 찾아내므로, 2시간 이상에서 원시 컨텍스트 모델을 능가하거나 동등한 성능을 낼 수 있습니다.

### 어떤 경로를 선택할지

15분 클립에서 프론티어 정확도를 원한다면: 오픈 72B + 네이티브 컨텍스트가 보통 잘 작동합니다. Qwen2.5-VL-72B를 선택하세요.

30분에서 1시간 길이의 콘텐츠: 오픈 모델은 LongVILA 또는 Video-XL, 클로즈드 모델은 Gemini 2.5 Pro를 사용하세요. 품질 기준이 중요합니다 — 프론티어는 클로즈드 모델로 이동합니다.

2시간 이상의 콘텐츠: VideoAgent 또는 유사한 검색 패턴을 사용하세요. 대안으로, 더 작은 청크로 요약하고 계층적 요약을 입력하는 방법도 있습니다.

### 2026년 생산 패턴

실제로, 생산 환경의 긴 비디오 파이프라인은 하이브리드입니다:

1. 전체 비디오에 동적 FPS 샘플링 + 공격적인 풀링을 실행합니다(100k 토큰의 전역 표현을 얻습니다).
2. 72B VLM에 전달하여 전역 요약을 생성합니다.
3. 사용자가 상세한 질문을 하면, 요약을 인덱스로 사용하여 에이전트 검색을 실행합니다.

## 사용하기

`code/main.py`:

- 1분에서 3시간까지의 비디오에 대해 다양한 FPS + 풀링으로 토큰 예산을 계산합니다.
- Needle-in-a-haystack 실행을 시뮬레이션합니다: 랜덤한 타임스탬프에 마커를 주입하고, 질문을 요청하며, 리콜 점수를 매깁니다.
- 다운스트림 VLM에 전달할 특정 클립을 선택하는 에이전트 검색 라우터 시뮬레이터를 포함합니다.

예산 테이블을 실행하고 규모 격차를 느껴 보세요.

## 출시하기

이 강의는 `outputs/skill-long-video-strategy-planner.md`를 생성합니다. 영상 길이와 쿼리 복잡도를 고려하여 브루트 컨텍스트(brute-context), 압축(compression), 에이전트 기반 검색(agentic retrieval) 중 하나를 선택하고, 지연 시간(latency) 및 품질 기대치를 계산합니다.

## 연습 문제

1. 1 FPS, 프레임당 81 토큰인 45분 강연의 총 토큰 수는 몇 개이며, 어떤 모델의 컨텍스트 윈도우에 fits합니까?

2. 바늘 찾기 테스트(needle-in-a-haystack test)를 설계해 보세요: 몇 분 지점에 마커를 삽입하며, 정확한 쿼리 형식은 무엇입니까?

3. 1시간 영상을 대상으로 브루트 컨텍스트 방식의 Qwen2.5-VL-72B (80k 컨텍스트)와 VideoAgent (Claude 3.5 + 검색)를 비교해 보세요. 재현율(recall)은 어느 쪽이 더 높습니까? 지연 시간(latency)은 어느 쪽이 더 짧습니까?

4. 링 어텐션(ring attention)의 메모리 비용은 시퀀스 길이에 대해 선형적으로, 장치 수에 대해 선형적으로 증가합니다. 그 이유를 설명하고, 링 회전(ring-rotation) 단계를 제거하면 무엇이 실패합니까?

5. Gemini 1.5의 5절 '바늘 찾기 테스트(needle-in-a-haystack)'를 읽어 보세요. 논문은 1M 토큰과 10M 토큰 경계에서의 재현율(recall)에 대해 무엇을 발견했습니까?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| 브루트 컨텍스트 | "단순히 더 많은 토큰" | LLM 컨텍스트를 수백만 토큰으로 확장하여 한 번의 패스로 모든 것을 처리 |
| 링 어텐션 | "LWM 스타일 병렬 처리" | 각 장치가 청크를 보유하고 회전하는 분산 어텐션 패턴 |
| 토큰 압축 | "요약 토큰" | LLM 이전에 학습된 압축기를 통해 클립당 토큰 수를 줄임 |
| 바늘 찾기 테스트 | "NIH 테스트" | 랜덤한 지점에 고유한 마커를 삽입하고, 테스트 시 모델이 이를 재현(recall)하도록 요청 |
| 에이전트 기반 검색 | "LLM을 쿼리 플래너로 사용" | LLM이 검색 도구에 관련 클립을 요청하고, VLM으로 이를 읽은 후 답변을 구성 |
| VideoAgent | "비디오용 검색 패턴" | 표준적인 에이전트 기반 검색 설계: 질문 -> 도구 -> 클립 -> 답변 |
