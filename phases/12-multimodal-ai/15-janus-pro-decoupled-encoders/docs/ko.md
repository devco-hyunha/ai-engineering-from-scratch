# Janus-Pro: 통합 멀티모달 모델을 위한 분리된 인코더

> 통합 멀티모달 모델에는 피할 수 없는 긴장 관계가 있습니다. 이해(Understanding)는 시맨틱 특징을 원합니다. SigLIP이나 DINOv2는 개념 수준의 정보가 풍부한 출력 벡터를 생성합니다. 생성(Generation)은 재구성 친화적인 코드를 원합니다. VQ 토큰은 선명한 픽셀로 다시 합쳐져야 합니다. 두 목표는 단일 인코더에서는 양립할 수 없습니다. Janus (DeepSeek, 2024년 10월)와 Janus-Pro (DeepSeek, 2025년 1월)는 해결책이 '시도를 멈추는 것'이라고 주장합니다. 두 인코더를 분리하는 것입니다. 트랜스포머 본체는 두 작업 간에 공유하되, 이해는 SigLIP를 통해 라우팅하고 생성은 VQ 토크나이저를 통해 라우팅합니다. 7B 모델에서 Janus-Pro는 GenEval에서 DALL-E 3를 능가하며 MMMU에서 LLaVA와 동등한 성능을 보입니다. 이 강의는 왜 두 개의 인코더가 하나의 인코더가 실패하는 지점에서 성공하는지 그 이유를 읽어 나갑니다.

**유형:** Build
**언어:** Python (stdlib, 이중 인코더 라우팅 + 공유 본체 신호)
**선수 요건:** 12단계 · 13단계 (Transfusion), 12단계 · 14단계 (Show-o)
**시간:** 약 120분

## 학습 목표

- 단일 공유 인코더가 이해 또는 생성 품질 중 하나를 희생하는 이유를 설명해 보세요.
- Janus-Pro의 라우팅을 설명해 보세요. 이해를 위해 입력 측에 SigLIP 특징을 사용하고, 생성을 위해 입력과 출력 모두에 VQ 토큰을 사용합니다.
- Janus가 실패한 지점에서 Janus-Pro가 성공하게 만든 데이터 믹스 스케일링을 추적해 보세요.
- 분리형(Janus-Pro), 결합 연속형(Transfusion), 결합 이산형(Show-o) 아키텍처를 비교해 보세요.

## 문제점

통합 모델은 이해와 생성 전반에 걸쳐 트랜스포머 본체를 공유합니다. 이전 시도들(Chameleon, Show-o, Transfusion)은 모두 양방향에 하나의 시각적 토크나이저를 사용합니다. 토크나이저는 타협안입니다:

- 재구성(생성)에 최적화됨: VQ-VAE는 세밀한 픽셀 디테일을 포착하지만 시맨틱 일관성이 약한 토큰을 생성합니다.
- 시맨틱(이해)에 최적화됨: SigLIP 임베딩은 'cat' 이미지를 'cat' 토큰 근처에 그룹화하지만 좋은 재구성을 허용하지 않습니다.

Show-o와 Transfusion은 이 때문에 한 방향에 눈에 띄는 품질 세금을 지불합니다. Janus-Pro는 이렇게 묻습니다: 작업의 요구 사항이 다름에도 왜 하나의 토크나이저를 요구해야 할까요?

## 개념

### 분리된 시각적 인코딩

Janus-Pro의 아키텍처는 두 인코더를 분리합니다:

- 이해 경로. 입력 이미지 → SigLIP-SO400m → 2층 MLP → 트랜스포머 본체.
- 생성 경로. 입력 이미지(기존 이미지를 조건으로 사용하는 경우) → VQ 토크나이저 → 토큰 ID → 트랜스포머 본체.
- 출력 생성. 트랜스포머가 예측한 이미지 토큰 → VQ 디코더 → 픽셀.

트랜스포머 본체는 공유됩니다. 본체의 상하류는 모두 작업별입니다.

입력은 프롬프트 형식으로 구분됩니다: `<understand>` 태그는 SigLIP을 통해 라우팅되고, `<generate>`는 VQ를 통해 라우팅됩니다. 또는 라우팅은 작업에서 암시적으로 결정됩니다.

### 이 방식이 작동하는 이유

이해 손실은 SigLIP 특징을 사용하며, 이는 CLIP 스타일 사전 학습으로 시맨틱 유사성에 맞게 조정되었습니다. 입력 특징이 작업에 더 적합하기 때문에 모델의 인식 벤치마크가 Show-o / Transfusion보다 개선됩니다.

생성 손실은 VQ 토큰을 사용하며, 이는 토크나이저가 재구성(reconstruction)에 맞게 조정했습니다. VQ 코드가 픽셀로 깔끔하게 복원되므로 이미지 품질이 Show-o보다 개선됩니다.

공유 트랜스포머 본체는 두 입력 분포(SigLIP와 VQ)를 보고 둘 모두와 함께 작동하는 것을 학습합니다. 주장: 충분한 데이터 + 충분한 매개변수라면, 본체가 전환을 흡수합니다.

### 데이터 확장 — Janus vs Janus-Pro

Janus(원본, arXiv 2410.13848)는 분리(decoupling)를 도입했지만 작은 규모(1.3B 매개변수, 제한된 데이터)였습니다. Janus-Pro(arXiv 2501.17811)는 확장했습니다:

- 7B 매개변수(1.3B 대비).
- 1단계(정렬)용 이미지-텍스트 쌍 90M(72M에서 증가).
- 2단계(통합)용 72M(26M에서 증가).
- 3단계용 이미지 생성 지시문 샘플 200k 추가.

결론: Janus-Pro-7B는 MMMU에서 LLaVA와 동등하고(60.3 vs ~58), GenEval에서 DALL-E 3을 능가합니다(0.80 vs 0.67). 하나의 오픈 모델이 통합 스펙트럼의 양쪽 모두에서 경쟁력을 가집니다.

### JanusFlow — rectified flow 변형

JanusFlow(arXiv 2411.07975)는 VQ 생성 경로를 rectified-flow 생성 경로(연속)로 교체합니다. 분리는 SigLIP-for-understanding + rectified-flow-for-generation이 됩니다. 품질 상한이 더 높아집니다. 아키텍처는 분리된 인코더-공유 본체로 유지됩니다.

### 공유 본체의 역할

트랜스포머 본문은 두 가지 입력 분포를 가진 통합 시퀀스를 처리합니다. 그 역할은 다음과 같습니다:

- 이해를 위해: SigLIP 특징 + 텍스트 토큰을 소비 → 텍스트를 자기회귀(Autoregressive) 방식으로 생성합니다.
- 생성을 위해: 텍스트 토큰 + (선택적 이미지 VQ 토큰)을 소비 → 이미지 VQ 토큰을 자기회귀(Autoregressive) 방식으로 생성합니다.

본문은 블록별 모달리티 특화 가중치가 없습니다. Qwen이나 Llama 내부에서 기대할 수 있는 텍스트 스타일 트랜스포머(Transformer)이며, 두 개의 입력 어댑터가 추가되어 있습니다.

흥미롭게도, 이는 Janus-Pro의 본문을 사전 학습된 LLM (대규모 언어 모델)(LLM (Large Language Model))으로 초기화할 수 있음을 의미합니다. Janus-Pro는 DeepSeek-MoE-7B로 초기화합니다. 이 선택은 중요합니다: 순수하게 처음부터 학습된 통합 모델이 도달하기 어려운 추론 능력을 LLM이 기여하기 때문입니다.

### InternVL-U와 비교

InternVL-U (12.10강)는 2026년 후속 모델입니다. 이는 다음을 결합합니다:

- 네이티브 멀티모달 사전 학습(InternVL3 백본).
- 분리된 인코더 라우팅(SigLIP 입력, VQ + 확산(Diffusion) 헤드 출력).
- 통합 이해 + 생성 + 편집.

InternVL-U는 Janus-Pro의 아키텍처 선택을 더 큰 프레임워크로 포괄합니다. 분리된 인코더 아이디어는 이제 대규모 통합 모델의 기본이 되었습니다.

### 한계

분리된 인코더는 아키텍처 복잡성을 추가합니다. 훈련해야 할 두 개의 토크나이저, 유지해야 할 두 개의 입력 경로, 두 세트의 실패 모드. 생성이 필요하지 않은 제품에는 Janus-Pro는 과잉 설계입니다 — LLaVA 계열의 이해 모델을 선택하세요.

이해가 필요하지 않은 제품에는 Janus-Pro는 과잉 자격입니다 — Stable Diffusion 3 / Flux 모델을 선택하세요.

둘 다 필요한 제품에는 Janus-Pro가 이제 참조 오픈 아키텍처입니다.

## 사용하기

`code/main.py`는 Janus-Pro 라우팅을 시뮬레이션합니다:

- 두 개의 목(mock) 인코더: SigLIP 스타일(256차원 시맨틱 벡터 생성) 및 VQ 스타일(정수 코드 생성).
- 태스크 태그에 따라 인코더를 선택하는 프롬프트 라우터.
- 어떤 인코더가 생성했는지와 관계없이 토큰 시퀀스를 처리하는 공유 본문(대체).
- 1단계(정렬)에서 3단계(지시문 미세 조정) 가중치 샘플 스케줄로 전환.

3가지 예제에 대한 라우팅 경로를 출력하세요: 이미지 QA, T2I, 이미지 편집.

## 출시하기

이 강의는 `outputs/skill-decoupled-encoder-picker.md`를 생성합니다. 프론티어급 품질의 통합 생성 및 이해를 원하는 제품이 Janus-Pro, JanusFlow 또는 InternVL-U를 선택하고 구체적인 데이터 규모 권장 사항을 제시합니다.

## 연습 문제

1. Janus-Pro-7B는 GenEval에서 DALL-E 3를 능가합니다. 7B 오픈 모델이 생성에서는 프론티어 독점 모델과 대등한 성능을 내면서도 이해에서는 그렇지 못한 이유를 설명하세요.

2. 라우터 함수를 구현하세요: 프롬프트 텍스트가 주어지면 `understand` 또는 `generate`로 분류합니다. "설명한 후 스케치하세요"와 같은 모호한 프롬프트는 어떻게 처리하나요?

3. JanusFlow는 VQ 경로를 rectified flow로 대체합니다. 트랜스포머 본문은 이제 무엇을 출력하며, 손실(loss)에는 어떤 변화가 생기는가요?

4. Janus-Pro 아키텍처가 하나의 분리된 인코더를 추가하여 처리할 수 있는 네 번째 작업을 제안하세요. 예: 이미지 분할(DINO 스타일), 깊이(MiDaS 스타일).

5. Janus-Pro의 섹션 4.2를 읽고 데이터 스케일링에 대해 살펴보세요. Janus 대비 T2I 품질 향상에는 어떤 데이터 단계가 가장 크게 기여하나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| 분리된 인코딩 | "두 개의 시각 인코더" | 방향별 분리된 토크나이저 또는 인코더: 이해용 시맨틱, 생성용 복원 |
| 공유 본문 | "하나의 트랜스포머" | 단일 트랜스포머가 어느 인코더의 출력이나 처리하며, 모달리티별 가중치가 없음 |
| 이해용 SigLIP | "시맨틱 특징" | 풍부한 개념적 특징을 제공하지만 복원 성능이 낮은 CLIP 계열 비전 타워 |
| 생성용 VQ | "복원 코드" | 픽셀로 깔끔하게 디코딩되는 벡터 양자화 토큰 |
| JanusFlow | "Rectified-flow 변형" | VQ 대신 연속적인 flow-matching 생성 헤드를 사용하는 Janus-Pro |
| 라우팅 태그 | "태스크 태그" | 입력 인코더를 선택하는 프롬프트 마커 (`<understand>` / `<generate>`) |
