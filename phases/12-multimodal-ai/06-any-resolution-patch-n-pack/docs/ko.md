# 임의 해상도 비전: Patch-n'-Pack과 NaFlex

> 실제 이미지는 224x224 정사각형이 아닙니다. 영수증은 9:16, 차트는 16:9, 의료 스캔은 4096x4096일 수 있으며, 모바일 스크린샷은 9:19.5입니다. 2024년 이전 VLM의 해답인 모든 것을 고정된 정사각형으로 리사이즈하는 방식은 OCR, 문서 이해, 고해상도 장면 파싱을 가능하게 하는 신호를 버렸습니다. NaViT (Google, 2023)는 블록 대각선 마스킹을 통해 가변 해상도 패치를 단일 트랜스포머 배치에 패킹할 수 있음을 보여 주었습니다. Qwen2-VL의 M-RoPE (2024)는 절대 위치 테이블을 완전히 제거했습니다. LLaVA-NeXT의 AnyRes는 고해상도 이미지를 기본 이미지와 하위 이미지로 타일링했습니다. SigLIP 2의 NaFlex 변형 (2025)은 모든 종횡비를 단일 체크포인트로 서빙하려는 오픈 VLM의 기본 인코더가 되었습니다. 이 강의는 patch-n'-pack을 처음부터 끝까지 구현합니다.

**유형:** Build
**언어:** Python (stdlib, patch packer + 블록 대각선 마스크)
**선수 요건:** 12단계 · 01강 (ViT 패치), 12단계 · 05강 (LLaVA)
**시간:** 약 120분

## 학습 목표

- 가변 해상도 이미지 배치에서 패치를 하나의 시퀀스로 패킹하고 블록 대각선 어텐션 마스크를 구축해 보세요.
- 주어진 작업에 대해 AnyRes 타일링 (LLaVA-NeXT), NaFlex (SigLIP 2), M-RoPE (Qwen2-VL) 중 하나를 선택해 보세요.
- 리사이즈 없이 OCR, 차트, 사진에 대한 토큰 예산을 계산해 보세요.
- 정사각형 리사이즈의 세 가지 실패 모드인 찌그러진 텍스트, 잘린 콘텐츠, 패딩에 낭비된 토큰을 나열해 보세요.

## 문제점

트랜스포머는 시퀀스를 기대합니다. 배치는 같은 길이의 시퀀스 스택입니다. 이미지가 224x224라면 매번 196개의 패치 토큰을 얻게 되며, 패딩이 필요 없고 작업이 완료됩니다. 224로 학습하고 224로 추론하며, 해상도에 대해 다시는 생각하지 않습니다.

세상은 협력하지 않습니다. 문서는 세로 방향 (8.5x11 인치, 약 2:3)입니다. 차트 스크린샷은 가로 방향 (16:9)입니다. 영수증은 길고 얇습니다 (1:3). 의료 영상은 2048x2048 이상으로 제공됩니다. 모바일 기기 스크린샷은 1170x2532 (0.46:1)입니다.

2024년 이전의 세 가지 옵션과 각각이 실패하는 이유:

1. 고정된 정사각형 (224x224 또는 336x336)으로 리사이즈합니다. 찌그러짐은 텍스트와 얼굴을 왜곡합니다. 다운스케일링은 차트 레이블과 OCR 콘텐츠를 파괴합니다. LLaVA-1.5까지 표준 관행이었습니다.
2. 고정된 종횡비로 잘라내기(Crop). 이미지의 대부분을 버리게 되며, 잘라낼 위치를 선택하는 것 자체가 하나의 비전 문제입니다.
3. 가장 긴 변에 맞춰 패딩(Pad)하기. 왜곡은 해결되지만, 세로로 긴 이미지에서는 패딩 토큰에 50% 이상의 토큰을 낭비하게 됩니다. 모든 패딩 토큰에 대해 2차적인 어텐션 비용이 발생합니다.

2024-2025년의 해답: 트랜스포머가 이미지의 원본 해상도에서 패치를 처리하도록 하고, 낭비되는 연산 없이 이질적인 배치(batch)를 하나의 시퀀스에 어떻게-packed할지 알아내는 것입니다.

## 개념

### NaViT와 patch-n'-pack

NaViT (Dehghani et al., 2023)는 이 방법이 대규모로 작동한다는 것을 보여준 논문입니다. 아이디어는 기계적입니다:

1. 배치(batch) 내의 각 이미지에 대해 선택된 패치 크기(예: 14)로 원본 패치 그리드를 계산합니다.
2. 각 이미지의 패치를 자체 가변 길이 시퀀스로 평탄화(Flatten)합니다.
3. 배치를 위해 모든 이미지의 패치를 하나의 긴 시퀀스로 연결(Concatenate)합니다.
4. 이미지 A의 패치가 이미지 A 내에서만 어텐션하도록 블록 대각(block-diagonal) 어텐션 마스크를 구성합니다.
5. 패치별 위치 정보(2D RoPE 또는 분수 위치 임베딩)를 전달합니다.

336x336 (576 토큰), 224x224 (256 토큰), 448x336 (768 토큰) 크기의 이미지 세 장으로 이루어진 배치는 1600x1600 블록 대각 마스크를 가진 하나의 1600 토큰 시퀀스가 됩니다. 패딩이 없습니다. 낭비되는 연산이 없습니다. 트랜스포머는 임의의 종횡비를 처리합니다.

NaViT는 또한 학습 중 분수 패치 드롭(fractional patch dropping)을 도입했습니다. 배치 전체에서 무작위로 패치의 50%를 드롭하는 방식으로, 정규화(regularization)와 학습 속도 향상을 모두 달성합니다. SigLIP 2는 이 방식을 상속받았습니다.

### AnyRes (LLaVA-NeXT)

LLaVA-NeXT의 AnyRes는 실용적인 대안입니다. 고정된 인코더(CLIP 또는 SigLIP, 336)가 주어졌을 때, 고해상도 이미지를 타일링(tiling)합니다:

1. 이미지의 종횡비에 가장 잘 맞는 (1x1), (1x2), (2x1), (1x3), (3x1), (2x2) 등 predefined set에서 그리드 레이아웃을 선택합니다.
2. 전체 이미지를 그리드에 타일링하며, 각 타일은 336x336 크롭이 됩니다.
3. 썸네일(thumbnail)도 생성합니다. 전체 이미지를 336x336으로 리사이즈하여 전역 컨텍스트(global-context) 토큰으로 만듭니다.
4. 동결된(frozen) 336 인코더를 통해 모든 타일을 인코딩합니다. 타일 토큰과 썸네일 토큰을 연결(Concatenate)합니다.

2x2 그리드와 썸네일을 사용하는 672x672 이미지의 경우: 4 * 576 + 576 = 2880개의 시각적 토큰이 됩니다. 비용이 많이 들지만 효과적입니다 — LLM이 지역적 세부 사항과 전역적 컨텍스트를 모두 인식할 수 있습니다.

인코더가 고정(frozen)되어 있고 단일 해상도만 지원할 때 AnyRes는 선택할 수 있는 경로입니다. 큰 이미지에서는 토큰 수가 폭발적으로 증가합니다 (4x4 그리드를 사용하는 1344x1344 이미지는 9216 + 576 ≈ 9800 토큰으로, 8k LLM 컨텍스트의 대부분을 채웁니다).

### M-RoPE (Qwen2-VL)

Qwen2-VL은 멀티모달 로터리 위치 임베딩(Multimodal Rotary Position Embedding)을 도입했습니다. NaViT의 소수점 위치나 AnyRes의 타일 및 썸네일 방식 대신, 각 패치는 3D 위치(시간, 높이, 너비)를 포함합니다. 쿼리/키 회전은 임의의 H, W 및 시간 길이를 처리합니다.

M-RoPE는 재학습 없이 네이티브 동적 해상도를 지원합니다. 추론 시 임의의 HxW 이미지를 입력하면, 패치 임베더가 H/14 x W/14개의 토큰을 생성하고, 각 토큰은 (t=0, r=row, c=col) 위치를 받으며, RoPE가 올바른 주파수로 어텐션을 회전시킵니다. Qwen2.5-VL과 Qwen3-VL은 이를 계승하고 있습니다. InternVL3의 V2PE는 모달리티별 가변 인코딩을 사용하는 동일한 개념입니다.

AnyRes와 달리, M-RoPE는 네이티브 해상도에서 O(H x W / P^2)개의 토큰을 사용하며, 곱셈식 타일 오버헤드가 없습니다. NaViT와 달리, 여전히 포워드당 단일 이미지를 기대합니다. 해상도 간 배칭은 여전히 patch-n'-pack이 필요합니다.

### NaFlex (SigLIP 2)

NaFlex는 SigLIP 2 체크포인트의 네이티브-flex 모드입니다. 단일 모델이 추론 시 여러 시퀀스 길이(256, 729, 1024 토큰)를 지원합니다. 내부적으로는 학습 중 NaViT 스타일의 patch-n'-pack을 사용하며, 각 패치에 절대 소수점 위치를 적용합니다. 장점: 하나의 체크포인트로, 작업에 따라 추론 시 토큰 예산을 선택할 수 있습니다.

시맨틱 작업(분류, 검색)의 경우 256 토큰을 사용합니다. OCR이나 차트 이해의 경우 1024 토큰을 사용합니다. 재학습이 필요 없습니다.

### 패킹 마스크

블록 대각선 마스크는 대부분의 구현이 어려움을 겪는 부분입니다. `i=0..B-1`개의 이미지와 `n_i` 길이를 포함하는 `N_total` 길이의 패킹된 시퀀스에 대해, `(N_total, N_total)` 형태의 `M` 마스크는 두 인덱스가 같은 이미지의 블록에 속하면 1이고, 그렇지 않으면 0입니다. 누적 길이 목록에서 이를 구축할 수 있습니다:

```
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = 1 iff there exists b where offsets[b] <= i < offsets[b+1] and offsets[b] <= j < offsets[b+1]
```

PyTorch에서는 `torch.block_diag` 또는 명시적인 gather를 사용하여 한 줄로 처리할 수 있습니다. FlashAttention의 가변 길이 경로(`cu_seqlens`)는 마스크를 완전히 생략하고 누적 길이 텐서를 직접 사용하여 시퀀스 내에서 어텐션을 수행합니다. 이는 일반적인 배치에서 밀집 마스크보다 약 10배 더 빠릅니다.

### 토큰 예산

작업에 따라 전략을 선택해 보세요:

- OCR / 문서: 1024-4096 토큰. SigLIP 2 NaFlex는 1024 토큰을 사용하거나, AnyRes 3x3 + 썸네일을 사용합니다.
- 차트 및 UI: 384-448 네이티브 해상도에서 729-1024 토큰. Qwen2.5-VL의 동적 해상도 및 최대 픽셀 상한을 사용합니다.
- 자연 사진: 256-576 토큰이면 충분합니다. 다운스트림 LLM이 충분히 인식할 수 있습니다. 콘텐츠 밀도가 높은 곳에 토큰을 할당하세요.
- 비디오: 공간 풀링 후 프레임당 64-128 토큰, 2-8 FPS. 12.17강에서 이 내용을 다룹니다.

2026년 생산 규칙: 작업별 최대 픽셀 상한을 선택하고, 그 상한까지 네이티브 종횡비로 인코딩한 후, 배치를 패킹하고 패딩을 생략하세요. Qwen2.5-VL은 정확히 이 설정을 위해 `min_pixels`과 `max_pixels`을 제공합니다.

## 사용하기

`code/main.py`는 정수 픽셀 좌표를 가진 이질적인 이미지 배치에 대해 patch-n'-pack을 구현합니다. 이 기능은:

- (H, W) 이미지 크기 목록을 입력받습니다.
- 패치 크기 14에서 각 이미지의 패치 시퀀스 길이를 계산합니다.
- 총 길이가 `sum(n_i)`인 하나의 시퀀스로 패킹합니다.
- 블록 대각선 어텐션 마스크(명확성을 위해 밀집)를 구축합니다.
- 패킹된 비용과 정사각형 리사이즈 및 AnyRes 타일링을 비교합니다.
- 혼합 배치(영수증, 차트, 스크린샷, 사진)에 대한 토큰 예산 표를 출력합니다.

실행해 보세요. 도출된 수치들은 2026년 모든 오픈 VLM이 patch-n'-pack을 사용하는 이유입니다.

## 출시하기

이 강의는 `outputs/skill-resolution-budget-planner.md`을 생성합니다. 혼합 종횡비 작업량(OCR, 차트, 사진, 비디오 프레임)과 총 토큰 예산이 주어지면, 올바른 전략(NaFlex, AnyRes, M-RoPE 또는 고정 정사각형)을 선택하고 요청별 구성을 출력합니다. 제품용 VLM을 설계할 때 이 스킬을 사용하세요. 이는 지연 시간 예산을 파괴하는 조용한 10배 토큰 팽창을 방지합니다.

## 연습 문제

1. 영수증은 600x1500 (1:2.5)입니다. 패치 크기 14일 때, 원본 해상도에서 토큰은 몇 개가 되나요? 336으로 정사각형 리사이즈한 후에는 몇 개가 되나요? 실제 OCR 정확도 측면에서 어느 쪽이 더 큰 손실을 입나요?

2. 길이가 256, 576, 729, 1024인 네 장의 이미지 배치를 위한 블록 대각(mask)를 구성해 보세요. 어텐션 행렬이 2585x2585이며 `256^2 + 576^2 + 729^2 + 1024^2`개의 비영(non-zero) 항목을 정확히 포함하는지 확인하세요.

3. 패치 크기 14인 1792x896 이미지에 대해 다음을 비교하세요: (a) 336으로 정사각형 리사이즈 후 인코딩, (b) AnyRes 2x1 + 썸네일, (c) 원본 해상도에서의 M-RoPE. 어느 방법이 가장 적은 토큰을 사용하나요? 어느 방법이 가장 많은 세부 정보를 보존하나요?

4. 분수 패치 드롭(fractional patch dropping)을 구현하세요. 주어진 팩킹된 시퀀스에서 토큰의 50%를 균일한 확률로 무작위로 드롭하고, 블록 대각(mask)를 이에 따라 업데이트하세요. mask의 희소성(sparsity) 변화를 측정하세요.

5. Qwen2-VL 논문(arXiv:2409.12191)의 섹션 3.2를 읽어 보세요. `min_pixels`과 `max_pixels`이 무엇을 제어하며 왜 두 경계 모두 중요한지 두 문장으로 설명하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| Patch-n'-pack | "NaViT 스타일 팩킹" | 서로 다른 이미지에서 가변 길이 패치 시퀀스를 하나의 배치 차원으로 연결(concatenate)하는 것 |
| 블록 대각 mask | "팩킹 mask" | 각 이미지의 패치가 팩킹 내의 이웃이 아닌 자기 자신에만 어텐션하도록 제한하는 어텐션 mask |
| AnyRes | "LLaVA-NeXT 태일링(tiling)" | 고해상도 이미지를 고정 크기 태일의 그리드와 전역 썸네일로 분할; 모든 태일을 고정 인코더로 인코딩 |
| NaFlex | "SigLIP 2 네이티브-flex" | 재학습 없이 추론 시 256/729/1024 토큰 예산을 제공하는 단일 SigLIP 2 체크포인트 |
| M-RoPE | "멀티모달 RoPE" | 위치 테이블 없이 임의의 H, W, T를 처리하는 3D 회전 위치 인코딩(시간, 행, 열) |
| cu_seqlens | "FlashAttention 팩킹" | FlashAttention varlen 경로가 밀집 블록 대각 mask 대신 사용하는 누적 길이 텐서 |
| min_pixels / max_pixels | "해상도 경계" | 매우 작거나 매우 큰 입력에서 토큰 수를 제한하는 Qwen2.5-VL의 요청 단위 매개변수 |
| 시각 토큰 예산 | "이미지당 토큰 수" | 이미지당 방출되는 패치 토큰의 대략적인 개수; LLM의 프롬프트 예산과 어텐션 비용을 설정 |
