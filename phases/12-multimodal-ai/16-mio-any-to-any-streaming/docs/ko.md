# MIO와 Any-to-Any 스트리밍 멀티모달 모델

> GPT-4o는 대부분의 오픈 모델이 복제할 수 없는 제품을 출시했습니다. 음성으로 듣고, 영상을 보며, 실시간으로 응답하는 에이전트입니다. 2024년 말 오픈 생태계의 답은 MIO (Wang et al., 2024년 9월)였습니다. MIO는 텍스트, 이미지, 음성, 음악의 토큰화를 수행하고, 인터리브(interleaved)된 시퀀스에 대해 하나의 인과적 트랜스포머를 학습하며, 모든 모달리티에서 모든 모달리티로 생성합니다. AnyGPT (Zhan et al., 2024년 2월)는 개념 증명(proof of concept)이었고, MIO는 이를 확장한 버전이며, Unified-IO 2 (Allen AI, 2023년 12월)는 비전 + 액션 그라운딩을 포함하는 사촌 격입니다. 이 강의는 any-to-any 패턴을 읽습니다. 네 개의 토크나이저, 하나의 트랜스포머, 스트리밍 친화적인 디코딩입니다.

**유형:** Learn
**언어:** Python (stdlib, 4개 모달리티 토큰 할당자 + 스트리밍 디코딩 루프)
**선수 요건:** 12단계 · 11강 (Chameleon), 6강 (음성과 오디오)
**시간:** 약 120분

## 학습 목표

- 충돌 없이 텍스트, 이미지, 음성, 음악 토큰을 수용하는 공유 어휘를 설계해 보세요.
- SEED-Tokenizer (이미지)와 SpeechTokenizer 잔차 VQ (음성)의 압축 및 재구성 트레이드오프를 비교해 보세요.
- any-to-any 생성을 구축하는 4단계 커리큘럼을 설명해 보세요.
- 세 가지 오픈 any-to-any 레시피(MIO, AnyGPT, Unified-IO 2)와 주요 트레이드오프를 나열해 보세요.

## 문제점

통합 멀티모달 모델은 주장하기는 쉽지만, 대규모로 구축하기는 어렵습니다. 2024년까지 대부분의 "any-to-any" 시스템은 파이프라인 방식이었습니다. 비전 모델 → 텍스트 표현 → 음성 모델 → 오디오. 각 단계는 정보를 손실하고, 지연을 추가하며, 학습을 복잡하게 만듭니다. GPT-4o의 데모 영상은 단일 모델 대안으로 1초 미만 응답을 보여 주었고, 오픈 시스템은 몇 달 뒤처졌습니다.

엔지니어링 과제:

- 모든 모달리티에 토크나이저가 존재해야 하며, 재구성을 위해 충분히 손실 없는 압축을 수행하고, 트랜스포머가 소비할 수 있는 속도로 토큰을 생성해야 합니다.
- 단일 어휘는 텍스트(32k+), 이미지(16k+), 음성(4k+), 음악(8k+)에 대한 공간을 할당해야 합니다. 최소 4만 개 이상의 항목이 필요합니다.
- 학습 데이터는 모든 입력-출력 쌍(텍스트→이미지, 이미지→음성, 음성→이미지 등)을 포함해야 하거나, 모델이 이를 구성(compose)해야 합니다.
- 추론은 대화 지연 시간(<500ms의 첫 오디오 바이트까지의 시간)을 위해 출력 토큰을 충분히 빠르게 스트리밍해야 합니다.

## 개념

### 네 가지 모달리티를 위한 네 가지 토크나이저

MIO의 토크나이저 스택:

- 텍스트: 표준 바이트 쌍 인코딩 (BPE)(Byte Pair Encoding (BPE)), 어휘 약 32000개.
- 이미지: SEED-Tokenizer (2023) — 이산 코드북을 가진 양자화된 변분 오토인코더 (VAE)(VAE (Variational Autoencoder)), 4096개 항목, 이미지당 32x32 토큰.
- 음성: SpeechTokenizer residual-VQ (2023) — 16kHz 파형을 8개의 계층적 코드북으로 인코딩합니다. 첫 번째 레벨은 거친 내용(content)을 포함하며, 이후 레벨은 운율(prosody)과 화자 식별자(speaker identity)를 추가합니다.
- 음악: 유사한 residual-VQ (Meta의 MusicGen / Encodec 계열), 4-8개 코드북.

각 모달리티는 정수 토큰을 생성합니다. 토큰은 공유 어휘에서 서로 겹치지 않는 ID 범위를 가집니다:

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

총합: 약 48k 어휘. 입력 임베딩과 출력 투영은 이 전체를 포함합니다.

### 스트리밍 디코딩

음성 생성은 residual-VQ를 사용합니다. 트랜스포머는 기본(layer 0) 음성 토큰을 예측하며, 병렬 디코딩된 residual quantizer가 이후 레이어를 예측합니다. 각 layer 0 토큰은 16kHz에서 약 50ms의 오디오에 해당합니다.

스트리밍 패턴:

1. 사용자가 마이크에 말하면, 실시간 오디오 토크나이저가 50ms마다 음성 토큰을 방출합니다.
2. MIO는 토큰이 도착하는 즉시 소비합니다(프롬프트 프리필(Prefill) + 증분 순전파).
3. 출력 토큰은 생성되는 대로 스트리밍되며, 병렬 음성 디코더가 이를 약 50-150ms 지연으로 오디오 샘플로 변환합니다.
4. 첫 오디오 바이트까지의 시간: MIO 논문에서 약 300-500ms로, GPT-4o의 약 250ms에 근접합니다.

Mini-Omni (arXiv:2408.16725), GLM-4-Voice (arXiv:2412.02612), Moshi (arXiv:2410.00037)는 상호 보완적인 스트리밍 음성-LLM 설계입니다. 특히 Moshi는 단일 GPU에서 160ms 왕복 시간을 달성합니다.

### 4단계 커리큘럼

MIO의 학습 커리큘럼:

1. 1단계 — 정렬(Alignment). 대규모 모달리티 쌍 코퍼pus: 텍스트-이미지, 텍스트-음성, 텍스트-음악. 각 쌍은 자체 토큰 어휘 세그먼트를 사용합니다. 공유 어휘를 학습합니다.
2. 2단계 — 인터리빙(interleaved). 멀티 모달리티 인터리빙 문서(이미지 + 비디오가 포함된 블로그, 전사(transcript)가 포함된 팟캐스트 등). 모달리티 간 컨텍스트를 학습합니다.
3. 3단계 — 음성 강화. 음성 품질을 높이기 위해 추가 오디오 데이터를 사용하며, 텍스트 기능은 유지합니다.
4. 4단계 — SFT (지도 미세 조정)(SFT (Supervised Fine-Tuning)). VQA, 캡셔닝, 내레이션, 음성 간 대화 등 다양한 모달리티에 걸쳐 지시문 튜닝을 수행합니다.

단계가 누락되면 특정 기능이 저하됩니다. 2단계를 건너뛰면 모델이 교차 모달리티 컨텍스트를 잃고, 3단계를 건너뛰면 음성 품질이 떨어집니다.

### 시각적 사고의 연쇄(Chain-of-visual-thought)

MIO는 시각적 사고의 연쇄(Chain-of-visual-thought)를 도입합니다. 모델은 추론 단계로 중간 이미지 토큰을 생성합니다. "고양이가 나무를 오르고 있나요?"라는 질문에 대해 모델은 다음과 같이 동작합니다:

1. 장면을 렌더링하는 `<image>` 토큰을 생성합니다 (입력 이미지나 스케치에서 생성).
2. 스케치를 분석하는 텍스트를 생성합니다.
3. 최종 답변을 생성합니다.

렌더링된 중간 이미지는 메모장 역할을 합니다. 공간 추론 작업에서 벤치마크 성능이 향상됩니다. 이 아이디어는 텍스트 추론에서의 사고의 연쇄 (CoT)(Chain of Thought (CoT))와 유사합니다.

### any-to-any 분야의 경쟁 제품

- AnyGPT (arXiv:2402.12226): 4가지 모달리티 (텍스트, 이미지, 음성, 음악)를 지원하며, 유사한 설계입니다.
- Unified-IO 2 (arXiv:2312.17172): 비전 액션 출력, 깊이, 법선 벡터를 추가합니다. 더 다양한 작업을 지원하지만 규모는 더 작습니다.
- NExT-GPT (arXiv:2309.05519): LLM (대규모 언어 모델)(LLM (Large Language Model)) + 모달리티별 확산 모델(Diffusion Model) 디코더를 사용합니다. 단일 모델 접근 방식이 아닙니다.
- CoDi (arXiv:2305.11846): 조합 가능한 확산 모델(Diffusion Model)을 사용하며, 공유 잠재 공간(Latent Space)을 통해 any-to-any를 구현합니다.

MIO는 순수 토큰 기반 any-to-any에 가장 가깝습니다. AnyGPT는 개념적 선구자입니다.

### 지연 시간 예산

대화형 제품에서는 모든 구성 요소의 지연 시간이 중요합니다:

- 마이크에서 오디오 토큰까지: 약 50ms.
- 프리필(Prefill) (오디오 토큰 + 히스토리): 8B 모델에서 약 100ms.
- 첫 출력 토큰: 약 50ms.
- 병렬 잔차 VQ + 음성 디코더: 약 100-150ms.

첫 오디오 바이트까지의 총 시간: 최소 약 300ms. GPT-4o는 약 250ms를 주장합니다. Moshi는 160ms를 주장합니다. MIO/AnyGPT는 공개 벤치마크 기준 400-600ms 범위입니다.

### any-to-any가 어려운 이유

2026년에도 오픈 any-to-any 모델은 두 가지 축에서 폐쇄형 모델보다 뒤처집니다:

- 음성 품질. 잔차 VQ 토크나이저는 손실률이 높으며, 대화형 음성은 ElevenLabs급 음성 대비 로봇처럼 들립니다.
- 모달리티 간 추론. 모델에게 "보이는 것에 대해 노래하라"고 요청하는 것은 순수 비전 작업보다 실패율이 더 높습니다.

이것들은 오픈 연구 문제입니다. Qwen3-Omni (12.20강)는 2025년 가장 진보된 오픈 시도입니다.

## 사용하기

`code/main.py`:

- 4가지 모달리티 어휘 할당을 정의하고 출력합니다.
- 멀티모달 입력 목록(텍스트, 이미지, 오디오 클립, 음악)을 토크나이저 라우터를 통해 라우팅합니다.
- 지연 시간 카운팅이 포함된 텍스트-음성 응답에 대한 스트리밍 디코딩을 시뮬레이션합니다.
- 인코더, 프리필, 디코더 지연 시간을 고려하여 예상 첫 오디오 바이트까지의 시간을 계산합니다.

## 연습 문제

1. 제품이 음성 입력을 받아 음성 출력을 반환합니다. 엔드투엔드 지연 시간 예산 목표는 무엇인가요? 시간을 소비하는 구성 요소를 나열해 보세요.

2. SpeechTokenizer residual-VQ는 8개의 코드북을 사용합니다. 잔여 레벨을 병렬 디코딩하는 것이 왜 필요한지(순차적 디코딩 대비)와 어떤 지연 시간 절감 효과가 있는지 제안해 보세요.

3. 어휘가 텍스트 32k + 이미지 4k + 음성 4k입니다. 음악 8k와 약 10개의 구분자를 추가합니다. 은닉 차원(hidden dim)이 4096일 때 임베딩 매트릭스 매개변수 비용은 얼마인가요?

4. Chain-of-visual-thought는 중간 이미지를 생성합니다. 어떤 종류의 질문이 이점을 얻나요? 어떤 종류의 질문이 추가 토큰으로 인해 피해를 입나요?

5. Moshi(arXiv:2410.00037)를 읽어 보세요. 그 모델의 "내면 독백(inner monologue)" 기법을 설명하고 MIO의 chain-of-visual-thought와 비교해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| Any-to-any | "멀티모달 입/출력" | 텍스트, 이미지, 음성, 음악을 모든 방향으로 수용하고 생성하는 단일 모델 |
| Residual-VQ | "음성 토크나이저 스택" | 각 레이어가 정보를 추가하는 다중 코드북 토큰화; 기본 레이어는 내용(content), 이후 레이어는 운율(prosody) |
| SEED-Tokenizer | "이미지 코드" | MIO가 사용하는 4096 항목 코드북을 가진 이산 이미지 토크나이저 |
| 시각적 사고의 연쇄 | "시각적 스크래치패드" | 모델이 최종 답변 전에 추론 단계로 중간 이미지를 생성합니다 |
| 첫 오디오 바이트까지의 시간 | "TTFAB" | 사용자 음성에서 첫 오디오 출력까지의 지연 시간; 대화식 느낌을 위해 500ms 미만 |
| 4단계 커리큘럼 | "학습 레시피" | 정렬 -> 인터리브드 -> 음성 강화 -> SFT 순서 |
