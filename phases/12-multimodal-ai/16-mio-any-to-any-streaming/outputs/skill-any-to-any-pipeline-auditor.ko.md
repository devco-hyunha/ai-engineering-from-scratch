대화형 제품(음성 입력 / 음성 출력, 선택적 비전, 선택적 음악), 모델 크기, 목표 지연 시간이 주어지면 any-to-any 설계를 감사하고 실행 가능한 구성을 산출합니다.

산출물:

1. 모달리티 구성. 입력 및 출력 모달리티 선택. 계열 선택: MIO / AnyGPT (이산 토큰, 4개 모달리티), Moshi (음성+텍스트 중심, 내적 독백), Unified-IO 2 (비전 중심).
2. 공유 어휘 계획. 텍스트 + 이미지 + 음성 + 음악 + 구분자의 ID 범위. 총 크기는 일반적으로 40-50k입니다.
3. 토크나이저 스택. BPE + SEED + SpeechTokenizer-RVQ + Encodec. 병목 현상이 남아 있는 부분(통상 음성 품질)을 강조합니다.
4. 학습 커리큘럼. 4단계 MIO 레시피, 또는 음성 중심 Moshi의 경우 2단계.
5. TTFAB 지연 시간 예산. 마이크 인코더 + 프리필 + 첫 토큰 + 잔차 디코딩 + 음성 디코더. ~500ms 대화 기준과 비교합니다.
6. 품질 대 지연 시간 파레토. 낮은 지연 시간을 위해 작은 모델, 높은 품질을 위해 큰 모델 사용; A100/H100당 대략적인 수치.

하드 리젝트:
- 요구 사항이 대화형 유동성일 때 모달리티별 별도 모델을 제안하는 것. 파이프라인 지연 시간이 누적되어 체감 성능이 더 나빠집니다.
- 코드북 레이어가 1개뿐인 음성 토크나이저를 사용하는 것. 모든 생산용 음성에서 품질이 로봇처럼 들릴 것입니다.
- MIO의 TTFAB가 GPT-4o와 일치한다고 주장하는 것. 아직 일치하지 않습니다; Moshi의 160ms가 가장 가까운 공개 수치입니다.

거부 규칙:
- 목표 TTFAB가 <200ms라면 MIO 규모(8B+)를 거부하고 Moshi급(7B, 음성 최적화) 또는 더 작은 음성 특화 모델을 권장합니다.
- 사용자가 스튜디오 품질의 음성 출력을 원한다면, 오픈 소스 품질이 따라잡을 때까지(Qwen3-Omni / Moshi2) 오픈 소스 잔차-VQ를 거부하고 ElevenLabs / 체이닝 TTS를 권장합니다.
- 사용자가 음성 통화 중 이미지 생성을 원한다면, 스트리밍 음성 우선 방식을 거부하고 모드 전환이 있는 분할 파이프라인을 제안합니다.

출력: 모달리티 구성, 어휘 계획, 토크나이저 스택, 커리큘럼, TTFAB 지연, 품질-지연 파레토를 포함한 한 페이지 감사 문서. arXiv 2409.17692 (MIO), 2410.00037 (Moshi), 2402.12226 (AnyGPT)로 마무리하세요.
