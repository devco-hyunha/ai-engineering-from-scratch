# 옴니 모델: Qwen2.5-Omni와 Thinker-Talker 분리

> 2024년 5월 GPT-4o의 제품 데모는 기반 모델 자체보다 제품 형태 때문에 파괴적이었습니다. 사용자가 말하면 모델이 카메라가 보는 것을 인식하고, 250ms 미만에 응답하는 음성 인터페이스였습니다. 오픈 생태계는 2024년과 2025년 내내 이 제품 수준에 도달하기 위해 경쟁했습니다. Qwen2.5-Omni (2025년 3월)는 참고할 만한 오픈 디자인입니다. Thinker (대규모 텍스트 생성 트랜스포머)와 Talker (병렬 음성 생성 트랜스포머)로 구성되며, 스트리밍 음성 토큰으로 연결됩니다. Mini-Omni는 이를 단순화했고, Moshi는 지연 시간을 맞췄으며, GLM-4-Voice는 이를 중국어로 확장했습니다. 이 강의에서는 Thinker-Talker 아키텍처와 스트리밍 실시간 대화가 가능하게 하는 지연 시간 예산을 살펴봅니다.

**유형:** Build
**언어:** Python (표준 라이브러리, 스트리밍 파이프라인 지연 시뮬레이터 + VAD 루프)
**선수 요건:** 12단계 · 19강 (오디오-LLM), 12단계 · 16강 (any-to-any)
**시간:** 약 180분

## 학습 목표

- 추론 파이프라인을 Thinker (텍스트 추론)와 Talker (음성 합성)로 분리하고, 병렬 스트리밍이 작동하는 이유를 설명해 보세요.
- 대화형 상호작용의 첫 오디오 바이트까지의 시간 (TTFAB) 예산을 구성 요소별로 계산해 보세요.
- Thinker 내에서 비전, 오디오, 텍스트에 걸친 TMRoPE의 시간 정렬 위치 인코딩을 설명해 보세요.
- 세 가지 실시간 대화 패턴인 반이중(half-duplex), 턴 테이킹(turn-taking), 전이중(full-duplex)을 나열해 보세요.

## 문제점

실시간 음성 어시스턴트는 많은 작업을 빠르게 수행해야 합니다:

1. 사용자를 듣습니다. 실시간 음성 토큰화, 음성 활동 감지 (VAD)를 통해 사용자가 말을 끝냈는지 파악합니다.
2. 선택적으로 봅니다. 2-4 FPS의 카메라 입력을 오디오와 함께 Thinker로 스트리밍합니다.
3. 생각합니다. 대화 이력을 조건으로 응답을 구성합니다.
4. 말합니다. 오디오 토큰을 합성하고, 파형으로 디코딩하여 사용자의 스피커로 스트리밍합니다.

각 단계가 지연 시간을 추가합니다. 대화 느낌이 들려면 총 왕복 시간이 500ms 미만이어야 합니다. 그 이하에서는 사용자가 지연을 인지하지 못합니다. GPT-4o는 약 250ms, Moshi는 약 160ms, Qwen2.5-Omni는 약 350-500ms를 주장합니다.

모든 구성 요소는 스트리밍되어야 합니다. "모든 것을 배치 처리한 후 디코딩"하는 방식은 허용되지 않습니다.

## 개념

### Thinker와 Talker

Qwen2.5-Omni의 분해:

- Thinker: 텍스트 생성 트랜스포머(7B-80B). 인터리브된 텍스트 + 이미지 + 오디오 토큰을 소비합니다. 발화할 내용을 나타내는 텍스트 토큰을 출력합니다.
- Talker: 음성 생성 트랜스포머(200M-1B)로 더 작습니다. Thinker의 텍스트 출력 토큰과 최근 음성 컨텍스트 토큰을 소비합니다. 이산 음성 토큰(residual-VQ 인덱스)을 출력합니다.
- 음성 디코더: 음성 토큰을 실시간으로 오디오 샘플로 변환하는 스트리밍 파형 디코더(SNAC, MoVQGAN 계열).

분리가 중요합니다. Thinker는 좋은 추론을 위해 커야 합니다. Talker는 지역적 작업(텍스트를 음성 토큰으로 변환)이므로 작을 수 있습니다. 더 큰 Talker는 더 표현력이 높지 않으며, 더 느립니다.

두 개를 병렬로 실행합니다:

1. Thinker가 텍스트 토큰 t_i를 방출합니다.
2. Talker가 t_i를 소비(스트리밍을 통해)하고 음성 토큰 s_i, s_{i+1}, ..., s_{i+k}를 방출합니다.
3. 음성 디코더가 음성 토큰을 도착하는 대로 소비하고 오디오 샘플을 방출합니다.
4. Thinker가 텍스트 토큰 t_{i+3}에 도달했을 때, Talker는 이미 t_0..t_{i+2}에 대한 오디오를 스트리밍했습니다.

### TMRoPE — 시간 정렬된 멀티모달 위치

Thinker는 이미지 프레임(예: 4 FPS로 도착), 오디오 프레임(초당 50 프레임으로 도착), 대화 기록의 텍스트를 통합해야 합니다. 단순한 순서(모든 이미지, 그 다음 모든 오디오, 그 다음 텍스트)는 시간 정렬을 잃습니다.

TMRoPE는 모든 토큰에 절대 타임스탬프를 할당합니다. t=2.3s의 비전 토큰, t=2.32s의 오디오 토큰, t=2.35s의 사용자 텍스트 토큰 "stop". RoPE는 타임스탬프에 따라 어텐션을 회전시키므로, 모델은 이를 시간적으로 동시인 것으로 인식합니다.

이것은 "인사하면서 손을 흔들었다"가 작동하기 위한 인프라입니다. 모델은 개념적으로 같은 순간에 비디오 프레임과 오디오를 봅니다.

### 스트리밍 음성 합성

음성 토큰은 스트리밍되어야 합니다. Mini-Omni (Xie & Wu, 2024)는 "언어 모델이 듣고, 생각하면서 말하기"를 도입했습니다: Thinker 출력 토큰과 Talker 출력 토큰이 같은 시퀀스에서 교대로 나타납니다. Talker는 Thinker가 다음 텍스트 토큰을 확정하는 즉시 발화합니다. 배치 경계는 없습니다.

Moshi (Défossez et al., 2024년 10월)는 가장 빠른 오픈 구현입니다. 단일 A100에서 160ms TTFAB를 달성합니다. 아키텍처: 단일 7B 트랜스포머가 교대로 위치하는 텍스트 및 음성 토큰을 방출하며, "내적 독백(inner monologue)"이 생각 스트림과 말하기 스트림을 분리합니다. 이는 Thinker + Talker를 하나의 모델로 융합하고 세심하게 학습한 것과 실질적으로 동일합니다.

### VAD 및 턴 테이킹(turn-taking)

음성 활동 감지(Voice Activity Detection, VAD)는 입력 측에서 실행됩니다. 두 가지 패턴이 있습니다:

- 반이중(Half-duplex): 사용자가 말하고 모델이 듣습니다. 모델이 말하고 사용자가 듣습니다. VAD 침묵 감지(~200ms)를 통해 명확한 핸드오프(Handoff)가 이루어집니다.
- 전이중(Full-duplex): 양쪽이 동시에 말할 수 있습니다. 모델은 백채널("uh-huh")을 하거나 인터럽트할 수 있습니다. 훨씬 더 어렵습니다. Moshi는 이를 지원합니다.

Qwen2.5-Omni는 침묵 임계값을 통한 턴 테이킹(turn-taking)으로 기본적으로 반이중(Half-duplex)을 지원합니다. 전이중(Full-duplex)은 애플리케이션 계층의 처리가 필요합니다.

### Qwen3-Omni (2025년 11월)

후속 모델입니다. Qwen3-80B Thinker, 더 큰 Talker, 개선된 TMRoPE-v2를 사용합니다. 지연 시간은 GPT-4o의 250ms에 가깝습니다. 오픈 가중치입니다. OmniBench 벤치마크는 Gemini 2.0 Live와 경쟁력 있는 수준입니다.

### 프로덕션 지연 예산

일반적인 스트리밍 상호작용의 경우:

- 마이크 -> 오디오 토큰: 40-80ms.
- 프리필(Prefill) (프롬프트 + 히스토리): 7B에서 100-200ms, 70B에서는 훨씬 더 오래 걸립니다.
- 첫 번째 Thinker 텍스트 토큰: 40ms.
- Talker가 첫 번째 텍스트 토큰을 처리: 20ms.
- 첫 번째 음성 토큰 확정: 40ms.
- Residual-VQ 디코딩: 30ms.
- 음성 파형 디코딩: 50-80ms.

총 TTFAB: 7B에서 320-510ms, 70B에서 600-900ms. 프론티어 품질은 보통 70B+를 의미하므로, 프론티어 지연 격차가 존재합니다.

### 토큰 속도 계산

16kHz 음성에서 기본 음성 토큰이 50Hz인 경우, 출력 1초당 50개의 음성 토큰이 필요합니다. Talker는 이를 따라잡기 위해 초당 50개 이상의 토큰을 생성해야 합니다. H100에서 일반적인 LLM 처리량이 초당 30-80개 토큰인 경우, 작은 크기(200-300M)의 Talker는 충분히 빠릅니다. 7B Talker는 뒤처질 것입니다.

이것이 "메인 모델만 사용하라"는 접근법 대신 작은 전용 Talker 모델이 존재하는 이유입니다.

```figure
l5-thinker-talker
```

## 사용하기

`code/main.py`:

- 모의 토큰 생성 속도로 Thinker-Talker 파이프라인을 시뮬레이션합니다.
- 설정 가능한 모델 크기와 마이크 샘플링 속도에 대해 TTFAB를 계산합니다.
- VAD 침묵 임계값을 사용하여 반이중(turn-taking) 통신을 시연합니다.

## 출시하기

이 강의는 `outputs/skill-omni-streaming-budget.md`를 생성합니다. 실시간 음성 제품의 목표 TTFAB 및 기능 세트(비전 입력, 이중 언어, 전이중)가 주어지면 Qwen2.5-Omni, Qwen3-Omni, Moshi 또는 Mini-Omni 중 하나를 선택하고 Thinker/Talker의 크기를 결정합니다.

## 연습 문제

1. 목표 TTFAB가 300ms입니다. 7B Thinker와 300M Talker를 사용하여 모든 구성 요소의 지연 시간을 작성해 보세요.

2. Qwen2.5-Omni는 TMRoPE를 사용합니다. 사용자가 t=1s에 말하기 시작하고 카메라가 t=1.2s에 제스처를 포착하는 프롬프트에 대해 모델이 무엇을 보는지 설명해 보세요.

3. 전이중(full-duplex) 지원은 모델이 듣는 동안 오디오를 생성해야 합니다. 이를 가르치는 훈련 데이터 형식을 제안해 보세요.

4. Moshi 논문 섹션 4를 읽어 보세요. "내적 독백(inner monologue)" 분리 방식과 이것이 Thinker-Talker 분리를 피하는 이유를 설명해 보세요.

5. 처리량 예산을 계산해 보세요. 16kHz 음성에서 기본 레이어 토큰이 초당 50개일 때, Talker는 토큰을 얼마나 빠르게 생성해야 따라잡을 수 있나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| Thinker | "추론 뇌" | 무엇을 말할지 생성하는 대규모 텍스트 생성 트랜스포머 |
| Talker | "음성 생성 입" | Thinker의 텍스트에서 이산 음성 토큰을 생성하는 작은 트랜스포머 |
| TTFAB | "지연 예산" | Time-to-first-audio-byte: 사용자 음성 종료부터 첫 오디오 샘플 출력까지의 시간 |
| TMRoPE | "시간 정렬 RoPE" | 비전, 오디오, 텍스트에 걸쳐 절대 타임스탬프를 사용하는 위치 인코딩 |
| 반이중(Half-duplex) | "턴 테이킹(turn-taking)" | 사용자와 모델이 번갈아 통신하며, VAD 침묵 감지로 사용자 완료 여부 확인 |
| 풀듀플렉스 | "동시" | 모델이 동시에 말하고 들을 수 있으며, 백채널이 가능합니다 |
| 내적 독백 | "Moshi 분리" | 사고 스트림과 발화 스트림이 교대로 진행되는 단일 모델 설계 |
