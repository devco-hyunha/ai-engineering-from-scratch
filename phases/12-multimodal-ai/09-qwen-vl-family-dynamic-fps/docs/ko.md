# Qwen-VL 계열과 동적 FPS 비디오

> Qwen-VL 계열 — Qwen-VL (2023), Qwen2-VL (2024), Qwen2.5-VL (2025), Qwen3-VL (2025) — 은 2026년 현재 가장 영향력 있는 오픈 비전-언어 모델 계보입니다. 각 세대는 오픈 생태계가 12개월 내에 모방한 하나의 결정적인 아키텍처적 베팅을 수행했습니다: M-RoPE를 통한 네이티브 동적 해상도, 절대 시간 정렬을 포함한 동적 FPS 샘플링, ViT에서의 윈도우 어텐션, 그리고 구조화된 에이전트 출력 형식입니다. Qwen3-VL에 이르러 레시피는 안정화되었습니다: 네이티브 종횡비 입력을 사용하는 2D-RoPE-ViT 인코더, 대형 Qwen3 언어 기반 모델로 투사하는 MLP 프로젝터, 그리고 OCR, 그라운딩, 에이전트 동작을 일급 목표로 강조하는 학습 단계가 그것입니다. 이 강의를 통해 계열을 시간 순서대로 읽어보면서 모든 설정이 왜 그 위치에 있는지 이해해 보세요.

**유형:** Learn
**언어:** Python (stdlib, M-RoPE 인코더 + 동적 FPS 샘플러)
**선수 요건:** 12단계 · 06강 (patch-n'-pack)
**시간:** 약 120분

## 학습 목표

- M-RoPE의 세 축 회전(시간, 높이, 너비)을 계산하고 세 축이 모두 필요한 이유를 설명해 보세요.
- 비디오에 대해 동적 FPS 샘플링 전략을 선택하고 초당 토큰 수와 이벤트 감지 정확도 간의 관계를 추론해 보세요.
- Qwen-VL의 네 가지 세대별 업그레이드를 순서대로 나열하고 각각이 무엇을 가능하게 했는지 설명해 보세요.
- Qwen2.5-VL 스타일의 JSON 에이전트 출력 형식을 연결하고 VLM 응답에서 구조화된 도구 호출을 파싱해 보세요.

## 문제점

Qwen-VL은 LLaVA-1.5와 BLIP-2에 대한 직접적인 대응으로 2023년 8월에 출시되었습니다. Qwen 팀이 겨냥한 격차는 세 가지였습니다: 해상도, 비디오, 그리고 구조화된 출력.

해상도: LLaVA-1.5는 336x336 해상도로 실행되었습니다. 사진에는 적합했지만, 중국어 청구서나 밀집된 스프레드시트 스크린샷에는 쓸모가 없었습니다. Qwen-VL의 첫 번째 혁신은 448x448 해상도와 바운딩 박스 기반 그라운딩 출력으로, 모델이 대상을 가리킬 수 있게 했습니다.

비디오: Video-LLaMA는 프레임별 인코더를 쌓아 LLM에 공급했습니다. 짧은 클립에는 작동했지만, 시간 축이 신호인 다중 분 단위 비디오에는 작동하지 않았습니다. Qwen 팀은 시간을 이해하는 단일 인코더를 원했습니다.

구조화된 출력: LLaVA는 자유 형식 텍스트를 생성했습니다. 에이전트(Agent)는 JSON이 필요합니다. Qwen-VL는 바운딩 박스 좌표를 텍스트로 포함하는 명시적인 JSON 출력 형식으로 학습되었습니다.

Qwen-VL의 모든 생성은 이 세 가지 축 중 하나를 확장합니다.

## 개념

### Qwen-VL (2023년 8월)

첫 번째 세대: OpenCLIP ViT-bigG/14를 인코더(Encoder)로 사용(2.5B 파라미터(Parameter)), LLama 호환 Q-Former(1단계, 256개 쿼리), Qwen-7B 기반. 기여:

- 448x448 해상도 (당시 오픈 VLM(Vision-Language Model) 중 SOTA).
- 그라운딩(Grounding): 명시적인 좌표 토큰(Token) 출력이 포함된 이미지-텍스트 쌍으로 학습. "The cat is at <box>(112, 204), (280, 344)</box>".
- 처음부터 중국어 + 영어 다국어 학습.

당시 벤치마크: 영어에서는 GPT-4V와 경쟁력 있었으며, 중국어에서는 압도적이었습니다. 그라운딩 감독이 진정한 헤드라인이었습니다.

### Qwen2-VL (2024년 9월) — M-RoPE 및 네이티브 해상도

Qwen2-VL은 고정 해상도 + Q-Former 스택을 네이티브 동적 해상도 ViT 인코더로 대체했습니다. 주요 변경 사항:

- 네이티브 동적 해상도. ViT는 28로 나누어떨어지는 모든 HxW를 허용합니다(패치(Patch) 14, 2x 공간 병합). 1120x672 이미지(40x24 병합 패치)는 960개의 시각적 토큰을 생성합니다. 리사이즈, 타일링, 썸네일 없음.
- M-RoPE (Multimodal RoPE). 각 토큰은 1D 대신 3D 위치(t, h, w)를 가집니다. 이미지에서는 t=0, 비디오에서는 t = frame_index. RoPE는 축별 주파수로 쿼리/키 벡터를 회전합니다. 위치 임베딩(Embedding) 테이블 없음.
- MLP 프로젝터. Q-Former를 제거하고 병합된 패치 토큰에 2층 MLP를 사용합니다.
- 동적 FPS의 비디오. 비디오는 기본적으로 1-2 FPS로 샘플링되지만, 모델은 임의의 프레임 수를 허용합니다.

결과: Qwen2-VL-7B는 여러 멀티모달 벤치마크에서 GPT-4o와 일치했으며, DocVQA에서 이를 능가했습니다(94.5 vs 88.4). 아키텍처 변경이 결정적인 움직임이었습니다.

### Qwen2.5-VL (2025년 2월) — 동적 FPS + 절대 시간

Qwen2.5-VL의 큰 변화는 비디오였습니다. 동적 FPS는 단순히 "필요할 때 더 많은 프레임을 샘플링하는 것"이 아닙니다. 논문은 이를 형식화했습니다:

- 절대 시간 토큰. 위치 인덱스(프레임 0, 1, 2...) 대신 실제 타임스탬프를 사용합니다. "0:04에, 고양이가 점프한다." 모델은 `<time>0.04</time>` 토큰이 프레임 토큰과 교대로 배치된 것을 봅니다.
- 동적 FPS. 느린 영상은 1 FPS로 샘플링하고, 액션이 많은 영상은 4+ FPS로 샘플링합니다. 사용자나 트레이너가 선택하며, M-RoPE가 이에 적응합니다.
- ViT에서의 윈도우 어텐션. 처리량(throughput)을 위해 공간 어텐션은 윈도우화(블록 내 지역)되며, 몇몇 레이어마다 전역 어텐션이 적용됩니다.
- 명시적인 JSON 출력 형식. 도구 호출(tool-call) 데이터로 학습되었습니다: "{\"tool\": \"click\", \"coords\": [380, 220]}". 에이전트 준비가 즉시 완료된 상태입니다.
- MRoPE-v2 스케일링. 위치가 최대 입력 크기에 따라 스케일링되므로, 10분짜리 영상도 주파수 범위를 초과하지 않습니다.

벤치마크: Qwen2.5-VL-72B는 대부분의 비디오 벤치마크에서 GPT-4o를 능가하고, 문서 벤치마크에서는 Gemini 2.00강 동등하며, GUI 접지(grounding)에서 오픈 모델 SOTA를 기록했습니다 (ScreenSpot: GPT-4o의 38% 대비 84% 정확도).

### Qwen3-VL (2025년 11월)

Qwen3-VL은 재발명하기보다 통합하는 점진적 업그레이드입니다: 더 큰 LLM 백본(Qwen3-72B), 확장된 학습 데이터, 개선된 OCR, Qwen3의 "thinking mode"를 통한 더 강한 추론. ViT와 M-RoPE는 유지됩니다. 논문은 아키텍처보다 데이터 및 학습 개선에 초점을 맞춥니다.

계보의 핵심 takeaway: 2025년까지 Qwen-VL 아키텍처는 안정화되었습니다. 추가 세대는 원시(primitives)가 아닌 연산량과 데이터를 스케일링합니다.

### M-RoPE의 수학적 원리

고전적 RoPE는 차원 `d`인 쿼리 `q`를 위치 `m`에 대해 쌍을 이루는 좌표를 사용하여 회전시킵니다:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE는 은닉 차원을 세 개의 밴드로 분할합니다. `d = 96`이라고 가정해 보세요. 32개 차원을 시간(temporal)에, 32개를 높이(height)에, 32개를 너비(width)에 할당합니다. 각 밴드는 자체 축 위치에 따라 회전합니다. (t=5, h=10, w=20)에 있는 패치는 세 밴드에 각각 `R_t(5)`, `R_h(10)`, `R_w(20)` 회전이 적용됩니다.

텍스트 토큰은 `t = text_index, h = 0, w = 0` (또는 정규화된 선택)를 사용하여 호환성을 유지합니다. 비디오 프레임은 `t = frame_time, h = row, w = col`를 사용합니다. 단일 이미지는 `t = 0`를 사용합니다.

장점: 하나의 위치 인코딩이 분기 코드나 다른 위치 테이블 없이 텍스트, 이미지, 비디오를 모두 처리합니다.

### 동적 FPS 샘플링 로직

기간이 `T`초인 비디오와 목표 토큰 예산 `B`이 주어지면:

1. 감당할 수 있는 최대 FPS를 계산하세요: `fps_max = B / (T * tokens_per_frame)`.
2. `fps <= fps_max`을 만족하는 `{1, 2, 4, 8}`에서 목표 FPS를 선택하세요.
3. 움직임이 크다면 (광학 흐름 히어리스틱이나 명시적 사용자 요청) 더 높은 FPS를 선택하세요. 움직임이 작다면 더 낮은 FPS를 선택하세요.
4. 선택한 FPS로 균일하게 샘플링하고, 프레임 사이에 `<time>t</time>` 토큰을 삽입하세요.

Qwen2.5-VL은 이 로직을 암묵적으로 학습합니다. 추론 시 사용자는 `fps` 매개변수를 통해 제어합니다. 4 FPS의 60초 액션 시퀀스에서 프레임당 81개 토큰이면 총 19440개 토큰으로, 32k 컨텍스트에서 관리 가능합니다.

### 구조화된 에이전트 출력

Qwen2.5-VL의 에이전트 학습은 구조화된 도구 호출을 명시적으로 목표로 합니다:

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

파싱은 결정적입니다: 모델 출력에 대해 JSON.parse를 수행합니다. 정규식과 모호성 처리가 필요했던 자유 형식 "(1024, 512)에 클릭"과 비교해 보세요. 이 변화는 Qwen2.5-VL의 ScreenSpot 점수가 Qwen2-VL의 55%에서 84%로 급상승한 이유입니다.

```figure
mm-mrope-axes
```

## 사용하기

`code/main.py`는 다음을 구현합니다:

- 텍스트, 이미지 패치, 비디오 프레임을 혼합한 팩드 시퀀스에 대한 M-RoPE 위치 계산.
- 동적 FPS 샘플러: (기간, 예산, 움직임 수준)이 주어지면 FPS를 선택하고 프레임 타임스탬프를 생성합니다.
- 좌표 필드를 포함하는 도구 호출 응답을 처리하는 장난감 Qwen2.5-VL JSON 출력 파서.

실행해 보세요. 5분짜리 비디오에서 고정 FPS를 동적 FPS로 교체할 때의 차이를 느껴 보세요.

2. 10분짜리 보안 카메라 녹화를 1 FPS로 처리하면 몇 개의 프레임이 생성됩니까? 384 해상도에서 3x 풀(pool)을 적용하면 총 토큰 수는 몇 개입니까? Qwen2.5-VL의 기본 32k 컨텍스트가 이를 처리할 수 있습니까?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| M-RoPE | "멀티모달 RoPE" | 은닉 차원에서 시간, 높이, 너비 밴드를 포함하는 3D 회전 위치 임베딩 |
| 동적 FPS | "스마트 샘플링" | 움직임, 지속 시간, 토큰 예산에 따라 영상별로 선택된 프레임 샘플링 비율 |
| 절대 시간 토큰 | "타임스탬프 토큰" | `<time>t</time>` 시퀀스에 인터리빙되어 모델이 프레임 인덱스가 아닌 실제 초(seconds)를 인식하도록 함 |
| 윈도우 어텐션 | "로컬 어텐션" | 속도 향상을 위해 작은 윈도우로 제한된 공간 셀프 어텐션; 전역 어텐션은 주기적으로 추가됨 |
| 구조화된 에이전트 출력 | "JSON 모드" | 좌표와 도구 이름을 포함하는 파싱 가능한 JSON을 VLM이 생성하도록 학습 데이터를 통해 지도하는 방식 |
| min_pixels / max_pixels | "해상도 경계" | 요청별 Qwen2.5-VL 제어는 총 픽셀 수 및 따라서 토큰 수의 경계를 설정함 |
| 그라운딩(Grounding) | "가리키기(Point-at-it)" | 바운딩 박스 좌표를 텍스트 토큰으로 출력하는 것; Qwen-VL v1부터 사용됨 |
