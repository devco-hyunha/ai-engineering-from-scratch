# 모델 평가 전략

모든 ML 모델을 올바르게 평가하기 위한 체크리스트입니다. 가장 흔한 평가 실수를 피하려면 이 순서를 따르세요.

## 1단계: 데이터를 올바르게 분할하기

- 전처리(스케일링, 결측치 채우기, 인코딩) 전에 분할하세요
- 분류 작업에는 층화 분할(stratified splits)을 사용하세요
- 마지막에 딱 한 번만 만지는 테스트 세트(test set)를 예약하세요
- 소규모 데이터셋의 경우 단일 분할 대신 5-폴드 또는 10-폴드 교차 검증(cross-validation)을 사용하세요
- 시계열의 경우 시간 기반 분할을 사용하세요(절대 셔플하지 마세요)

## 2단계: 올바른 지표 선택하기

### 분류

| 상황 | 이 지표 사용 | 이유 |
|-----------|----------------|-----|
| 균형 잡힌 클래스, 단순 비교 | 정확도(Accuracy) | 해석이 쉽고, 클래스가 균등할 때 의미가 있습니다 |
| 오탐(False positives) 비용이 큰 경우(스팸 필터, 사기 알림) | 정밀도(Precision) | 플래그된 항목 중 실제로 양성인 비율을 측정합니다 |
| 미탐(False negatives) 비용이 큰 경우(암 선별 검사, 보안) | 재현율(Recall) | 실제 양성 중 포착한 비율을 측정합니다 |
| 정밀도와 재현율의 균형이 필요한 경우 | F1 점수 | 조화 평균이며, 극단적인 불균형을 벌합니다 |
| 임계값(threshold) 전반에 걸쳐 모델 비교 | AUC-ROC | 임계값에 독립적인 순위 품질 |
| 불균형 데이터 | F1, AUC-ROC, 또는 PR-AUC | 불균형 클래스에서는 정확도가 오해를 불러일으킵니다 |

### 회귀

| 상황 | 이 지표 사용 | 이유 |
|-----------|----------------|-----|
| 표준 회귀, 이상치 허용 | RMSE | 타겟과 같은 단위를 사용하며, 큰 오류에 벌점을 부여합니다 |
| 이상치에 강건한 평가 | MAE | 모든 오류를 동일하게 취급하며, 이상치에 지배되지 않습니다 |
| 서로 다른 스케일에서 모델 비교 | R-제곱(R-squared) | 정규화된 0-1 스케일(설명된 분산의 비율) |
| 비즈니스가 금액을 요구하는 경우 | MAE 또는 RMSE | 오류 크기로 직접 해석 가능합니다 |

## 3단계: 기준선(baselines) 설정하기

모델을 평가하기 전에, 기준 성능을 계산해 보세요:
- 분류: 다수 클래스 예측기 (항상 가장 흔한 클래스를 예측)
- 회귀: 항상 학습 타겟의 평균을 예측
- 이러한 기준선을 넘지 못하는 모델은 학습이 되지 않은 것입니다

## 4단계: 교차 검증

- 안정적인 추정치를 위해 K-fold (K=5 또는 K=10)를 사용해 보세요
- 분류에는 층화 K-fold를 사용해 보세요
- 폴드 간 평균과 표준 편차를 보고해 보세요
- 평균=0.85이고 표준 편차=0.02인 모델은 평균=0.87이고 표준 편차=0.10인 모델보다 더 신뢰할 수 있습니다

## 5단계: 통계적으로 모델 비교

- 유의성을 확인하지 않고 평균 점수가 가장 높은 모델을 선택하지 마세요
- 교차 검증 폴드 간에 짝을 이룬 t-검정을 사용해 보세요
- |t| < 2.78 (K=5, df=4, p<0.05인 경우)이면, 차이는 우연에 의한 것일 수 있습니다
- 성능 차이가 유의하지 않은 경우, 더 단순한 모델을 고려해 보세요

## 6단계: 흔한 실수 확인

- 데이터 누수: 테스트 데이터 정보가 학습에 유입되었나요? (분할 전 스케일링, 타겟 파생 특징)
- 클래스 불균형: 정확도가 소수 클래스의 낮은 성능을 숨기고 있나요?
- 과적합: 학습 성능과 검증 성능의 차이가 큰가요?
- 너무 많은 평가: 테스트 세트를 한 번 이상 살펴본 적이 있나요?

## 7단계: 최종 성능 보고

- 학습 세트와 검증 세트를 합쳐서 학습해 보세요
- 보유한 테스트 세트에서 정확히 한 번만 평가해 보세요
- 가능하다면 신뢰 구간과 함께 선택한 지표를 보고해 보세요
- 기준선 비교를 명시해 보세요 (무작위/평균보다 얼마나 더 좋은지)
