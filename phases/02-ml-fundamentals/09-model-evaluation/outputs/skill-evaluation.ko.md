# 모델 평가 전략 (Model Evaluation Strategy)

어떤 ML 모델이든 올바르게 평가하기 위한 체크리스트입니다. 이 순서를 따르면 가장 흔한 평가 실수를 피할 수 있습니다.

## 1단계: 데이터를 올바르게 분할

- 전처리(스케일링, 대치, 인코딩) 전에 분할
- 분류 작업에는 stratified 분할 사용
- 맨 끝에 정확히 한 번만 만지는 테스트 세트 확보
- 작은 데이터셋에는 단일 분할 대신 5-fold 또는 10-fold 교차검증
- 시계열에는 시간 기반 분할 (절대 섞지 말 것)

## 2단계: 맞는 지표 선택

### 분류

| Situation | Use this metric | Why |
|-----------|----------------|-----|
| 균형 클래스, 단순 비교 | Accuracy | 해석이 쉽고, 클래스가 같을 때 의미 있음 |
| 위양성이 비쌈 (스팸 필터, 사기 알림) | Precision | 플래그된 항목 중 실제로 양성인 비율 |
| 위음성이 비쌈 (암 검진, 보안) | Recall | 실제 양성 중 몇이나 잡는지 |
| precision과 recall의 균형 필요 | F1 Score | 조화평균, 극단적 불균형을 벌함 |
| 임계값을 넘어 모델 비교 | AUC-ROC | 임계값에 무관한 순위 품질 |
| 불균형 데이터 | F1, AUC-ROC, 또는 PR-AUC | 불균형 클래스에서 accuracy는 오해를 줌 |

### 회귀

| Situation | Use this metric | Why |
|-----------|----------------|-----|
| 표준 회귀, 이상치 허용 | RMSE | 타깃과 같은 단위, 큰 오차를 벌함 |
| 이상치에 견고한 평가 | MAE | 모든 오차를 동등하게, 이상치에 지배되지 않음 |
| 서로 다른 스케일의 모델 비교 | R-squared | 정규화된 0-1 스케일 (설명된 분산 비율) |
| 비즈니스가 금액 단위를 요구 | MAE 또는 RMSE | 오차 크기로 바로 해석 가능 |

## 3단계: 베이스라인 잡기

모델을 평가하기 전에 베이스라인 성능을 계산하세요:
- 분류: 다수 클래스 예측기 (항상 가장 흔한 클래스를 예측)
- 회귀: 항상 학습 타깃의 평균을 예측
- 이 베이스라인을 이기지 못하는 모델은 학습하고 있지 않습니다

## 4단계: 교차검증

- 안정적인 추정을 위해 K-fold (K=5 또는 K=10) 사용
- 분류에는 stratified K-fold 사용
- fold에 걸친 평균과 표준편차를 보고
- mean=0.85, std=0.02인 모델이 mean=0.87, std=0.10인 모델보다 신뢰할 만합니다

## 5단계: 모델을 통계적으로 비교

- 유의성을 확인하지 않고 평균 점수가 가장 높은 모델을 고르지 마세요
- 교차검증 fold에 걸쳐 paired t-test를 쓰세요
- |t| < 2.78이면 (K=5, df=4, p<0.05) 차이는 우연일 수 있습니다
- 성능 차이가 유의하지 않으면 더 단순한 모델을 고려하세요

## 6단계: 흔한 실수 점검

- 데이터 누수: 테스트 정보가 학습으로 흘러 들어갔는가? (분할 전 스케일링, 타깃 파생 특성)
- 클래스 불균형: accuracy가 소수 클래스의 나쁜 성능을 숨기고 있는가?
- 과적합: 학습과 검증 성능 격차가 큰가?
- 너무 많은 평가: 테스트 세트를 한 번보다 많이 봤는가?

## 7단계: 최종 성능 보고

- 학습 + 검증을 합쳐 재학습
- 홀드아웃 테스트 세트에서 정확히 한 번 평가
- 가능하면 신뢰구간과 함께 선택한 지표를 보고
- 베이스라인 비교를 명시 (무작위/평균보다 얼마나 나은지)
