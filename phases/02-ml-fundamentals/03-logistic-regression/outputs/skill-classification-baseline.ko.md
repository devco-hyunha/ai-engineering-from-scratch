# 분류 기준선 가이드

복잡한 모델을 시도하기 전에 로지스틱 회귀로 기준선을 설정해 보세요. 몇 초 만에 학습이 완료되고, 확률을 생성하며, 완전히 해석 가능합니다. 놀랍게도 많은 실제 문제에서는 더 복잡한 모델이 필요하지 않습니다.

## 의사 결정 체크리스트

1. 의사 결정 경계가 선형일 가능성이 높습니까?
   - 예: 로지스틱 회귀가 충분할 가능성이 높습니다
   - 아니요: 개선 정도를 측정하기 위한 기준선으로 여전히 필요합니다

2. 특징(feature)이 몇 개 있습니까?
   - 50개 미만: 표준 로지스틱 회귀가 잘 작동합니다
   - 50~10,000개: L2 정규화(Ridge)를 추가하세요
   - 10,000개 초과 (예: TF-IDF 텍스트 특징): L1 정규화(Lasso) 또는 LinearSVC를 사용하세요

3. 데이터셋이 불균형합니까?
   - 5:1 비율 미만: 조정 없이도 괜찮을 가능성이 높습니다
   - 5:1~50:1: sklearn에서 `class_weight="balanced"`를 사용하세요
   - 50:1 초과: 클래스 가중치와 적절한 지표(정밀도, 재현율 또는 F1)를 결합하세요

4. 특징이 서로 다른 스케일입니까?
   - 로지스틱 회귀 전에 항상 표준화하세요. 이는 기울기 기반 최적화를 사용하며, 스케일링되지 않은 특징은 수렴을 늦추거나 의사 결정 경계를 왜곡합니다.

5. 누락된 값이 있습니까?
   - 피팅(fitting) 전에 보간(impute)하세요. 로지스틱 회귀는 NaN을 처리할 수 없습니다.
   - 숫자 열에는 중앙값 보간을, 범주형에는 최빈값 보간을 사용하세요.

## 로지스틱 회귀가 충분히 좋은 경우

- 대부분 선형적인 특징 관계가 있는 이진 분류
- 확률 출력(클래스 레이블만으로는 부족)이 필요합니다
- 해석 가능성이 요구됩니다 (계수는 표준화 후 특징의 중요성 방향과 상대적 크기를 나타냅니다)
- 학습 데이터가 작습니다 (수백에서 수천 개의 샘플)
- 실시간 서빙을 위한 빠른 모델이 필요합니다 (추론 시 단일 내적(dot product))
- 규제 또는 컴플라이언스 요건이 설명 가능성을 요구합니다

## 언제 업그레이드해야 하는가

- 정확도가 목표보다 훨씬 낮게 정체되어 있고, 기능 엔지니어링을 시도해 봤습니다
- 기능과 타겟 간의 관계가 명확히 비선형입니다 (잔차 플롯을 확인해 보세요)
- 대규모 표 데이터(10k+ 행)가 있습니다: 그래디언트 부스팅(XGBoost 또는 LightGBM)을 시도해 보세요
- 기능에 다항식 기능으로 포착할 수 없는 복잡한 상호작용이 있습니다
- 이미지, 텍스트, 시퀀스 데이터가 있습니다: 원시 입력에 대한 로지스틱 회귀는 작동하지 않습니다

## 분류 기준선(Baseline)을 위한 전처리 단계

1. **학습/테스트 분할**을 먼저 수행합니다. 모든 전처리 전에 수행해야 합니다. 이는 데이터 누수를 방지합니다.
2. **결측값 처리**: 수치형은 중앙값으로, 범주형은 최빈값으로 채웁니다.
3. **범주형 인코딩**: 카디널리티가 낮은 경우(10개 미만) 원-핫 인코딩을, 더 높은 경우 타겟 인코딩을 사용합니다. 타겟 인코딩은 학습 폴드에서만 피팅합니다 (누수를 방지하기 위해 Out-of-Fold 인코딩을 사용하세요).
4. **수치형 스케일링**: StandardScaler (평균 0, 분산 1)를 사용합니다. 학습 데이터에 피팅하고, 두 데이터 모두에 변환합니다.
5. **로지스틱 회귀 피팅** `C=1.0` (기본 정규화)를 수행합니다.
6. **평가**: 혼동 행렬, 정밀도, 재현율, F1을 평가합니다. 정확도만으로는 충분하지 않습니다.
7. **임계값 튜닝**: 기본값 0.5는 거의 항상 최적값이 아닙니다. 0.1부터 0.9까지 스윕(sweep)하여 정밀도/재현율 우선순위에 맞는 임계값을 선택하세요.

## 공통 실수

- 불균형 데이터에서 정확도만 평가하는 것 (다수 클래스를 예측하는 모델은 높은 점수를 받지만 쓸모가 없습니다)
- 기능 스케일링을 잊는 것 (스케일링되지 않은 기능으로 로지스틱 회귀를 학습하면 학습이 느려지고 더 나쁜 해로 수렴합니다)
- 테스트 세트를 사용하여 결정 임계값을 튜닝하는 것 (검증 세트나 교차 검증을 사용하세요)
- 기준선을 건너뛰고 바로 XGBoost로 가는 것 (설명 가능성을 잃고 기준점이 없습니다)
- 다중 공선성을 확인하지 않는 것 (높이 상관된 기능은 계수 분산을 부풀립니다)

## 빠른 참조

| 시나리오 | 모델 | 정규화 | 주요 설정 |
|----------|-------|---------------|-------------|
| 소수의 특징, 해석 가능 | LogisticRegression | L2 (기본값) | C=1.0 |
| 많은 특징, 일부는 무관함 | LogisticRegression | L1 | penalty="l1", solver="saga" |
| 고차원 희소 데이터 (텍스트) | SGDClassifier | L1 또는 ElasticNet | loss="log_loss" |
| 불균형 클래스 | LogisticRegression | L2 | class_weight="balanced" |
| 확률 필요 | LogisticRegression | L2 | predict_proba() |
| 클래스 레이블만 필요 | LinearSVC | L2 | 대규모 데이터에서 LR보다 빠름 |
