# 특성 선택 전략 (Feature Selection Strategy)

올바른 특성 선택 방법을 고르고 적용하기 위한 빠른 참조입니다.

## 1단계: 정리부터 시작

어떤 방법이든 적용하기 전에, 명백히 쓸모없는 특성을 제거하세요:

- **상수 특성**: 분산 = 0. 제거하세요.
- **준상수 특성**: 분산 < 0.01 (또는 자신의 임계값). 제거하세요.
- **중복 특성**: 동일한 열. 하나 남기고 나머지를 버리세요.
- **ID 열**: 행마다 고유, 일반화 가능한 정보 없음. 제거하세요.

수 초면 끝나고, 지저분한 실제 데이터셋에서 특성의 10-30%를 없앨 수 있습니다.

## 2단계: 상황에 맞는 방법 선택

### 빠른 결정 트리

1. **특성 < 50개?** 상호정보량 순위로 시작. 상위 K개 유지.
2. **특성 50 - 500개?** 먼저 분산 임계값, 그다음 선형 모델이면 L1(Lasso), 트리면 트리 중요도.
3. **특성 > 500개?** 방법을 연쇄: 분산 임계값 -> 상호정보량 필터(상위 50%) -> 남은 것에 RFE.
4. **해석 가능성이 필요?** L1 정규화는 정확한 0/비0을 줍니다. 트리 중요도는 순위 점수를 줍니다.
5. **비선형 관계를 잡아야 하나?** 상호정보량 또는 트리 기반 중요도. L1은 피하세요(선형만).
6. **특성 상호작용이 필요?** RFE 또는 트리 기반 중요도. 필터 방법은 상호작용을 놓칩니다.

### 방법 참조

| Method | When to Use | When to Avoid |
|--------|------------|---------------|
| Variance threshold | 항상, 첫 단계로 | 이 단계를 건너뛰지 말 것 |
| Mutual information | 빠른 순위, 비선형 관계 | 특성 상호작용 탐지가 필요할 때 |
| RFE | 철저한 선택, 중간 특성 수 | 매우 비싼 모델, 특성 > 1000 |
| L1 / Lasso | 선형 모델, 빠른 임베디드 선택 | 비선형 문제, 고도로 상관된 특성 |
| Tree importance | 비선형 관계, 특성 상호작용 | 고카디널리티 특성에 편향 |
| Permutation importance | 모델 무관 검증, 최종 점검 | 초기 스크리닝에는 너무 느림 |

## 3단계: 선택 검증

- 선택된 특성 vs 전체 특성으로 모델 성능 비교
- 단일 train/test 분할이 아니라 교차검증 사용
- 성능이 1-2% 이상 떨어지면 유용한 특성을 제거했을 수 있음
- 성능이 오르면 노이즈를 성공적으로 제거한 것

## 4단계: 흔한 함정 다루기

### 상관된 특성
- L1은 상관 그룹에서 임의로 하나를 고르고 나머지를 0으로 만듦
- 먼저 상관 행렬을 계산하고 어떤 상관 특성을 유지할지 결정
- 트리 중요도는 상관된 특성에 걸쳐 중요도를 분산시킴

### 데이터 누수
- 특성 선택은 학습 데이터에만 맞춤
- 같은 선택을 테스트 데이터에 적용
- 교차검증에서는 특성 선택이 각 폴드 안에서 일어나야 함

### 특성 선택에 과적합
- 반복이 너무 많은 RFE는 학습 세트에 과적합할 수 있음
- 선택에 쓴 데이터가 아닌 홀드아웃으로 검증
- 더 견고한 결과를 위해 안정성 선택(부분표본 반복) 사용

## 5단계: 프로덕션 체크리스트

- [ ] 첫 필터로 분산 임계값 적용
- [ ] 특성 선택은 학습 데이터에만 피팅
- [ ] 선택된 특성 문서화 (이름, 사용한 방법, 점수)
- [ ] 성능 비교: 선택 특성 vs 전체 특성
- [ ] 교차검증, 단일 분할 평가 아님
- [ ] 특성 선택이 학습 파이프라인에 통합됨 (수동이 아님)
- [ ] 특성 드리프트 모니터링 (선택된 특성이 낡을 수 있음)
