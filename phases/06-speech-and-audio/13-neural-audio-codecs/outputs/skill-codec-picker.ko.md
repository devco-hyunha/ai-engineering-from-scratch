주어진 작업(생성형 LM, 압축, 풀 듀플렉스 대화, 음악 편집, 충실도 목표)에 대해 다음을 출력합니다:

1. 코덱. EnCodec-24k · EnCodec-48k · DAC-44.1k · SNAC-24k · Mimi · (대안: 비신경 압축용 Opus). 한 문장 이유.
2. 프레임 레이트 + 코드북. 비트레이트 예산, 코드북 수(보통 4-12), 목표 클립 길이에 대한 시퀀스 길이.
3. 토큰화 방식. 평평한(flat) vs 계층적(hierarchical, SNAC) vs 의미+음향(semantic+acoustic, Mimi). LM이 토큰을 소비하는 방식.
4. 디코더. 코덱 내장 디코더 · 외부 보코더(HiFi-GAN) · LM 전용(보코더 없음, 코덱 토큰을 직접 예측). 이유를 설명합니다.
5. 학습 함의. 인코더/디코더를 학습해야 하는가? 도메인 오디오에 미세 조정(음성 전용 → 도메인 특화 음악)? 동결된(off-the-shelf) 상용 코덱인가?

타이트한 지연 예산에서의 AR-LM 작업에 DAC를 거부합니다 — 86 Hz 프레임 레이트 × 8 코드북 = 10초당 5,504 토큰, 빠른 생성에는 너무 길습니다. 음악에 Mimi를 거부합니다 — 음성 전용으로 튜닝되었습니다. 의미 조건부 생성에 EnCodec을 거부합니다 — 의미 코드북이 없어, 텍스트로부터 음성이 흐려집니다.

예시 입력: "텍스트 음성 변환(TTS)용 AR LM을 구축하세요. 목표 TTFA는 200 ms입니다. 영어 전용입니다."

예시 출력:
- 코덱: Mimi. 의미+음향 분리는 텍스트 → 코드북 0 → 코드북 1-7 분해를 가능하게 하며, 이는 빠르고 음성 클로닝을 지원합니다.
- 프레임 레이트 + 코드북: 12.5 Hz · 8 코드북 · 4.4 kbps. 10초 = 1,000 토큰.
- 토큰화: 텍스트 + 화자 참조로부터 코드북 0을 먼저 예측합니다; 그 후 코드북 0 + 화자 참조를 주어 코드북 1-7을 예측합니다(depth-transformer 패턴).
- 디코더: Mimi의 내장 디코더, 외부 보코더가 필요 없습니다.
- 학습: 텍스트-코덱 LM을 학습합니다; Mimi는 동결합니다.
