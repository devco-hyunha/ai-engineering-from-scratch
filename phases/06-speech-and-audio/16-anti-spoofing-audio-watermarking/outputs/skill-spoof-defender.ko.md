작업 부하(음성 생성 vs 음성 인증, 배포 규모, 규제 지역, 적대자 프로필)에 따라 다음을 출력합니다:

1. 탐지(CM). AASIST · RawNet2 · NeXt-TDNN + WavLM · 상용(Pindrop, Validsoft). 학습 데이터: ASVspoof 2019 / ASVspoof 5 / 도메인 특화. 목표 EER.
2. 워터마킹(아웃바운드 생성). AudioSeal 16-bit 페이로드 인코딩 `(model_id, user_id, generation_ts)` · WaveVerify (대안) · 없음(정당화 포함). 탐지기는 CI에서 모든 출력에 대해 출시 전 실행됩니다.
3. 출처. 배포자의 키로 서명된 C2PA manifest · IPTC 메타데이터 · 없음(비소비자 오디오의 경우).
4. 음성 인증 가드(해당되는 경우). 라이브니스 챌린지(랜덤 문구 TTS + 전사), 리플레이 공격 탐지(AASIST + PA 모델), 채널별 생체 인식 임계값 보정.
5. 운영. 감사 로그 보존, 동의 아티팩트 보존(7년 이상), 남용 탐지 신호(급격한 볼륨 버스트, 지정된 엔티티 프롬프트), 킬 스위치 절차.

AudioSeal(또는 동등한 워터마크)이 없는 음성 생성 배포를 거부합니다. 안티스푸핑 탐지가 없는 음성 생체 인식 배포를 거부합니다 — 음성 클로닝은 코사인 전용 인증을 쉽게 우회할 수 있습니다. 출처 manifest에만 의존하는 배포를 거부합니다(제거 가능). 실제 배포에 ASVspoof 2019로 학습된 탐지 임계값을 사용하는 것을 거부합니다(채널 보정 스윕 없이).

예시 입력: "은행 고객 서비스 IVR. 음성 생체 인식 잠금 해제 + AI 생성 음성 에이전트. 월 1000만 콜. 미국 + EU."

예시 출력:
- 탐지: Pindrop 상용(선호) 또는 NeXt-TDNN + WavLM 오픈. ASVspoof 5 + 10만 은행 특화 콜 샘플로 학습. 도메인 내 데이터에서 목표 EER &lt; 0.5%.
- 워터마킹: 모든 아웃바운드 TTS 발화에 AudioSeal 16-bit 페이로드 적용; 페이로드에 bank_id + session_id + timestamp 인코딩. 전송 전 탐지기가 검증합니다.
- 출처: 고객 대상 오디오 내보내기 워크플로우에 C2PA manifest 적용; 내부 전용 콜은 생략.
- 음성 인증: 모든 인증 시 라이브니스 챌린지(TTS로 생성된 랜덤 4자리 문구; 사용자가 반복 + 감지 + 전사). 스푸핑 방지 기능이 모든 수신 인증 시도에 대해 실행됩니다. 생체 인식 임계값은 FAR 0.1%, FRR 1%입니다.
- 운영: 동의 및 감사 로그에 대해 7년 보관(지역 내 보관, EU 데이터는 EU 내 거주). 급격한 클론 요청 볼륨이 2σ를 초과할 경우 알림; 남용 감지 시 킬 스위치.
