작업 설명과 선택적인 조직 구조가 주어지면, 조정 패턴(평면형 감독자, 계층형, 순차형)을 추천하고 방지해야 할 구체적인 실패 모드들을 나열하세요.

다음 내용을 생성하세요:

1. **작업 형태 분석.** 작업이 하나의 선형 흐름, 독립적인 분기가 있는 팬아웃(fan-out), 또는 자체 하위 팀을 가진 중첩된 팀 중 어느 것에 해당합니까? 근거를 제시하세요.
2. **패턴 판정.** 순차형, 평면형 감독자, 또는 계층형입니다. 계층형인 경우, 깊이를 지정하세요(2단계가 강력히 권장되며, 3단계는 강력한 감사 필요성이 있을 때만 허용됩니다).
3. **분해 계획.** 최상위 관리자가 수행해야 할 정확한 분할입니다. 각 분기에 대해 하위 관리자와 범위를 지정하세요.
4. **조율 예산.** 최상위 관리자가 확정해야 하는 라운드 수입니다. 기본값은 2입니다.
5. **가드레일(Guardrails).** 최소한 세 가지 가드레일: 각 레벨별 카나리 워커(Canary Worker), 모든 합성에 대한 출처 증명(Provenance Attestation) 체인, 분해 드리프트(decomposition drift)에 대한 알림.
6. **실패 모드 체크리스트.** 작업 형태를 고려할 때 {작업 할당 오류, 출력 오해석, 합의 루프} 중 어느 것이 가장 가능성 높습니까? 각 모드에 대해 구체적인 증상 하나와 완화 조치 하나를 설명하세요.

하드 리젝트(Hard Rejects):

- 구체적인 감사 또는 조직 요구 사항이 이를 요구한다고 명시하지 않고 깊이 > 2를 제안하는 모든 추천은 거부됩니다.
- 단일 선형 흐름 작업에 대해 계층형을 사용하는 것은 거부됩니다. 이러한 작업은 순차형 파이프라인이어야 합니다.
- 명시적인 조율 예산이 없는 설계는 거부됩니다.

거부 규칙:

- 작업이 단일 에이전트(~10개 도구 호출 미만)에 적합할 정도로 단순하다면, 계층형을 거부하고 단일 에이전트를 추천하세요.
- 작업에 자연스러운 팀 경계가 없다면(모든 하위 단계가 다른 모든 단계에 의존하는 경우), 거부하고 대신 그룹 채팅 패턴을 추천하세요.
- 사용자가 "현실성"(인간 조직이 깊기 때문) 때문에 계층형을 원한다면, 인간 계층은 LLM 계층에 매핑되지 않으며 더 평면적인 구조를 추천해야 함을 지적하세요.

출력: 한 페이지 분량의 브리프. 패턴 판정으로 시작하고, 세 가지 가장 큰 위험과 그에 대한 가드레일로 마무리하세요.
