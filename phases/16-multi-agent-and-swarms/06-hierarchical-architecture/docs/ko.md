# 계층적 아키텍처와 그 실패 모드

> 계층적 구조는 감독자가 중첩된 형태입니다. 매니저 에이전트가 하위 매니저를 관리하고, 하위 매니저가 워커를 관리합니다. CrewAI `Process.hierarchical`는 교과서적인 버전입니다: `manager_llm`가 동적으로 작업을 위임하고 출력물을 검증합니다. LangGraph의 동등한 구현은 `create_supervisor(create_supervisor(...))`입니다. 작업이 실제 조직도인 경우 자연스러운 패턴입니다. 또한 매니저 루프로 붕괴될 가능성이 가장 높은 패턴이기도 합니다. 매니저 에이전트가 작업을 잘못 배정하거나, 하위 출력물을 오해석하거나, 합의에 도달하지 못합니다. 순차적 구조가 종종 더 잘 작동합니다.

**유형:** 학습 + 빌드
**언어:** Python (표준 라이브러리)
**선수 요건:** 16단계 · 05강 (감독자 패턴)
**시간:** 약 60분

## 문제점

감독자 패턴이 이해되면, 자연스러운 다음 단계는 "워커가 스스로 감독자라면 어떻게 될까?"입니다. 팀은 하위 팀을 가지고 있고, 회사는 부서 내의 부서를 가지고 있습니다. 계층적 아키텍처는 이를 반영합니다.

문제는 LLM 매니저가 인간 매니저와 같지 않다는 점입니다. 인간 매니저는 보고하는 직원들이 무엇을 아는지 안정적인 사전 지식을 가지고 있습니다. LLM 매니저는 매 턴마다 컨텍스트에 있는 내용으로 조직을 재추론합니다. 그 컨텍스트에 작은 드리프트가 발생하면, 전체 트리가 작업을 잘못 배분합니다.

## 개념

### 구조

```
                 Manager
                 ┌─────┐
                 └──┬──┘
           ┌────────┴────────┐
           ▼                 ▼
       Sub-Mgr A         Sub-Mgr B
       ┌─────┐           ┌─────┐
       └──┬──┘           └──┬──┘
         ┌┴──┬──┐          ┌┴──┐
         ▼   ▼  ▼          ▼   ▼
       W1  W2  W3         W4  W5
```

모든 내부 노드는 계획하고, 위임하고, 종합합니다. 리프 노드만 작업을 수행합니다.

### 장점

- **명확한 조직 매핑.** 실제 작업이 부서별인 경우 ("법무가 문서를 검토하고, 재무가 문서를 검토하고, 엔지니어링이 문서를 검토한 후, 경영진을 위해 요약"), 계층 구조가 명확합니다.
- **지역적 요약.** 각 하위 매니저는 상위 매니저가 보기 전에 팀의 출력물을 종합합니다. 상위 매니저는 15개의 워커 출력물이 아니라 3개의 하위 매니저 요약본을 봅니다.

### 단점

2026년 사후 분석에서 계속 발견되는 세 가지 실패 모드:

1. **작업 배정 오류.** 매니저가 목표를 읽고, 환각(Hallucination)으로 분해를 생성하고, 잘못된 하위 매니저에게 위임합니다. 하위 매니저는 주어진 대로 순종적으로 작업하므로, 오류는 상위 종합 단계에서만 드러납니다. 이는 인간이 잡을 수 있었던 위치에서 한 단계 떨어져 있습니다.
2. **출력 오해석.** 하위 관리자가 "주장 X를 검증할 수 없음"이라고 반환하면, 상위 관리자는 이를 "주장 X가 확인되지 않음"으로 요약합니다. 모든 단계에서 의미가 변질됩니다.
3. **합의 루프.** 두 하위 관리자가 의견 불일치를 보이면, 상위 관리자가 조정을 요청하고, 하위 관리자는 다시 하위로 위임하며, 작업자가 재실행하고, 하위 관리자는 약간 다른 답변을 반환하며, 루프가 반복됩니다. CrewAI의 `Process.hierarchical`는 단계 제한으로 이를 방지하지만, 그 제한 자체가 하이퍼파라미터가 됩니다.

### 결정적인 질문

순차적(선형 파이프라인) 대 계층적: 작업이 실제로 독립적인 하위 팀을 포함하는지, 아니면 트리인 척하는 하나의 선형 흐름인지 확인해 보세요. 후자라면 순차적 방식을 사용하세요. 전자라면 계층적 방식을 사용하되, 명시적인 조정 규칙을 예산에 포함하세요.

### 역할 프레임워크 구현

CrewAI의 `Process.hierarchical`는 전문가 크루 위에 관리자 LLM을 연결합니다. 관리자는:

- 상위 수준 작업을 수신하고,
- 하위 작업을 크루에 할당하고,
- 크루의 출력물을 평가하고,
- 수락, 재위임, 반복 여부를 결정합니다.

문서: https://docs.crewai.com/en/introduction (Core Concepts 아래 "Hierarchical Process"를 찾아보세요).

### 그래프 프레임워크 구현

LangGraph는 중첩된 `create_supervisor` 호출을 사용합니다. 내부 감독자는 자체 그래프를 가지며, 외부 감독자는 내부 그래프를 불투명한 노드로 취급합니다. 이는 CrewAI보다 디버깅이 더 깔끔합니다(각 그래프를 개별적으로 단계별로 추적할 수 있음)하지만, 트리의 동적 재구성을 표현하기는 더 어렵습니다.

참고: https://reference.langchain.com/python/langgraph-supervisor.

```figure
swarm-hierarchy-token
```

## 구현하기

`code/main.py`는 3단계 계층을 실행합니다:

- 상위 관리자: 작업을 "엔지니어링"과 "법률" 분기로 분할,
- 엔지니어링 하위 관리자: "프론트엔드"와 "백엔드" 작업자로 분할,
- 법률 하위 관리자: 작업자 한 명.

데모는 해피 패스(모두가 동의하는 경우)와 **교란된 패스**를 대비합니다. 교란된 패스에서는 상위 관리자의 분해가 "법률"을 "재무"로 잘못 라벨링하며, 오류가 연쇄적으로 전파되는 것을 관찰합니다. 하위 관리자는 순종적으로 재무 작업을 수행하고, 상위 합성자는 재무 발견 사항을 보고하며, 원래의 법률 질문은 답변되지 않습니다.

실행:

```
python3 code/main.py
```

출력에는 "요청한 내용"과 "제공된 내용"을 나란히 비교하는 두 경로가 명확하게 표시됩니다.

## 사용하기

`outputs/skill-hierarchy-fitness.md`는 주어진 작업에 계층적, 순차적, 또는 평면형 감독자를 사용해야 하는지 평가합니다. 입력: 작업 설명, 조직 구조, 조정 예산. 출력: 방지해야 할 특정 실패 모드와 함께 패턴 권장 사항.

## 출시하기

계층적 구조를 출시한다면:

- **트리 깊이를 2로 제한하세요.** 세 단계는 이미 관측 가능성에서 대부분의 오류를 숨깁니다.
- **명시적인 조정 예산을 설정하세요.** 최상위 관리자가 확정해야 하는 최대 라운드를 설정합니다. 보통 2입니다.
- **모든 합성에 출처를 포함하세요.** 각 노드의 요약은 어떤 리프 출력에서 생성되었는지 인용해야 합니다.
- **분해 드리프트에 대한 경보를 설정하세요.** 각 단계에서 관리자의 분해를 기록하고 사용자 쿼리와 비교합니다. 분해가 더 이상 쿼리를 포함하지 않으면 경보를 발동합니다.

## 연습 문제

1. `code/main.py`를 실행하고 정상 경로와 교란된 경로를 비교하세요. 최상위 출력이 사용자의 질문에서 완전히 벗어날 때까지 몇 단계의 관리자 핸드오프가 필요합니까?
2. 세 번째 단계(최상위 → 하위 → 하위 하위 → 워커)를 추가하세요. 깊이가 증가함에 따라 교란된 경로가 스스로 수정하는 빈도와 완전히 벗어날 빈도를 측정하세요.
3. 각 하위 관리자에서 원본 사용자 질문을 변경하지 않고 항상 요청하는 "카나리" 워커를 구현하세요. 카나리 답변을 사용하여 분해 드리프트를 감지하세요. 카나리가 합성된 답변과 불일치할 때 관리자는 어떻게 반응해야 합니까?
4. CrewAI의 `Process.hierarchical` 문서를 읽어보세요. CrewAI가 적용하는 구체적인 가드레일 하나(단계 제한, manager_llm 제약)를 식별하고, 그 가드레일이 목표로 하는 실패 모드를 설명하세요.
5. 중첩된 LangGraph 감독자와 CrewAI 계층적 구조를 비교하세요. 조정 루프를 감지하는 데 더 저렴한 것은 무엇입니까?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 계층적 | "조직도 패턴" | 감독자 위에 감독자; 리프만 작업 수행. |
| 관리자 LLM | "상사" | 내부 노드에서 분해, 할당 및 검증을 수행하는 LLM. |
| 분해 드리프트 | "상사가 줄거리를 잃어버림" | 최상위 관리자의 분할이 더 이상 원본 질문을 포함하지 않음. |
| 조율 루프 | "끝없는 회의" | 하위 관리자가 의견 불일치를 보이며, 상위가 재위임하고, 작업자가 재실행하며, 예산이 소진될 때까지 루프가 반복됩니다. |
| 깊이 2 상한 | "2단계보다 깊게 내려가지 마세요" | 경험적 가드레일: 3단계 이상은 관측 가능성을 붕괴시킵니다. |
| 카나리 질문 | "모든 단계에서 원본 진리(Ground Truth)" | 드리프트를 감지하기 위해, 작업자에게 항상 원본 쿼리를 변경하지 않은 상태로 질문하는 것. |
| 출처 추적 체인 | "누가 무엇을 말했는가" | 각 합성 결과에서 이를 생성한 리프 출력까지 거슬러 올라가는 추적. |
