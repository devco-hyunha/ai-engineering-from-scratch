# 핸드오프와 루틴 — 상태 비저장 오케스트레이션

> OpenAI의 Swarm (2024년 10월)은 다중 에이전트 오케스트레이션을 두 가지 기본 요소로 단순화했습니다: **루틴** (시스템 프롬프트로서의 지침 + 도구)과 **핸드오프** (다른 Agent를 반환하는 도구). 상태 머신도, 분기 DSL도 없습니다. LLM은 올바른 핸드오프 도구를 호출하여 라우팅합니다. OpenAI Agents SDK (2025년 3월)는 프로덕션용 후속 제품입니다. Swarm 자체는 가장 깔끔한 개념적 참조로 남아 있습니다. 전체 소스 코드는 몇백 줄에 불과합니다. API 표면이 대략 "agent = prompt + tools; handoff = function returning agent"와 같기 때문에 이 패턴이 빠르게 확산되었습니다. 한계: 상태 비저장이므로 메모리 관리는 호출자의 몫입니다.

**유형:** Learn + Build
**언어:** Python (stdlib)
**선수 요건:** 16단계 · 04강 (기본 모델)
**시간:** 약 60분

## 문제점

모든 다중 에이전트 프레임워크는 자체 DSL을 학습하길 요구합니다: LangGraph의 노드와 엣지, CrewAI의 크루와 작업, AutoGen의 GroupChat과 관리자. DSL은 실제 추상화이지만, 필요 이상으로 복잡하게 느껴지게 만듭니다.

Swarm은 반대 방향으로 접근합니다: 모델이 이미 가진 도구 호출 기능을 사용하세요. 핸드오프는 도구 호출이 됩니다. 오케스트레이터는 현재 대화를 유지하는 에이전트입니다. 상태 머신은 에이전트의 시스템 프롬프트에 내재되어 있습니다.

## 개념

### 두 가지 기본 요소

**루틴.** 에이전트의 역할과 사용 가능한 도구를 정의하는 시스템 프롬프트입니다. 범위가 지정된 지침 세트라고 생각하세요: "당신은 트리아지 에이전트입니다. 사용자가 환불에 대해 묻는다면 환불 에이전트로 핸드오프하세요."

**핸드오프.** 에이전트가 호출할 수 있으며 새로운 Agent 객체를 반환하는 도구입니다. Swarm 런타임은 Agent 반환 값을 감지하고 다음 턴의 활성 에이전트를 전환합니다.

이것이 전체 추상화입니다.

```
def transfer_to_refunds():
    return refund_agent  # Swarm이 Agent 반환을 감지하면 → 활성 에이전트를 전환합니다

triage_agent = Agent(
    name="triage",
    instructions="Route the user to the right specialist.",
    functions=[transfer_to_refunds, transfer_to_sales, transfer_to_support],
)
```

트리아지 에이전트의 시스템 프롬프트는 사용자 메시지에 기반하여 올바른 핸드오프를 선택하도록 합니다. LLM의 도구 호출이 라우팅을 수행합니다.

### 왜 빠르게 확산되었는가

- **작은 API.** 학습해야 할 개념이 두 개뿐입니다.
- **모델이 이미 수행하는 기능을 활용합니다.** 도구 호출은 모든 프로바이더에서 이미 프로덕션 수준입니다.
- **상태 머신 부담이 없습니다.** 그래프를 설명하지 않아도 되며, 에이전트의 프롬프트가 누구에게 핸드오프할지 설명합니다.

### 상태 비저장의 트레이드오프

Swarm은 실행 간에 명시적으로 상태 비저장입니다. 프레임워크는 실행 중 메시지 히스토리를 유지하지만, 아무것도 영속화하지 않습니다. 메모리, 연속성, 장기 실행 작업은 모두 호출자의 문제입니다.

프로덕션 환경(OpenAI Agents SDK, 2025년 3월)에서는 이것이 주요 변경 사항 중 하나였습니다. SDK는 핸드오프 프리미티브를 유지하면서 내장 세션 관리, 가드레일, 추적을 추가합니다.

### Swarm/핸드오프가 적합한 경우

- **트리아지 패턴.** 최전선 에이전트가 사용자를 전문가에게 라우팅합니다.
- **스킬 기반 핸드오프.** "작업에 코드가 필요하면 코더를 호출하고, 연구가 필요하면 리서처를 호출합니다."
- **짧고 범위가 한정된 대화.** 고객 지원, FAQ에서 티켓으로, 단순한 워크플로.

### Swarm이 어려움을 겪는 경우

- **공유 메모리가 있는 장기 세션.** 핸드오프는 대화 상태를 새 에이전트의 프롬프트와 히스토리로 리셋합니다. 호출자가 관리하는 메모리 없이는 에이전트 간에 영속적인 상태가 없습니다.
- **병렬 실행.** 핸드오프는 한 번에 하나씩 진행되며, 활성 에이전트가 전환됩니다. 병렬 처리는 호출자가 여러 Swarm 실행을 오케스트레이션해야 합니다.
- **감사와 재현.** 상태 비저장 실행은 정확히 재현하기 어렵습니다. LLM의 핸드오프 선택은 결정적이지 않습니다.

### OpenAI Agents SDK (2025년 3월)

프로덕션 후속 버전은 다음을 추가합니다:

- **세션 상태.** 실행 간에 영속적인 스레드.
- **가드레일.** 입력/출력 검증 훅.
- **추적.** 모든 도구 호출과 핸드오프가 기록됩니다.
- **핸드오프 필터.** 핸드오프 시 어떤 컨텍스트가 전달되는지 제어합니다.

핸드오프 프리미티브는 유지되며, 그 주위에 프로덕션 에르고노믹스가 추가됩니다.

### Swarm vs GroupChat

둘 다 LLM 기반 라우팅을 사용하지만, **누가 다음을 선택하는지**에서 다릅니다:

- GroupChat: 선택자(함수 또는 LLM)가 외부에서 다음 화자를 선택합니다.
- 스웜(Swarm): 현재 에이전트(Agent)가 핸드오프(Handoff) 도구를 호출하여 후속 에이전트를 선택합니다.

스웜(Swarm)은 "에이전트가 다음을 결정"하는 방식이고, 그룹 채팅(GroupChat)은 "매니저가 다음을 결정"하는 방식입니다. 스웜의 결정은 활성 에이전트의 도구 호출에 있으며, 그룹 채팅의 결정은 `GroupChatManager`에 있습니다.

```figure
sw-handoff-routing
```

## 구현하기

`code/main.py`는 스웜(Swarm)을 처음부터 구현합니다: Agent 데이터 클래스, 핸드오프(Handoff) 메커니즘(도구가 Agent를 반환), 에이전트 전환을 감지하는 실행 루프(run loop).

데모: 트리아지(triage) 에이전트가 환불, 영업, 지원 전문가로 라우팅합니다. 각 전문가에게는 자체 도구가 있습니다. 실행 루프는 각 핸드오프(Handoff)를 출력합니다.

실행:

```
python3 code/main.py
```

## 사용하기

`outputs/skill-handoff-designer.md`는 주어진 작업을 위한 핸드오프(Handoff) 토폴로지를 설계합니다: 어떤 에이전트(Agent)가 존재하는지, 어떤 핸드오프를 호출할 수 있는지, 어떤 컨텍스트가 전달되는지.

## 출시하기

체크리스트:

- **핸드오프 로깅.** 모든 핸드오프(Handoff)는 from-agent, to-agent, 컨텍스트 스냅샷을 포함하는 추적(Trace) 이벤트를 기록합니다.
- **컨텍스트 전달 규칙.** 핸드오프(Handoff) 시 무엇을 전달할지 결정하세요: 전체 히스토리(비용이 높음), 마지막 N개 메시지, 또는 요약.
- **핸드오프 가드레일(Guardrails).** 다른 도구 권한을 가진 전문가로의 핸드오프(Handoff)는 인증되어야 합니다. 그렇지 않으면 프롬프트 인젝션(Prompt Injection)이 원치 않는 핸드오프를 강제할 수 있습니다.
- **루프 감지.** 두 에이전트(Agent)가 서로 반복적으로 핸드오프(Handoff)하는 것은 흔한 실패입니다. 간단한 last-K 링 체크로 감지하세요.
- **폴백 에이전트.** 핸드오프(Handoff) 대상이 존재하지 않으면 안전한 기본값으로 폴백하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| Routine | "에이전트 프롬프트" | 시스템 프롬프트 + 도구 목록. 역할과 사용 가능한 핸드오프를 정의합니다. |
| Handoff | "다른 에이전트로 전달" | 활성 에이전트가 호출할 수 있는 도구로, 새로운 Agent를 반환합니다. 런타임이 활성 에이전트를 전환합니다. |
| Stateless | "실행 간 메모리 없음" | Swarm은 아무것도 저장하지 않으며, 메모리는 호출자의 책임입니다. |
| Active agent | "지금 누가 말하고 있는지" | 현재 대화를 담당하는 에이전트입니다. 핸드오프가 이를 변경합니다. |
| Context transfer | "핸드오프 시 이동하는 내용" | 진입하는 에이전트가 보는 히스토리에 대한 정책: 전체, 최근 N개, 또는 요약본. |
| Handoff loop | "에이전트 간 핑퐁" | 두 에이전트가 서로 계속 전달하는 실패 모드입니다. |
| OpenAI Agents SDK | "프로덕션 Swarm" | 2025년 3월 후속 제품; 핸드오프 프리미티브 위에 세션, 가드레일, 추적을 추가합니다. |
| Handoff filter | "전달 게이트" | 핸드오프 경계에서 컨텍스트를 검사하고 수정하는 SDK 기능입니다. |
