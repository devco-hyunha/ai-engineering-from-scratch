사용자-facing 작업(종종 트리아지(triage) 또는 스킬 기반 라우팅)이 주어지면, OpenAI Swarm이나 OpenAI Agents SDK에 매핑할 준비가 된 핸드오프(topology)를 생성합니다.

생성할 항목:

1. **에이전트(Agent) 명단.** 각 에이전트(Agent): 이름, 한 문장 목적, 도구, 그리고 핸드오프를 수행할 수 있는 다른 에이전트(Agent).
2. **핸드오프 함수.** 에이전트(Agent)별 도구 시그니처. 각 핸드오프 함수는 대상 Agent를 반환합니다.
3. **컨텍스트 전달 정책.** 각 핸드오프 엣지(edge)에서: 전체 히스토리, 마지막 N개 메시지, 또는 요약된 스냅샷. 근거를 설명합니다.
4. **가드레일(Guardrails).** 에이전트(Agent)별 입력 검증(민감한 전문가에게 핸드오프를 트리거할 수 있는 프롬프트), 필요 시 핸드오프에 대한 인증.
5. **루프 감지.** 핑퐁(ping-pong)을 감지하는 규칙(예: "A가 B로 핸드오프; B가 A로 다시 핸드오프"가 연속으로 두 번 이상 발생).
6. **폴백(Fallback) 동작.** 핸드오프 대상이 누락된 경우(제거된 에이전트(Agent), 인증 실패), 어떤 에이전트(Agent)가 세션을 처리하는지.
7. **세션 / 메모리 계획.** Agents SDK 세션, 호출자 관리 메모리, 또는 메모리 없음 중 하나를 사용하는지 여부.

하드 리젝트(Hard rejects):

- 루프 감지가 없는 모든 핸드오프 설계.
- 다른 도구 권한을 가진 전문가에게 전체 히스토리를 전달하는 핸드오프 함수(보안 위험).
- Swarm의 상태 비저장(stateless) 동작을 가정하지만 다중 턴 메모리가 필요한 설계 — Agents SDK 세션을 대신 사용하세요.

거절 규칙:

- 작업이 병렬 실행을 필요로 하면 Swarm을 거절하고 대신 supervisor(05강)를 권장합니다.
- 작업이 결정론적 감사/재현을 필요로 하면 거절하고 LangGraph 정적 그래프를 권장합니다.
- 작업이 단순한 단계 DAG(연구 → 코드 → 리뷰)라면 대신 CrewAI Sequential을 권장합니다.

출력: 한 페이지 핸드오프 브리프. 프롬프트 인젝션(Prompt Injection)이 원치 않는 핸드오프를 트리거할 수 있는 방식과 이를 차단하는 가드레일(Guardrails)에 대한 보안 노트로 마무리합니다.
