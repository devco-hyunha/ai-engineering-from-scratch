멀티 에이전트 프레임워크(또는 이를 사용하는 코드베이스)가 주어지면, 독자가 한 단락으로 프레임워크를 이해할 수 있도록 네 가지 기본 축 매핑을 생성합니다.

다음 내용을 생성합니다:

1. **에이전트 정의.** 에이전트는 어떻게 구성됩니까? 어떤 매개변수를 사용합니까? 어떤 상태를 유지합니까? 정확한 클래스나 팩토리를 명시합니다.
2. **핸드오프 메커니즘.** 세 가지 핸드오프 패턴 중 어떤 것을 사용합니까? 함수 반환, 그래프 엣지, 또는 화자 선택 중 하나입니까? 하이브리드라면 어떤 것이 주요합니까? 하나의 핸드오프를 트리거하는 최소한의 코드를 보여줍니다.
3. **공유 상태 모델.** 전체 메시지 풀입니까, 투영된 뷰입니까? 메모리 내 상태입니까, 내구성 있는 상태(체크포인팅)입니까? 동시 작성자에 대해 스레드 안전합니까? 누가 충돌을 조정합니까?
4. **오케스트레이터 유형.** 정적, LLM 선택, 핸드오프 주도, 또는 큐 주도입니까? LLM 선택이라면 기본 모델은 무엇입니까? 정적이라면 그래프는 순환형입니까, DAG입니까?
5. **축 간 트레이드오프.** 결정성, 확장성 한계, 디버깅 용이성, 일반적인 실패 모드에 대해 각각 한 문장으로 설명합니다.

허용되지 않는 사항:

- 추상화가 "새로운" 것이라고 주장하면서 네 가지 기본 축 중 하나로 축소되지 않는다는 것을 증명하지 않는 모든 매핑은 허용되지 않습니다. 축소할 수 없다면, 다섯 번째 기본 축을 발명하지 말고 간격을 정확히 명시합니다.
- 마케팅 문서만 인용하는 프레임워크 비교는 허용되지 않습니다. 항상 프레임워크 저장소나 공식 쿡북에서 구체적인 코드 예제를 인용합니다.
- 프레임워크가 최적화하는 기본 축을 명시하지 않고 "프레임워크 X는 에이전트에 더 좋습니다"와 같은 진술은 허용되지 않습니다.

거부 규칙:

- 프레임워크가 클로즈드 소스이고 공개 문서가 에이전트-핸드오프-상태-오케스트레이터 인터페이스를 노출하지 않는다면, 내부 구조 없이는 매핑이 불가능하다고 명시합니다.
- 사용자가 프레임워크 없이 코드베이스(직접 만든 에이전트)를 제공한다면, 커스텀 구현을 매핑하고 설계가 부족한 기본 축을 플래그합니다.
- 프레임워크가 2024년 이전 버전(원본 AutoGen v0.2, Swarm 이전)이고 더 이상 유지되지 않는다면, 후속 버전이 매핑을 유지하는지 여부에 대해 한 줄의 노트를 포함하세요.

출력: 한 페이지 분량의 프레임워크 브리프. 한 문장 요약("프레임워크 X는 핸드오프를 그래프 엣지로 고정하고 리듀서를 통해 공유 상태를 노출합니다.")으로 시작한 뒤, 위의 다섯 섹션을 나열하고, 마지막으로 이 프레임워크의 프리미티브가 가장 잘 맞는 프로덕션 프로젝트를 명시하는 마무리 단락을 작성하세요.
