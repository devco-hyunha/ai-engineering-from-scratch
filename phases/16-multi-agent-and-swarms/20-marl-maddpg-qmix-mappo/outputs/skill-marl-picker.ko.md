멀티 에이전트 작업 설명이 주어지면 MARL 알고리즘을 선택합니다.

다음 내용을 생성합니다:

1. **작업 분류.** 완전 협력(공유 보상), 완전 경쟁(영합), 혼합, 일반 합. 에이전트 수. 동질 대 이질.
2. **관측 가능성.** 완전(모든 에이전트가 전역 상태를 봄), 부분(각 에이전트가 자신의 관측만 봄) 또는 통신 지원.
3. **행동 공간.** 이산(Atari 스타일, SMAC) 또는 연속(particle world, MuJoCo). 알고리즘 선택에 영향을 미칩니다.
4. **보상 구조.** 밀집(단계별 형성) 대 희소(종료 시만). 밀집은 MAPPO를 실용적으로 만듭니다. 희소는 크레딧 할당 지원(QMIX의 가치 분해)이 필요합니다.
5. **알고리즘 권장.** Yu et al. 2022에 따라 MAPPO를 기본으로 시작합니다. 다음으로 전환합니다:
   - QMIX는 협력 + 동질 + 강한 희소 보상 크레딧 할당이 필요할 때
   - MADDPG는 혼합(협력 + 경쟁) + 연속 행동일 때
   - 확장(QTRAN, QPLEX, FACMAC)은 단조성 제약이 너무 restrictive일 때
6. **훈련 인프라.** 충분한 상호작용 데이터, 컴퓨팅 예산, 보상 형성 전문성, 안정성 예산(실험당 5-10 시드)이 있습니까? 그렇지 않다면 LLM 에이전트용 프롬프트 수준 정책을 권장합니다.
7. **배포 계약.** CTDE: 배포 시 각 에이전트는 로컬 관측만 봅니다. 런타임 코드가 이를 준수하도록 계약을 명시적으로 작성합니다.

하드 거부:

- 첫 실행에 MAPPO가 아닌 기본을 선택하는 것. MAPPO는 2026년 기본입니다. 여기서 시작하세요.
- 혼합 협력-경쟁 작업에 QMIX를 사용하는 것. 가치 분해는 단조 집합을 가정합니다.
- 상호작용 데이터나 보상 신호가 없는 LLM 에이전트 시스템에 MARL 훈련을 권장하는 것. 데이터가 갖춰질 때까지 프롬프트 수준 정책이 더 잘 수행됩니다.
- 에이전트별 관측 및 행동을 로깅하지 않고 훈련하는 것. 디버깅이 불가능합니다.

거절 규칙:

- 작업의 상호작용 데이터가 약 1000 에포크(Epoch) 미만인 경우, 프롬프트 수준 정책이나 지도 미세 조정(SFT)(Supervised Fine-Tuning)을 권장합니다.
- 작업이 비마르코프적(메모리 필요)이지만 권장 사항에 재귀적 크리틱이 포함되지 않은 경우, 해당 공백을 표시합니다.
- 작업이 일반 합 게임 경쟁적(다중 균형)인 경우, MARL만으로는 하나의 균형을 선택하지 못합니다. 메커니즘 설계나 균형 선택을 권장합니다.

출력: 한 페이지 브리프. 한 문장 권장 사항("MAPPO 기본값과 중앙 집중식 가치 함수; 에이전트별 이산 액터; 배포 시 CTDE; 실험당 5개 시드.")으로 시작한 후, 위의 7개 섹션을 작성합니다. 데이터 수집, 학습, 평가, 롤아웃(Rollback)을 포함한 학습에서 배포까지의 파이프라인으로 마무리합니다.
