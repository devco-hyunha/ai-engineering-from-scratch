# 협상 및 교섭

> 에이전트(Agent)는 자원, 가격, 작업 할당 및 조건을 협상합니다. 2026년 벤치마크 세트는 명확합니다. NegotiationArena (arXiv:2402.05863)는 LLM이 페르소나 조작("절박함")을 통해 보상을 약 20% 개선할 수 있음을 보여줍니다. "Measuring Bargaining Abilities" (arXiv:2402.15813)는 구매자가 판매자보다 협상이 더 어렵고 규모 확장이 도움이 되지 않는다는 것을 보여주며, 그들의 **OG-Narrator** (결정적 오퍼 생성기 + LLM 내레이터)는 거래 성사율을 26.67%에서 88.88%로 높였습니다. Large-Scale Autonomous Negotiation Competition (arXiv:2503.06416)은 약 18만 건의 협상을 진행했으며, **사고의 연쇄(CoT)를 숨기는** 에이전트(Agent)가 상대방에게 추론을 숨김으로써 승리한다는 것을 발견했습니다. Bhattacharya et al. 2025는 Harvard Negotiation Project 지표에 따라 Llama-3가 가장 효과적, Claude-3가 공격적, GPT-4가 가장 공정하다고 순위 매겼습니다. 이 강의는 Contract Net Protocol (FIPA 조상, 02강)을 구현하고, LLM 스타일의 구매자/판매자를 연결하며, OG-Narrator 스타일의 분해를 실행하고, 각 구조적 선택에 따라 거래 성사율이 어떻게 변하는지 측정합니다.

**유형:** Learn + Build
**언어:** Python (stdlib)
**선수 요건:** 16단계 · 02 (FIPA-ACL 유산), 16단계 · 09 (병렬 스웜 네트워크)
**시간:** 약 75분

## 문제점

두 에이전트(Agent)는 가격에 합의해야 합니다. 순수한 언어 프롬프트에 맡겨두면, 2024-2026 LLM은 놀라울 정도로 낮은 비율로 거래를 성사시킵니다 (arXiv:2402.15813의 엄격하게 매개변수화된 교섭에서 약 27%). 규모는 이를 해결하지 못합니다. GPT-4는 GPT-3.5보다 교섭 구조적으로 더 뛰어나지 않으며, 교섭의 *언어*에만 더 뛰어납니다.

근본적인 문제는 LLM이 두 가지 작업, 즉 오퍼를 결정하는 것과 오퍼를 내레이션하는 것을 혼동한다는 점입니다. OG-Narrator는 이 둘을 분리했습니다. 결정적 오퍼 생성기가 수치적 움직임을 계산하고, LLM은 내레이션만 수행합니다. 거래 성사율은 약 89%로 급증합니다.

이는 고전적인 다중 에이전트 발견을 반영합니다. 메커니즘을 통신 계층과 분리하는 것이 승리합니다. Contract Net Protocol (FIPA, 1996; Smith, 1980)은 참조 작업 시장 메커니즘입니다. 내레이션 슬롯에 LLM을 연결하면 현대적인 LLM 기반 작업 시장을 얻을 수 있습니다.

## 개념

### Contract Net, 한 단락으로 요약

스미스(Smith)의 1980년 계약망 프로토콜(Contract Net Protocol): **매니저(manager)**가 **제안 요청(call for proposals, cfp)**을 브로드캐스트합니다. **입찰자(bidders)**는 자신의 오퍼를 담은 **제안(propose)** 메시지로 응답합니다. 매니저는 승자를 선택하여 승자에게 **제안 수락(accept-proposal)**을, 패자에게 **제안 거절(reject-proposal)**을 전송합니다. 승자가 작업을 수행합니다. 선택적 메시지: **거부(refuse)** (입찰자가 제안하지 않음을 표시). FIPA는 이를 `fipa-contract-net` 상호작용 프로토콜로 법제화했습니다.

### OG-Narrator가 승리하는 이유

"언어 모델의 협상 능력 측정(Measuring Bargaining Abilities of Language Models)" (arXiv:2402.15813)은 다음을 관찰했습니다:

- LLM은 종종 협상 규칙을 위반합니다 (무의미한 가격으로 오퍼를 제시하거나, 상대방의 ZOPA를 무시합니다).
- 앵커링이 잘되지 않습니다 (나쁜 첫 오퍼를 수용하며, 전략적 금액이 아닌 상징적 금액으로 역제안합니다).
- 규모만으로는 이러한 문제를 해결하지 못합니다. 더 큰 모델은 유사한 전략적 오류를 범하면서도 더 그럴듯한 언어를 생성합니다.

OG-Narrator의 분해:

```
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ offer generator  │ price → │  LLM narrator    │ → message
           │  (deterministic) │        │  (writes the     │
           │                  │        │   human-style    │
           └──────────────────┘        │   accompaniment) │
                                       └──────────────────┘
```

오퍼 생성기는 고전적인 협상 전략입니다: Rubinstein 협상 모델, Zeuthen 전략, 또는 가격에 대한 단순한 티포타트(tit-for-tat)입니다. LLM은 서술합니다. 메시지는 결정론적 가격과 자연어 프레이밍을 포함합니다.

거래 성사율이 급증하는 이유는 다음과 같습니다:
- 가격이 협상 구역(bargaining zone) 내에 유지됩니다.
- 앵커는 감정적이지 않고 전략적입니다.
- LLM은 잘하는 일을 수행합니다: 글쓰기.

### NegotiationArena의 발견

arXiv:2402.05863은 표준 벤치마크를 제공합니다. 주요 발견:

- LLM은 페르소나를 채택함으로써("나는 금요일까지 이 것을 절박하게 팔아야 해") 보상을 약 20% 개선할 수 있습니다. 페르소나 조작은 실제 전술입니다.
- 공정하고 협력적인 에이전트는 적대적인 에이전트에게 이용당합니다. 방어는 명시적인 카운터 포스트링(counter-posturing)을 필요로 합니다.
- 대칭적인 쌍은 벤치마크 시나리오의 약 40%에서 불공평한 결과로 수렴합니다.

이것은 "LLM이 협상 능력이 떨어진다"는 것이 아닙니다. "LLM은 인간처럼, 이용 가능한 부분을 포함하여, 너무 많이 협상한다"는 것입니다.

### 사고의 연쇄(CoT) 은폐

대규모 자율 협상 대회(Large-Scale Autonomous Negotiation Competition) (arXiv:2503.06416)는 많은 LLM 전략에 걸쳐 약 18만 건의 협상을 진행했습니다. 승자는 상대방에게 자신의 추론을 은폐했습니다:

- 에이전트가 공개적으로 보이는 스크래치패드에 "저는 $75; my reservation price is $70에만 가겠습니다"라고 출력하면, 상대는 이를 읽게 됩니다.
- 승자는 전략을 비공개로 계산합니다. 출력 채널에는 제안과 최소한의 필수 서술만 포함됩니다.

이는 고전 게임 이론( rationality와 정보에 대한 Aumann의 1976년 연구)의 2026년 버전입니다. 비공개 가치(valuation)를 공개하면 보상이 감소합니다. LLM은 이를 직관적으로 이해하지 못하며, 상대에게 공개되는 추론 추적(reasoning traces)에 자신의 유보 가격을 기꺼이 입력합니다.

엔지니어링 시사점: 비공개 스크래치패드 컨텍스트와 공개 메시지 컨텍스트를 분리해야 합니다. 이는 선택 사항이 아닙니다.

### Bhattacharya et al. 2025 — 모델 순위

Harvard Negotiation Project 지표(원칙 기반 협상, BATNA 준수, 이익 상호성)에 대해:

- **Llama-3**는 거래 성사(거래율 + 보상)에 가장 효과적이었습니다.
- **Claude-3**는 가장 공격적인 협상자였습니다(높은 앵커, 늦은 양보).
- **GPT-4**는 가장 공정했습니다(페어링 간 보상 변동이 가장 작음).

이는 2025년 스냅샷입니다. 핵심은 2026년 4월에 어떤 모델이 이기는지가 아니라, 서로 다른 기본 모델이 지속적인 협상 스타일을 가진다는 점입니다. 이질적인 앙상블(15강)은 이를 다양성 원천으로 포함합니다.

### Contract Net + LLM을 통한 작업 할당

LLM 다중 에이전트에서의 Contract Net 현대적 재사용:

1. 매니저 에이전트가 작업을 단위로 분해합니다.
2. 작업 설명과 함께 `cfp`을 워커 에이전트에게 브로드캐스트합니다.
3. 각 워커는 제안을 반환합니다: `(price, eta, confidence)`. 여기서 가격은 토큰, 컴퓨팅 단위, 또는 달러일 수 있습니다.
4. 매니저는 승자(작업에 따라 단일 또는 복수)를 선택하고 보상합니다.
5. 거절된 워커는 다른 작업에 입찰할 수 있습니다.

조정이 동기화 채팅이 아닌 브로드캐스트 및 응답 방식이므로, 100명 이상의 워커에서도 잘 확장됩니다. 프로덕션에서 사용됨: Microsoft Agent Framework의 오케스트레이션 패턴, 일부 LangGraph 구현.

### LLM 이해관계자 상호 협상

NeurIPS 2024 (https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf)는 **비공개 점수**와 **최소 수용 임계값**을 가진 다자간 점수 산정 게임을 도입합니다. 각 이해관계자는 비공개 효용을 가지며, LLM은 메시지로부터 이를 추론해야 합니다. 이는 양자 협상에서 N자 연대 형성으로의 일반화입니다. 이질적인 작업자 역량을 가진 생산 작업 시장에서 관련이 있습니다.

### 서술 대 메커니즘 규칙

2024-2026년 모든 협상 벤치마크에서 일관된 엔지니어링 규칙은 다음과 같습니다:

> LLM이 서술하게 하세요. LLM이 오퍼를 계산하지 않도록 하세요.

오퍼가 숫자(가격, ETA, 수량)여야 한다면, 협상 상태에서 결정적으로 생성하고 LLM이 프레이밍을 생성하게 하세요. 오퍼가 제안 구조(작업 분해, 역할 할당)여야 한다면, LLM이 초안을 작성하게 하되, 전송 전에 스키마와 제약 조건을 검증하세요.

## 구현하기

`code/main.py`는 다음을 구현합니다:

- `ContractNetManager`, `ContractNetTask`, `Bid` — 관리자 + 입찰자, CFP 브로드캐스트, 제안 수집, 낙찰.
- `og_narrator_bargain(state, rng)` — OG-Narrator 구매자: 중점 방향으로 결정적인 Zeuthen식 양보.
- `seller_response(state, rng)` — 결정적인 판매자 역오퍼 정책(두 스타일 모두의 구조적 진실).
- `naive_llm_bargain(state, rng)` — 모든 LLM 협상자를 시뮬레이션합니다: 높은 분산을 가진 가격을 선택하며, ZOPA 밖인 경우가 많습니다.
- 측정: 매 시마다 새로운 예약 가격이 샘플링된 1000번의 시도에 대한 거래율.

실행하세요:

```
python3 code/main.py
```

예상 출력: naive-LLM 거래율 ~65-75%; OG-Narrator 거래율 ~85-95%; 15-25 포인트의 격차는 오퍼 생성과 서술을 분리하는 구조적 이점입니다. 세 입찰자와 한 작업을 가진 Contract Net 작업 시장 할당 예시도 포함됩니다.

## 사용하기

`outputs/skill-bargainer-designer.md`는 협상 프로토콜을 설계합니다: 누가 오퍼를 생성하는지(결정적 또는 LLM), 누가 서술하는지, 비공개 스크래치패드가 공개 메시지와 어떻게 분리되는지, 거래율이 어떻게 모니터링되는지.

## 출시하기

생산 협상 체크리스트:

- **스크래치패드 분리.** 비공개 상태는 절대 상대의 컨텍스트에 도달하지 않습니다. 이는 협상 불가능한 사항입니다.
- **결정적 오퍼 생성.** 가격, 수량, 예상 도착 시간(ETA): 프롬프트가 아닌 계산으로 처리합니다.
- **모든 수신 오퍼를 스키마로 검증합니다.** ZOPA 밖의 오퍼는 프로토콜 경계에서 거부합니다.
- **라운드 수를 제한합니다.** 최대 3-5 라운드; 교착 상태가 발생하면 중재자에게 에스컬레이션합니다.
- **거래 성사율과 보상 분산을 지속적으로 측정합니다.** 거래 성사율이 떨어지는 것은 증상입니다 — 종종 프롬프트 드리프트나 상대방 측 공격의 신호입니다.
- **거부된 모든 제안에 결정적 근거를 기록합니다.** Contract Net 관리자 입장에서, 낙찰되지 않은 입찰자는 이유를 이해해야 합니다.

## 연습 문제

1. `code/main.py`을 실행합니다. OG-Narrator가 naive-LLM보다 거래 성사율에서 얼마나 더 잘하는지 확인합니다. 얼마나 차이가 나나요?
2. **페르소나 기반 보상 개선**(arXiv:2402.05863)을 구현합니다. 구매자는 내러레이션에서만 "이번 주에 꼭 사야 하는" 페르소나를 채택하고, 오퍼 생성기는 변경하지 않습니다. 거래 성사율이나 보상이 변하나요?
3. Chain of Thought(CoT) **은폐**를 구현합니다. 상대방에게 전달되지 않는 비공개 스크래치패드 문자열을 유지합니다. 실수로 이를 유출하면(채널을 바꿔 시뮬레이션) 어떤 일이 일어나나요?
4. Contract Net을 예약 가격(reserve price)이 있는 N-입찰자 경매로 확장합니다. 모든 입찰이 예약 가격을 초과할 때, 관리자는 최저 가격과 최고 품질 중 어떻게 결정하나요? 어떤 낙찰 규칙을 선택하며, 그 이유는 무엇인가요?
5. Harvard Negotiation Project 지표에 관한 Bhattacharya et al. 2025를 읽습니다. 서로 다른 스타일(공격적 vs 공정)의 두 협상자를 구현합니다. 대칭 및 비대칭 페어링에서 보상 분산을 측정합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| Contract Net | "태스크 마켓" | Smith 1980, FIPA 1996. cfp + propose + accept/reject. 표준 태스크 마켓입니다. |
| ZOPA | "합의 가능 영역" | 구매자의 최대값과 판매자의 최소값 간 겹침. 이 밖의 오퍼는 성사될 수 없습니다. |
| BATNA | "협상된 합의에 대한 최선의 대안" | 이 거래가 실패할 경우의 대안입니다. 예약 가격을 설정합니다. |
| OG-Narrator | "오퍼 생성기 + 내러레이터" | 분해: 결정적 오퍼, LLM 내러레이션. |
