병렬 서브 에이전트 연구가 유리한 사용자 쿼리가 주어지면, 모든 프레임워크(LangGraph, OpenAI Agents SDK, CrewAI Hierarchical)에 연결할 수 있는 감독자 패턴 설계를 생성합니다.

생성할 항목:

1. **복잡도 추정.** 이 쿼리는 단순(1 에이전트, 3-10 도구 호출), 중간(2-4 워커), 또는 복잡(5+ 워커)한가요? Anthropic의 규모-노력(scale-effort) 휴리스틱을 사용하여 한 문장으로 근거를 제시합니다.
2. **리드 시스템 프롬프트.** 다음을 포함해야 합니다: (a) 분해 지침, (b) 종합 지침, (c) 리드는 원본 소스 콘텐츠를 읽지 않고 워커 요약만 읽는다는 명시적 규칙.
3. **워커 시스템 프롬프트.** 역할별로 하나씩 작성하며, 각 프롬프트는 좁은 범위와 리드가 기대하는 출력 형식을 명시합니다.
4. **서브 질문 분해 규칙.** 리드는 쿼리를 어떻게 분해하나요? 먼저 넓게 나누고 좁게 나누는 방식인가요, 아니면 직접 분해하는 방식인가요? 서브 질문을 부적합하게 만드는 요건은 무엇인가요(다른 질문과 겹침, 너무 넓음)?
5. **종합 템플릿.** 명시적인 충돌 처리 규칙: 두 워커가 모순되는 사실을 반환하면, 종합 단계는 하나를 조용히 선택하는 대신 불일치를 드러내야 합니다.
6. **모델 페어링.** 리드에는 어떤 모델(추론 티어)을, 워커에는 어떤 모델(더 빠르고 저렴한 티어)을 사용하나요? 트레이드오프를 설명합니다.
7. **관측 가능성 요구 사항.** 최소 추적 지점: 계획, 각 워커의 시작/종료, 종합 입력, 종합 출력.

하드 리젝트(Hard rejects):

- 리드가 스스로 도구 사용을 수행하는 모든 설계는 거부합니다. 리드는 계획과 종합만 수행합니다.
- 범위 이탈을 허용하는 워커 프롬프트(예: 경계 없이 "X와 관련된 모든 것을 연구" 등)는 거부합니다.
- 충돌을 숨기는 종합 템플릿은 거부합니다.

거부 규칙:

- 쿼리가 단순한 경우(총 도구 호출이 10회 미만으로 추정됨), 설계를 거부하고 단일 에이전트 방식을 권장합니다. Anthropic의 15배 토큰 비용 발견을 인용합니다.
- 쿼리가 순차적(2단계가 1단계의 출력에 의존)이라면, 이를 거부하고 파이프라인/체인 패턴을 권장해 주세요.
- 사용자가 결정성과 감사(audit)를 위해 최적화하고 있다면, 슈퍼바이저를 거부하고 LangGraph 정적 그래프를 권장해 주세요.

출력: 한 페이지 분량의 설계 브리프. 복잡도 추정과 패턴 적합성 판정("슈퍼바이저가 적합합니다")으로 시작하세요. 시스템이 연속적으로 실행될 경우, 무지개 배포(rainbow deployment)에 대한 주의 사항을 마지막에 포함하세요.
