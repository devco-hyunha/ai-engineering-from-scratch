# 평가 및 조정 벤치마크

> 2025-2026년 벤치마크 5종이 멀티 에이전트 평가 공간을 다루고 있습니다. **MultiAgentBench / MARBLE** (ACL 2025, arXiv:2503.01935)은 스타/체인/트리/그래프 토폴로지를 마일스톤 KPI로 평가합니다. **연구에는 그래프가 가장 적합**하며, 인지적 계획은 마일스톤 달성률을 약 3% 높입니다. **COMMA**는 멀티모달 비대칭 정보 조정 능력을 평가합니다. GPT-4o를 포함한 최신 모델들도 랜덤 기준선을 넘지 못합니다. **MedAgentBoard** (arXiv:2505.12371)는 네 가지 의료 작업 범주를 다루며, 멀티 에이전트가 단일 LLM을 능가하지 못하는 경우가 많음을 발견합니다. **AgentArch** (arXiv:2509.10769)는 도구 사용 + 메모리 + 오케스트레이션(Orchestration)을 결합한 엔터프라이즈 에이전트 아키텍처를 벤치마킹합니다. **SWE-bench Pro** ([arXiv:2509.16941](https://arxiv.org/abs/2509.16941))는 비즈니스 앱, B2B 서비스, 개발자 도구를 아우르는 41개 저장소에 걸쳐 1865개의 문제를 포함하고 있습니다. 프론티어 모델은 Pro에서 약 23%, Verified에서 70% 이상을 기록합니다 — 이는 오염에 대한 현실 점검입니다. Claude Opus 4.7 (2026년 4월)은 명시적인 에이전트 팀 조정으로 Pro에서 **64.3%**를 기록한 것으로 보고됩니다 (Anthropic의 공식 출처는 아직 공개되지 않았습니다 — 예비 데이터로 취급하세요). Verdent (에이전트 스캐폴드)는 Verified에서 **76.1% pass@1**을 달성합니다 ([Verdent technical report](https://www.verdent.ai/blog/swe-bench-verified-technical-report)). **AAAI 2026 Bridge Program WMAC** (https://multiagents.org/2026/)은 2026년 커뮤니티의 초점입니다. 이 강의는 MARBLE의 지표에 기반하여 토폴로지와 지표 간 스윕을 수행하고, "SWE-bench Verified를 통과하는 것만으로는 일반화 증거가 아니다"라는 규칙을 고정합니다.

**유형:** Learn
**언어:** Python (stdlib)
**선수 요건:** 16단계 · 15강 (투표 및 토론 토폴로지), 16단계 · 23강 (실패 모드)
**시간:** 약 75분

## 문제점

논문이 "우리 멀티 에이전트 시스템이 더 좋다"라고 주장할 때, 핵심 질문은 "무엇보다 더 좋은가, 어떤 작업에서, 어떻게 측정했는가"입니다. 2023-2024년 멀티 에이전트 평가는 혼란스러웠습니다. 모두가 자체 지표, 자체 기준선, 자체 작업 세트를 선택했습니다. 2025-2026년 벤치마크가 구조를 도입했습니다.

공유 벤치마크가 없으면 두 멀티 에이전트 시스템을 의미 있게 비교할 수 없습니다. 더 나쁜 점은, 홀드아웃 벤치마크가 없으면 프론티어 모델이 오염될 수 있다는 것입니다. SWE-bench Verified는 2025년 중반까지 학습 코퍼스에 부분적으로 오염되었습니다. 프론티어 점수가 부풀려졌고, Pro는 오염되지 않은 현실 점검용으로 설계되었습니다.

이 강의는 2026년 표준 벤치마크 다섯 가지를 나열하고, 각 벤치마크가 무엇을 측정하는지 설명하며, 벤치마크 주장을 비판적으로 읽는 방법을 가르쳐 줍니다.

## 개념

### MultiAgentBench (MARBLE) — ACL 2025

arXiv:2503.01935. 연구, 코딩, 계획 작업에 대해 네 가지 조정 토폴로지(star, chain, tree, graph)를 평가합니다. 마일스톤 기반 KPI는 최종 성공뿐만 아니라 부분적인 진행 상황을 추적합니다.

측정된 결과:

- **Graph** 토폴로지는 연구 시나리오에 가장 적합하며, 모든 에이전트 간 상호 비판을 지원합니다.
- **Chain**은 단계별 정밀화 코딩에 가장 적합합니다.
- **Star**는 빠른 사실적 통합에 가장 적합합니다.
- **조정 비용(Coordination tax)**은 graph 토폴로지에서 약 4개 이상의 에이전트부터 나타납니다.
- **인지 계획(Cognitive planning)**은 모든 토폴로지 전반에서 마일스톤 달성률을 약 3% 증가시킵니다.

사용 시점: 조정 토폴로지를 동등한 조건에서 비교하고 싶을 때입니다. MARBLE 저장소(https://github.com/ulab-uiuc/MARBLE)는 평가기를 제공합니다.

### COMMA — 멀티모달 비대칭 정보

에이전트들이 서로 다른 관측 모달리티를 가지고 있으며 완전한 정보 공유 없이 조정해야 하는 작업을 다룹니다. 보고된 결과는 당혹스럽습니다. GPT-4o를 포함한 최첨단 모델들은 COMMA에서 에이전트 간 협업 시 **랜덤 베이스라인**을 넘어서는 데 어려움을 겪습니다. 이는 멀티 에이전트 모달리티가 충분히 학습되지 않고 평가되지 않았다는 신호입니다. LLM은 단일 모달리티 협업을 합리적으로 처리하지만, 멀티 모달리티 조정은 붕괴합니다.

사용 시점: 시스템이 멀티모달리티 또는 비대칭 정보 조정을 포함할 때입니다. COMMA의 귀무(null) 결과는 주장하기 전에 측정해야 한다는 경고입니다.

### MedAgentBoard — 도메인 스트레스 테스트

arXiv:2505.12371. 네 가지 의료 작업 범주: 진단, 치료 계획, 보고서 생성, 환자 커뮤니케이션. 멀티 에이전트 vs 단일 LLM vs 전통적인 규칙 기반 시스템을 비교합니다.

발견 사항: 멀티 에이전트는 대부분의 범주에서 단일 LLM을 압도하지 못합니다. 멀티 에이전트의 이점은 좁습니다. 하위 작업이 명확하게 분리될 때(진단 + 치료) 작업 분해가 도움이 되지만, 조정 오버헤드가 전문화 이득을 초과할 때(보고서 생성)는 오히려 해가 됩니다.

사용 시점: 도메인에 명확한 단일 LLM 기준선이 있는 경우. MedAgentBoard의 교훈이 일반화된다면, 제안된 많은 멀티 에이전트 시스템은 과잉 설계된 것입니다.

### AgentArch — 엔터프라이즈 아키텍처

arXiv:2509.10769. 도구 사용, 메모리, 오케스트레이션이 계층적으로 결합된 엔터프라이즈 환경. 벤치마크는 각 계층의 기여도를 분리합니다: 도구 추가가 얼마나 도움이 되는가? 메모리 추가는? 멀티 에이전트 오케스트레이션 추가는?

사용 시점: 엔터프라이즈 에이전트 스택을 설계하며 각 계층의 정당성을 입증해야 할 때. AgentArch는 가치를 측정할 수 없는 기능을 구매하는 것을 피하는 데 도움을 줍니다.

### SWE-bench Pro — 현실 점검

arXiv:2509.16941. 비즈니스 앱, B2B 서비스, 개발자 도구를 아우르는 41개 저장소의 1865개 문제. 이후의 학습 컷오프로 **오염되지(uncontaminated)** 않도록 설계되었습니다. 프론티어 모델은 Pro에서 약 23%, Verified에서 70% 이상을 기록합니다. 이 격차는 오염 신호입니다.

2026년 4월 점수:
- Pro에서의 Claude Opus 4.7: **64.3%** (명시적인 에이전트 팀 조정을 사용하여 보고됨; Anthropic의 공식 출처는 아직 공개되지 않음 — 예비적인 것으로 취급하세요).
- Verified에서의 Verdent (에이전트 스캐폴드): **76.1% pass@1** ([technical report](https://www.verdent.ai/blog/swe-bench-verified-technical-report)).
- 에이전트 스캐폴딩 없이 Pro에서의 프론티어 원시 점수: 약 23-35% ([SWE-bench Pro paper](https://arxiv.org/abs/2509.16941)).

요점: "SWE-bench Verified를 능가했다"는 더 이상 능력의 증거가 아닙니다. Pro가 현재 게이트 테스트입니다. 에이전트 팀 스캐폴딩은 Pro에서 측정 가능한 향상(~30-40 포인트 델타)을 산출하며, 이는 2026년 멀티 에이전트 조정에 대한 가장 강력한 경험적 논거 중 하나입니다.

### AAAI 2026 WMAC

AAAI 2026 Bridge Program — 멀티 에이전트 조정 워크숍 (https://multiagents.org/2026/). 2026년 멀티 에이전트 AI 연구의 커뮤니티 초점. 승인된 논문과 워크숍 절차는 새로운 방법을 평가하는 표준 장소입니다. 생산 결정을 위해 arXiv 프리프린트보다 WMAC 승인된 주장을 우선시하세요.

### 벤치마크 주장을 회의적으로 읽기 — 2026 체크리스트

누군가 멀티 에이전트 결과를 주장할 때:

1. **어떤 벤치마크, 어떤 분할?** SWE-bench Verified vs Pro는 매우 중요합니다. 잘못된 분할에서 보고된 숫자는 가치가 없습니다.
2. **오염 확인.** 벤치마크가 모델의 학습 컷오프 이후에 공개되었나요? 아니라면 주의해서 다루세요.
3. **기준 비교.** 단일 LLM 기준, 랜덤 기준, 이전 멀티 에이전트 작업과 비교하세요. "동일 시스템의 튜닝되지 않은 버전과 비교"는 아닙니다.
4. **통계적 유의성.** N번의 시도, p-값, 신뢰 구간. 프런티어 모델은 분산이 높으므로 단일 실행은 오해를 불러일으킬 수 있습니다.
5. **작업 다양성.** 하나의 작업인가요, 여러 작업인가요? 생산 환경에서는 일반화가 중요합니다.
6. **비용 공개.** 작업당 토큰 수, 실시간. 비용이 20배인 90% 해결책은 능력 주장이 아니라 비즈니스 결정입니다.

### 대부분의 벤치마크가 잘 측정하지 못하는 것

- **장기 조정.** 며칠간의 실시간 상호작용. 현재 모든 벤치마크는 짧은 기간 동안 실행됩니다.
- **적대적 복원력.** 한 에이전트가 악의적이거나 손상된 경우 어떻게 되나요?
- **배포 중 드리프트.** 벤치마크는 정적이며, 생산 환경의 분포는 이동합니다.
- **비용 정규화 성능.** 대부분의 벤치마크는 원시 정확도를 보고하며, 달러당 정확도를 보고하지 않습니다.

실제로 중요하게 여기는 축에 대해 자체 내부 벤치마크를 구축하는 것이 종종 옳은 선택입니다.

## 구현하기

`code/main.py`는 비인터랙티브 워크스루입니다:

- 토이 작업에서 3개의 멀티 에이전트 시스템을 시뮬레이션합니다.
- 각 시스템에 대해 MARBLE 스타일 마일스톤 메트릭을 계산합니다.
- "학습" 세트에서 작업을 제외하여 오염 확인을 실행합니다.
- 명시적으로 랜덤 기준과 비교합니다.
- 벤치마크 주장 스코어카드를 출력합니다.

실행:

```bash
python3 code/main.py
```

예상 출력: 원시 정확도, 마일스톤 달성, 작업당 비용, 랜덤 기준 대비 델타, 오염 확인 노트가 포함된 시스템 스코어카드입니다.

## 사용하기

`outputs/skill-benchmark-reader.md`는 모든 멀티 에이전트 벤치마크 주장을 읽고 주의 점검 체크리스트를 적용합니다. 출력: 등급과 주의 사항입니다.

## 출시하기

생산 평가 규율:

- **실제 생산 분포를 반영하는 내부 벤치마크를 구축하세요.** 공개 벤치마크는 참고 자료일 뿐, 대체재가 아닙니다.
- **모든 비교에 무작위 기준선을 포함하세요.** 조율 작업에서 무작위 기준을 큰 격차로 이기지 못한다면, 그 작업은 잘 정의되지 않았을 수 있습니다.
- **정확도와 함께 비용을 보고하세요.** 토큰 비용과 실제 소요 시간. 운영 팀은 둘 다 필요합니다.
- **분기마다 벤치마크를 재구축하세요.** 프로덕션 분포가 변합니다; 오래된 벤치마크는 오해를 불러일으킵니다.
- **공개된 벤치마크에 대한 과적합을 피하세요.** 팀이 SWE-bench Pro 점수를 위해 특별히 최적화한다면, 프로덕션에서는 성능이 저하될 것입니다.

## 연습 문제

1. `code/main.py`을 실행하세요. 세 개의 시뮬레이션된 시스템 중 마일스톤당 비용이 가장 좋은 시스템이 무엇인지 식별하세요. 원시 정확도가 가장 높은 시스템과 일치합니까?
2. MultiAgentBench (arXiv:2503.01935)를 읽어보세요. 자체 작업 도메인에 대해 MARBLE이 권장하는 네 가지 토폴로지 중 하나를 결정하세요. 논문의 결과를 근거로 정당화하세요.
3. SWE-bench Pro 논문을 읽어보세요. 구체적으로 무엇이 오염에 저항성을 갖게 합니까? 동일한 기법을 관심 있는 다른 벤치마크에 적용할 수 있을까요?
4. COMMA의 멀티모달 조율에 대한 발견을 읽어보세요. 내부 벤치마크에 추가할 수 있는 간단한 멀티모달 조율 작업을 설계하세요. 무엇이 유용한 신호로 간주됩니까?
5. 최근 다중 에이전트 논문의 헤드라인 결과에 벤치마크 주장 체크리스트를 적용하세요. 주장에 어떤 등급을 부여하시겠습니까?

| SWE-bench Pro | "오염에 저항성" | 1865개 문제, 41개 저장소; Verified에서 70%+ 대비 약 23% (오염 신호). |
| 마일스톤 달성 | "부분 점수" | 최종 성공뿐만 아니라 진행을 보상하는 벤치마크. |
| 오염 | "벤치마크가 학습에 유입됨" | 출시 후, 벤치마크가 학습 코퍼스에 유입되어 점수가 인플레이션됩니다. |
| WMAC | "AAAI 2026 브리지 프로그램" | 다중 에이전트 조정 워크숍; 커뮤니티의 중심점입니다. |
