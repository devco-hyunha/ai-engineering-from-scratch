게시된 또는 내부의 다중 에이전트 벤치마크 성능 주장을 주어진 경우, 주장을 채점하고 주의 사항을 드러내 보세요.

다음 내용을 생성하세요:

1. **벤치마크 + 분할 식별.** 어떤 벤치마크(MARBLE, COMMA, MedAgentBoard, AgentArch, SWE-bench Pro, SWE-bench Verified, 사용자 정의)? 어떤 분할(전체, 홀드아웃, 오염 제거)? 알 수 없는 분할은 자격 요건에 미달합니다.
2. **오염 상태.** 테스트 중인 모델의 학습 컷오프 이후의 벤치마크인가요? 벤치마크가 학습 컷오프보다 이전이라면, 오염 위험을 표시하고 주장을 할인하세요.
3. **기준선 품질.** 단일 LLM 대비, 랜덤 대비, 이전 다중 에이전트 작업 대비. 튜닝되지 않은 동일 시스템 대비는 기준선이 아닙니다; 이는 애블레이션(ablation)입니다.
4. **통계적 유의성.** N번의 시도, 신뢰 구간 또는 표준 오차, p-값 또는 동등한 지표. N < 50번의 시도에서 통계가 없는 주장은 근거가 부족합니다.
5. **작업 다양성.** 하나의 작업, 하나의 도메인, 아니면 여러 개? 단일 작업 주장은 일반화를 의미하지 않습니다.
6. **비용 공개.** 작업당 토큰 수, 작업당 벽시계 시간, 작업당 달러 비용. 비용이 20배인 90% 해결은 비즈니스 결정입니다; 비용이 없으면 주장은 불완전합니다.
7. **문자 등급 + 한 문장 판정.**

   - **A:** 모든 6가지 검사가 통과; 주장은 아마도 견고합니다.
   - **B:** 한 가지 약점; 주의 사항이 명시된 주장은 타당합니다.
   - **C:** 두 가지 약점; 주장은 시사적이지만 재현이 필요합니다.
   - **D:** 세 가지 이상의 약점; 주장은 증거가 아닙니다.
   - **F:** 자격 요건에 미달하는 문제(공개되지 않은 분할에서의 오염, 통계 없음, 기준선 없음).

하드 리젝트(Hard rejects):

- Verified vs Pro를 지정하지 않고 "SWE-bench"를 인용하는 주장. 40+ 포인트의 격차로 인해 이 모호한 보고는 용인될 수 없습니다.
- 기준선 비교가 없는 주장. "우리 시스템은 X%를 수행합니다"는 결과이지 숫자일 뿐입니다.
- 멀티 에이전트 시스템에 대해 20회 미만의 시도로 이루어진 주장. 분산이 너무 높습니다.
- 멀티 에이전트 시스템에 대해 비용이 보고되지 않은 주장. 조정 비용은 상당합니다.

거부 규칙:

- 벤치마크가 공개되어 있지 않고 사용자에게 내부 감사 기록이 없는 경우, 등급을 부여할 수 없습니다. 평가 산출물을 공개할 것을 권장합니다.
- 주장이 현재 동료 심사 중(아카이브(arXiv) 사전 공개 논문, 제출되지 않은 논문)인 논문에서 나온 경우, 재현될 때까지 예방 차원에서 등급을 한 단계 낮추십시오.
- 사용자가 주장자 본인이 감사를 요청하는 경우, 감사를 즉시 수행하십시오. 주장이 아직 출판 준비가 되지 않은 경우 플래그를 지정하십시오.

출력: 한 페이지의 등급 카드. 한 문장 요약("등급: C — 좋은 벤치마크 선택, 적절한 기준선, 그러나 오염 검사 및 비용 공개 없음.")으로 시작한 후, 위의 7개 섹션을 포함합니다. "등급을 높이기 위해 수정해야 할 사항"의 우선순위 목록으로 마무리하십시오.
