# 신경망 디버그 체크리스트

학습이 잘못되었을 때 사용하는 체계적인 디버깅 프로토콜입니다. 순서대로 진행해 보세요. 대부분의 버그는 첫 3단계에서 발견됩니다.

## 학습 전 (버그 예방)

1. 모델 아키텍처와 매개변수 수를 출력하세요. 데이터에 비해 모델 크기가 합리적입니까?
2. 무작위 입력으로 단일 순방향 전파(forward pass)를 실행하세요. 출력 형상이 타겟 형상과 일치합니까?
3. 레이블이 올바른 dtype인지 확인하세요 (CrossEntropyLoss는 Long, BCELoss는 Float가 필요합니다).
4. 데이터 정규화를 검증하세요: 입력의 평균은 0에 가깝고 표준 편차는 1에 가까워야 합니다.
5. 무작위 (입력, 레이블) 쌍 5개를 출력하세요. 레이블이 예상한 것과 일치합니까?
6. 학습/테스트 분할에 중복된 샘플이 없는지 확인하세요.

## 단일 배치 과적합 테스트 (60초, 버그의 80%를 포착)

1. 학습 세트에서 8-32개 샘플을 가져오세요.
2. 합리적인 학습률로 200 스텝 동안 학습하세요.
3. 손실은 0에 가까워져야 하며, 학습 정확도는 100%에 도달해야 합니다.
4. 실패할 경우: 버그는 모델, 손실 함수, 또는 학습 루프에 있습니다. 데이터나 하이퍼파라미터의 문제가 아닙니다.
5. 통과할 경우: 전체 학습으로 진행하세요.

## 손실이 감소하지 않음

1. 학습률을 확인하세요. 3가지 값을 시도해 보세요: 현재/10, 현재, 현재*10
2. 레이어별 기울기 노름(gradient norms)을 출력하세요. 모두 0이면 죽은 네트워크(dead network)나 분리된 그래프(detached graph)를 의미합니다.
3. 매개변수에 `requires_grad=True`이 있는지 확인하세요. `loss.backward()`이 호출되는지 확인하세요.
4. `optimizer.zero_grad()`이 `loss.backward()`보다 먼저 호출되는지 확인하세요.
5. `optimizer.step()`이 `loss.backward()`보다 나중에 호출되는지 확인하세요.
6. 모델 매개변수가 옵티마이저에 전달되는지 확인하세요: `optimizer = Adam(model.parameters())`

## 손실이 NaN 또는 Inf임

1. 학습률을 10배 줄이세요.
2. 모든 log() 호출에 epsilon을 추가하세요: `torch.log(x + 1e-7)`
3. 모든 나눗셈에 epsilon을 추가하세요: `x / (y + 1e-8)`
4. BCE 손실 전에 예측값을 클램프(clamp)하세요: `torch.clamp(pred, 1e-7, 1 - 1e-7)`
5. `torch.autograd.detect_anomaly()`를 사용하여 정확한 연산을 찾아보세요
6. 입력 데이터에 NaN이 있는지 확인하세요: `assert not torch.isnan(x).any()`

## 손실 함수가 진동합니다

1. 학습률을 3~10배 낮추세요
2. 배치 크기를 늘리세요 (기울기 잡음을 줄입니다)
3. 기울기 클리핑을 추가하세요: `torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)`
4. SGD에서 Adam으로 전환하세요 (매개변수별 적응형 학습률)
5. 학습의 첫 5~10% 동안 학습률 워밍업을 추가하세요

## 과적합 (학습 정확도는 높고, 테스트 정확도는 낮음)

1. 드롭아웃을 추가하세요 (p=0.1로 시작하여 0.5까지 늘리세요)
2. 옵티마이저에 가중치 감쇠를 추가하세요: `Adam(params, weight_decay=1e-4)`
3. 모델 크기를 줄이세요 (레이어 수를 줄이거나 레이어 폭을 좁히세요)
4. 데이터 증강을 추가하세요
5. 조기 종료(early stopping)를 사용하세요: 검증 손실이 5 에포크 이상 증가하면 멈추세요
6. 학습 세트와 테스트 세트 간에 데이터 누수가 있는지 확인하세요

## 과소 적합 (학습 및 테스트 정확도 모두 낮음)

1. 모델 용량을 늘리세요 (레이어 수를 늘리거나 레이어 폭을 넓히세요)
2. 더 많은 에포크 동안 학습하세요
3. 학습률을 조심스럽게 늘리세요
4. 모델이 학습할 수 있는지 확인하기 위해 정규화를 일시적으로 제거하세요
5. 모델이 작업에 충분히 표현력이 있는지 확인하세요

## 죽은 ReLU 뉴런

1. 레이어별 0 활성화 비율을 확인하세요. 50% 이상이면 문제입니다
2. LeakyReLU(0.01) 또는 GELU로 전환하세요
3. 가중치에 Kaiming 초기화를 사용하세요
4. 학습률을 낮추세요 (큰 업데이트는 뉴런을 죽은 영역으로 밀어낼 수 있습니다)
5. 활성화 함수 전에 배치 정규화를 추가하세요

## 빠른 참조: 학습률 시작점

| 옵티마이저 | 작업 | 시작 학습률 |
|-----------|------|------------|
| Adam | 처음부터 학습 | 1e-3 |
| Adam | 사전 학습된 모델 미세 조정 | 1e-5 |
| SGD + 모멘텀 | 처음부터 학습 | 1e-1 |
| SGD + 모멘텀 | 사전 학습된 모델 미세 조정 | 1e-3 |
| AdamW | 트랜스포머 학습 | 3e-4 |

## 빠른 참고: 배치 크기 효과

| 배치 크기 | 기울기 잡음 | 메모리 | 일반화 |
|-----------|---------------|--------|---------------|
| 8-16 | 높음 (잡음 많음) | 낮음 | 종종 더 좋음 |
| 32-64 | 중간 | 중간 | 좋은 기본값 |
| 128-256 | 낮음 (매끄러움) | 높음 | 워밍업이 필요할 수 있음 |
| 512+ | 매우 낮음 | 매우 높음 | 학습률 스케일링이 필요 |

## 아무것도 작동하지 않을 때

1. 모델을 숨겨진 레이어 1개로 단순화해 보세요. 학습이 되나요?
2. 데이터를 100개 샘플로 단순화해 보세요. 과적합이 되나요?
3. 손실 함수를 MSE로 바꿔 보세요. 수렴하나요?
4. 옵티마이저를 SGD(lr=0.01)로 바꿔 보세요. 진전이 있나요?
5. 데이터를 합성 데이터(예: y = x[0] > 0)로 바꿔 보세요. 학습이 되나요?
6. 이 중 어느 것도 작동하지 않는다면: 버그는 당신이 보고 있지 않은 코드(데이터 로딩, 전처리, 텐서 모양)에 있습니다
