# 에이전트 프레임워크의 트레이드오프 — 그래프, 역할, 액터 오케스트레이션

> 모든 프레임워크는 동일한 데모(연구 에이전트가 보고서를 작성)를 판매하며 동일한 버그(상태 스키마가 오케스트레이션 레이어와 충돌)를 숨깁니다. 문제의 형태와 프레임워크의 추상화가 일치하는 것을 선택하세요. 나머지는 두 번 작성해야 하는 접착제(glue)일 뿐입니다.

**유형:** Learn
**언어:** Python
**선수 요건:** 11단계 · 09강 (함수 호출), 11단계 · 16강 (LangGraph)
**시간:** 약 45분

## 문제점

하나 이상의 LLM 호출이 필요한 작업이 있습니다. 연구 워크플로우(계획, 검색, 요약, 인용)일 수도 있고, 코드 리뷰 파이프라인(diff 파싱, 비판, 패치, 검증)일 수도 있으며, 항공편 예약, 이메일 작성, 비용 보고서 제출을 수행하는 다중 턴(multi-turn) 어시스턴트일 수도 있습니다. 프레임워크를 선택합니다.

3일 후, 프레임워크의 추상화가 누수(leak)된다는 사실을 발견합니다. CrewAI는 역할을 제공하지만, "연구자"가 "작성자"에게 구조화된 계획을 전달해야 할 때 충돌합니다. AutoGen은 에이전트 간 채팅을 제공하지만, 일급(first-class) 상태가 없으므로 체크포인트는 대화 로그의 pickle 파일이 됩니다. LangGraph는 상태 그래프를 제공하지만, 에이전트가 무엇을 할지 알기 전에 모든 전환(transitions)을 이름 지어야 합니다. Agno는 단일 에이전트 추상화를 제공하지만, 세 개의 동시 작업자로 확장(fan out)하려고 시도하면 비명을 지릅니다.

해결책은 "최고의 프레임워크를 선택하는 것"이 아닙니다. 프레임워크의 핵심 추상화를 문제의 형태에 맞추는 것입니다. 이 강의는 그 지도를 그려 나갑니다.

## 개념

![Agent framework matrix: core abstraction vs problem shape](../assets/framework-matrix.svg)

2026년 현황을 지배하는 네 개의 프레임워크가 있습니다. 그들의 핵심 추상화는 동일하지 않습니다.

| 프레임워크 | 핵심 추상화 | 최적의 적합성 | 최악의 적합성 |
|-----------|------------------|----------|-----------|
| **LangGraph** | `StateGraph` — 타입이 지정된 상태, 노드, 조건부 엣지, 체크포인터. | 명시적 상태와 인간 개입 루프(HITL) 인터럽트가 있는 워크플로우; 시간 여행(time-travel) 디버깅이 필요한 프로덕션 에이전트. | 토폴로지가 불명확한 느슨한 역할 기반 브레인스토밍. |
| **CrewAI** | `Crew` — 역할 (목표, 배경 스토리), 작업, 프로세스 (순차적 또는 계층적). | 짧은 선형/계층적 계획을 사용하는 역할극 또는 페르소나 기반 워크플로. | 크루의 턴 히스토리를 넘어서는 상태 유지 기능; 복잡한 분기 처리. |
| **AutoGen** | `ConversableAgent` 쌍 — 종료 조건까지 턴 단위로 대화하는 두 개 이상의 에이전트. | 사고가 채팅에서 자연스럽게 드러나는 다중 에이전트 *대화* (교사-학생, 제안자-비평가, 행위자-리뷰어). | 알려진 DAG를 가진 결정론적 워크플로; 재시작 간에 내구성 있는 상태가 필요한 모든 경우. |
| **Agno** | `Agent` — 단일 LLM + 도구 + 메모리, 팀으로 조합 가능. | 빠르게 구축할 수 있는 단일 에이전트와 경량 팀; 강력한 멀티모달 및 내장 저장소 드라이버. | 커스텀 리듀서를 사용하는 깊고 명시적으로 분기된 그래프. |

### "추상화"의 실제 의미

프레임워크의 핵심 추상화는 아키텍처를 제안할 때 화이트보드에 그리는 것입니다.

- **LangGraph** → 그래프를 그립니다. 노드는 단계, 엣지는 전이이며, 모든 지점의 상태 객체는 타입이 지정됩니다. 멘탈 모델은 상태 머신입니다.
- **CrewAI** → 조직도를 그립니다. 각 역할에는 직무 설명이 있으며, 매니저가 작업을 라우팅합니다. 멘탈 모델은 전문가 소규모 팀입니다.
- **AutoGen** → Slack DM을 그립니다. 두 에이전트가 서로 메시지를 주고받으며, 조율자가 필요하면 세 번째가 참여합니다. 멘탈 모델은 채팅입니다.
- **Agno** → 도구가 매달린 단일 상자를 그립니다. 팀을 위해 상자를 나란히 배치합니다. 멘탈 모델은 "배터리가 포함된 에이전트"입니다.

### 상태(State)에 대한 질문

상태는 프로덕션 환경에서 대부분의 프레임워크 선택이 무너지는 지점입니다.

- **LangGraph.** 타입이 지정된 상태 (`TypedDict` 또는 Pydantic 모델), 필드별 리듀서, 일급 체크포인터 (SQLite/Postgres/Redis). 재개, 인터럽트 및 시간 여행이 기본 제공됩니다. *(11단계 · 16강 참조.)*
- **CrewAI.** 상태는 `context` 필드를 통해 작업 간에 문자열로 흐르거나 `output_pydantic`을 통해 구조화됩니다. 기본 제공되는 내구성 있는 크루 단위 저장소가 없으므로, 크루가 재시작을 견뎌야 한다면 자체적으로 추가해야 합니다.
- **AutoGen.** 상태는 채팅 기록과 사용자 정의 `context`입니다. 대화 기록은 지속되지만, 어댑터를 작성하지 않는 한 임의의 워크플로 상태는 지속되지 않습니다.
- **Agno.** 내장 저장소 드라이버(SQLite, Postgres, Mongo, Redis, DynamoDB)가 `storage=`를 통해 `Agent`에 연결되어 대화 세션과 사용자 메모리가 자동으로 지속됩니다. 완전한 그래프 체크포인터가 아니라 세션 저장소입니다.

### 분기 질문

모든 비자명한 에이전트는 분기합니다. 누가 분기를 결정하는지가 중요합니다.

- **LangGraph** — 조건부 엣지를 통해 사용자가 결정합니다. 라우팅은 명명된 분기를 가진 Python 함수입니다. 분기는 컴파일된 그래프의 일급 객체이며, 체크포인터는 어떤 분기가 선택되었는지 기록합니다.
- **CrewAI** — 계층 모드에서는 매니저가 결정하고, 순차 모드에서는 빌드 시점에 사용자가 결정합니다. 라우팅은 작업 목록에 내재되어 있으며, 매니저의 프롬프트 외부에는 일급 "if"가 없습니다.
- **AutoGen** — 에이전트가 채팅을 통해 결정합니다. 분기는 누가 다음에 말하는지에서 발생적으로 나타납니다. `GroupChatManager`가 다음 화자를 선택합니다. `speaker_selection_method`를 직접 작성할 수 있지만, 기본값은 LLM 주도입니다.
- **Agno** — 에이전트가 다음에 호출할 도구를 선택하여 결정합니다. 팀에는 코디네이터/라우터/협업자 모드가 있으며, 그 이상의 분기는 개발자의 책임입니다.

### 관측 가능성 질문

- **LangGraph** — LangSmith 또는 모든 OTel 익스포터를 통해 OpenTelemetry를 지원합니다. 모든 노드 전환은 추적 스팬이며, 체크포인트는 재생 가능한 추적으로도 이중 기능합니다. LangSmith는 퍼스트 파티 옵션이며, Langfuse/Phoenix에도 어댑터가 있습니다.
- **CrewAI** — 2025년 후반부터 일급 OpenTelemetry를 지원하며, Langfuse, Phoenix, Opik, AgentOps와 통합됩니다.
- **AutoGen** — `autogen-core`를 통해 OpenTelemetry를 통합합니다. AgentOps와 Opik에 커넥터가 있습니다. 추적 세분화는 노드별이 아니라 에이전트 메시지별입니다.
- **Agno** — 내장 `monitoring=True` 플래그와 OpenTelemetry 익스포터를 지원하며, 세션 추적을 위해 Langfuse와 긴밀하게 통합됩니다.

### 비용 및 지연

네 가지 프레임워크 모두 호출당 오버헤드(프레임워크 로직, 검증, 직렬화)를 추가합니다. 오버헤드가 증가하는 순서는 대략 Agno ≈ LangGraph < CrewAI ≈ AutoGen입니다. 차이는 프레임워크가 얼마나 추가적인 LLM 라우팅을 수행하는지에 의해 결정됩니다. CrewAI의 계층적 매니저는 다음에 누가 실행될지 결정하는 데 토큰을 사용하며, AutoGen의 `GroupChatManager`도 similarly 토큰을 사용합니다. LangGraph는 `llm.invoke`을 작성한 위치에서만 토큰을 사용합니다. Agno의 단일 에이전트 경로는 얇습니다.

실행당 비용이 중요한 경우, LLM이 선택하는 라우팅보다 명시적 라우팅(LangGraph edges, AutoGen `speaker_selection_method`)을 선호하세요.

### 상호 운용성

- **LangGraph** ↔ **LangChain** 도구, 리트리버, LLM. 일급 MCP 어댑터(도구를 MCP 서버로 가져옴).
- **CrewAI** ↔ 도구는 `BaseTool`를 상속합니다. LangChain 도구, LlamaIndex 도구, MCP 도구 모두 적응하여 들어옵니다. Crew 간 위임은 `allow_delegation=True`을 통해 수행됩니다.
- **AutoGen** → `FunctionTool`는 모든 Python 호출 가능한 객체를 래핑합니다. MCP 어댑터를 사용할 수 있습니다. 에이전트 간 패턴은 AG2 생태계와 긴밀하게 결합되어 있습니다.
- **Agno** → `@tool` 데코레이터 또는 BaseTool 하위 클래스. MCP 어댑터. 도구는 에이전트와 팀 간에 공유할 수 있습니다.

## 스킬

> 주어진 에이전트 문제에 특정 프레임워크가 왜 적합한지 한 문장으로 설명할 수 있습니다.

사전 구축 체크리스트:

1. **모양을 그리세요.** 이것은 그래프(타입화된 상태, 명명된 전이)인가요? 역할극(전문가가 작업을 전달)인가요? 채팅(완료될 때까지 에이전트가 대화)인가요? 도구를 가진 단일 에이전트인가요?
2. **누가 분기하는지 결정하세요.** 개발자가 결정하는 분기 → LangGraph. 매니저 에이전트가 결정하는 분기 → CrewAI 계층적. 채팅에서 발생하는 분기 → AutoGen. 도구 호출이 결정하는 분기 → Agno.
3. **상태 예산을 확인하세요.** 체크포인트에서 재개해야 하나요? 시간 여행이 필요하나요? 실행 중 인간 개입이 필요하나요? 그렇다면 LangGraph가 기본입니다. Agno 세션은 대화 범위 상태(state)를 다룹니다.
4. **비용 예산을 확인하세요.** LLM이 선택하는 라우팅은 턴당 추가 토큰이 필요합니다. 에이전트가 하루에 수천 번 실행된다면, 명시적 라우팅을 선호하세요.
5. **프레임워크 오버헤드를 예산에 포함하세요.** 모든 프레임워크는 추가 의존성입니다. 작업이 LLM 호출 두 번과 도구 하나라면, 순수 Python으로 30줄을 작성하세요. 프레임워크가 없는 것보다 저렴한 프레임워크는 없습니다.

그래프, 조직도, 채팅, 에이전트 박스를 그리기 전에 프레임워크를 선택하는 것을 거부하세요. 실제로 필요한 것을 위해 프레임워크의 상태 모델과 싸워야 하는 것을 선택하는 것도 거부하세요.

## 의사 결정 매트릭스

| 문제 형태 | 권장 프레임워크 | 이유 |
|---------------|---------------------|-----|
| 타입이 지정된 상태, 인간 승인, 장기 실행을 포함하는 워크플로우 DAG | LangGraph | 일급 상태, 체크포인터, 인터럽트, 시간 여행 지원. |
| 명확한 역할을 가진 연구/글쓰기 파이프라인 | CrewAI (순차적) 또는 LangGraph 서브그래프 | CrewAI는 역할별 작업 표현이 간단하며, 분기가 복잡해지면 LangGraph로 확장하세요. |
| 제안자-비평가 또는 교사-학생 대화 | AutoGen | 두 에이전트 채팅이 기본 형태입니다. |
| 도구, 세션, 메모리를 가진 단일 에이전트 | Agno | 가장 얇은 설정, 내장 저장소 및 메모리. |
| 리듀서를 사용하는 수천 개의 병렬 팬아웃 | LangGraph + `Send` | 일급 병렬 디스패치 API를 제공하는 유일한 프레임워크입니다. |
| 빠른 프로토타입, 프레임워크 약속 없음 | 순수 Python + 제공자 SDK | 프레임워크가 없는 것이 가장 빠른 프레임워크입니다. |

## 연습 문제

1. **쉬움.** 같은 작업("Anthropic 본사 연구, 200단어 브리프 작성, 출처 인용")을 LangGraph(네 개의 노드: 계획, 검색, 작성, 인용)와 CrewAI(세 개의 역할: 연구자, 작가, 편집자)로 구현하세요. 실행당 토큰 비용과 코드 줄 수를 보고하세요.
2. **중간.** 같은 작업을 AutoGen(연구자 ↔ 작가 채팅, `GroupChat`로 편집자 참여)과 Agno(`search_tools` 및 `write_tools`를 가진 단일 에이전트, 세션 저장소 포함)로 구축하세요. 네 가지 구현을 (a) 실행당 비용, (b) 충돌 후 재개 능력, (c) 작성 단계 전 인간 승인 주입 능력에 대해 순위를 매기세요.
3. **어려움.** 짧은 문제 설명(JSON: `{has_typed_state, has_roles, has_dialogue, has_parallel_fanout, needs_resume}`)을 받아 한 문장 근거와 함께 권장 사항을 반환하는 의사 결정 트리 스크립트 `pick_framework.py`를 구축하세요. 직접 설계한 6가지 사례로 검증하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|-----------------------|
| 오케스트레이션(Orchestration) | "에이전트들이 어떻게 조정하는가" | 다음에 실행할 노드/역할/에이전트를 결정하는 계층. |
| 내구성 있는 상태 | "재시작 후 재개" | 프로세스 종료 후에도 유지되며 체크포인트나 세션 저장소에 연결되는 상태. |
| LLM 선택 라우팅 | "모델이 결정" | 플래너 LLM가 매 턴마다 다음 단계를 선택합니다. 유연하지만 모든 결정에 토큰이 소모됩니다. |
| 명시적 라우팅 | "개발자가 결정" | Python 함수나 정적 엣지가 다음 단계를 선택합니다. 저렴하고 감사(audit)가 가능합니다. |
| Crew | "CrewAI 팀" | 역할 + 작업 + 프로세스(순차적 또는 계층적)가 단일 실행 가능한 형태로 묶여 있습니다. |
| GroupChat | "AutoGen의 다중 에이전트 채팅" | 스피커 선택기를 통해 N개의 에이전트 간에 관리되는 대화입니다. |
| Team (Agno) | "다중 에이전트 Agno" | 에이전트 집합에 대한 라우팅 / 조정 / 협업 모드입니다. |
| StateGraph | "LangGraph의 그래프" | 타입 지정된 상태, 노드, 조건부 엣지, 체크포인터 추상화입니다. |
