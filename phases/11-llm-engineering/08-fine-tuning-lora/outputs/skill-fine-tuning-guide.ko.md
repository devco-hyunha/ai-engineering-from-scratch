# 미세 조정 의사결정 가이드

미세 조정 전에, 아래 순서대로 시도해 보세요:

```
1. Prompt engineering (minutes, $0)
2. Few-shot examples in prompt (minutes, $0)
3. RAG for knowledge retrieval (days, $10-100/month)
4. Fine-tuning with LoRA/QLoRA (days, $5-50 per experiment)
5. Full fine-tuning (weeks, $100-10,000 per run)
```

이전 단계가 측정 가능한 수준으로 불충분한 경우에만 다음 단계로 넘어가세요.

## 미세 조정해야 하는 경우

- 프롬프트로는 달성할 수 없는 일관된 출력 스타일이나 형식이 모델에 필요합니다
- 더 큰 모델의 품질을 증류하고 있습니다 (8B 모델로 GPT-4 품질을 구현)
- 지연 시간이 중요하며, 소수 예시(Few-Shot)가 너무 많은 토큰을 추가합니다
- 모델이 복잡한 추론 패턴을 신뢰성 있게 따르도록 해야 합니다
- 원하는 입력-출력 행동에 대한 고품질 예제가 1,000개 이상 있습니다

## 미세 조정하지 말아야 하는 경우

- 적절한 프롬프트로 모델이 이미 원하는 작업을 수행합니다
- 모델이 사실을 알아야 합니다 (대신 RAG (검색 증강 생성)(RAG (Retrieval-Augmented Generation))를 사용하세요)
- 훈련 예제가 500개 미만입니다 (과적합(Overfitting) 가능성이 높습니다)
- 작업이 자주 변경됩니다 (재훈련 비용이 높습니다)
- 특정 출력에 어떤 데이터가 영향을 미쳤는지 감사해야 합니다 (미세 조정은 블랙박스입니다)

## 방법 선택

| GPU VRAM | 7B 모델 | 13B 모델 | 70B 모델 |
|----------|----------|-----------|-----------|
| 16GB (T4) | QLoRA | 불가능 | 불가능 |
| 24GB (3090/4090) | QLoRA 또는 LoRA | QLoRA | 불가능 |
| 40GB (A100) | LoRA 또는 전체 | QLoRA 또는 LoRA | QLoRA |
| 80GB (A100/H100) | 전체 | LoRA 또는 전체 | QLoRA 또는 LoRA |

## LoRA 구성 체크리스트

1. r=16, alpha=32로 시작하세요 (대부분의 작업에 안전한 기본값)
2. q_proj와 v_proj를 먼저 타겟팅하세요 (최소 실행 가능한 LoRA)
3. QLoRA에는 학습률(Learning Rate) 2e-4, LoRA fp16에는 5e-5를 사용하세요
4. lora_dropout=0.05로 설정하세요
5. 1-3 에포크(Epoch) 동안 훈련하세요 (더 많은 에포크는 과적합(Overfitting) 위험을 높입니다)
6. 보유한 평가 세트(Eval Set)에서 100 스텝마다 평가하세요
7. 체크포인트(Checkpoint)를 저장하고 평가 손실(Loss)이 가장 낮은 것을 선택하세요

## 공통 실수

- 에포크를 너무 많이 훈련하는 것 (소규모 데이터셋에서는 2-3 에포크 이후 과적합 발생)
- 전체 미세 조정과 동일한 학습률을 사용하는 것 (LoRA는 더 높은 학습률이 필요)
- 패딩 토큰 설정을 잊는 것 (Llama 모델에서 NaN 손실 발생)
- 기본 모델을 동결하지 않는 것 (LoRA의 목적에 반함)
- 훈련 데이터에서만 평가하는 것 (항상 10-20%를 평가용으로 남겨 두세요)
- 프롬프트 엔지니어링 기준선을 건너뛰는 것 (프롬프트로 이미 해결되는 문제를 미세 조정하는 것)

## 품질 검증

훈련 후, 200개 이상의 남겨진 예제에서 비교하세요:
1. 최적의 프롬프트를 사용한 기본 모델 (기준선)
2. LoRA 어댑터를 사용한 기본 모델 (미세 조정된 모델)
3. 동일한 프롬프트를 사용한 GPT-4 또는 Claude (상한선)

LoRA 모델이 프롬프트 기준선을 넘지 못한다면, 더 많은 컴퓨팅이 아니라 훈련 데이터나 구성을 개선해야 합니다.

## 어댑터 관리

- 다중 작업 서빙을 위해 어댑터를 분리하여 유지하세요 (요청마다 어댑터를 교체)
- 단일 작업 배포를 위해 어댑터를 기본 가중치에 병합하세요
- 어댑터를 Hugging Face Hub에 저장하세요 (10-100MB, 버전 관리 및 공유가 쉬움)
- 배포 전에 병합된 모델의 출력이 병합되지 않은 출력과 일치하는지 테스트하세요
- TIES-Merging 또는 DARE를 사용하여 여러 어댑터를 하나로 결합하세요

## 훈련 디버깅

손실이 감소하지 않는다면:
1. 학습률을 확인하세요 (LoRA에는 너무 낮을 수 있으며, 2e-4를 시도해 보세요)
2. LoRA 레이어가 실제로 기울기를 받고 있는지 확인하세요
3. 기본 모델 가중치가 동결되어 있는지 확인하세요
4. 데이터 형식을 확인하세요 (토크나이저가 모델의 예상 형식과 일치해야 함)

손실이 감소하지만 평가 품질이 나쁘다면:
1. 훈련 데이터 품질 문제 (쓰레기 입력, 쓰레기 출력)
2. 과적합 (에포크를 줄이고, 드롭아웃을 늘리고, 더 많은 데이터를 추가하세요)
3. 잘못된 대상 모듈 (복잡한 작업의 경우 MLP 레이어를 추가하세요)
4. 랭크가 너무 낮음 (r=32 또는 r=64를 시도해 보세요)
