# 함수 호출 패턴

도구를 사용하는 LLM (대규모 언어 모델) 애플리케이션을 구축할 때, 이 의사결정 프레임워크를 적용해 보세요.

## 함수 호출을 사용해야 하는 경우

**함수 호출을 사용해야 하는 경우:**
- 모델이 실시간 데이터(날씨, 주식 가격, 데이터베이스 쿼리)를 필요로 할 때
- 작업이 사이드 이펙트(이메일 전송, 레코드 생성, 코드 배포)를 요구할 때
- 모델이 사용자 의도에 따라 여러 행동 중 하나를 선택해야 할 때
- 외부 시스템과 상호작용하는 에이전트(Agent)를 구축하고 있을 때

**대신 구조화된 출력(Structured Output)을 사용해야 하는 경우:**
- 텍스트에서 데이터를 추출해야 할 때(외부 호출이 필요하지 않음)
- 출력이 최종 산출물이며, 중간 단계가 아닐 때
- 선택할 수 있는 여러 도구가 아닌 단일 스키마만 있을 때

**둘 다 사용해야 하는 경우:**
- 모델이 도구를 호출한 후, 도구 결과를 특정 출력 형식으로 구조화해야 할 때

## 도구 설계 지침

1. **하나의 도구, 하나의 행동.** 쿼리, 삽입, 업데이트 및 삭제를 모두 처리하는 `manage_database`이라는 이름의 도구는 너무 광범위합니다. `query_records`, `insert_record`, `update_record`로 분리하세요. 모델은 구체적인 도구를 사용할 때 더 잘 선택합니다.

2. **설명문은 프롬프트입니다.** 모델은 도구 설명문을 읽어 선택을 결정합니다. 주니어 개발자를 위한 지침을 작성하듯이 설명문을 작성하세요. 도구가 무엇을 하는지뿐만 아니라 무엇을 반환하는지도 포함하세요.

3. **열거형으로 제한하세요.** 매개변수(Parameter)에 유효한 값이 3~10개라면 열거형(enum)을 사용하세요. 제한하지 않으면 모델은 "celsius", "Celsius", "C", "metric" 같은 문자열을 만들어낼 것입니다.

4. **도구가 적을수록 좋습니다.** GPT-4o는 5~10개의 도구를 잘 처리합니다. 20개 이상의 도구에서는 선택 정확도가 떨어집니다. 50개 이상의 도구에서는 10~15%의 잘못된 도구 선택이 발생할 것으로 예상하세요. 관련 기능을 그룹화하거나 라우팅 계층을 사용하세요.

5. **필수(required)는 필수입니다.** 도구가 필수 파라미터 없이 작동할 수 없는 경우에만 필수로 표시하세요. 좋은 기본값을 가진 선택 파라미터는 도구 호출 실패를 줄여줍니다.

## 제공자별 패턴

### OpenAI (GPT-4o, o3, GPT-4o-mini)

```python
tools=[{"type": "function", "function": {"name": ..., "parameters": ...}}]
tool_choice="auto"       # 모델이 결정
tool_choice="required"   # 최소 한 개의 도구를 호출해야 함
tool_choice={"type": "function", "function": {"name": "specific_tool"}}
```

- 병렬 도구 호출 지원 (하나의 응답에 `tool_calls` 여러 개 포함)
- 도구 호출 ID는 결과와 함께 전달해야 함
- `gpt-4o-mini`는 10배 저렴하며 단순한 도구 라우팅을 잘 처리합니다
- 구조화된 출력 모드(structured outputs mode)는 도구 파라미터와 함께 작동하여 스키마 준수를 보장합니다

### Anthropic (Claude 3.5 Sonnet, Claude 4 Opus)

```python
tools=[{"name": ..., "description": ..., "input_schema": ...}]
tool_choice={"type": "auto"}     # 모델이 결정
tool_choice={"type": "any"}      # 최소 한 개의 도구를 호출해야 함
tool_choice={"type": "tool", "name": "specific_tool"}
```

- 도구 호출은 `type: "tool_use"`를 가진 콘텐츠 블록으로 나타납니다
- 결과는 `type: "tool_result"`를 가진 사용자 메시지에 포함됩니다
- 필드 이름은 `input_schema`이며 `parameters`가 아닙니다 (흔한 마이그레이션 버그)
- 응답당 여러 도구 호출 지원

### Google (Gemini 2.0 Flash, Gemini 2.0 Pro)

```python
function_declarations=[{"name": ..., "description": ..., "parameters": ...}]
function_calling_config={"mode": "AUTO"}   # 또는 "ANY" 또는 "NONE"
```

- 최상위 레벨에서 `function_declarations`를 사용
- 결과는 `function_response` 파트를 통해 반환
- 병렬 함수 호출 지원

### 오픈 소스 모델 (Llama 3, Hermes, Qwen)

- 표준화된 형식 없음 -- 모델 및 서빙 프레임워크에 따라 다름
- Hermes 형식(NousResearch)이 가장 일반적인 미세 조정(fine-tuned) 관례입니다
- vLLM은 지원되는 모델에 대해 OpenAI 호환 도구 호출을 지원합니다
- Ollama는 호환되는 모델에 대해 기본 도구 호출을 지원합니다
- 프로덕션 전에 도구 선택 정확도를 테스트하세요 -- Berkeley Function Calling Leaderboard 기준 오픈 모델은 GPT-4o보다 정확도가 15-30% 낮습니다

## 오류 처리 패턴

### 구조화된 오류 반환

```json
{"error": true, "message": "City 'Toky' not found. Did you mean 'Tokyo'?", "code": "NOT_FOUND", "suggestions": ["Tokyo"]}
```

실행 가능한 정보를 포함하세요. "Not found"는 좋지 않습니다. "Not found, did you mean X?"는 좋습니다. 모델은 오류 메시지를 사용하여 스스로 수정합니다.

### 재시도 전략

1. 도구 호출이 수정 가능한 오류(오타, 잘못된 enum 값)로 실패
2. 오류를 도구 결과로 모델에 전달하세요
3. 모델이 조정하고 재시도합니다
4. 도구 호출당 최대 3회 재시도
5. 3회 실패 후 오류를 사용자에게 반환하세요

### 타임아웃 처리

모든 도구 실행에 타임아웃을 설정하세요. 30초가 합리적인 기본값입니다. 도구가 타임아웃되면 모델이 사용자에게 알릴 수 있도록 구조화된 타임아웃 오류를 반환하여, 시스템이 멈추지 않도록 하세요.

## 보안 체크리스트

| 점검 항목 | 이유 | 방법 |
|-------|-----|-----|
| 함수 허용 목록 | 임의 코드 실행 방지 | 사용자가 필요한 도구만 등록하세요 |
| 인자 타입 검증 | 타입 혼동 공격 방지 | 실행 전 타입을 확인하세요 |
| 문자열 인자 정제 | 인젝션 방지 | 특수 문자를 거부하거나 이스케이프하세요 |
| 데이터베이스 쿼리 파라미터화 | SQL 인젝션 방지 | 모델이 생성한 SQL을 직접 전달하지 마세요 |
| 도구 결과 필터링 | 데이터 유출 방지 | API 키, PII, 내부 오류를 제거하세요 |
| 도구 호출 속도 제한 | 무한 루프 방지 | 대화당 최대 10-20회 호출 |
| 모든 도구 호출 로깅 | 감사 추적 | 도구 이름, 인자, 결과, 타임스탬프를 저장하세요 |
| 경로 순회 차단 | 파일 시스템 접근 방지 | 파일 도구에서 `..` 및 절대 경로를 거부하세요 |
| 코드 실행 샌드박스 | 시스템 접근 방지 | 컨테이너나 제한된 내장 함수를 사용하세요 |
| 반환 크기 검증 | 컨텍스트 채우기 방지 | 10KB를 초과하는 결과를 잘라내세요 |

## 성능 최적화

- **병렬 호출:** 모델이 여러 독립적인 도구를 요청할 경우, `asyncio.gather()` 또는 `concurrent.futures`를 사용하여 동시 실행하세요
- **캐싱:** 동일 세션에서 동일한 인자에 대한 도구 결과를 캐싱하세요 (날씨는 60초 동안 변하지 않습니다)
- **스트리밍:** 도구 결과가 가져오는 동안 모델의 최종 응답을 스트리밍하세요
- **도구 가지치기:** 컨텍스트가 제한적인 경우, 현재 쿼리와 관련된 도구 정의만 포함하세요 (분류기를 사용하여 필터링)
- **라우팅용 소형 모델:** 도구 선택에는 `gpt-4o-mini` 또는 `claude-haiku-4-5`를 사용하고, 결과를 더 강력한 모델에 전달하여 종합하세요

## 공통 실패 패턴

| 실패 | 원인 | 해결 |
|---------|-------|-----|
| 잘못된 도구 선택 | 모호한 설명 | 특정 트리거 단어를 사용하여 설명을 재작성 |
| 필수 인자 누락 | 모델이 매개변수를 잊음 | 매개변수 설명에 명확한 예시 추가 |
| 무한 도구 루프 | 모델이 동일한 도구를 계속 호출 | 최대 반복 횟수 설정 (5-10) 및 반복 호출 감지 |
| 환각된 인자 | 모델이 그럴듯하지만 잘못된 값을 생성 | 열거형 사용, 알려진 값에 대해 검증 |
| 도구 결과가 너무 큼 | API가 100KB의 데이터를 반환 | 피드백하기 전에 잘라내거나 요약 |
| 모델이 도구 결과를 무시 | 결과 형식이 혼란스러움 | 명확한 필드 이름을 가진 깔끔한 JSON 반환 |
