# 컨텍스트 엔지니어링(Context Engineering)

LLM (대규모 언어 모델)(LLM (Large Language Model)) 애플리케이션을 구축할 때, 이 프레임워크를 적용하여 컨텍스트 조립 파이프라인을 설계해 보세요.

## 핵심 원칙

1. **컨텍스트는 희소합니다.** 128K 윈도우는 커 보이지만 금방 채워집니다. 모든 구성 요소를 명시적으로 예산화하세요.
2. **어텐션(Attention)은 고르지 않습니다.** 모델은 시작과 끝에 더 집중합니다. 중요한 정보를 그곳에 배치하세요. 중간은 죽은 구역입니다.
3. **동적 방식이 정적 방식보다 낫습니다.** 쿼리마다 다른 컨텍스트가 필요합니다. 시작 시 한 번이 아니라 쿼리별로 조립하세요.
4. **적은 것이 더 많습니다.** 선별된 10K 컨텍스트는 무분별하게 덤프된 100K 컨텍스트보다 성능이 좋습니다. 총 정보량보다 신호 대 잡음비가 더 중요합니다.
5. **모든 것을 측정하세요.** 측정하지 않은 것은 최적화할 수 없습니다. 모든 요청에서 구성 요소별 토큰(Token) 수를 세세요.

## 컨텍스트 예산 가이드라인

| 구성 요소 | 일반적인 범위 | 우선순위 | 압축 전략 |
|-----------|-------------|----------|---------------------|
| 시스템 프롬프트(System Prompt) | 200-1,000 토큰 | 고정, 높음 | 간결하게 작성하고 중복 제거 |
| 도구 정의 | 500-3,000 토큰 | 동적, 중간 | 쿼리 의도에 따라 가지치기 |
| 검색된 컨텍스트 | 1,000-5,000 토큰 | 동적, 높음 | 리랭킹(Reranking) + 임계값 + 중복 제거 |
| 대화 기록 | 500-5,000 토큰 | 동적, 중간 | 이전 턴 요약 |
| 소수 예시(Few-Shot) 예제 | 500-2,000 토큰 | 동적, 높음 | 작업 유사성에 따라 선택 |
| 사용자 쿼리 | 50-500 토큰 | 고정, 최상 | N/A |
| 생성 예약 | 2,000-8,000 토큰 | 고정 | 예상 출력 길이에 따라 조정 |

## 각 메모리 유형 사용 시점

**단기 (대화 기록):** 현재 세션입니다. 요약으로 관리합니다. 5-10 교환 이상 오래된 턴은 압축하세요. 마지막 3-4 턴은 원문 그대로 유지하세요.

**장기 (사실 데이터베이스):** 세션을 넘어 지속되는 선호도와 프로젝트 사실. 세션 시작 시 검색합니다. 예: "사용자는 Python을 선호", "프로젝트는 PostgreSQL을 사용", "팀은 trunk-based 개발을 따름". CLAUDE.md, 데이터베이스, 또는 구조화된 메모리 시스템에 저장합니다.

**일화 (과거 상호작용):** 현재 작업과 관련된 특정 과거 대화. 임베딩으로 저장하고 유사성으로 검색합니다. "지난 주에 유사한 인증 문제를 디버깅했다"는 일화 기억입니다.

## 도구 선택 전략

모든 요청에 모든 도구를 포함하지 마세요. 이는 토큰을 낭비하고 모델을 혼란스럽게 합니다.

1. 쿼리 의도 분류 (코드, 이메일, 캘린더, 연구, 데이터)
2. 의도를 도구 카테고리에 매핑
3. 매칭되는 도구만 포함
4. 의도가 모호하면 상위 2개 카테고리의 도구를 포함
5. 폴백으로 "일반" 도구 (웹 검색 등)를 항상 포함

예상 절감 효과: 명확한 의도를 가진 쿼리에서 도구 정의 토큰의 60-80%를 절감합니다.

## 검색 모범 사례

- **검색 후 리랭킹.** 벡터 유사성은 거친 필터입니다. 리랭커 (크로스 인코더 또는 LLM 기반)는 정밀도를 크게 개선합니다.
- **관련성 임계값 설정.** 코사인 유사도가 0.3 미만인 청크는 포함하지 마세요. 이는 잡음을 추가합니다.
- **중복 제거.** 두 청크가 80% 이상의 내용을 공유하면 점수가 높은 것만 유지하세요.
- **lost-in-the-middle 순서 적용.** 가장 관련성 높은 청크를 처음과 끝에 배치하세요.
- **총 검색 토큰 제한.** 15개의 평범한 청크보다 3-5개의 고도로 관련성 높은 청크가 더 좋습니다.

## 이력 관리

- 마지막 3-4 턴을 원문 그대로 유지 (모델은 최근 컨텍스트가 필요)
- 이전 턴을 요약하여 다이제스트로 변환 ("X를 논의하고, Y를 결정했으며, Z에서 차단됨")
- 정보를 추가하지 않는 시스템 생성 턴 제거 (사용자-facing 콘텐츠가 없는 도구 호출)
- 이력이 가용 예산의 30%를 초과하면 압축 트리거

## 적신호

- 시스템 프롬프트가 2,000 토큰 초과: 동적이어야 할 정보가 포함된 가능성
- 모든 요청에 모든 도구가 포함됨: 의도 기반 선택을 구현하세요
- 검색에 관련성 필터링이 없음: 노이즈를 컨텍스트 윈도우에 쏟아붓고 있습니다
- 이력(히스토리)이 무한히 증가: 요약이 구현되지 않았습니다
- 생성 예약 공간이 없음: 모델이 응답을 잘라냅니다
- 동일한 정보가 3곳(시스템 프롬프트, 검색된 문서, 이력)에 있음: 중복을 제거하세요
- 컨텍스트 활용률이 60% 초과: 모델이 "생각"할 공간이 너무 적습니다
