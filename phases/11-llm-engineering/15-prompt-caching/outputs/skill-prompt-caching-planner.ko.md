프롬프트(시스템 + 도구 + 소수 예시 + 검색 + 기록 + 사용자)와 사용 프로필(시간당 요청 수, 필요한 TTL, 제공자)이 주어지면 다음을 출력합니다:

1. 레이아웃. 단일 캐시 분기점이 표시된 섹션 순서 재배열; 어떤 섹션이 안정적이고 어떤 섹션이 변동적인지 설명합니다.
2. 제공자 모드. Anthropic cache_control, OpenAI 자동, 또는 Gemini CachedContent. TTL 및 재사용 패턴에 근거하여 정당화합니다.
3. 손익분기점. TTL 내의 쓰기당 예상 읽기 수; 캐시 미사용 대비 순 비용과 계산.
4. 검증 계획. 두 번째 동일한 요청에서 cache_read_input_tokens > 0임을 보장하는 CI 단정; 캐시된 토큰과 캐시되지 않은 토큰으로 대시보드를 분리합니다.
5. 실패 모드. 이 설정에서 캐시가 미스될 가능성이 가장 높은 세 가지 이유(동적 타임스탬프, 도구 순서 변경, 유사 중복 텍스트)를 나열하고 각각을 방지하는 방법을 설명합니다.

동적 필드가 분기점 위에 배치된 캐시 계획을 출시하는 것을 거부합니다. 2배 쓰기 프리미엄을 회수할 재사용 수 없이 1h TTL을 활성화하는 것을 거부합니다.
