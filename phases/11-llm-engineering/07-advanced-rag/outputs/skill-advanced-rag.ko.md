# 고급 RAG 패턴

기본 RAG: 쿼리 임베딩 -> 벡터 검색 -> top-k -> 생성.
고급 RAG: 쿼리 임베딩 + BM25 -> 랭킹 융합 -> 리랭킹 -> top-k -> 생성.

```
query -> [vector search (top-50)] -+-> RRF fusion -> reranker (top-5) -> prompt -> LLM
                                   |
query -> [BM25 search (top-50)]  --+
```

## 기본 RAG에서 업그레이드해야 하는 시점

- 검색 품질이 Recall@5 70% 미만으로 떨어질 때
- 사용자가 부정확하거나 관련 없는 답변을 보고할 때
- 코퍼pus가 10만 개 청크를 초과할 때
- 쿼리가 문서와 다른 어휘를 사용할 때
- 다중 홉(multi-hop) 질문이 일관되게 실패할 때

## 구현 체크리스트

1. 벡터 인덱스 옆에 BM25 인덱스를 추가하세요
2. 두 검색을 병렬로 실행하세요 (각각 top-50)
3. 상호 랭킹 융합 (RRF)(Reciprocal Rank Fusion)으로 병합하세요 (k=60)
4. 크로스 인코더로 상위 후보를 리랭킹하세요
5. 최종 프롬프트에 top-5를 사용하세요
6. 테스트 세트에 충실성(faithfulness) 평가를 추가하세요

## 기법 선택 가이드

- **하이브리드 검색**: 프로덕션에서는 항상 사용하세요. 쿼리 시간에는 추가 비용이 들지 않습니다.
- **리랭킹**: Recall@50은 좋지만 Recall@5가 나쁜 경우 사용하세요. 50-200ms 지연이 추가됩니다.
- **HyDE**: 쿼리가 모호하거나 문서와 다른 어휘를 사용하는 경우 사용하세요. LLM 호출이 한 번 추가됩니다.
- **부모-자식 청크**: 작은 청크가 컨텍스트를 결여하고 큰 청크가 관련성을 희석하는 경우 사용하세요.
- **메타데이터 필터링**: 코퍼pus에 명확한 카테고리(날짜, 소스 유형, 부서)가 있는 경우 사용하세요.
- **쿼리 분해**: 여러 문서의 정보가 필요한 다중 홉 질문에 사용하세요.

## 공통 실수

- BM25와 벡터 검색을 서로 다른 청크 세트에서 실행하는 것 (동일한 코퍼pus를 검색해야 합니다)
- 리랭킹을 위해 너무 작은 후보 풀을 사용하는 것 (top-10은 너무 적습니다; top-50을 사용하세요)
- 모든 쿼리에 HyDE를 추가하는 것 (어휘 불일치가 병목인 경우에만 도움이 됩니다)
- 변화를 평가하지 않는 것 (각 기법 적용 전후에 Recall@k를 측정하세요)
- 실패 지점을 측정하기 전에 파이프라인을 과잉 설계하는 것

## 평가 워크플로

1. 알려진 답변 청크를 가진 50개 이상의 테스트 질문을 생성해 보세요
2. 각 검색 방법에 대해 Recall@5와 Recall@10을 측정해 보세요
3. 검색이 성공한 쿼리에 대해 생성된 답변의 충실도를 측정해 보세요
4. 코퍼스가 확장됨에 따라 주간 단위로 지표를 추적해 보세요
5. 추가 기법을 도입하기 전에 개별 실패 사례를 조사해 보세요
