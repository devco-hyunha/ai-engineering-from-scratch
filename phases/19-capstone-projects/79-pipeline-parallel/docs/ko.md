# 파이프라인 병렬화 및 버블 분석

> 텐서 병렬화(Tensor Parallelism)는 행렬 곱을 랭크(ranks) 간에 분할합니다. 파이프라인 병렬화(Pipeline Parallelism)는 모델을 랭크 간에 분할하며, 각 랭크에 하나의 스테이지(stage)를 배치합니다. 마이크로배치(microbatches)는 파이프라인을 통해 흐릅니다. 시작과 끝에 있는 빈 시간은 버블(bubble)이며, 이를 최소화하는 것이 전체 기술의 핵심입니다.

**유형:** Build
**언어:** Python
**선수 요건:** 19단계 C트랙 42-49강
**시간:** 약 90분

## 학습 목표

- 순차적 모델을 N개의 스테이지로 분할하고 N개의 랭크에 걸쳐 순방향 파이프라인을 시뮬레이션해 보세요.
- GPipe 스케줄(순방향 채우기, 이후 역방향)을 사용하여 M개의 마이크로배치를 파이프라인에 스케줄링하고 버블 비율을 계산해 보세요.
- Megatron-LM 및 PipeDream에서 사용되는 인터리브드(interleaved) 1F1B 스케줄과 버블을 비교해 보세요.
- 스테이지 할당을 방어하세요: 스테이지당 동일한 연산량이 스테이지당 동일한 매개변수 수보다 더 중요합니다.

## 문제점

700억 매개변수 모델은 fp16에서 매개변수만으로도 140 GB가 필요합니다. 소비자용 GPU는 이를 수용할 수 없습니다. ZeRO-3는 매개변수를 랭크 간에 샤딩(sharding)하지만, 각 순방향 단계마다 전체 레이어를 allgather하기 위해 모든 랭크가 필요하며, 레이어당 log(N) 횟수의 홉(hops)을 지불합니다. 파이프라인 병렬화는 다른 경로를 취합니다: 모델을 N개의 스테이지로 잘라 각 랭크에 하나의 스테이지를 배치합니다. 레이어 1의 순방향 연산은 랭크 0에서 완료되고 활성화 텐서(activation tensor)를 랭크 1에 전달합니다; 랭크 1은 레이어 2를 실행하고 랭크 2에 전달합니다; 이런 식으로 계속됩니다. 역방향은 반대 방향으로 흐릅니다. 각 랭크는 하나의 스테이지만 보유하므로 메모리가 선형적으로 감소합니다; 연산은 순차적이며, 이것이 버블 문제입니다.

버블은 파이프라인 시작 시의 유휴 시간(첫 번째 마이크로배치가 마지막 스테이지에 도달할 때까지 대기)과 끝 시의 유휴 시간(마지막 마이크로배치가 역방향으로 배수될 때까지 대기)입니다. M개의 마이크로배치와 N개의 스테이지가 있을 때 스테이지당 버블 비율은 (N-1)/(M+N-1)입니다. M=8, N=4일 때 이는 27%입니다. M=64, N=4일 때는 4.5%입니다. 단계당 마이크로배치가 많을수록 버블은 줄어들며, 이는 마이크로배치당 배치 크기가 작음을 의미하며, 마이크로배치 설계를 주도하는 제약 조건입니다.

## 개념

```mermaid
flowchart LR
  R0["랭크 0: 스테이지 0 / 레이어 0"] --> R1["랭크 1: 스테이지 1 / 레이어 1"]
  R1 --> R2["랭크 2: 스테이지 2 / 레이어 2"]
  R2 --> R3["랭크 3: 스테이지 3 / 손실(loss)"]
  R3 -.backward.-> R2
  R2 -.backward.-> R1
  R1 -.backward.-> R0
```

### GPipe 스케줄

모든 M개의 마이크로배치를 사용하여 파이프라인의 순방향(Foward)을 모두 채운 후, 역방향(Backward)을 시작하고 역순으로 처리합니다. 모든 마이크로배치의 활성화 값은 역방향 처리까지 유지해야 하므로, 메모리는 M에 비례하여 선형적으로 증가합니다. 순방향은 M+N-1 사이클이 소요되며, 역방향도 M+N-1 사이클이 소요됩니다. 각 스테이지의 유용한 작업은 2M 사이클이며, 각 스테이지의 버블은 2(N-1) 사이클입니다. 순방향과 역방향 각각이 1 단위 시간을 소요할 때, 버블 비율은 (N-1)/(M+N-1)입니다. M을 N보다 훨씬 크게 선택하면 버블을 숨길 수 있습니다.

### 1F1B 스케줄

교차 실행: 마이크로배치의 순방향 처리가 마지막 스테이지에 도달하면 즉시 역방향 처리를 시작하여 역순으로 스트리밍합니다. 각 스테이지는 순방향과 역방향을 하나씩 교대로 수행합니다. 버블은 여전히 N-1이지만, 활성화 메모리는 마이크로배치 개수가 아닌 파이프라인 깊이에 의해 제한됩니다. 프로덕션 파이프라인은 1F1B(Megatron, PipeDream)을 사용합니다. 이 강의에서는 GPipe가 더 단순하므로 먼저 구현하고, 1F1B는 연습 문제로 다룹니다.

### 스테이지별 연산량이 동일해야 하는 이유

스테이지 0이 50ms, 스테이지 1이 100ms를 소요한다면, 모든 사이클은 스테이지 1에 의해 결정됩니다. 다른 스테이지들은 스테이지 1이 완료될 때까지 매 사이클마다 50ms 동안 유휴 상태로 대기합니다. 매개변수 개수를 동일하게 맞추는 것은 잘못된 기준입니다. 트랜스포머의 연산량은 각 레이어의 어텐션과 MLP에 의해 지배되며, 임베딩 레이어는 매개변수가 많지만 연산량은 적습니다. 스테이지 할당은 스테이지별 가중치가 아닌 스테이지별 FLOPs를 균등하게 맞춰야 합니다.

### 마이크로배치와 배치의 차이

파이프라인은 각각 크기 B인 M개의 마이크로배치를 실행합니다. 유효 배치 크기는 M*B입니다. 파이프라인 스텝이 끝날 때의 기울기는 결합된 M*B개 샘플에 대한 기울기입니다. 버블 비율은 M에 의존하며, 옵티마이저는 M*B를 봅니다. M을 조정하는 것은 버블(M이 클수록 낮아짐)과 마이크로배치별 메모리(GPipe의 경우 M이 클수록 활성화 메모리가 높아짐) 사이의 트레이드오프입니다.

## 구현하기

`code/main.py`는 다음을 구현합니다:

- `PipelineStage`: 하나의 스테이지 매개변수를 저장하고 `forward(activation)`를 노출하는 작은 `nn.Module`입니다.
- `Pipeline(stages, num_microbatches)`: 스테이지별 시뮬레이션된 벽시계 시간을 사용하여 시뮬레이션된 스테이지에서 GPipe 스케줄을 오케스트레이션합니다.
- `bubble_fraction(num_stages, num_microbatches)`: 폐형식 (N-1)/(M+N-1)입니다.
- 마이크로배치별 추적과 측정된 버블 비율을 출력하는 4스테이지 데모입니다.

실행해 보세요:

```bash
python3 code/main.py
```

출력: 단계별 마이크로배치 간트 차트와 폐형 예측에 대한 버블 비율입니다.

## 실전에서의 프로덕션 패턴

세 가지 패턴이 파이프라인을 충분히 견고하게 만들어 출시할 수 있습니다.

**활성화 체크포인팅(Activation Checkpointing)은 파이프라인과 짝을 이룹니다.** GPipe에서 M개의 마이크로배치가 처리 중일 때, 활성화 메모리는 마이크로배치 하나의 M배입니다. 활성화 체크포인팅은 역전파 시 순전파를 재계산하여 연산량을 메모리와 교환합니다; 이 조합이 긴 시퀀스에 대해 파이프라인을 관리 가능하게 만듭니다.

**단계 균형은 측정된 것이지, 가정된 것이 아닙니다.** 프로덕션 팀은 대상 하드웨어에서 실제 레이어별 연산량(FLOPs 및 벽시계 시간)을 측정하는 프로파일링 패스를 실행한 후, 그 측정값에 따라 분할합니다. Megatron-LM `--num-layers-per-stage` 플래그는 단계별 레이어별 비용이 다를 때 불균등한 레이어 수를 허용하기 위해 목록을 받습니다.

**송수신(send-recv) 스케줄은 데드락을 피해야 합니다.** 모든 단계가 수신보다 먼저 전송하는 파이프라인은 네트워크에서 데드락에 빠집니다. 표준적인 해결책은 교대하는 것입니다: 짝수 랭크(rank) 단계는 먼저 전송한 후 수신하고, 홀수 랭크 단계는 먼저 수신한 후 전송합니다. 이 강의는 랭크를 명시적으로 스케줄링하여 패턴을 명확히 보여줍니다.

## 사용하기

프로덕션 패턴:

- **Megatron-LM.** 대규모 파이프라인 병렬화의 참조 구현입니다. 1F1B를 사용하며 텐서 + 파이프라인 + 데이터 병렬화를 결합하여 지원합니다.
- **DeepSpeed Pipeline.** ZeRO와 통합됩니다; ZeRO-1 + 파이프라인은 가장 큰 오픈 모델에 공통적으로 사용되는 조합입니다.
- **PyTorch Pipe.** `torch.distributed.pipeline.sync.Pipe` 위에 구축된 PyTorch 네이티브 파이프라인 래퍼입니다.

## 연습 문제

1. 1F1B를 구현하고 버블 비율이 GPipe와 일치하지만 활성화 메모리가 제한됨을 확인하세요.
2. 더 깊은 모델에서 실제 단계별 시간을 프로파일링하고 측정된 벽시계 시간에 따라 단계를 재균형하세요.
3. 파이프라인 마이크로배치 전체에 걸쳐 기울기 누적(Gradient Accumulation)을 추가하고, 기울기가 동등한 전체 배치 순전파의 기울기와 같음을 확인하세요.
4. 파이프라인에 활성화 체크포인팅(Activation Checkpointing)을 결합하여 메모리 감소량과 연산 비용을 측정해 보세요.
5. 파이프라인을 DDP와 결합하고(각 파이프라인 랭크는 데이터 병렬 그룹 내에서 복제됨) 2D 스케줄을 추론해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 파이프라인 | "깊이 방향의 모델 병렬화" | 랭크당 하나의 스테이지, 활성화가 스테이지 간에 흐름 |
| 버블 | "파이프라인 유휴 시간" | 시작과 끝에 (N-1) 단계가 있으며 일부 스테이지는 작업이 없음 |
| 마이크로배치 | "배치의 조각" | 하나의 순방향/역방향 단위; M이 증가하면 버블이 축소됨 |
| GPipe | "채우고 비우기" | 모든 M 순방향 연산이 역방향 연산보다 먼저 수행됨; 활성화 메모리 사용량이 높음 |
| 1F1B | "교대 스케줄" | 스테이지당 순방향 하나, 역방향 하나; 활성화 메모리가 제한됨 |
