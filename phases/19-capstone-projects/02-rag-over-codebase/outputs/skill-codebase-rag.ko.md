총 200만 줄 이상의 코드를 포함하는 10개 이상의 저장소가 주어졌을 때, ingestion 파이프라인, 하이브리드 인덱스, 그리고 검증 가능한 file:line 앵커로 저장소 간 질문에 답변하는 인용 강제 쿼리 에이전트를 구축해 보세요.

구축 계획:

1. tree-sitter로 모든 파일을 파싱합니다. 함수 및 클래스 노드 경계에서 청킹합니다. `{repo, path, start_line, end_line, symbol, body}`를 저장합니다.
2. 프롬프트 캐시된 시스템 프롬프트를 사용하여 Claude Haiku 4.5 또는 Gemini 2.5 Flash로 모든 청크를 요약합니다. 한 문장 요약을 청크 옆에 저장합니다.
3. 세 가지 구조에 인덱싱합니다: Qdrant (밀집, Voyage-code-3 또는 nomic-embed-code), Tantivy (필드 가중치가 있는 BM25), kuzu (import, call, 상속을 위한 심볼 그래프 엣지).
4. 세 가지 노드를 가진 LangGraph 쿼리 에이전트를 구축합니다: retrieve (밀집 병렬 BM25), rerank (Cohere rerank-3 또는 bge-reranker-v2-gemma-2b), synth (프롬프트 캐싱 및 file:line 인용 요구 사항이 있는 Claude Sonnet 4.7).
5. 사후 필터링: 검증 가능한 `(repo/path:start-end)` 앵커가 없는 주장은 거부합니다. 재질문하거나 삭제합니다.
6. 심볼 수준 diff를 계산하고 변경된 청크만 재임베딩하는 git push 웹훅을 연결합니다. 목표: 200만 LOC 함대에서 50개 파일 커밋을 60초 이내에 검색 가능하게 하는 것.
7. 100개 질문의 홀드아웃 세트(held-out set)로 평가합니다. MRR@10, nDCG@10, 인용 충실도(citation faithfulness), 지연 시간 백분위수를 보고합니다.
8. 평가를 재실행하고 MRR@10 감소가 5% 이상일 때 알림을 보내는 주간 드리프트(drift) 작업을 실행합니다.

평가 루브릭:

| 가중치 | 기준 | 측정 |
|:-:|---|---|
| 25 | 검색 품질 | 100개 질문 홀드아웃 세트에서의 MRR@10 및 nDCG@10 |
| 20 | 인용 충실도 | 검증 가능한 file:line 앵커가 있는 답변 주장의 비율 |
| 20 | 지연 시간 및 규모 | 인덱싱된 코퍼스 크기에서 10k QPS의 p95 쿼리 지연 시간 |
| 20 | 증분 인덱싱 정확성 | 50개 파일 커밋의 git push부터 검색 가능 상태까지의 시간 |
| 15 | UX 및 답변 형식 | 인용 클릭 가능성, 스니펫 미리보기, 후속 조치 제공 |

하드 거부:

- AST 인식 청킹 대신 고정 크기 토큰 청킹. 생성된 코드가 많은 코퍼스를 오염시킵니다.
- BM25나 리랭커 없이 코사인 유사도만 사용하는 검색. 정확한 심볼 이름 쿼리에서 실패하는 것으로 알려져 있습니다.
- 필수적인 file:line 인용이 없는 답변.
- git push마다 전체 코퍼스를 재임베딩하는 것; 점진적으로 처리해야 합니다.

거부 규칙:

- 라이선스를 읽지 않은 저장소를 인덱싱하는 것을 거부합니다. 일부는 서드파티 벡터 스토어에 임베딩하는 것을 금지합니다.
- 인덱스가 본 적 없는 파일을 인용한다고 주장하는 쿼리에 답변하는 것을 거부합니다; 반환하기 전에 항상 앵커를 검증합니다.
- p95가 4초 이상인 답변을 제공하는 것을 거부합니다; 대신 후속 처리 핸들과 함께 부분적인 결과를 반환합니다.

출력: 인제스트 파이프라인, LangGraph 쿼리 에이전트, 100개 질문이 라벨링된 평가 세트, Langfuse 대시보드 링크, 그리고 세 가지 검색 실패 모드(생성된 코드 오염, 롱테일 심볼 리콜, 저장소 간 심볼 해석)와 각각을 수정한 정확한 변경 사항을 명시한 문서가 포함된 저장소입니다.
