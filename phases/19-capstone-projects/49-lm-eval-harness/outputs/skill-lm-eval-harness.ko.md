## 언제 사용해야 하는가

고정된 작업 세트에 대해 두 모델, 두 체크포인트, 또는 두 프롬프트 템플릿을 비교할 때 사용하세요. 출시된 모든 것과 시간이 지남에 따라 모니터링해야 하는 모든 것에 적용됩니다.

## 작업 사양

예제당 한 줄의 JSONL 형식입니다:

```json
{"id": "ex-001", "prompt": "...", "targets": ["..."], "metric": "exact_match", "extras": {}}
```

파일 내의 모든 예제는 하나의 지표를 공유합니다. 파일 이름이 작업 이름이 됩니다.

## 지표

| 지표 | 시그니처 | 사용 용도 |
|--------|-----------|---------|
| 정확 일치(Exact Match) | 소문자화 및 공백 정규화, 일치 여부 | 산술, 사실적 답변 |
| 부분 문자열 포함(Substring Contains) | 정규화된 예측에 대상이 포함되어야 함 | 앵커 단어를 포함한 자유 형식 생성 |
| 객관식(Multiple Choice) | 첫 글자 일치 | A/B/C/D 형식의 질문 |
| ROUGE-L | 토큰화된 텍스트에 대한 LCS F1 | 요약, 패러프레이즈 |
| 코드 실행(Code Exec) | io_pairs에 대해 예측의 `f`을 실행하고 일치 수를 계산 | 코드 생성 |

모든 지표는 [0.0, 1.0] 범위의 float를 반환합니다. 작업 점수는 평균입니다.

## 어댑터

```python
class Adapter(Protocol):
    name: str
    def generate(self, prompts: list[str]) -> list[str]: ...
```

어댑터는 모델 전용 코드입니다.

## 리더보드 JSON

스키마 문자열, 타임스탬프, 작업별 점수와 지연 시간, 전체 평균을 포함합니다. 실행을 비교할 때 예제별 기록을 포함하여 예측 수준의 회귀가 보이도록 하세요.

## 실패 모드

- 지표가 [0, 1] 범위 밖으로 반환되면: 전체 점수가 해석 불가능해집니다.
- 하나의 작업 파일에 혼합된 지표: 어서션이 발생합니다. 파일당 하나의 지표만 유지하세요.
- 제한된 네임스페이스 없는 코드 실행(Code Exec): 임의의 코드 실행이 발생합니다.
- 스키마 문자열 없음: 형식 진화가 다운스트림 대시보드를 파괴합니다.
