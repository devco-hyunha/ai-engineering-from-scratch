# 비디오 생성

> 이미지는 2-D 텐서입니다. 비디오는 3-D 텐서입니다. 이론은 동일하지만, 연산은 10-100배 더 어렵습니다. OpenAI의 Sora (2024년 2월)는 이것이 가능하다는 것을 증명했습니다. 2026년에는 Veo 2, Kling 1.5, Runway Gen-3, Pika 2.0, WAN 2.2가 텍스트로부터 1080p 해상도의 프로덕션 비디오를 생성하며, 오픈 웨이트 스택(CogVideoX, HunyuanVideo, Mochi-1, WAN 2.2)은 12개월 뒤처져 있습니다.

**유형:** Build
**언어:** Python
**선수 요건:** 8단계 · 07강 (Latent Diffusion), 7단계 · 09강 (ViT), 8단계 · 06강 (DDPM)
**시간:** 약 45분

## 문제점

10초 길이의 1080p 비디오를 24fps로 생성하면 1920×1080×3 픽셀 크기의 프레임이 240개입니다. 이는 클립당 약 1.5 GB의 원시 데이터입니다. 픽셀 공간에서의 확산은 불가능합니다. 다음이 필요합니다:

1. **시공간 압축.** 프레임을 인코딩하는 것이 아니라, 비디오를 시공간 패치 시퀀스로 인코딩하는 VAE가 필요합니다.
2. **시간적 일관성.** 프레임은 수 초에 걸쳐 콘텐츠, 조명, 객체 식별자를 공유해야 합니다. 네트워크는 움직임을 모델링해야 합니다.
3. **연산 예산.** 동일한 모델 크기의 비디오 학습은 이미지 학습보다 10-100배 더 비쌉니다.
4. **조건부.** 텍스트, 이미지 (첫 번째 프레임), 오디오, 또는 다른 비디오가 조건이 될 수 있습니다. 대부분의 프로덕션 모델은 이 네 가지를 모두 허용합니다.

이 문제를 해결한 아키텍처는 시공간 패치에 적용된 **Diffusion Transformer (DiT)**이며, 거대한 (프롬프트, 캡션, 비디오) 데이터셋으로 학습됩니다. 확산 손실은 06강과 동일합니다.

## 개념

![Video diffusion: patchify, DiT, decode](../assets/video-generation.svg)

### 패치화

비디오를 3D VAE (학습된 시공간 압축)로 인코딩합니다. 잠재 변수의 모양은 `[T_latent, H_latent, W_latent, C_latent]`입니다. 크기가 `[t_p, h_p, w_p]`인 패치로 분할합니다. Sora 스타일 모델의 경우, `t_p = 1` (프레임별 패치) 또는 `t_p = 2` (두 프레임마다)를 사용합니다. 10초 길이의 1080p 비디오는 약 20,000-100,000개의 패치로 압축됩니다.

### 시공간 DiT

트랜스포머는 패치의 평평한 시퀀스를 처리합니다. 각 패치는 3D 위치 임베딩 (시간 + y + x)을 가집니다. 어텐션은 일반적으로 분해됩니다:

- **공간 어텐션** 각 프레임의 패치 내에서.
- **시간 어텐션** 동일한 공간 위치에서 프레임 간에.
- **전체 3D 어텐션**은 16-100배 더 비쌉니다. 저해상도나 연구 환경에서만 사용됩니다.

### 텍스트 조건부 생성

대형 텍스트 인코더(T5-XXL)와의 교차 어텐션(Cross-Attention)을 사용합니다. Sora는 T5-XXL을, CogVideoX-5B는 T5-XXL을 사용합니다. 긴 프롬프트가 중요합니다. Sora의 학습 데이터셋에는 GPT로 생성된 밀집 재설명(dense re-captions)이 포함되었으며, 클립당 평균 200토큰을 사용했습니다.

### 학습

시공간(latent)에 대한 표준 확산 손실(diffusion loss, ε 또는 v 예측)을 사용합니다. 데이터: 웹 비디오 + 약 1억 개의 큐레이션된 클립 + 합성 텍스트 캡션. 연산량: 작은 연구 실행만으로도 10,000+ GPU 시간이 필요하며, Sora 규모는 100,000+입니다.

## 구현하기

`code/main.py`는 핵심적인 시공간 DiT 개념을 시뮬레이션합니다. 작은 합성 비디오를 패치화(patchify)하고, 각 패치에 위치 임베딩을 추가한 후, 패치에 대한 트랜스포머 스타일의 어텐션을 통해 전체 시퀀스를 디노이즈합니다. numpy는 사용하지 않으며 순수 Python입니다. 인접한 프레임의 패치가 디노이저와 위치 임베딩을 공유할 때, 1-D에서도 시간적 일관성이 나타난다는 것을 보여줍니다.

### 1단계: 합성 1-D "비디오"를 패치화(patchify)하기

```python
def make_video(T_frames=8, rng=None):
    # "비디오"는 매끄러운 궤적을 따르는 1-D 값의 시퀀스입니다
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 2단계: 프레임별 위치 임베딩

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 3단계: 디노이저가 전체 시퀀스를 참조

각 프레임을 독립적으로 디노이즈하는 대신, 우리의 작은 네트워크는 모든 프레임 값과 그 위치 임베딩을 연결(concatenate)하여 모든 프레임의 노이즈를 공동으로 예측합니다.

### 4단계: 시간적 일관성 테스트

학습 후, 비디오를 샘플링합니다. 프레임 간 델타(delta)를 측정합니다. 모델이 시간적 구조를 학습했다면, 각 프레임을 독립적으로 샘플링했을 때보다 델타가 더 작게 유지됩니다.

## 함정

- **프레임별 독립 샘플링 = 플리커(flicker).** 각 프레임에 대해 이미지 확산(image diffusion)을 별도로 실행하면, 각 프레임의 노이즈가 독립적이므로 출력에 플리커가 발생합니다. 비디오 확산은 어텐션이나 공유 노이즈를 통해 프레임을 결합하여 이를 해결합니다.
- **소박한 3D 어텐션 = OOM.** 10초 1080p 잠재(latent) 표현에 대한 완전한 3D 어텐션은 수백억 번의 연산이 필요합니다. 공간 + 시간으로 분해(factorize)하세요.
- **데이터 캡셔닝이 크기보다 중요합니다.** Sora가 이전 연구 대비 주요 업그레이드한 점은 약 10배 더 상세한 캡션(GPT-4로 재라벨링된 클립)으로 학습한 것입니다. OpenAI의 기술 보고서에서 이 점을 명시적으로 언급했습니다.
- **첫 프레임 조건부 생성.** 대부분의 프로덕션 모델은 첫 프레임으로 이미지를 입력으로 받습니다. 이는 "이미지-투-비디오(image-to-video)" 모드이며, 학습에 이 변형이 포함됩니다.
- **물리 드리프트(drift).** 긴 클립(>10초)은 미묘한 불일치가 누적됩니다. 슬라이딩 윈도우 생성 + 키프레임 앵커링이 도움이 됩니다.

## 프로덕션 노트: 비디오 라텐트는 메모리 대역폭 문제입니다

10초 1080p 클립을 24 fps로 생성하면 240 프레임 × 1920 × 1080 × 3 ≈ 1.5 GB의 원시 픽셀이 됩니다. 4× 비디오 VAE 압축 (`2 × spatial × 2 × temporal`)을 거치면 요청당 라텐트는 약 100 MB가 됩니다. 이를 시공간 DiT로 30 스텝, 배치 1로 실행하면 스텝당 약 3 GB가 HBM을 통해 이동합니다 — 병목은 FLOPs가 아니라 메모리 대역폭입니다.

프로덕션 추론 문헌의 추론 장에서 바로 가져온 세 가지 프로덕션 조정 항목입니다:

- **DiT에 대한 TP.** 텍스트-비디오 모델은 일반적으로 10B 파라미터 이상입니다. 4개의 H100에 걸친 TP=4가 표준이며, 405B급 모델의 경우 PP=2 × TP=2를 사용합니다. 스텝당 지연은 올-리듀스 한계까지 TP에 따라 대략 선형으로 감소합니다.
- **프레임 배칭 = 연속 배칭.** 생성 시 비디오는 개념적으로 어텐션으로 연결된 프레임의 배치입니다. 연속 배칭(인플라이트 스케줄링)이 적용됩니다: 모델 아키텍처가 슬라이딩 윈도우 생성을 허용한다면, 프레임 `t-1`이 반환되는 동안 프레임 `t+1`의 렌더링을 시작합니다.
- **클립 수준 프리필 캐시.** 이미지-비디오의 경우, 첫 프레임 조건은 LLM의 프롬프트 프리필과 유사합니다: 한 번 계산하고 시간적 디코더 패스 전체에서 재사용합니다. 이는 사실상 비디오용 KV 캐시입니다.
