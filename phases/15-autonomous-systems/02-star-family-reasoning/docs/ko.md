# STaR, V-STaR, Quiet-STaR — 자기 학습 추론

> 가장 작은 자기 개선 루프는 근거(rationale) 내부에 있습니다. 모델이 사고의 연쇄(CoT)를 생성하고, 정답에 도달한 것만 유지하며, 그 데이터로 미세 조정(Fine-tuning)합니다. 이것이 STaR입니다. V-STaR은 검증기를 추가하여 추론 시점의 선택을 개선합니다. Quiet-STaR은 근거를 모든 토큰 단위로 확장합니다. 세 방법 모두 작동합니다. 그중 어느 것도 마법이 아닙니다 — 루프는 우연히 정답에 도달한 모든 지름길을 보존합니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 부트스트랩 루프 시뮬레이터)
**선수 요건:** 13단계 · 01-03 (추론 및 CoT), 15단계 · 01 (장기적 관점)
**시간:** 약 60분

## 문제점

모델에 추론을 가르치는 가장 단순한 방법은 사람이 작성한 추론 흔적(reasoning trace)을 수집하는 것입니다. 이는 비용이 많이 들고 느리며, 사람이 작성할 의향이 있는 고품질 사고의 연쇄(CoT)의 양에 의해 한계가 정해집니다.

STaR (Self-Taught Reasoner, Zelikman et al., 2022)은 이렇게 묻습니다: 모델이 스스로 근거를 작성하고 이를 알려진 정답과 채점한다면 어떨까요? 루프는 다음과 같습니다:

1. 추론 흔적과 정답을 샘플링합니다.
2. 최종 정답이 맞다면 흔적을 유지합니다.
3. 유지된 흔적으로 미세 조정(Fine-tuning)합니다.
4. 반복합니다.

이 방법은 작동합니다. GSM8K와 CommonsenseQA 모두 새로운 인간 주석 없이 개선되었습니다. 하지만 이 루프에는 내장된 편향이 있습니다: 정답을 산출한 모든 근거는, 추론 자체가 타당했는지 여부와 관계없이 유지됩니다. V-STaR (Hosseini et al., 2024)은 학습된 검증기로 이 문제를 해결합니다. Quiet-STaR (Zelikman et al., 2024)은 이 아이디어를 토큰 단위 내부 근거로 일반화합니다.

## 개념

### STaR: 효과가 있었던 것에 대한 부트스트랩

약한 추론 능력을 가진 기본 모델에서 시작합니다. 각 학습 문제에 대해 근거와 정답을 샘플링합니다. 정답이 라벨과 일치하면 (문제, 근거, 정답) 삼중항을 유지합니다. 유지된 집합으로 모델을 미세 조정(Fine-tuning)합니다. 반복합니다.

한 가지 중요한 변형이 있습니다. 모델이 문제를 절대 맞힐 수 없다면, 루프는 그 문제에서 학습할 수 없습니다. STaR은 **합리화(rationalization)**를 추가합니다: 모델이 실패한 문제에 대해, 정답을 힌트로 주입하고 모델이 정답으로 이어지는 근거를 생성하도록 다시 프롬프트합니다. 합리화된 근거는 학습 세트에 추가됩니다.

원 논문(Zelikman et al., 2022)의 결과: GPT-J 기본 모델은 합리화를 포함한 반복적인 STaR 라운드를 통해 GSM8K에서 5.8%에서 10.7%로 개선되었습니다 — 절대적으로 약 5% 포인트입니다. CommonsenseQA에서는 STaR로 학습된 GPT-J 6B가 72.5%에 도달하여, 수작업으로 주석된 근거로 학습된 GPT-3 175B (~73%)와 비교할 만한 수준입니다 — 이는 약 30배 더 큰 모델입니다.

### V-STaR: DPO로 검증자 훈련하기

STaR은 잘못된 근거를 버립니다. Hosseini et al. (2024)는 이것도 데이터라고 관찰했습니다: 모든 (근거, "이것이 맞는지") 쌍은 검증자를 훈련하는 데 사용할 수 있습니다. 그들은 정답과 오답 모두에 대해 직접 선호 최적화(DPO)를 사용하여 랭커를 구축합니다. 추론 시 N개의 근거를 샘플링하고 검증자의 최상위 선택을 고릅니다.

보고된 델타: GSM8K와 MATH에서 이전 자기 개선 기준선 대비 +4에서 +17% 포인트입니다. 대부분의 이득은 추가적인 생성자 미세 조정보다 추론 시 선택을 위해 검증자를 사용하는 데서 옵니다.

### Quiet-STaR: 토큰별 내부 근거

Zelikman et al. (2024)는 질문했습니다: 모델이 문제와 답변 사이뿐만 아니라 모든 토큰 위치에서 짧은 내부 근거를 생성하도록 학습한다면 어떨까요? Quiet-STaR은 모델이 각 예측 토큰 전에 숨겨진 "생각"을 방출하도록 훈련하고, 학습된 가중치를 통해 생각 인식 예측과 기본 예측을 혼합합니다.

결과: Mistral 7B는 작업별 미세 조정 없이 GSM8K에서 5.9%에서 10.9%로, CommonsenseQA에서 36.3%에서 47.2%로 절대 제로샷 개선이 있었습니다. 모델은 "언제 생각할지"를 학습했습니다 — 어려운 토큰은 더 긴 내부 근거를 얻고, 쉬운 토큰은 거의 얻지 못합니다.

### 세 가지 모두 안전 관련 우려를 공유하는 이유

세 가지 방법 모두 최종 정답을 기울기 신호로 사용합니다. 결함 있는 추론(지름길 이용, 추측, 일반화되지 않는 패턴 사용)을 통해 정답에 도달한 근거는 긍정적으로 강화됩니다. 분포 내(in-distribution) 문제에서는 지름길이 작동합니다. 분포 외(out-of-distribution) 문제에서는 조용히 실패합니다.

V-STaR의 검증기는 근거를 순위에 따라 학습함으로써 완화하려고 하지만, 검증기는 동일한 레이블 세트에서 학습됩니다. 정직한 불확실성보다 잘 형식화된 잘못된 추론을 선호하도록 학습될 수 있습니다. 더 안전한 설계는 STaR 스타일 데이터를 (a) 과정 감독 보상 모델(정답뿐만 아니라 중간 단계에 보상을 부여)과 (b) 단순한 지름길을 깨뜨리는 유지된 OOD 평가와 결합하는 것입니다.

### 비교

| 방법 | 학습 신호 | 추론 비용 | 데이터 낭비 | 알려진 실패 모드 |
|---|---|---|---|---|
| STaR | 정답인 경우 (근거, 정답) 유지 | 1x | 모든 잘못된 근거 폐기 | 지름길 근거 |
| STaR + 합리화 | 위 방법 + 정답 힌트 재시도 | 1x | 적음 | 합리화된 근거가 신뢰하기 어려울 수 있음 |
| V-STaR | STaR + 두 클래스 모두에서 DPO 검증기 | Nx (best-of-N) | 최소화 | 검증기가 확신 있는 오류를 강화할 수 있음 |
| Quiet-STaR | 토큰별 근거 + 혼합 가중치 | 1.5-3x | 최소화 | 여전히 정답 조건부 기울기 |

### 2026년 스택에서의 위치

STaR은 오래된 기법입니다. 하지만 이 패턴은 2025-2026년 전반에 걸쳐 다시 나타납니다. 검증 가능한 수학 문제에 대한 RL(DeepSeek-R1, Kimi-k1.5, o1)은 STaR의 정답 조건부 기울기 신호를 확장한 것입니다. 과정 보상 모델(Lightman et al., 2023; OpenAI의 "Let's verify step by step")은 과정 감독 대안입니다. AlphaEvolve(3강)는 레이블 대신 프로그램 평가자를 사용하는 STaR의 코드 버전입니다. Darwin Godel Machine(4강)는 에이전트 스캐폴딩 자체에 대한 STaR입니다.

STaR을 이해하면 이 모든 것이 명확해집니다. 이는 최소한의 자기 개선 루프입니다.

## 사용하기

`code/main.py`는 장난감 산술 작업에서 시뮬레이션된 STaR 루프를 실행합니다. 다음을 관찰할 수 있습니다:

- 부트스트랩 라운드에 따라 정확도가 상승하는 방식.
- 지름길이 슬쩍 끼어드는 방식: 시뮬레이터에는 정답을 40% 확률로 맞히지만 일반화 성능이 떨어지는 "게으른" 근거(reasoning) 클래스가 포함되어 있습니다. STaR이 이를 유지하는지 확인해 보세요.
- 검증자(V-STaR 스타일)는 추론 시에는 도움이 되지만, 학습 중에 도입된 지름길을 완전히 제거하지는 못합니다.

## 연습 문제

1. 시뮬레이터를 실행하세요. 지름길 빈도를 0으로 설정한 후 0.4로 설정하세요. 두 실행 모두 학습 분포에서 >90%의 정확도를 달성했음에도 불구하고, 최종 정확도는 얼마나 차이가 나나요?

2. 시뮬레이터에 유지된 OOD 테스트를 추가하세요. 다른 분포에서 문제를 추출하고, 부트스트랩된 모델을 인-디스트리뷰션(in-distribution) 및 OOD 세트 모두에서 평가하세요. 격차를 정량화하세요.

3. Quiet-STaR 논문(arXiv:2403.09629)의 3장을 읽어보세요. "생각 끝(end-of-thought)" 토큰과 혼합 가중치 헤드(mixing-weight head)에 대해 각각 세 문장으로 설명하세요.

4. STaR의 정답 유지 필터(keep-if-correct filter)를 각 근거 단계를 독립적으로 보상하는 프로세스 감독(process-supervised) 대안과 비교하세요. 라벨링 비용 차이와 가능한 품질 차이를 식별하세요.

5. 배포된 모델에서 지름길 근거를 포착할 수 있는 평가 하나를 설계하세요. 완벽할 필요는 없으며, STaR 루프가 강화하는 가장 단순한 지름길을 무너뜨릴 수 있어야 합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| STaR | "Self-Taught Reasoner" | 정답을 도출하는 모델 생성 근거로 미세 조정; 반복 |
| Rationalization | "Hinted retry" | 기본 모델이 실패한 문제에 정답을 주입하고 근거를 다시 프롬프트 |
| V-STaR | "Verifier STaR" | 정답 및 오답 근거 모두로 검증자를 DPO 학습하고, 추론 시 선택에 사용 |
| Quiet-STaR | "Per-token rationales" | 모든 토큰 위치에서 숨겨진 생각을 생성; 기본 예측과 혼합 |
| Answer-conditioned gradient | "Outcome-based signal" | 학습 루프가 최종 정답을 보상하며, 추론 단계는 보상하지 않음 |
| Process reward model | "Step-level verifier" | 결과(outcome)가 아닌 단계별 정확도로 학습된 보상 모델 — STaR과 대비됨 |
| Shortcut 근거 | "정답, 잘못된 추론" | 일반화되지 않는 패턴으로 라벨에 도달하는 근거; STaR은 이것을 유지합니다 |
