제안된 Claude Code 작업에 대해 에이전트가 실행을 시작하기 전에 권한 모드를 선택하고, 예산을 설정하며, 최소 격리 수준을 지정해 보세요.

다음 내용을 생성합니다:

1. **작업 프로필.** 작업이 수행하는 내용을 한 문장으로, 문제가 발생했을 때의 피해 범위(폭발 반경)를 한 문장으로 서술합니다.
2. **모드 추천.** `plan`, `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions` 중 하나를 선택합니다. 피해 범위(폭발 반경)를 참고하여 한 문장으로 정당화합니다.
3. **예산 수치.** `max_turns`, `max_budget_usd` 및 도구별 상한에 대한 구체적인 값을 설정합니다. 1시간 이상의 무인 실행의 경우, 롤백할 수 없는 인간 실수에 대해 지불할 의향이 있는 금액과 같거나 그 이하의 달러 상한을 지정합니다.
4. **격리 요구 사항.** 파일 시스템 범위(프로젝트 디렉토리만, 스크래치 디렉토리, 임시 컨테이너), 네트워크 정책(아웃바운드 금지, 허용 목록만, 전체 허용), 자격 증명 표면(없음, 범위 지정된 토큰, 넓은 토큰)을 지정합니다. `bypassPermissions` 또는 `dontAsk`의 경우, 프로덕션 자격 증명이 마운트되지 않은 임시 컨테이너 내에서 실행되어야 합니다.
5. **궤적 감사 계획.** 실행 후 사람이 궤적을 어떻게 검토할지 설명합니다. `auto`, `dontAsk` 및 30분 이상의 기간에 대한 실행에 필수입니다.

하드 거부 조건:
- 커밋되지 않은 변경 사항이 있는 저장소에 대해 `bypassPermissions`를 사용하는 경우.
- 예산 상한 없이 `auto`를 사용하는 경우.
- 환경에 넓은 자격 증명(AWS, GCP, 저장소 범위의 GitHub PAT)이 있는 상태에서 `acceptEdits` 이상의 모드를 사용하는 경우.
- 궤적 감사가 예약되지 않은 1시간 이상의 무인 실행.
- Auto Mode 분류기만으로는 새로운 작업 분포에 충분하다고 주장하는 경우.

거부 규칙:
- 사용자가 실패의 피해 범위(폭발 반경)를 명시할 수 없는 경우, 거부하고 시작하기 전에 최악의 경우를 명시한 문장을 요구합니다.
- 사용자가 프로덕션 데이터베이스 자격 증명이 도달 가능한 워크스페이스에서 `auto`를 요청하는 경우, 거부하고 먼저 범위 지정된 자격 증명이나 임시 컨테이너를 요구합니다.
- 제안된 예산 상한이 사용자가 나쁜 실행에서 감당할 수 있는 손실 한도를 초과하는 경우, 이를 거부하고 더 낮은 상한을 요구합니다.

출력 형식:

다음 내용을 포함한 한 페이지 실행 카드를 반환합니다:
- **작업 요약** (한 문장)
- **폭발 반경** (한 문장, 최악의 경우)
- **모드** (명시적)
- **예산** (`max_turns`, `max_budget_usd`, 도구별 상한)
- **격리** (fs 범위, 네트워크 정책, 자격 증명 표면)
- **감사 계획** (누가 궤적을 검토하는지, 언제, 어떤 평가 기준에 따라)
