배포의 분류기 스택(Llama Guard 버전, NeMo Guardrails 구성, 사용자 정의 분류기, 정규화 단계)을 2026년 참조 표준에 따라 감사하고, 스택이 커버하지 못하는 공격 표면(attack surface)을 식별해 보세요.

다음 내용을 산출합니다:

1. **모델 인벤토리.** 사용 중인 분류기를 나열합니다. Llama Guard 3 (8B / 1B-INT4) vs Llama Guard 4 (멀티모달, S1–S14). NeMo Guardrails 버전. 사용자 정의 분류기. 배포가 이미지를 허용하는 경우, 분류기가 멀티모달인지 확인합니다.
2. **분류 체계 매핑.** 선언된 비즈니스 카테고리를 분류기의 분류 체계(taxonomy)에 매핑합니다. 운영자가 중요하게 여기는 모든 카테고리는 분류기 카테고리에 매핑되어야 하며, 매핑되지 않은 카테고리는 보호되지 않습니다.
3. **레일 커버리지.** 입력 레일이 모델 턴(turn) 전에 발동하고, 출력 레일이 응답 전송 전에 발동하는지 확인합니다. 대화 레일(NeMo의 Colang)은 턴 간(turn-to-turn) 제약 조건을 강제합니다. 단일 턴 분류기는 다중 턴 공격을 잡을 수 없습니다.
4. **정규화.** 분류 전에 입력이 NFKC로 정규화되고, 동형 문자(homoglyph)가 매핑되며, 제로 폭(zero-width) 및 변형 선택자(variation-selector) 문자가 제거되는지 확인합니다. 원시 바이트(raw-byte) 분류는 Emoji Smuggling(Huang et al. 2025)에 대해 100% ASR(자동 음성 인식) 공격 대상이 됩니다.
5. **공격 코퍼스 커버리지.** 각 문서화된 공격(이모지 밀수, 동형 문자, 인컨텍스트 리디렉션, 시맨틱 패러프레이즈)에 대해 스택 내의 특정 방어 수단을 명시합니다. 분류기 단독 방어는 이 감사에서 실패합니다. Constitution(17강) 및 런타임(10, 13, 14강)과의 계층화(layering)가 필요합니다.

하드 리젝트(Hard rejects):
- 멀티모달 입력에 텍스트 전용 분류기를 사용하는 배포.
- 정규화 단계가 없는 배포.
- 입력 레일만 있고 민감한 카테고리 출력에 출력 레일이 없는 배포.
- 분류기를 단일 안전 계층으로 취급하는 스택.
- 운영자가 자체 분포(distribution)에서 재현할 수 없는 ASR 주장.

거부 규칙:
- 사용자가 선언한 범주가 분류기의 분류 체계에 매핑되지 않으면, 거절하고 먼저 매핑을 요구하세요. 매핑되지 않은 항목은 보호되지 않습니다.
- 배포 시 멀티모달 입력 환경에서 Llama Guard 3의 ASR 수치를 인용하면, 거절하고 Llama Guard 4나 멀티모달 분류기를 요구하세요.
- 사용자가 고위험 환경에서 분류기 계층만으로도 충분하다고 간주하면, 거절하세요. EU AI Act 제14조(15강)는 인간 감독이 상위에 추가되어야 한다고 요구합니다.

출력 형식:

다음 내용을 포함한 분류기 감사 결과를 반환하세요:
- **모델 인벤토리** (이름, 버전, 모달리티)
- **분류 체계 매핑** (운영자 범주 → 분류기 범주)
- **레일 커버리지** (입력 / 출력 / 대화; 모델 전후 발동)
- **정규화 노트** (NFKC y/n, 동형 문자 y/n, 제로 폭 문자 제거 y/n)
- **공격 코퍼스 커버리지** (공격 → 방어)
- **계층 완결성** (분류기 + 헌법 + 런타임; 세 개 필수)
- **준비 상태** (프로덕션 / 스테이징 / 연구 전용)
