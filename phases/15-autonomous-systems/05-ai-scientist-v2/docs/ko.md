# AI Scientist v2 — 워크숍 수준의 자율 연구

> Sakana의 AI Scientist v2 (Yamada et al., arXiv:2504.08066)는 가설, 코드, 실험, 그림, 작성, 제출을 포함한 전체 연구 루프를 실행합니다. 생성된 논문이 ICLR 2025 워크숍의 동료 심사를 통과한 최초의 시스템입니다. 독립적인 평가 (Beel et al.)에 따르면 실험의 42%가 코딩 오류로 실패했으며, 문헌 검토가 확립된 개념을 자주 새로운 것으로 잘못 분류했습니다. Sakana의 자체 문서에서는 코드베이스가 LLM이 작성한 코드를 실행하며 Docker 격리를 권장한다고 경고합니다. 이 그림의 양쪽 모두 핵심입니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 연구 루프 상태 기계 장난감)
**선수 요건:** 15단계 · 03강 (AlphaEvolve), 15단계 · 04강 (DGM)
**시간:** 약 60분

## 문제점

연구는 개방형 작업입니다. AlphaEvolve의 알고리즘적 검색이나 DGM의 벤치마크로 제한된 자기 수정과 달리, 연구 결과에는 기계가 검증 가능한 정확성 기준이 없습니다. 논문은 단위 테스트가 아니라 심사자에 의해 판단됩니다. 이는 루프를 닫기 어렵게 만들며, 닫히면 더 가치 있습니다. 왜냐하면 연구는 누적적 진보가 존재하는 곳이기 때문입니다.

AI Scientist v1 (Sakana, 2024)은 사람이 작성한 템플릿에서 시작하여 루프를 닫았습니다. LLM은 고정된 골격 내에서 실험을 채웠습니다. AI Scientist v2 (Yamada et al., 2025)는 비전-언어 모델 (VLM)(Vision-Language Model (VLM)) 비판 루프를 사용하는 에이전트 트랜스포머 검색(agentic tree search)을 통해 템플릿 요구 사항을 제거합니다. 이 시스템은 아이디어를 생성하고, 실험을 구현하며, 그림을 만들고, 논문을 작성하고, 심사자 피드백에 대해 반복합니다.

동료 심사 판정: v2가 생성한 논문 한 편이 ICLR 2025 워크숍에서 채택되었습니다 (공개됨). 독립적인 평가 판정: 이 시스템은 신뢰할 수 있는 수준에서 멀리 떨어져 있습니다. 두 판정 모두 사실입니다.

## 개념

### 아키텍처

1. **아이디어 생성.** LLM은 주제와 이전 문헌을 조건으로 연구 아이디어를 제안합니다. v1은 템플릿을 사용했습니다. v2는 가설 공간에 대한 에이전트 검색을 사용합니다.
2. **신규성 확인.** 문헌 검색 단계는 아이디어가 이미 출판되었는지 확인합니다. Beel et al.의 평가에서 발견된 오분류가 발생하는 단계입니다. 확립된 방법이 자주 새로운 것으로 분류됩니다.
3. **실험 계획.** 에이전트(Agent)가 실험 프로토콜을 작성하고 코드를 작성합니다.
4. **실행.** 코드가 샌드박스(Sandbox)에서 실행됩니다. 실패는 재시도 루프(Retry Loop)로 피드백됩니다. Beel 등의 측정 결과, 이 단계에서 실험의 42%가 코딩 오류로 실패했습니다.
5. **그림 생성.** 비전-언어 모델 (VLM)(Vision-Language Model (VLM))이 생성된 그림을 읽고 명확성을 위해 다시 작성합니다. 이는 v2의 주요 기술적 추가 사항이었습니다.
6. **논문 작성.** LLM (대규모 언어 모델)(LLM (Large Language Model))이 논문을 초안하고 내부 리뷰어(Reviewer)와 반복합니다.
7. **선택 사항: 제출.** 논문이 저널에 제출됩니다.

### 워크숍 수용 결과가 의미하는 바

v2가 생성한 논문 한 편이 ICLR 2025 워크숍의 동료 심사를 통과했습니다. 저자들은 프로그램 위원회에 논문의 출처를 공개했습니다. 이 수용은 하나의 데이터 포인트(데이터 포인트)이며, 시스템이 "연구를 수행한다"고 주장하는 근거는 아닙니다.

중요한 맥락: 워크숍 논문은 주요 컨퍼런스 논문보다 기준이 낮습니다. 동료 심사는 노이즈가 많으며, 매일 제출된 논문 중 일부만 수용됩니다. 하나의 성공은 개념 증명(Proof of Concept)일 뿐, 신뢰성 주장이 아닙니다. Nature 2026 논문은 엔드투엔드 루프를 문서화했으며 인간 연구자가 공동 저자로 참여했습니다. "시스템이 Nature 논문을 작성했다"는 아닙니다.

### 독립적 평가가 발견한 사항

Beel 등(arXiv:2502.14297)은 외부 평가를 수행했습니다. 주요 발견:

- **실험 실패.** 실험의 42%가 코딩 오류(잘못된 import, 모양 불일치, 정의되지 않은 변수)로 실패했습니다. 재시도 루프(Retry Loop)는 일부만 잡았습니다.
- **신규성 오명명.** 문헌 검색 단계는 확립된 개념을 신규로 자주 표시했습니다. 이는 연구의 환각(Hallucination)에 해당합니다.
- **표현 품질 격차.** 비전-언어 모델 (VLM)(Vision-Language Model (VLM))의 그림 비평은 출판급 시각 자료를 생성하여 근본적인 실험적 약점을 가렸습니다.

마지막 발견은 이 단계에서 중요합니다. 설득력 있는 연구를 수행하지 않으면서 설득력 있는 출력(Output)을 생성하는 시스템은 명백히 실패하는 시스템보다 더 위험합니다. 평가는 그림에서 멈추지 않고 근본적인 주장에까지 도달해야 합니다.

### 샌드박스(Sandbox) 탈출 우려

Sakana의 저장소 README는 다음과 같이 경고합니다:

> 이 소프트웨어는 LLM이 생성한 코드를 실행하는 특성을 가지고 있어 안전성을 보장할 수 없습니다. 위험한 패키지, 통제되지 않은 웹 접근, 의도하지 않은 프로세스 생성 등의 위험이 있습니다. 사용 시 위험을 감수해야 하며, Docker 격리를 고려해 보세요.

이것은 검증되지 않은 영역에서의 자율성의 운영 형태입니다. LLM이 코드를 작성하고, 코드가 실행되며, 코드는 프로세스가 허용하는 모든 작업을 수행할 수 있습니다. 파일 시스템, 네트워크, 프로세스 동작을 하드 리미트로 제한하는 샌드박스가 없다면, 자율적인 연구 에이전트는 데이터를 유출(Data Exfiltration)하거나, 컴퓨팅 자원을 소진하거나, 자기 자신을 재작성할 수 있습니다.

AlphaEvolve의 샌드박스 스토리는 평가자가 엄격하기 때문에 더 쉽습니다. AI Scientist v2의 루프는 개방형 코드를 개방형 목표로 실행합니다. 따라서 더 강력한 격리(Docker 최소; seccomp / gVisor 권장)가 필요하며, 시스템 밖으로 나가기 전에 모든 제출물에 대한 수동 검토가 필요합니다.

### 프론티어 스택에서 v2의 위치

| 시스템 | 목표 | 출력 유형 | 평가자 | 알려진 실패 |
|---|---|---|---|---|
| AlphaEvolve | 알고리즘 | 코드 | 단위 + 벤치마크 | 평가자 엄격성에 의해 제한됨 |
| DGM | 에이전트 스캐폴딩 | 코드 | SWE-bench | 보상 해킹 |
| AI Scientist v2 | 연구 논문 | 텍스트 + 코드 + 그림 | 동료 심사 (약함) | 실험 실패, 라벨 오기, 연약함을 가리는 다듬기 |

v2는 세 가지 중 가장 약한 자동 평가자, 가장 넓은 출력 표면, 그리고 공개 산출물까지 가장 짧은 경로를 가지고 있습니다. 운영 통제(샌드박스, 검토, 공개)가 안전 작업의 대부분을 수행하고 있습니다.

## 사용하기

`code/main.py`는 v2 루프를 상태 머신으로 시뮬레이션합니다: 아이디어 → 신규성 체크 → 실험 → 그림 → 작성 → 검토 → 승인 또는 반복. 각 상태는 Beel 등의 연구 결과에서 가져온 설정 가능한 실패 확률을 가지고 있습니다. N번 루프에 대해 시뮬레이터를 실행하고 다음을 세어 보세요:

- 얼마나 많은 아이디어가 제출에 도달하는지.
- 다듬어진 논문이 숨기는 치명적인 실험적 결함이 있는 제출물이 얼마나 많은지.
- 재시도 예산이 품질과 수확량 간에 어떻게 트레이드오프되는지.

## 연습 문제

1. `code/main.py`을 기본 매개변수로 실행해 보세요. 루프 실행 중 "깨끗한" 논문이 생성되는 비율은 얼마이며, 그림 비평이 숨겨버린 실험 결함(flaw)이 있는 논문이 생성되는 비율은 얼마입니까?

2. 기본값은 이미 Beel et al.의 42% / 25%를 사용합니다. `--experiment-failure 0.20 --novelty-mislabel 0.10`으로 재실행한 후 `--experiment-failure 0.60 --novelty-mislabel 0.40`으로 재실행해 보세요. 두 실행 간에 다듬어졌지만 결함이 있는 논문이 차지하는 비율이 어떻게 변합니까?

3. Sakana의 AI Scientist v2 저장소 README에서 샌드박스 요구 사항을 읽어 보세요. 다일(multi-day) 자율 실행을 위해 Docker 외에 적용할 추가 제한 두 가지를 나열해 보세요.

4. Beel et al.의 섹션 4에서 발표 품질 격차(presentation-quality gap)에 대해 읽어 보세요. 다듬어지고 있어 보이지만 실험적으로 결함이 있는 논문을 잡아낼 추가 평가자(evaluator) 하나를 설계해 보세요.

5. "박사 학위 소지자가 모든 논문을 읽는 것"보다 확장성이 좋은 연구 에이전트 출력에 대한 인간 검토 프로토콜을 제안해 보세요. 병목 현상을 식별하고 이를 해결하는 설계를 해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| AI Scientist v1 | "Sakana의 템플릿 기반 연구 에이전트" | 고정된 골격(scaffold)에 실험을 채워 넣음 |
| AI Scientist v2 | "템플릿 없는 연구 에이전트" | VLM 그림 비평을 포함한 에이전트 트리 검색 |
| 에이전트 트리 검색 | "분기하는 연구 에이전트" | 여러 실험 계획을 병렬로 확장; 내부 비평가로 가지치기(pruning) |
| 비전-언어 비평 | "그림에 대한 VLM 다듬기(polish)" | 멀티모달 모델이 그림을 읽고 명확성을 위해 재작성 |
| 문헌 검색 | "신규성 확인" | 선행 연구를 검색하여 아이디어의 신규성을 확인 — 오라벨(mislabel)로 문서화됨 |
| 다듬기 가림(masking) | "예쁜 논문, 망가진 연구" | 발표 품질이 실험 품질을 초과하여 약점을 숨김 |
| 샌드박스 탈출 | "LLM 코드가 탈출" | 에이전트가 실행한 코드가 루프 설계자가 의도하지 않은 작업을 수행 |
