제안된 장기 실행 에이전트 배포(Temporal + OpenAI Agents SDK, PostgreSQL 체크포인터를 사용하는 LangGraph, Microsoft Agent Framework, Claude Code Routines, Cloudflare Durable Objects, 또는 자체 구축한 유사 시스템)에 대해 내구성 있는 실행(Durable Execution) 패턴과 비교하여 설계를 감사해 보세요.

다음 내용을 산출합니다:

1. **활동 인벤토리.** 모든 활동(LLM 호출, 도구 호출, HTTP 요청, 파일 쓰기)을 나열합니다. 각 활동이 재시도 정책, 시간 제한, 멱등성 키(Idempotency)를 포함하는 활동으로 감싸져 있는지 확인합니다. 활동 경계 밖의 원시 LLM 호출은 신뢰성 공백입니다.
2. **워크플로 결정성.** 워크플로 코드 내부의 모든 비결정적 읽기(벽시계, 난수, 외부 상태)를 식별합니다. 각각은 사이드이펙트 활동으로 등록되어 재실행 시 동일한 값을 반환해야 합니다. 숨겨진 비결정성은 재실행 드리프트의 가장 흔한 원인입니다.
3. **체크포인트 백엔드.** 백엔드(PostgreSQL, SQLite, Redis, Durable Objects)를 명시합니다. 배포 후에도 생존하는지 확인합니다. SQLite는 개발 전용입니다. Redis는 AOF 또는 스냅샷 구성이 필요합니다. Cloudflare Durable Objects는 투명하지만 고유 키 규율이 필요합니다.
4. **인간 입력 상태.** 인간 개입 루프(HITL)를 위한 일시 중지가 폴링 루프가 아닌 일급 워크플로 상태인지 확인합니다. 워크플로는 승인 도착 시 정확히 재개되는 외부 신호(승인 큐, 웹훅, `interrupt()` 프리미티브)에서 차단되어야 합니다.
5. **재개 시 인간 개입 루프(HITL) 정책.** 충돌 후 재개하는 경우, 다음 활동을 실행하기 전에 새로운 인간 개입 루프(HITL)가 필요한지 명시합니다. 이 정책이 없으면, 충돌 전에 부여된 승인이 컨텍스트가 변경된 상태에서 승인된 작업을 다시 실행할 수 있습니다. 긴 시간 범위에 있어 중요합니다.

하드 리젝트:
- LLM 호출이 활동으로 감싸지지 않은 Agent SDK 사용.
- 배포 후 생존하지 못하는 체크포인트 백엔드.
- 벽시계나 난수를 활동 감싸기 없이 임베드한 워크플로.
- 인간 입력을 신호가 아닌 폴링 루프로 모델링합니다.
- HITL-on-resume 정책이 없는 장기 실행 (1시간 이상)
- 내구성 위에 예산 킬 스위치 (13강)가 계층화되지 않은 실행

거부 규칙:
- 사용자가 사이드 효과 활동에 명시적인 멱등성(Idempotency)이 없는 내구성 워크플로우를 제안하면, 거부하고 먼저 멱등성 키를 요구합니다. 그렇지 않으면 재시도가 이중 실행을 유발합니다.
- 사용자가 재생 테스트 (워크플로우 실행, 실행 중 크래시, 재생, 이중 사이드 효과 없음 단정)를 제시할 수 없다면, 거부하고 프로덕션 전에 해당 테스트를 요구합니다.
- 사용자가 HITL 체크포인트가 없는 24시간 무인 실행을 제안하면, 거부합니다. 35분 저하 (12강 노트)는 내구성이 정확하더라도 신뢰성 문제를 만듭니다.

출력 형식:

다음 내용을 포함한 설계 리뷰 메모를 반환합니다:
- **활동 테이블** (활동, 재시도 정책, 타임아웃, 멱등성 키)
- **결정성 감사** (비결정적 읽기 및 각각의 처리 방식)
- **체크포인트 백엔드** (이름, 배포 생존 여부, 재생 테스트 상태)
- **HITL 상태 형태** (1급 상태 / 폴링 / 누락)
- **HITL-on-resume 정책** (명시적, 근거 포함)
- **준비 상태** (프로덕션 / 스테이징 / 연구 전용)
