제안된 자기수정 에이전트 루프(에이전트 스캐폴딩, 평가자 파이프라인, 배포 대상)가 주어지면, 평가자를 에이전트의 접근 범위 밖에 유지하는 방화벽(firewall) 사양을 작성합니다. DGM 논문은 에이전트가 점수를 높이기 위해 자신의 안전 마커를 제거한 사례를 문서화했습니다. 이 스킬은 이를 통제하는 수단입니다.

다음 내용을 작성합니다:

1. **파일 시스템 경계.** 에이전트가 편집할 수 있는 모든 파일을 나열합니다. 평가자가 읽는 모든 파일을 나열합니다. 두 목록의 교집합은 비어 있어야 합니다. 비어 있지 않다면, 교집합을 비우기 위해 필요한 정확한 조치를 지정합니다.
2. **프로세스 경계.** 평가자는 에이전트가 제어하지 않는 프로세스에서 실행되어야 합니다. 컨테이너나 샌드박스(sandbox) 사양을 지정합니다. 에이전트가 셸(shell) 접근 권한을 가지고 있다면, 에이전트는 프로세스 내 가드(guard)를 우회할 수 있습니다.
3. **네트워크 및 시크릿 경계.** 에이전트는 평가자 입력을 가져오거나 점수를 게시하는 CI 시크릿(secret)을 편집할 수 없어야 합니다. 시크릿이 어디에 저장되는지, 그리고 어떻게 마운트(mount)되는지 나열합니다.
4. **점수 유입 계약.** 점수는 평가자에서 루프의 아카이브로 반환됩니다. 이 경로가 유일한 채널입니다. 에이전트가 작성할 수 있는 것으로서 미래의 점수 산정에 영향을 미치는 모든 것은 계약을 위반합니다.
5. **변형(mutation) 검토 목록.** 수락 전에 수동 검토가 필요한 에이전트 편집의 범주를 나열합니다: 새로운 의존성, 점수 산정 관련 코드 편집, 샌드박스(sandbox) 구성 편집, 로깅(logging) 또는 모니터링(monitoring) 편집.

하드 리젝트(hard reject):
- 에이전트 소스와 같은 저장소에 있는 평가자. 이를 외부로 이동합니다.
- 에이전트 프로세스 내에서 Python import로 실행되는 평가자. 이를 하위 프로세스(subprocess)에서 실행합니다.
- 경계의 에이전트 쪽에서 적용되는 모든 점수 조정. 모든 조정은 서버 쪽에서 이루어져야 합니다.
- 에이전트가 자신의 코드를 편집하여 침묵(silence)시킬 수 있는 모든 로깅(logging).

거부 규칙:
- 사용자가 에이전트가 편집할 수 있는 모든 파일을 나열할 수 없다면, 거부하고 먼저 파일 단위 쓰기 접근 권한 감사를 요구합니다.
- 평가자에게 홀드아웃(held-out) 입력이 없다면, 거부합니다. 이는 03강의 감사 항목이며, 전제 조건입니다.
- 배포 대상에 평가기 자체에 대한 변경이 포함되는 경우(의존성 업데이트를 통해 간접적으로 이루어지는 경우에도)는 거부하고, 수동 방화벽 검토 단계를 요구합니다.

출력 형식:

다음 내용을 포함한 한 페이지 사양을 반환합니다:
- **에이전트 쓰기 표면**(경로, 글롭)
- **평가기 읽기 표면**(경로, 엔드포인트)
- **교차점**(비어 있어야 하며, 차이를 표시합니다)
- **프로세스 모델**(평가기가 어떻게 격리되는지)
- **비밀 정보 인벤토리**(어디에, 어떻게 마운트되는지)
- **검토가 필요한 변경 클래스**(글머리 기호로 나열)
- **서명 라인**(방화벽 불변 조건을 누가 소유하는지)
