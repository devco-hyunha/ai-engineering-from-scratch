# 자율 코딩 에이전트 생태계 (2026)

> SWE-bench Verified는 3년 미만의 기간 동안 4%에서 80.9%로 상승했습니다. 동일한 Claude Sonnet 4.5는 SWE-agent v1에서 43.2%, Cline 자율 모드에서 59.8%의 점수를 기록했습니다. 이제 모델 자체만큼이나 모델周围的인 스캐폴딩이 중요해졌습니다. OpenHands (구 OpenDevin)는 가장 활발한 MIT 라이선스 플랫폼이며, CodeAct 루프는 JSON 도구 호출 대신 샌드박스에서 Python 액션을 직접 실행합니다. 주요 수치들은 방법론적 문제를 숨기고 있습니다: SWE-bench Verified의 500개 작업 중 161개는 1~2줄 변경만 필요하며, SWE-bench Pro (10줄 이상 작업)는 동일한 최첨단 모델에서 23~59%에 머무릅니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, CodeAct vs JSON 도구 호출 비교)
**선수 요건:** 14단계 · 07강 (도구 사용), 15단계 · 01강 (장기 에이전트)
**시간:** 약 45분

## 문제점

"어떤 코딩 에이전트가 최적인가"는 잘못된 질문입니다. 올바른 질문은 다음과 같습니다: 내 작업과 일치하는 작업 분포에서, 프로덕션에서 실행할 스캐폴딩을 사용했을 때, 엔드투엔드 신뢰성은 얼마인가?

2022년에서 2026년 사이, 이 분야는 스캐폴딩 — 검색 레이어, 플래너, 샌드박스, 편집-검증 루프, 피드백 형식 —이 핵심적인 역할을 한다는 것을 학습했습니다. Claude Sonnet 4.5는 SWE-agent v1에서 SWE-bench Verified 점수 43.2%를 기록했으며, 동일한 모델이 Cline의 자율 스캐폴딩 내부에서는 59.8%를 기록했습니다. 가중치는 동일하지만 절대 점수 차이가 16.6점입니다. 기본 모델은 구성 요소이며, 루프가 제품입니다.

동반 문제는 벤치마크 포화가 퇴행을 숨긴다는 것입니다. SWE-bench Verified는 거의 포화 상태에 가까우며, 쉬운 작업 꼬리 (500개 작업 중 ≤2줄 변경이 필요한 161개)가 상위 점수를 끌어올립니다. 실제 품질은 SWE-bench Pro (10줄 이상 변경)와 같은 분포에서 더 잘 측정되며, 여기서 동일한 리더들도 여전히 23~59%에 머무릅니다.

## 개념

### SWE-bench, 한 단락

SWE-bench (Jimenez et al.)는 실제 GitHub 이슈와 정답 패치를 사용하여, 에이전트가 테스트 스위트를 통과하는 패치를 생성하도록 요청합니다. SWE-bench Verified (OpenAI, 2024)는 모호하거나 깨진 작업을 제거한 인간이 큐레이션한 500개 작업 하위 집합입니다. SWE-bench Pro는 더 어려운 후속 벤치마크로, 10줄 이상의 변경이 필요한 작업을 포함하며, 현재 최첨단 에이전트들은 23–59%의 성능을 기록하고 있습니다.

### 2022년 → 2026년 곡선이 실제로 보여주는 것

- **2022년**: 원시 SWE-bench에서 연구 모델의 성능은 약 4%입니다.
- **2024년**: GPT-4 + Devin 스타일 스캐폴딩은 약 14%, SWE-agent는 약 12%입니다.
- **2025년**: Aider와 SWE-agent 내부의 Claude 3.5/3.7 Sonnet은 40–55% 범위로 성능을 끌어올립니다.
- **2026년**: Claude Sonnet 4.5 및 최첨단 경쟁자들은 SWE-bench Verified에서 70–80% 이상의 성능을 기록합니다. Epoch AI의 리더보드가 이를 실시간으로 추적합니다.

상승 기울기는 세 가지 복합적인 요인에서 비롯되었습니다: 더 나은 기본 모델, 더 나은 스캐폴딩 (CodeAct, 리플렉션, 검증자 루프), 그리고 더 나은 벤치마크 (Verified가 노이즈를 제거함).

### CodeAct vs JSON 도구 호출

OpenHands (All-Hands-AI, arXiv:2407.16741, formerly OpenDevin)는 특정 아키텍처적 베팅을 취했습니다: 모델이 JSON 도구 호출을 방출하고 호스트가 이를 디코딩 및 실행하는 대신, 모델이 Python 코드를 방출하고 Jupyter 스타일 커널이 샌드박스에서 이를 실행합니다. 에이전트는 파일 순회, 도구 체이닝, 그리고 하나의 액션 내에서 자체 예외 처리를 수행할 수 있습니다.

트레이드오프:

- **JSON 도구 호출**: 모든 액션은 한 턴입니다; 감사하기 쉽습니다; 구성성이 제한됩니다; 각 호출이 명시적 검증자를 거치므로 기본적으로 안전합니다.
- **CodeAct**: 하나의 액션이 전체 프로그램이 될 수 있습니다; 구성성이 높습니다; 강화된 샌드박스가 필요합니다 (OpenHands는 Docker 격리를 사용함); 실패 모드에는 샌드박스 런타임이 허용하는 모든 것이 포함됩니다.

두 아키텍처 모두 프로덕션 환경에 있습니다. CodeAct는 오픈 플랫폼 (OpenHands, smolagents)에서 지배적입니다. JSON 도구 호출은 실행자를 제공자가 통제하는 관리형 서비스 (Anthropic Managed Agents, OpenAI Assistants)에서 여전히 지배적입니다.

### 2026년 환경에서의 스캐폴드

| 스캐폴드 | 라이선스 | 실행 모델 | 주목할 만한 특성 |
|---|---|---|---|
| OpenHands (OpenDevin) | MIT | Docker 내 CodeAct | 가장 활발한 오픈 플랫폼; 이벤트 스트림 재생 가능 |
| SWE-agent | MIT | Agent-Computer Interface (ACI) | 최초의 엔드투엔드 SWE-bench 스캐폴드 |
| Aider | Apache-2 | 로컬 저장소에서의 edit-via-diff | 최소한의 스캐폴드, 강력한 회귀 안정성 |
| Cline | Apache-2 | 도구 정책이 있는 VS Code 에이전트 | Sonnet 4.5에서 가장 높은 점수를 기록한 오픈 스캐폴드 |
| Devin (Cognition) | Proprietary | 관리형 VM + 플래너 | 최초의 "AI 소프트웨어 엔지니어" 제품 카테고리 |
| Claude Code | Proprietary | 권한 모드 + 루틴 | 10강에서 에이전트 루프를 상세히 다룹니다 |

### 스캐폴딩이 지배하는 이유

코딩 실행은 장기 궤적(01강)입니다. 신뢰성은 단계가 누적됨에 따라 증가합니다. 스캐폴딩이 점수를 높이는 세 가지 영역:

1. **검색**: 읽을 파일을 정확히 찾는 것은 조용한 병목입니다. SWE-agent의 ACI, OpenHands의 파일 인덱스, Aider의 repo-map은 모두 이 문제를 해결합니다.
2. **검증자 루프**: 테스트 실행, 스택 트레이스 읽기, 재시도는 SWE-bench에서 10점 이상의 차이를 만듭니다.
3. **오류 격리**: 오류 발생 시 롤백하는 샌드박스는 손상의 누적 방지합니다. 검증자 루프가 있는 모델과 없는 모델은 완전히 다른 제품처럼 보입니다.

### 벤치마크 포화와 실제 분포

OpenHands 저자와 Epoch AI는 SWE-bench Verified가 쉬운 꼬리를 가지고 있음을 지적합니다: 500개 작업 중 161개는 1~2줄의 변경만 필요합니다. 높은 점수는 부분적으로 이 꼬리에 의해 주도됩니다. SWE-bench Pro는 10줄 이상의 변경으로 제한하며, 프론티어 시스템에서도 23~59% 범위의 점수를 반환합니다. 프로덕션 분포는 Verified보다 Pro에 훨씬 가깝습니다.

에이전트 선택에 대한 시사점: 자체 버그 백로그의 Pro 유사 하위 집합을 실행하세요. 중요한 점수는 출시하는 작업에 대표적인 작업에서의 점수입니다.

## 사용하기

`code/main.py`는 고정된 미니 작업 분포에서 두 개의 토이 에이전트 스캐폴드를 비교합니다:

1. 한 턴에 하나의 액션을 취하는 **JSON 도구 호출** 스캐폴드.
2. 각 액션마다 작은 Python 스니펫을 방출할 수 있는 **CodeAct** 스캐폴드.

두 경우 모두 스텁 "모델"(결정적 규칙)을 사용하므로, 비교는 모델 품질이 아닌 스캐폴드를 분리합니다. 출력에 따르면 CodeAct 스캐폴드는 더 큰 액션별 폭발 반경의 대가로 더 적은 턴 수로 더 많은 작업을 해결합니다.

## 출시하기

`outputs/skill-scaffold-audit.md`는 도입 전에 제안된 코딩 에이전트 스캐폴드를 감사하는 데 도움이 됩니다: 검색 품질, 검증자 존재 여부, 샌드박스 격리, 그리고 벤치마크와 분포의 적합성입니다.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 동일한 작업 세트에서 각 스캐폴드가 몇 번의 턴을 사용하나요? 각 스캐폴드의 액션별 폭발 반경은 얼마인가요?

2. OpenHands 논문(arXiv:2407.16741)을 읽어 보세요. 이 논문은 복잡한 작업에서 CodeAct가 JSON 도구 호출보다 우수하다고 주장합니다. 논문이 인정하는 실패 모드 하나를 식별하고, 그 모드가 프로덕션 환경에서 지배적일 시점에 대해 한 문장을 작성해 보세요.

3. 두 파일에 걸쳐 10줄 이상의 변경이 필요한 버그 백로그의 작업 하나를 선택해 보세요. (a) JSON 도구 호출과 (b) CodeAct 하에서 프론티어 모델의 엔드투엔드 성공 확률을 추정해 보세요. 그 차이를 정당화해 보세요.

4. SWE-bench Verified에는 단일 파일, 1~2줄의 작업이 161개 있습니다. 이들을 제외하는 점수를 구성해 보세요. 리더보드 순위는 어떻게 바뀌나요?

5. "Introducing SWE-bench Verified" (OpenAI)를 읽어 보세요. 모호한 작업을 제거하기 위해 사용된 구체적인 방법론을 설명하고, 큐레이션이 놓칠 카테고리 하나를 지정해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| SWE-bench | "코딩 벤치마크" | 실제 GitHub 이슈와 정답 패치 및 테스트 스위트 |
| SWE-bench Verified | "정제된 하위 집합" | 500개의 인간 큐레이션 작업, 쉬운 꼬리 존재 |
| SWE-bench Pro | "더 어려운 하위 집합" | 10줄 이상의 변경; 프론티어는 23~59%에 위치 |
| CodeAct | "코드를 액션으로 사용" | 에이전트가 Python을 생성; Jupyter 스타일 커널이 샌드박스에서 실행 |
| JSON 도구 호출 | "함수 호출" | 각 액션은 실행 전에 검증되는 구조화된 JSON 페이로드 |
| 스캐폴드 | "에이전트 프레임워크" | 기본 모델 주위의 검색 + 계획자 + 실행자 + 검증자 루프 |
| ACI (에이전트-컴퓨터 인터페이스) | "SWE-agent의 형식" | 인간 셸이 아닌 LLM 인체공학에 맞춰 설계된 명령 집합 |
| 검증 루프 | "테스트 및 재시도" | 테스트 실행, 출력 읽기, 패치 수정; 모델 외 신뢰성 향상 폭이 가장 큼 |
