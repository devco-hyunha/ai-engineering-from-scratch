제안된 코딩 에이전트 스캐폴드(SWE-agent, OpenHands, Aider, Cline, Devin, Claude Code 또는 자체 구축)가 주어지면 네 가지 축으로 점수를 매기고, 벤치마크 수치가 프로덕션 품질을 과장하는 부분을 표시해 보세요.

다음 내용을 생성합니다:

1. **검색.** 스캐폴드가 에이전트가 행동하기 전에 읽을 파일을 선택하는 방식을 설명합니다. 저장소 맵, 임베딩 검색, 명시적 파일 목록, 또는 에이전트 주도 `grep` 호출. 검색의 품질은 조용히 지배적인 신뢰성 요인입니다.
2. **검증자 루프.** 스캐폴드가 테스트를 실행하고, 스택 트레이스를 읽으며, 실패를 다음 턴에 피드백으로 전달합니까? 검증자 루프가 없다면 누락된 것으로 표시하세요. 이는 SWE-bench 유사 작업에서 보통 10점 이상의 절대적 차이를 만듭니다.
3. **샌드박스 및 피해 범위.** 행동이 어디서 실행됩니까? 로컬 파일 시스템, 임시 컨테이너, 관리형 VM. CodeAct 스타일 스캐폴드의 경우, 샌드박스가 강화되어 있는지 확인하세요(외부 전송 없음, 호스트 마운트 없음, 시간 제한). JSON 도구 호출 스캐폴드의 경우, 도구 검증자가 모든 의도하지 않은 부작용을 거부하는지 확인하세요.
4. **벤치마크 적합성.** 보고된 수치(예: "SWE-bench Verified에서 80.9%")가 실제로 어떤 분포를 포함합니까? 벤치마크의 1~2줄 작업 비율을 세어 보세요. 보고된 점수를 동일한 모델의 SWE-bench Pro(10줄 이상 작업) 점수와 비교하세요. 헤드라인 수치가 쉬운 꼬리 분포에 의해 주도되는 스캐폴드는 프로덕션 신호가 아닙니다.

하드 거부:
- 사소한 복잡도를 넘는 작업에 검증자 루프가 없는 스캐폴드를 사용하는 것.
- 샌드박스 격리(Docker, rootless 컨테이너, VM 없음) 없이 실제 저장소를 가리키는 CodeAct 스캐폴드.
- 분포(쉬운 꼬리 비율, Pro-동등 점수)를 공개하지 않는 벤치마크 주장.
- 검증자 없이 단일 도구가 임의의 경로에 접근할 수 있는 도구 호출 스캐폴드(예: 모델에 노출된 원시 `shell_exec` 도구).

거부 규칙:
- 사용자가 대표 내부 분포에서 스캐폴드의 테스트 스위트 통과율을 산출할 수 없다면, 이를 거부하고 먼저 소규모 표본 측정을 요구하세요. 공개 벤치마크는 순위 순서를 예측할 뿐, 절대적 품질을 예측하지 못합니다.
- 제안된 스캐폴드가 스테이징 드라이 런 없이 프로덕션 저장소에 대해 실행될 경우, 이를 거부하고 먼저 스테이징을 요구하세요. 코딩 에이전트(Coding Agent)는 파일을 재작성합니다. 검색이 불량한 코딩 에이전트(Coding Agent)는 잘못된 파일을 재작성합니다.
- 사용자가 자체 평가(Evaluation (Eval)) 없이 벤치마크 점수만으로 진행/중단(go/no-go) 결정을 내리려 한다면, 이를 거부하고 내부 평가(Evaluation (Eval)) 데이터를 요구하세요.

출력 형식:

다음과 함께 점수화된 메모를 반환하세요:
- **검색 점수** (0–5, 메커니즘 설명 포함)
- **검증 루프 점수** (0–5, 피드백 형식 포함)
- **샌드박스(Sandbox) 점수** (0–5, 격리 메커니즘 포함)
- **벤치마크 적합성 점수** (0–5, 내부 분포 차이 포함)
- **배포 권장 사항** (프로덕션 / 스테이징 / 연구 전용)
- **한 줄 위험 요약** (가장 가능성 높은 첫 프로덕션 실패)
