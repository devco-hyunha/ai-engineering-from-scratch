# 자동화 정렬 연구 (Anthropic AAR)

> Anthropic는 독립적인 샌드박스에서 Claude Opus 4.6 자율 정렬 연구자 팀을 병렬로 운영했으며, 모든 샌드박스 외부에 로그가 저장되는 공유 포럼을 통해 이를 조정했습니다 (이로 인해 에이전트가 자신의 기록을 삭제할 수 없습니다). 약한 모델에서 강한 모델로 학습하는 문제(weak-to-strong training)에서 AAR은 인간 연구자보다 더 나은 성과를 보였습니다. Anthropic의 자체 요약에 따르면, 지정된 워크플로가 AAR의 유연성을 제한하고 성능을 저하시키는 경우가 많다고 지적합니다. 정렬 연구의 자동화는 RSP가 감지해야 하는 정확한 정렬 이탈 위험으로 타임라인을 압축하는 압축 단계입니다.

**유형:** Learn
**언어:** Python (stdlib, 병렬 연구 포럼 시뮬레이터)
**선수 요건:** 15단계 · 05강 (AI Scientist v2), 15단계 · 04강 (DGM)
**시간:** 약 60분

## 문제점

정렬 연구는 인간 연구자의 시간 측면에서 비용이 많이 듭니다. 확장 가능한 감독(scalable oversight), 보상 명세(reward specification), 약한 모델에서 강한 모델로 학습하는 문제(weak-to-strong training)와 같은 문제들은 반복당 몇 주가 걸리는 실험을 필요로 합니다. 프론티어 능력이 발전함에 따라, 정렬 작업량은 유능한 연구자의 공급 속도보다 더 빠르게 증가합니다.

자동화 정렬 연구(AAR)는 능력이 정렬을 앞지르고 있는 동일한 프론티어 모델들이 격차를 줄이는 데 기여할 수 있는지 묻습니다. Anthropic의 2026년 AAR 기반 약한 모델에서 강한 모델로 학습하는 연구에 대한 보고서(alignment.anthropic.com/2026/automated-w2s-researcher/)는 이 유형의 배포된 시스템에서 나온 최초의 공개 결과 중 하나입니다.

결과는 진정으로 긍정적입니다. AAR은 인간 기준선보다 연구 문제를 더 잘 해결했습니다. 이 결과는 또한 이 단계에서 발전시킨 모든 우려를 단일 시스템에 집중시킵니다. 정렬 연구를 자동화할 수 있다면, 안전 장치를 훼손하는 부분도 자동화할 수 있습니다. AI R&D 능력에 대한 RSP의 임계값은 이 루프를 염두에 두고 작성되었습니다.

## 개념

### 아키텍처 (공개적으로 설명된 대로)

- **병렬 에이전트.** 여러 Claude Opus 4.6 인스턴스가 AAR으로 실행되며, 각각은 독립적인 샌드박스에 있습니다. 샌드박스는 파일 시스템, 네트워크 및 프로세스 표면(surface)을 제한합니다.
- **공용 포럼.** 발견 사항은 모든 샌드박스 외부에 저장 백엔드가 위치한 공용 포럼에 게시됩니다. 에이전트는 포럼을 읽을 수 있지만, 자신의 샌드박스 내에서 포럼 레코드를 삭제하거나 편집할 수 없습니다.
- **작업 할당.** 인간이 설계한 작업 큐가 연구 문제를 AAR에 할당합니다. AAR은 분해안을 제안하고, 실험을 수행하며, 발견 사항을 작성합니다.
- **약한 모델에서 강한 모델로 훈련하는 데 초점.** 공개된 연구는 약한 모델에서 강한 모델로 훈련하는 것, 즉 더 약한 감독 모델로 더 강한 학생 모델을 훈련하는 것을 다루었습니다. AAR은 이 작업에서 인간 연구원보다 더 좋은 성능을 보였습니다.

### 샌드박스 외부 로그가 중요한 이유

로그 무결성 속성은 통제된 실험과 잠재적으로 오염된 실험의 차이입니다. AAR이 자신의 로그를 편집할 수 있다면, 실패하거나 의심스러운 실험을 은폐할 수 있습니다. Anthropic는 이 점을 직접적으로 지적합니다. 이 속성은 연구 출력물을 신뢰하기 위한 필수 조건이며, 이를 검증하는 것은 간단하지 않습니다.

인프라 측면에서의 유사점은 외부 저장소(예: S3 객체 잠금, 변경 불가능한 Datadog 로그)에 기록을 즉시 반영하는 추가 전용 로그입니다. 에이전트에는 과거 레코드를 수정할 자격이 없습니다. 이는 2026년 기업 보안 팀이 랜섬웨어에 저항하는 감사 추적 장치를 만들기 위해 사용하는 것과 동일한 패턴입니다.

### 규정된 워크플로우의 트레이드오프

Anthropic의 보고서에 따르면, 규정된 워크플로우는 AAR의 유연성을 제한하고 성능을 저하시키는 경우가 많습니다. 즉, 인간 설계자가 연구 계획을 단계별로 작성하면, AAR은 높은 수준의 목표와 분해 자유도를 부여받았을 때보다 더 나쁜 성능을 보입니다. 이는 에이전트 기반 연구(LangGraph, Microsoft의 Agent Framework) 전반의 결과와 일치합니다. 과도하게 지정된 스캐폴드는 유능한 에이전트에게 해를 끼칩니다.

안전성 함의는 미묘합니다. AAR의 성능을 향상시키는 유연성은 동시에 승인되지 않은 분해, 새로운 도구 사용, 목표 이탈을 허용하는 유연성이기도 합니다. 트레이드오프는 설계 공간의 결정입니다. 인간을 능가할 만큼의 유연성을 확보하면서도, 에이전트가 목표를 분포 밖으로 일반화할 여지를 주지 않으려면 얼마나 많은 유연성을 허용해야 할까요?

### 압축 위험

RSP v3.0 (19강)은 AI R&D 역량 임계값을 도입합니다: 인간 + AI 도구 대비 경쟁력 있는 비용으로 AI R&D 파이프라인을 완전히 자동화할 수 있는 능력입니다. DeepMind의 FSF v3에는 유사한 ML R&D 자율성 수준이 포함되어 있습니다. 두 프레임워크 모두 이 임계값을 강화된 통제의 트리거로 취급합니다.

AAR은 임계값에 한 단계 못 미칩니다: 파이프라인의 일부(특정하고 범위가 잘 정의된 작업에 대한 정렬 연구)를 자동화하지만, 엔드투엔드 역량 개발 루프는 자동화하지 않습니다. 시간표의 문제는 격차가 얼마나 빠르게 좁혀지는가입니다.

압축된 시간표는 복합적 실패에 대한 우려입니다. 정렬 연구와 역량 연구가 유사한 비율로 복합적으로 증가한다면, 정렬되지 않은 위험 표면은 역량만큼 빠르게, 혹은 그 이상으로 커집니다. 역량이 더 빠르게 복합적으로 증가한다면(역사적 추세), 격차는 넓어집니다. 이는 AAR이 조건부 좋은 것(qualified good)이라는 논거입니다: 연구 프로세스가 신뢰할 수 있을 때에만, 추가적인 정렬 결과가 격차를 줄입니다.

### AAR이 대체하지 않는 것

인간 연구자가 작업 큐를 설정하고, 결과를 검토하며, 헌법적 권한을 보유합니다. AAR은 파이프라인의 중간 부분을 가속화할 뿐, 끝부분은 가속화하지 않습니다. Anthropic의 공개된 출력물에는 AAR의 기여와 인간 연구자의 판단(무엇을 게시할지, 무엇을 철회할지, 무엇을 정제할지)이 모두 포함됩니다.

이는 연구 자체에 적용된 15강의 제안 후 커밋(propose-then-commit) 패턴과 일치합니다: AAR은 제안하고, 인간은 커밋합니다.

## 사용하기

`code/main.py`는 다중 AAR 연구 포럼을 시뮬레이션합니다. 세 개의 독립적인 "연구 에이전트"가 병렬로 실행되며, 선택적 변조 시도와 함께 발견 사항을 전용 추가(append-only) 포럼에 게시합니다.

관찰할 것:

- 샌드박스 외부 로깅이 로그 변조 시도를 어떻게 포착하는지.
- 자유로운 분해(free decomposition)를 통한 작업 할당이 더 어려운 문제에서 고정 워크플로우보다 어떻게 더 잘 수행되는지.
- 로그가 변조 증거(tamper-evident)가 아닌 경우, 단일 손상된 AAR이 포럼의 신호를 어떻게 오염시킬 수 있는지.

## 연습 문제

1. `code/main.py`를 실행하세요. "고정 워크플로우"와 "자유 분해" 설정을 비교하세요. 자유 분해가 항상 이기는가요, 아니면 고정 워크플로우가 경쟁력 있는 문제 클래스가 있나요?

2. 시뮬레이터를 수정하여 한 에이전트(Agent)가 로그 변조를 시도하도록 하세요. append-only 로그가 이를 감지하는지 확인하세요. 로그에서 감지 시그니처가 정확히 어떻게 보이는지 한 단락으로 서술하세요.

3. Anthropic의 weak-to-strong AAR 보고서를 읽어보세요. AAR이 인간 연구자를 능가한 특정 하위 작업을 식별하세요. 무엇이 이를 자동화에 적합하게 만들었나요?

4. AAR의 유연성(더 나은 결과)과 지정된 워크플로 제약(쉬운 감사) 사이의 균형을 맞추는 작업 큐 할당 정책을 설계하세요. 두 방식을 A/B 테스트하는 방법을 서술하세요.

5. RSP v3.0의 AI R&D-4 임계값을 읽어보세요. AAR이 현재 넘지 못하지만, 넘을 것으로 생각하는 요소를 한 단락으로 서술하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| AAR | "자동화된 정렬 연구자" | 정렬 문제를 자율적으로 수행하는 Claude Opus 4.6 인스턴스 |
| Weak-to-strong 학습 | "더 약한 감독자로 더 강한 모델을 학습" | AAR이 인간을 능가한 고전적인 확장 가능한 감독(scalable oversight) 벤치마크 |
| 공유 포럼 | "에이전트(Agent)가 발견 사항을 게시하는 곳" | append-only, 샌드박스(Sandbox) 외부 저장소 |
| 샌드박스(Sandbox) 외부 로그 | "에이전트(Agent)가 자신의 기록을 편집할 수 없음" | 외부 저장소에 대한 변조 증거(tamper-evident) write-through |
| 지정된 워크플로 | "인간 설계자의 단계별 계획" | AAR을 제약하며, 자유 분해(free decomposition) 대비 성능이 저하되는 경우가 많음 |
| 자유 분해 | "에이전트(Agent)가 작업 분해 방식을 결정" | 더 유능하지만, 감사하기 어려움 |
| AI R&D 임계값 | "RSP/FSF 역량 수준" | 경쟁력 있는 비용으로 R&D 파이프라인의 완전 자동화 |
| 압축된 타임라인 | "정렬(Alignment) 대 역량(Capability) 경쟁" | 역량이 정렬보다 더 빠르게 누적되면 정렬 불일치(misalignment) 위험이 증가 |
