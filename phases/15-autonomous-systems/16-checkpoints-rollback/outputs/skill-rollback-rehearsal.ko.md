제안된 장기 자율 워크플로우에 대해, 멱등성 + 전제 조건 + 검증 + 롤백 스택이 실제로 엔드 투 엔드로 작동함을 증명하는 롤백 리허설 테스트를 설계하고, 규제 기관 준비 상태를 위해 체크포인트 백엔드를 감사해 보세요.

다음 내용을 산출합니다:

1. **리허설 스크립트.** (a) 워크플로우를 시작하고, (b) 커밋 중 크래시를 발생시키며, (c) 재개하고, (d) 액션이 정확히 한 번 실행됨을 어서트(assert)하고, (e) 검증 실패를 주입하고, (f) 롤백이 실행되고 상태가 복원됨을 어서트하는 구체적인 테스트입니다. 이 테스트가 최소한 한 번 통과하지 않은 상태에서는 프로덕션 워크플로우가 실행되어서는 안 됩니다.
2. **멱등성 감사.** 멱등성 키가 제안 내용에서 파생됨(15강)을 확인하고, 커밋 로직이 명시적인 실행 상태(`pending` -> `executing` -> `committed`/`failed`)를 사용함을 확인합니다. 사이드 이펙트 전에 멱등성 키로 예약/잠금(reserve/lock)을 수행하고, 사이드 이펙트가 검증된 후에만 `committed`를 마킹합니다.
3. **전제 조건 인벤토리.** 워크플로우가 커밋 시점에 재확인해야 하는 모든 전제 조건을 나열합니다. 체크 시점과 사용 시점(time-of-check vs time-of-use)의 간격은 가장 흔한 프로덕션 버그입니다. 전제 조건은 제안(propose) 시점이 아닌 커밋 시점에 평가되어야 합니다.
4. **검증 인벤토리.** 모든 중대한 액션에 대해, 사이드 이펙트가 발생했음을 확인하는 특정 읽기(read)를 지정합니다. "200을 반환했다"는 허용되지 않습니다.
5. **롤백 인벤토리.** 모든 중대한 액션에 대해, 롤백을 인-밴드(in-band), 보상 트랜잭션(compensating transaction), 또는 아웃-오브-밴드(out-of-band) 알림으로 분류합니다. 노오프(no-op) 롤백("이것을 되돌릴 수 없음")은 제안(15강 메타데이터)에 명시적으로 언급되어야 합니다.

하드 리젝트(Hard rejects):
- 리허설된 롤백이 없는 워크플로우.
- 배포 시 데이터를 잃어버리는 체크포인트 백엔드.
- 실행 후가 아닌 실행 전에 상태를 기록하는 커밋 경로.
- 도구 호출의 반환 코드만 확인하는 "검증됨" 상태.
- 커밋 시점이 아닌 제안 시점에만 실행되는 전제 조건 체크.

거부 규칙:
- 사용자가 스테이징 환경에서 리허설 스크립트를 최소 한 번 실행하지 않은 경우, 프로덕션 롤아웃을 거부합니다.
- 사용자가 체크포인트 저장소 스키마를 제시할 수 없는 경우, 거부하고 먼저 스키마 문서화를 요구합니다. 규제 기관은 조회 가능한 상태를 원합니다.
- 워크플로우가 메모리 내 체크포인트(영속성 없음)에 의존하는 경우, 거부합니다.

출력 형식:

다음과 함께 리허설 계획을 반환합니다:
- **테스트 스크립트 개요** (단계를 어서션과 함께 나열)
- **멱등성(Idempotency) 표** (키 구성, 상태 쓰기 순서)
- **전제 조건 표** (체크 항목, 평가 시점, 결과)
- **검증 표** (동작, 이를 확인하는 읽기 연산)
- **롤백(Rollback) 표** (동작, 유형, 대상 상태)
- **백엔드 증명(Attestation)** (저장소, 배포 후 생존 여부(y/n), 조회 준비 여부(y/n))
- **준비 상태** (프로덕션 / 스테이징 / 연구 전용)
