# 브라우저 에이전트와 장기 웹 작업

> ChatGPT 에이전트 (2025년 7월)는 Operator와 deep research를 하나의 브라우저/터미널 에이전트로 통합하여 BrowseComp SOTA를 68.9%로 설정했습니다. OpenAI는 2025년 8월 31일에 Operator를 종료했습니다 — 제품 계층에서의 통합입니다. Anthropic의 Vercept 인수는 Claude Sonnet의 OSWorld 점수를 15% 미만에서 72.5%로 끌어올렸습니다. WebArena-Verified (ServiceNow, ICLR 2026)는 원본 WebArena의 11.3 퍼센트 포인트의 오탐(false-negative)률을 수정하고 258개 작업 Hard 하위 집합을 출시했습니다. 수치들은 실제입니다. 공격 표면도 실제입니다: OpenAI의 preparedness 책임자는 브라우저 에이전트에 대한 간접 프롬프트 주입(Indirect Prompt Injection)이 "완전히 패치할 수 있는 버그가 아니다"라고 공개적으로 선언했습니다. 문서화된 2025–2026년 공격: Tainted Memories (Atlas CSRF), HashJack (Cato Networks), 그리고 Perplexity Comet의 원클릭 하이재킹.

**유형:** Learn
**언어:** Python (stdlib, 간접 프롬프트 주입 공격 표면 모델)
**선수 요건:** 15단계 · 10강 (권한 모드), 15단계 · 01강 (장기 에이전트)
**시간:** 약 45분

## 문제점

브라우저 에이전트는 신뢰할 수 없는 콘텐츠를 읽고 중대한 조치를 취하는 장기 에이전트입니다. 에이전트가 방문하는 모든 페이지는 사용자가 작성하지 않은 입력입니다. 모든 페이지의 모든 양식은 잠재적인 명령 채널입니다. 2025–2026년 공격 코퍼스는 이것이 가설이 아님을 보여줍니다: Tainted Memories는 공격자가 조작된 페이지를 통해 에이전트의 메모리에 악성 지시를 바인딩할 수 있게 합니다; HashJack은 에이전트가 방문하는 URL 조각에 명령을 숨깁니다; Perplexity Comet의 하이재킹은 단 한 번의 클릭으로 발생합니다.

방어적 상황은 불편합니다. OpenAI의 preparedness 책임자는 노골적으로 말했습니다: 간접 프롬프트 주입(Indirect Prompt Injection)은 "완전히 패치할 수 있는 버그가 아닙니다." 이는 공격이 에이전트의 읽기 대 행동 경계에 위치하며, 이 경계는 구조적으로 모호하기 때문입니다 — 모델이 읽는 모든 토큰은 원칙적으로 지시로 읽힐 수 있습니다.

이 강의는 공격 표면을 명시하고, 벤치마크 현황(BrowseComp, OSWorld, WebArena-Verified)을 명시하며, 최소한의 간접 프롬프트 주입 시나리오를 모델링하여 14강과 18강에서 실제 방어에 대해 추론할 수 있도록 합니다.

## 개념

### 2026년 현황, 시스템별 한 단락

**ChatGPT 에이전트 (OpenAI).** 2025년 7월 출시. Operator (브라우징)와 Deep Research (수 시간 연구)를 통합했습니다. 독립형 Operator는 2025년 8월 31일에 종료되었습니다. BrowseComp에서 SOTA인 68.9%를 기록했으며, OSWorld와 WebArena-Verified에서도 강력한 수치를 달성했습니다.

**Claude Sonnet + Vercept (Anthropic).** Anthropic의 Vercept 인수는 컴퓨터 사용(computer-use) 기능에 집중했습니다. OSWorld에서 Claude Sonnet의 성능을 <15%에서 72.5%로 끌어올렸습니다. Claude Computer Use는 도구 API로 출시됩니다.

**Browser Use가 포함된 Gemini 3 Pro (DeepMind).** Browser Use 통합은 컴퓨터 사용 제어 기능을 제공합니다. FSF v3 (2026년 4월, 20강)는 ML R&D 영역에서의 자율성을 구체적으로 추적합니다.

**WebArena-Verified (ServiceNow, ICLR 2026).** 잘 알려진 문제를 해결했습니다: 원본 WebArena는 약 11.3%의 오탐(false-negative) 비율을 가졌습니다 (실제로는 해결된 작업이 실패로 표시됨). Verified 릴리스는 사람이 큐레이션한 성공 기준을 사용하여 재채점하며, 258개 작업의 Hard 하위 집합을 추가했습니다 (ICLR 2026 논문, openreview.net/forum?id=94tlGxmqkN).

### BrowseComp vs OSWorld vs WebArena

| 벤치마크 | 측정 항목 | 시간 범위 |
|---|---|---|
| BrowseComp | 시간 압박 하에서 개방형 웹에서 특정 사실을 찾는 능력 | 분 단위 |
| OSWorld | 에이전트가 전체 데스크톱(마우스, 키보드, 셸)을 조작하는 능력 | 수십 분 단위 |
| WebArena-Verified | 시뮬레이션된 사이트에서의 트랜잭션형 웹 작업 | 분 단위 |
| Hard 하위 집합 | 다중 페이지 상태 전환이 포함된 WebArena-Verified 작업 | 수십 분 단위 |

축이 다릅니다. 높은 BrowseComp 점수는 에이전트가 사실을 찾는다는 것을 의미하며, 항공권을 예약할 수 있다는 것을 의미하지는 않습니다. OSWorld 점수는 "내 데스크톱에서 작동하는가"에 더 가깝습니다. WebArena-Verified는 "작업 흐름을 완료할 수 있는가"에 더 가깝습니다. 모든 생산 환경에서의 결정은 작업 분포와 일치하는 벤치마크가 필요합니다.

### 공격 표면, 명명된

1. **간접 프롬프트 주입(Indirect Prompt Injection).** 신뢰할 수 없는 페이지 콘텐츠에 지침이 포함되어 있습니다. 에이전트가 이를 읽고 실행합니다. 공개된 사례: 2024년 Kai Greshake 등, 2025년 Tainted Memories 논문, 2026년 HashJack (Cato Networks).
2. **URL 조각 / 쿼리 주입(URL fragment / query injection).** 크롤링된 URL의 `#fragment` 또는 쿼리 문자열에 명령이 포함되어 있습니다. 눈에 띄게 렌더링되지 않지만, 에이전트의 컨텍스트 내부에 남아 있습니다.
3. **메모리 바인딩 공격.** 페이지가 에이전트에게 영구적인 메모리를 작성하도록 지시합니다 (12강에서 내구성 있는 상태를 다룹니다). 다음 세션에서 메모리가 가시적인 트리거 없이 페이로드를 실행합니다.
4. **인증된 세션에 대한 CSRF 형태의 공격.** 오염된 메모리 클래스: 에이전트가 어딘가에 로그인되어 있습니다. 공격자의 페이지가 상태 변경 요청을 발행하면, 에이전트가 사용자의 쿠키로 이를 실행합니다.
5. **원클릭 하이재킹.** 시각적으로 무해해 보이는 버튼이 에이전트가 따르는 페이로드를 포함하고 있습니다. Comet 클래스.
6. **에이전트 호스트 표면의 Content-Security-Policy 허점.** 렌더링 및 도구 계층 자체가 공격 벡터가 될 수 있습니다. 브라우저 내의 에이전트 스택은 넓습니다.

### "완전히 패치 불가능한" 이유

공격은 에이전트의 능력과 동형(isomorphic)입니다. 에이전트는 업무를 수행하기 위해 신뢰할 수 없는 콘텐츠를 읽어야 합니다. 에이전트가 읽는 모든 콘텐츠는 지시문을 포함할 수 있습니다. 에이전트가 따르는 모든 지시문은 사용자의 실제 요청과 정렬되지 않을 수 있습니다. 방어책(신뢰 경계, 분류기, 도구 허용 목록, 중대한 작업에 대한 인간 개입 루프 (HITL))은 공격 비용을 높이고 피해 범위를 줄입니다. 그러나 해당 공격 클래스를 완전히 차단하지는 못합니다.

이것은 Lob의 정리(8강)와 동일한 추론 패턴입니다. 에이전트는 다음 토큰이 안전하다는 것을 증명할 수 없습니다. 안전하지 않은 토큰을 더 잘 감지할 수 있는 시스템을 구축할 수 있을 뿐입니다.

### 실제로 출시되는 방어 태세

- **읽기 / 쓰기 경계.** 읽기는 절대 중대한 결과를 낳지 않습니다. 쓰기(양식 제출, 콘텐츠 게시, 사이드 효과가 있는 도구 호출)는 시작 콘텐츠가 신뢰 경계 외부에서 온 경우 새로운 인간 승인을 요구합니다.
- **작업별 도구 허용 목록.** 에이전트는 브라우징을 할 수 있습니다. 해당 도구가 작업에 명시적으로 활성화되지 않은 한, 송금 요청을 시작할 수 없습니다. 13강에서 예산을 다룹니다.
- **세션 격리.** 브라우저 에이전트 세션은 범위가 지정된 자격 증명만 사용하여 실행됩니다. 프로덕션 인증이나 개인 이메일은 없습니다. 모든 HTTP 요청의 로그는 감사용으로 보관됩니다.
- **콘텐츠 샌itizer.** 가져온 HTML은 모델 컨텍스트에 연결되기 전에 알려진 나쁜 패턴이 제거됩니다. (쉬운 공격을 줄입니다. 정교한 페이로드를 막지는 못합니다.)
- **중대한 작업에 대한 인간 개입 루프 (HITL).** 제안 후 커밋 패턴 (15강).
- **메모리에 카나리 토큰을 배치합니다.** 메모리 항목이 발동되면 사용자에게 표시됩니다 (14강).

## 사용하기

`code/main.py`는 세 개의 합성 페이지에 대한 소형 브라우저 에이전트 실행을 모델링합니다. 한 페이지는 무해하고, 한 페이지는 가시 텍스트에 직접 프롬프트 인젝션 블롭이 있으며, 한 페이지는 URL 조각 인젝션(가시적이지 않지만 에이전트의 컨텍스트 내부에 있음)이 있습니다. 스크립트는 (a) 단순한 에이전트가 하는 일, (b) 읽기/쓰기 경계가 잡아내는 것, (c) 샌itizer가 잡아내는 것, (d) 둘 다 잡아내지 못하는 것을 보여줍니다.

## 출시하기

`outputs/skill-browser-agent-trust-boundary.md`는 제안된 브라우저 에이전트 배포의 범위를 설정합니다: 어떤 신뢰 구역을 접촉하는지, 무엇을 쓰도록 승인되었는지, 그리고 첫 실행 전에 어떤 방어 장치가 준비되어야 하는지입니다.

## 연습 문제

1. `code/main.py`를 실행합니다. 샌itizer가 잡아내지만 읽기/쓰기 경계는 잡아내지 못하는 공격과, 읽기/쓰기 경계만 잡아내는 공격을 식별합니다.

2. HashJack 스타일의 URL 조각 인젝션 한 클래스를 감지하도록 샌itizer를 확장합니다. 합법적인 조각을 가진 무해한 URL에 대한 오탐율을 측정합니다.

3. 알고 있는 실제 브라우저 에이전트 워크플로우 하나를 선택합니다 (예: "항공권 예약"). 모든 읽기와 모든 쓰기를 나열합니다. HITL이 필요한 쓰기와 그 이유를 표시합니다.

4. WebArena-Verified ICLR 2026 논문을 읽습니다. 원본 WebArena의 점수 매기기 신뢰도가 낮았던 작업 카테고리 하나를 식별하고, Verified 하위 집합이 이를 어떻게 해결하는지 설명합니다.

5. 브라우저 에이전트 환경에 대한 메모리 카나리를 설계합니다. 무엇을, 어디에 저장하며, 무엇이 경보를 발동합니까?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| 간접 프롬프트 주입(Indirect Prompt Injection) | "나쁜 페이지 텍스트" | 에이전트가 읽는 페이지의 신뢰할 수 없는 콘텐츠에 에이전트가 실행하는 지침이 포함되어 있음 |
| 오염된 메모리(Tainted Memories) | "메모리 공격" | 에이전트가 공격자가 제공한 지침을 영구 메모리에 기록함; 다음 세션에서 발동됨 |
| HashJack | "URL 조각 공격" | URL 조각 / 쿼리 문자열에 숨겨진 페이로드가 에이전트의 컨텍스트에 있지만 가시적으로 렌더링되지 않음 |
| 원클릭 하이재킹(One-click hijack) | "나쁜 버튼" | 가시적인 인터페이스 요소가 에이전트가 실행하는 후속 페이로드를 포함하고 있음 |
| BrowseComp | "웹 검색 벤치마크" | 개방형 웹에서 특정 사실을 찾는 것; 분 단위 시간 범위 |
| OSWorld | "데스크톱 벤치마크" | 전체 OS 제어; 다단계 GUI 작업 |
| WebArena-Verified | "고정 웹 작업 벤치마크" | ServiceNow의 Hard 하위 집합이 포함된 WebArena 재채점 버전 |
| 읽기/쓰기 경계 | "사이드 이펙트 게이트" | 읽기는 절대 결과가 발생하지 않음; 신뢰 밖의 콘텐츠에 대한 쓰기는 새로운 승인이 필요함 |
