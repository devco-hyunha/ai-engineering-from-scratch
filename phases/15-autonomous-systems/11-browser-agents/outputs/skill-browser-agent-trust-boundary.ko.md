제안된 브라우저 에이전트 워크플로우에 대해, 모든 읽기 작업, 모든 쓰기 작업, 그리고 첫 실행에 필요한 최소 방어 스택을 나열하는 신뢰 경계 범위 설정 문서를 작성해 보세요.

다음 내용을 작성합니다:

1. **읽기 표면.** 에이전트가 가져올 모든 출처(origin)를 나열합니다. 각 출처를 신뢰 내(in-trust, 사용자 조직이 운영한 퍼스트 파티 사이트) 또는 신뢰 외(out-of-trust, 모든 서드파티, 모든 사용자 생성 콘텐츠, 모든 검색 결과)로 분류합니다. 모든 신뢰 외 읽기 작업은 잠재적인 프롬프트 인젝션(Prompt Injection) 채널로 취급해야 합니다.
2. **쓰기 표면.** 에이전트가 수행하도록 승인된 모든 중대한 작업(양식 제출, 콘텐츠 게시, 백엔드 도구 호출, 메모리 쓰기)을 나열합니다. 각 작업에 대해 영향 범위(blast radius)와 가역성을 명시합니다.
3. **필수 방어 체계.** 최소 스택: 콘텐츠 세니타이저, 읽기/쓰기 경계(콘텐츠 출처(content_origin)가 신뢰 외일 경우 쓰기 작업은 새로운 승인을 요구함), 작업별 도구 허용 목록, 범위화된 자격 증명을 사용한 세션 격리, 영구 메모리에 카나리 토큰(Canary Token) 배치, 비가역적 작업에 대한 인간 개입 루프(HITL).
4. **벤치마크-분포 적합성.** 에이전트가 BrowseComp, OSWorld, 또는 WebArena-Verified 점수를 보고하는 경우, 벤치마크와 실제 작업 간의 분포 중복을 명시합니다. 높은 BrowseComp 점수는 예약 흐름의 신뢰성을 예측하지 못합니다.
5. **알려진 공격 체크리스트.** 배포가 (a) 가시 텍스트 주입, (b) URL 조각/쿼리 주입, (c) 메모리 바인딩 공격(Tainted Memories 클래스), (d) 인증된 세션에 대한 CSRF 형태의 공격, (e) 원클릭 하이재킹에 대해 강화되어 있는지 확인합니다. 각 항목에 대해 구체적인 방어 체계와 발동 위치를 명시합니다.

하드 리젝트(Hard Rejects):
- 프로덕션 자격 증명에 접근할 수 있으나 세션 격리가 없는 브라우저 에이전트.
- 신뢰 외 콘텐츠에서 시작된 쓰기 작업이 새로운 인간 개입 루프(HITL) 승인을 요구하지 않는 모든 배포.
- 콘텐츠 세니타이저에만 의존하는 모든 배포(세니타이저는 쉬운 공격을 잡지만, 정교한 페이로드를 통과시킴).
- 카나리 항목이 없는 영구 메모리입니다.
- 쓰기 작업에 인간 개입 루프 (HITL)(Human-in-the-Loop (HITL))가 없는 금융 거래나 고객 데이터를 다루는 워크플로입니다.

거부 규칙:
- 사용자가 주입으로 인한 잘못된 쓰기의 피해 범위(blast radius)를 명시할 수 없다면, 거부하고 명시적인 문장을 요구합니다.
- 사용자가 범위 지정된 자격 증명이 없는 스택에서 브라우저 에이전트(Agent)를 제안한다면, 거부하고 먼저 별도의 신원을 요구합니다.
- 사용자가 벤치마크 점수 (BrowseComp, OSWorld, WebArena)를 에이전트(Agent)가 "할 수" 있다는 증거로 인용하여 생산 작업을 수행한다고 주장한다면, 거부하고 실제 분포에 대한 내부 평가(Evaluation (Eval))를 요구합니다.

출력 형식:

다음과 함께 신뢰 경계(Trust Boundary) 메모를 반환합니다:
- **읽기 표면 표** (출처, 신뢰 내 / 신뢰 외)
- **쓰기 표면 표** (작업, 피해 범위, 가역적 y/n)
- **방어 스택** (구성된 계층의 목록)
- **벤치마크 적합성 노트** (해당하는 경우)
- **알려진 공격 체크리스트** (5개 행, 각 행에 방어 기법 명시)
- **배포 결정** (생산 / 스테이징 / 연구 전용)
