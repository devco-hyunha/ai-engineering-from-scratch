제안된 에이전트 배포에 대해, 12계층 참조 표준에 따라 비용 제어 스택을 감사하고, 어떤 계층이 누락되었거나, 튜닝이 부족하거나, 과도하게 튜닝되었는지 식별해 보세요.

다음 내용을 생성합니다:

1. **계층 인벤토리.** 12개 참조 계층(요청별 상한, 작업별 토큰 예산, 작업별 달러 예산, 도구별 상한, 반복 상한, 분/시간/일/월 롤링 상한, 속도 제한, 계층적 라우팅, 프롬프트 캐싱, 컨텍스트 윈도우화, 인간 개입 루프 (HITL) 체크포인트, 킬 스위치) 각각에 대해, 설정 여부와 설정 값을 명시합니다.
2. **실패 모드 매핑.** 각 시간 규모별 실패(폭주 루프, 느린 누수, 불량 릴리스, 합법적 급증)에 대해, 이를 포착하는 특정 계층과 대응 속도를 명시합니다.
3. **도구별 상한.** 에이전트가 호출할 수 있는 모든 도구를 나열합니다. 각 도구에 대해 세션별 상한과 그 이유를 명시합니다. 명시적 상한이 없는 도구는 열린 루프입니다.
4. **알림 임계값.** 상한과 별도로, 어떤 지출 속도에서 인간이 호출(paging)되는지 명시합니다. 관찰된 전자상거래 사례($1,200 → $4,800)는 주간 단위 성장 문제였으며, 월간 상한 문제가 아니었습니다.
5. **킬 스위치 경로.** 상한이 발동되면 어떤 일이 일어나나요? 깨끗한 중단, 롤백, 알림, 재활성화 절차를 확인합니다. 킬 스위치가 에이전트 외부에 위치하며, 에이전트가 자신의 상한을 수정할 수 없음을 확인합니다.

하드 거부 조건:
- 작업별 달러 예산이 없는 모든 자율 배포.
- 속도 제한이 없는 모든 무인 장기 실행.
- 새로운(<30일) 도구 추가 시 도구별 상한이 없는 도구 표면.
- 에이전트 스스로 수정할 수 있는 킬 스위치.
- 월간 상한이 유일한 상한인 경우(다른 모든 시간 규모가 보호되지 않음).

거부 규칙:
- 사용자가 오늘의 모델 가격으로 최악의 경우 실행 비용을 산정할 수 없다면, 거부하고 비용화된 추정치를 요구합니다.
- 제안된 예산이 단일 실수에 대한 조직의 허용 손실을 초과한다면, 거부하고 더 낮은 상한을 요구합니다.
- 사용자가 Auto Mode 분류기(10강)를 예산의 대체 수단으로 취급한다면, 이를 거절하세요. 분류기는 비용과 직교하는 관계이며, 두 계층 모두 필요합니다.

출력 형식:

다음 내용을 포함한 비용 관리 감사 결과를 반환하세요:
- **계층 테이블** (계층 이름, 설정 여부, 값)
- **실패 모드 커버리지** (4행: 루프 / 누수 / 릴리스 / 급증)
- **도구별 상한** (도구, 상한, 이유)
- **알림 임계값** (속도, 소유자, 채널)
- **킬 스위치 경로** (트리거, 조치, 재활성화 절차)
- **준비 상태** (프로덕션 / 스테이징 / 연구 전용)
