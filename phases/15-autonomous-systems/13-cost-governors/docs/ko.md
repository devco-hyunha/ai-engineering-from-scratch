# 액션 예산, 반복 상한, 비용 가버너

> 중규모 전자상거래 에이전트의 월간 LLM 비용은 팀이 "주문 추적" 스킬을 활성화한 후 $1,200 to $4,800으로 급증했습니다. 이는 가격 버그가 아닙니다. 에이전트가 새로운 루프를 발견하고 그 안에서 계속 지출한 것입니다. Microsoft의 Agent Governance Toolkit (2026년 4월 2일)은 이 유형의 방어에 대한 규정을 명시합니다: 요청별 `max_tokens`, 작업별 토큰 및 달러 예산, 일별/월별 상한, 반복 상한, 단계별 모델 라우팅, 프롬프트 캐싱, 컨텍스트 윈도우화, 고비용 작업에 대한 인간 개입 루프 (HITL)(Human-in-the-Loop (HITL)) 체크포인트, 예산 초과 시 킬 스위치. Anthropic의 Claude Code Agent SDK는 동일한 프리미티브를 다른 이름으로 제공합니다. 금융 속도 제한 — 예를 들어 10분 내 $50 초과 시 접근 차단 — 은 월간 상한보다 루프를 더 빠르게 포착합니다.

**유형:** Learn
**언어:** Python (stdlib, 계층형 비용 가버너 시뮬레이터)
**선수 요건:** 15단계 · 10강 (권한 모드), 15단계 · 12강 (내구성 있는 실행(Durable Execution))
**시간:** 약 60분

## 문제점

자율 에이전트는 모든 턴에서 실제 비용을 지출합니다. 채팅봇의 잘못된 출력은 나쁜 답변일 뿐이지만, 에이전트의 잘못된 루프는 청구서입니다. 이 실패 모드에 대한 업계 문서화된 용어는 "Denial of Wallet"입니다. 에이전트는 계속 추론하고, 계속 도구 호출을 하고, 계속 과금하며, 아무것도 이를 멈추지 못합니다. 아무것도 이를 멈추도록 설계되지 않았기 때문입니다.

해결책은 하나의 숫자가 아닙니다. 요청별, 작업별, 시간별, 일별, 월별 등 다양한 시간 스케일과 세분화 수준에 걸친 제한 스택입니다. 잘 설계된 스택은 폭주 루프를 몇 분 내에, 느린 누수를 몇 시간 내에, 나쁜 릴리스를 하루 내에 포착합니다. 동일한 스택은 에이전트가 장기적이고 자율적일 때 예산을 유지합니다.

이는 엔지니어링 수업입니다. 수학은 단순하지만, 팀이 실패하는 부분은 규율입니다. 아래에 나열된 제한 목록은 모두 Microsoft Agent Governance Toolkit 또는 Anthropic Claude Code Agent SDK 문서에 명시되어 있습니다.

## 개념

### 비용 가버너 스택

1. **요청별 `max_tokens`.** 간단합니다. 단일 호출이 무제한 완성을 생성하는 것을 방지합니다.
2. **작업별 토큰 예산.** 전체 실행 동안 N 토큰을 초과하지 마세요. 상한에 도달하면 강제로 중단합니다.
3. **작업별 달러 예산.** 토큰과 동일하지만 통화 단위입니다. Claude Code에서는 `max_budget_usd`를 사용합니다.
4. **도구 호출 상한.** N번 `WebFetch` 호출, N번 `shell_exec` 호출 등 최대 횟수를 제한합니다.
5. **반복 상한 (`max_turns`).** 에이전트 루프의 총 반복 횟수; 무한 추론 루프를 방지합니다.
6. **분/시간/일/월 상한.** 롤링 윈도우 방식입니다. 다양한 시간 규모에서 누수를 포착합니다.
7. **재소진 속도 제한.** 예: "10분 내 지출이 $50를 초과하면 접근을 차단합니다." 월 상한이 발동하기 전에 루프 기반 소진을 포착합니다.
8. **계층적 모델 라우팅.** 기본적으로 더 작은 모델을 사용하며, 분류기가 작업이 더 큰 모델을 필요하다고 판단할 때만 상위 모델로 전환합니다.
9. **프롬프트 캐싱.** 시스템 프롬프트와 안정적인 컨텍스트를 제공자 캐시에 저장하여 재전송 시 토큰 비용이 거의 0에 가깝습니다.
10. **컨텍스트 윈도우 관리.** 활성 컨텍스트가 임계값 아래를 유지하도록 압축/요약을 수행하여 토큰 비용을 직접 줄입니다.
11. **고비용 작업에 대한 HITL 체크포인트.** 고비용이 예상되는 작업(긴 도구 호출, 대용량 다운로드, 비용이 큰 모델 업그레이드) 전에 인간 개입(HITL)을 요구합니다.
12. **예산 초과 시 킬 스위치.** 상한이 발동하면 세션이 중단됩니다. 상한이 기록되며, 별도의 재활성화 경로가 필요합니다.

### 왜 하나의 상한이 아닌 스택을 사용하는가

단일 월 상한은 지갑이 비워진 후에야 폭주하는 에이전트를 포착합니다. 단일 요청 상한은 세션 수준에서 아무것도 포착하지 못합니다. 다양한 실패 모드에는 다양한 시간 규모가 필요합니다:

- **폭주 루프** (에이전트가 5초 재시도 루프에 갇힘): 속도 제한으로 포착됩니다.
- **느린 누수** (에이전트가 작업당 예상 작업량의 약 2배를 수행): 일 상한으로 포착됩니다.
- **나쁜 릴리스** (새 버전이 토큰을 5배 사용): 주간/월 상한으로 포착됩니다.
- **정당한 급증** (버그가 아닌 실제 수요): 명확한 로그와 함께 시간/일 상한으로 포착됩니다.

### 하네스 예산 표면

Claude Code Agent SDK는 (공개 문서에) 다음을 노출합니다:

- `max_turns` — 반복 상한.
- `max_budget_usd` — 달러 상한; 초과 시 세션이 중단됩니다.
- `allowed_tools` / `disallowed_tools` — 도구 허용 목록 및 거부 목록.
- 사용자 정의 비용 회계를 위한 도구 사용 전 훅 지점.

권한 모드 사다리(10강)와 결합해 보세요. `max_budget_usd`이 없는 `autoMode` 세션은 통제되지 않은 자율성입니다. Anthropic은 Auto Mode가 예산 통제를 필요로 한다고 명시적으로 규정하며, 분류기는 비용과 독립적입니다.

### EU AI Act, OWASP Agentic Top 10

Microsoft의 Agent Governance Toolkit은 OWASP Agentic Top 10강 EU AI Act 제14조(인간 감독) 요구 사항을 다룹니다. EU에서의 프로덕션 환경에서는 로깅과 상한 enforcement가 선택 사항이 아닙니다.

### 관측된 $1,200 → $4,800 케이스

Microsoft 문서의 실제 사례: 새로운 도구가 추가된 후 월 비용이 3배로 증가한 e-commerce 에이전트. 이 도구는 에이전트가 모든 세션에서 주문 상태를 폴링할 수 있게 허용했습니다. 루프 감지 없음. 도구별 상한 없음. 주간 성장에 대한 알림 없음. 해결책은 도구별 상한과 일일 성장 알림이었습니다. 이는 템플릿입니다: 새로운 도구 표면은 새로운 잠재적 루프이며, 모든 새로운 도구에는 자체 상한과 자체 알림이 필요합니다.

## 사용하기

`code/main.py`은 레이어링된 비용 거버너 스택이 있는 경우와 없는 경우의 에이전트 실행을 시뮬레이션합니다. 시뮬레이션된 에이전트는 몇 번의 턴 후 폴링 루프로 드리프트하며, 레이어링된 스택은 속도 윈도우 내에서 이를 포착하는 반면, 단일 월 상한은 며칠 후에야 발동합니다.

## 연습 문제

1. `code/main.py`을 실행하세요. 폴링 루프 궤적에서 반복 상한보다 속도 제한이 먼저 발동하는지 확인하세요. 이제 속도 제한을 비활성화하고 반복 상한이 에이전트를 포착하기 전까지 에이전트가 얼마나 "소비"하는지 측정하세요.

2. 브라우저 에이전트(11강)를 위한 도구별 상한 세트를 설계하세요. 어떤 도구가 가장 엄격한 상한이 필요합니까? 어떤 도구는 위험 없이 무제한으로 실행할 수 있습니까?

3. Microsoft Agent Governance Toolkit 문서를 읽으세요. 툴킷이 명명하는 모든 상한 유형을 나열하세요. 각 유형을 실패 모드(폭주 루프, 느린 누수, 불량 릴리스, 급증) 중 하나에 매핑하세요.

4. 현실적인 작업(예: "저장소에서 50개 이슈를 트리아지")에 대한 야간 무인 실행의 가격을 산정하세요. `max_budget_usd`을 포인트 추정치의 2배로 설정하세요. 2배를 정당화하세요.

5. Claude Code의 `max_budget_usd`는 세션 누적 비용에 대해 발동합니다. 외부에서 적용할 보완적인 속도 제한을 설계해 보세요. 어떤 조건이 차단(cut-off)을 유발하며, 재활성화(re-enable)는 어떤 형태가 되어야 합니까?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|---|---|---|
| Denial of Wallet | "폭주하는 청구서" | 상한선 없이 지출을 생성하는 에이전트 루프 |
| max_tokens | "요청별 상한선" | 단일 완료(completion) 크기의 상한선 |
| max_turns | "반복 상한선" | 세션 내 에이전트 루프 반복 횟수의 상한선 |
| max_budget_usd | "달러 킬 스위치" | 세션 비용 상한선; 초과 시 중단 |
| Velocity limit | "속도 상한선" | 짧은 시간 창(window) 내 지출 제한 (예: $50 / 10분) |
| Tiered routing | "작은 모델 우선" | 저렴한 모델을 기본으로 사용; 분류기가 필요하다고 판단할 때만 상위 모델로 에스컬레이션 |
| Prompt caching | "캐시된 시스템 프롬프트" | 공급자 측 캐시가 재전송 토큰 비용을 거의 0으로 줄임 |
| HITL checkpoint | "인간 승인 게이트" | 비용이 많이 드는 작업 전에 인간 승인(HITL)이 필요 |
